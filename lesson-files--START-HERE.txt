A small journey through DML: final project

This project uses the eight invented sales from chapters 6-12.
The first four sales are February; four January sales provide history.
The FACT_SALES dataset reads the physical TABLE_SALES table.
The browser preview uses local arithmetic. It does not execute dmlc or a database.

1. Extract all files to one writable directory. Keep model.dml beside query.sql.
2. Make the bundled dmlc.exe available using an absolute path or PATH.
3. Run:
   dmlc.exe --lint model.dml --output-format=json
   dmlc.exe --compile --strict query.sql --model=model.dml --output-format=json --output-dir=gen
4. Inspect the output JSON and gen SQL files. The recorded capstone query has
   status findings and exit 1 because of key-union join and simplification warnings. That is not a
   passed strict check. Inspect unmatched keys and query membership before use.
   The SQL combines current and previous month values and customer-level AVG.
5. The stored compiler observations identify the checked executable and SQL.
   A different build can behave differently. Do not treat old observations as
   proof of the selected executable's behavior.

Optional SQL Server practice exercise:
- Use a NEW, EMPTY practice database. Review setup-mssql.sql before running it.
- Run setup-mssql.sql in that database. It creates TABLE_SALES, TABLE_REGION, and
  a daily DML_CALENDAR for December 2024 through February 2025.
- The amount column is decimal so ratios retain fractional values.
- Inspect and execute the generated SQL in the same database and session.
- Check source-key uniqueness and compare every result value with expected.csv.
- Browser calculations and compile observations do not establish live result
  parity. This database exercise has not been executed by the documentation build.
