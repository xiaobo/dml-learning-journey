DuckDB：按固定业务时区划分一天

本页目录

  • 用两个当地零点界定一天
  • 重复的当地时间不是重复的时刻
  • 复现和复用

先把时刻映射到业务时区，再定义日期和一天的边界。 本配方固定使用 America/New_York，只验证 DuckDB 的物理 SQL，不宣称 DML 提供跨数据库或每个用户可切换的时区能力。

明确输入的含义 #

输入使用带明确 UTC 偏移的 TIMESTAMPTZ，表示实际时刻；连接会话设为 UTC。业务时区是 America/New_York。没有偏移的时间戳不能直接当作 UTC；需要先确认源系统如何记录它。

SET TimeZone = 'UTC';
SELECT timezone('America/New_York', TIMESTAMPTZ '2024-01-01 02:00:00+00');

得到当地时间2023-12-31 21:00:00，业务日期属于前一天。按业务日期分组时，先做同样的转换，再取日期。

用两个当地零点界定一天 #

SELECT count(*)
FROM (VALUES
  (TIMESTAMPTZ '2024-03-10 04:59:59+00'),
  (TIMESTAMPTZ '2024-03-10 05:00:00+00'),
  (TIMESTAMPTZ '2024-03-11 03:59:59+00'),
  (TIMESTAMPTZ '2024-03-11 04:00:00+00')
) events(ts)
WHERE ts >= timezone('America/New_York', TIMESTAMP '2024-03-10 00:00:00')
  AND ts < timezone('America/New_York', TIMESTAMP '2024-03-11 00:00:00');

结果为2。起点包含、终点不包含；不要假定结束时间总是起点加24小时。验证中，春季切换日为23小时，秋季切换日为25小时。

重复的当地时间不是重复的时刻 #

2024-11-03 05:30 UTC 和06:30 UTC 均映射为当地01:30。这两个时刻不同，不能只凭当地日期时间去重；保留事件主键和原始时刻。

复现和复用 #

下载项目，按 README 的 JDBC 步骤运行 jdbc/VerifyJdbc.java。验证器检查跨午夜、重复小时、23/25小时日和半开区间筛选的实际结果；失败会以非零退出。

本次使用 JDBC 分发中的 DuckDB 1.5.4 驱动。若要在 DML 数据集中复用业务日期，可先用经过验证的数据库视图完成时区归一化，再把业务日期作为模型列；这个接入步骤仍需在你的模型和连接中验证。不要将此配方描述为已验证的任意时区模型。
