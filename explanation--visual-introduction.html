A small journey through DML

A traveler arrives with one question: how much did each region sell?

Open the illustrated, interactive tutorial. It now includes twelve chapters, graded exercises, saved progress, and a final report builder. The exercise guide follows the complete beginner project. This page retains the shorter conceptual introduction.

Each sale has an identity

The traveler records four sales. These are invented rows for the illustration, not records fetched from a database.

id region amount
1 North 10
2 North 20
3 South 30
4 South 40

The source dataset has dimension: [id]: one row represents one sale. Two sales can share a region, so region cannot identify a source row. A query can still group those rows by region.

The dimension explanation describes source identity and report grouping in detail.

DML records the reusable definitions

The traveler keeps a notebook of definitions. DML is that model, written in YAML. This fragment declares two atomic measures on the sales dataset:

FACT_SALES:
  type: dataset
  table: TABLE_SALES
  dimension: [id]
  columns:
    id:
    region:
    amount:
  measures:
    sales: SUM({amount})
    cnt: COUNT(1)

sales sums the amount. cnt counts source rows. Both are atomic measures: they inherit FACT_SALES and directly aggregate its rows or column expressions without referencing other measures. Reports can reuse them at compatible evaluation grains.

DMX expresses a calculation

The notebook also records how to calculate an average:

average_sale:
  type: measure
  formula: 'DIVIDE({sales}, {cnt})'

The YAML declares a measure. The formula inside it is DMX. {sales} and {cnt} reference measures, and DIVIDE returns NULL for a zero denominator. average_sale is composite because it references other measures; it has no dataset: property.

DMX is shared expression syntax inside model definitions and query expressions. It is not a separate processing step between the model and query. The expression reference owns the syntax.

The query chooses what one result row represents

The traveler turns a telescope toward the regions:

SELECT region, AGG(sales), AGG(average_sale)
FROM MODEL
GROUP BY region

AGG references a model measure. GROUP BY region chooses one result row per region. For the four invented sales, the arithmetic gives these values:

region sales average_sale
North 30 15
South 70 35

Without grouping fields, the same model measures give total sales of 100 and an average sale of 25. Grouping by id gives one result per sale. The source identity remains [id] in every case.

At the declared source key [id], the checked compiler simplifies the aggregate to a row expression and reports a strict finding. That simplification relies on id being unique in the source data. The total and regional queries pass strict compilation on the checked build.

The checked executable is dmlc 0.3.16, build 2026-10-17 05:00:24 Z. The tutorial compiler record includes its fingerprint and validation limits.

Compilation produces SQL

The compiler combines the model and query to generate SQL. The database executes that SQL against the real source table.
