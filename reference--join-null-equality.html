Join NULL equality

On this page

  • Output with NULL alignment keys
  • Population, fill, and densification
  • Build evidence

DML distinguishes joins that combine independently grouped keys from joins that preserve a driving row. The join's purpose determines how NULL keys compare.

Equality by join purpose #

Purpose Typical SQL Equality in ON NULL-key behavior
Combine keys from independent measure results, called key-union composition FULL OUTER JOIN, or densification with UNION and LEFT JOIN Ordinary = NULL keys on different sides remain unmatched
Attach attributes while preserving a driving row, including internal nullpk attachment LEFT JOIN NULL-safe equality Matching structural keys can attach even when a component is NULL

NULL-safe equality can use <=>, IS NOT DISTINCT FROM, or an equality test with an explicit both-NULL branch, depending on the dialect. A LEFT JOIN introduced for a particular calculation does not establish a global equality policy for every join.

Output with NULL alignment keys #

If both sides of a composition contain a NULL key, ordinary = leaves those groups unmatched. The output can contain two rows whose displayed key is NULL. coalesce in the key projection does not merge them.

Non-NULL matching keys align normally. A presence filter can restrict the result to groups from a chosen source. That filter changes the output population, not the equality operator.

An explicit expression such as coalesce(region, 'UNKNOWN') can make missing keys share a grouping value. The chosen sentinel then becomes part of the business key and can collide with a real value.

Population, fill, and densification #

A presence measure identifies whether a source group exists. An arbitrary nullable business measure does not prove presence.

Missing-row fill supplies a fallback measure value. Densification supplies missing entity or calendar rows. Neither operation establishes membership in a source population.

Build evidence #

The current checked cross-dataset example emits full join ... on t2.region = t1.region and passes strict compilation without findings. That result establishes compilation of this shape, not the correctness of every sparse-key population. Inspect complete result keys, one-sided groups and NULL handling before accepting the shape for a report.

The core specification, cross-dataset auto-join defines composition. Model review lists the checks for changed queries.
