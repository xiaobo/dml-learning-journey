物化：从声明到确认结果

本页目录
  • 1. 保存未优化结果
  • 2. 声明与安装
  • 3. 确认命中并比较结果
  • 4. 更新与失效
  • 5. 保留证据

结果正确、查询命中、更新后仍正确，三项都要核对。 只添加声明或看到 SQL 变短，不足以证明优化完成。

前提：已有编译器和目标连接，已验证未物化查询。以下是操作流程，不是所有数据库已验证通过的兼容性承诺。

1. 保存未优化结果 #

固定数据和筛选，保存原始结果、生成 SQL 和完整键。选择可加的销售额、成本、笔数；毛利率应重新计算，不能累加比例。粒度设计（英文）说明如何保留后续查询必需的字段。

2. 声明与安装 #

按声明参考（英文）选择粒度、指标和允许的物化。查看当前版本帮助后，在隔离练习库执行：

dmlc --advanced-help
dmlc --setup model.dml --connection=default

setup 会安装数据库物化过程，属于写操作。检查完整诊断。常规查询可能按需安装或刷新所需过程，实际行为以当前版本和连接为准。

3. 确认命中并比较结果 #

dmlc --validate-only query.sql --model=model.dml --connection=default --output-format=json
dmlc query.sql --model=model.dml --connection=default -o optimized.json --overwrite

检查生成 SQL/执行计划是否读取预期汇总对象。逐键逐列比较未优化结果，独立检查重复行、缺失组、NULL 和未格式化比例。更换维度和筛选后再检查，不假定所有问题都命中同一个汇总。

4. 更新与失效 #

在练习库增加已知记录，先计算应变化的结果，再运行查询。检查缓存是否刷新、输出是否变化。若诊断要求重新 setup，对同一模型与连接执行 setup 后重测。不要手改生成表掩盖问题。

记录源变更、刷新动作、命中对象和新结果。未完成该步骤，就不能宣称“实时更新”。各连接的刷新机制和权限需求分别验证。

5. 保留证据 #

检查项 证据
正确性 优化前后结果及差异
命中 SQL/执行计划中的实际对象
刷新 变更记录、刷新动作与新结果
效果 相同数据和口径下的计划；耗时需注明缓存和重复次数

本文补齐操作流程，未宣称新的物化实测结果。声明示例不是数据库兼容性报告。
