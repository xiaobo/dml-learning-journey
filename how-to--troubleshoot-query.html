Troubleshoot a query

Use this procedure when compilation fails, a strict warning appears, or emitted SQL contradicts the intended query. Use the selected dmlc.exe to resolve uncertain behavior.

Debugging workflow (Model Query SQL)

Use when run_query returns COMPILE_ERROR or messages mention UNION, JOIN, subquery, aggregation is not possible, ref {...} not defined, measure cannot be redefined, or use existing measure.

  1. Read the full error — including generated -- dialect: … SQL in the payload.
  2. Classify query type — detail (existence, list, single record) vs aggregation. Aggregation ⇒ FROM MODEL + AGG() (or FROM <name> when the model file is <name>.dml).
  3. Choose FROM — aggregation: FROM MODEL (or FROM <name> when the file is <name>.dml); detail: FROM MODEL.<dataset> / FROM <name>.<dataset>, no AGG, no GROUP BY. Keep the name aligned with the .dml file (model.dml ↔ FROM MODEL).
  4. Remove unsupported SQL — no subqueries, UNION, JOIN. Use fn-macros from system_macros.dml (rank, pot, grand) for portable windows, +d measures for multi-level aggregation, and .dml definitions for complex logic (Measure design, Modifier stacking). Dataset window placement for hand-authored OVER: Window placement. Raw OVER() in Model Query is allowed when no fn-macro covers the pattern.
  5. Measure vs column — in queries use AGG(measure); in .dml use {column} / '{measure: modifier}'; do not use {...} on bare columns in Model Query SQL except AGG({measure: modifier}).
  6. Debug incrementally — validate SELECT AGG(one_measure) FROM MODEL, then add GROUP BY and filters. Use MCP run_query with validateOnly: true, or CLI dmlc --validate-only <query.sql> --model=<model> --connection=<id> --output-format=json.

Reading MCP-wrapped errors

Wrapper labels (e.g. transport metadata) are context only. Read the inner compiler message and the generated SQL block. If stuck, reduce to one measure and add columns incrementally.

Prevention Checklist

Before submitting any DML or Model Query SQL:

  1. Measures use business names, not technical ones
  2. No AGG() inside .dml measure formulas
  3. No redundant aliases on plain AGG(measure)
  4. Time modifiers have a resolved time context and satisfy macro prerequisites
  5. Time filters use first-day format
  6. Time filters placed last in WHERE
  7. No subqueries, JOINs, or UNIONs
  8. Single-line Model Query SQL for MCP submission (examples in references/ may be multi-line for readability)
  9. Query type matches intent (detail vs aggregation)
  10. validateOnly: true passes
  11. No direct aggregation on MODEL.DATASET_* with GROUP BY — use FROM MODEL + AGG() or detail export
  12. Sparse / FOJ composites: activate fill default (isnull/ifnull/coalesce(公式, 字面量) outermost) on inputs you reference — P28b; embedding an activated dep still expands fill
  13. Measure-as-dimension: every measure-derived dimension has a complete explicit entity key (+d preferred); multiple labels have equal independent keys; every output measure safely rolls up from Q ∪ K; label filters apply after the label exists — P66–P68
  14. Fine-grain CTE WHERE then outer SUM: use SUMIF/SUM(iif) with matching {+d: …} — not bare measure filters on the coarse query — P69
  15. Window placement: detail OVER under columns: then atomic agg; post-GROUP-BY composite / {-d:} / {-df:} — never OVER on atomic measures — P70–P71
  16. Two grain fields aliasing one physical column: inspect every emitted rollup ON clause for the right key (P72); pk() into a declared-dimension sql: dataset is the explicit-key fallback (P77)
  17. Cross-dataset -df rollup composites are FULL OUTER: guard partner-only rows with '{primary_measure} is not null': (P73); partner temps may carry max() filler keys, so "extra rows" can look like valid self-pairs
  18. Never write same-object {+d:x,-d:x} / {+d:x,-df:x} — fail loudly, rewrite explicitly — P79
  19. -f does not drop query population filters; non-grain blocked filters need EXISTS — P80
  20. Cross-grain time dimension: replacement needs calendar bridge + broadcast — P81
  21. Bare {m:{+d:x}} is fine grain only; outer SUM/AVG/… required to roll back (except MAD label bindings)
