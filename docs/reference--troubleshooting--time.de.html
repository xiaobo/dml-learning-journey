Diese Einträge behandeln Periodenwerte, den Vergleichskontext und fehlende historische Daten. Die Auswertungssemantik legt die Regeln für den Zeitkontext fest.

P29. Zeitfilter mit einem Datum, das nicht auf den ersten Tag der Periode fällt #

Falsch: dt_month = '2024-01-15' oder dt_month = 'Jan 2024'. Korrektur: dt_month = '2024-01-01'. Verwenden Sie immer den ersten Tag der Periode.

P30. Der heutige Tag fehlt bei den letzten N Tagen #

Falsch: dt_date BETWEEN date(current_date, '-7 days') AND date(current_date, '-1 day'). Korrektur: dt_date BETWEEN date(current_date, '-6 days') AND date(current_date). Das ergibt 7 Tage einschließlich heute.

P31. Der laufende Monat ist in den letzten N Monaten enthalten #

Falsch: dt_month BETWEEN date(current_date, 'start of month', '-12 months') AND date(current_date, 'start of month'). Korrektur: dt_month BETWEEN date(current_date, 'start of month', '-12 months') AND date(current_date, 'start of month', '-1 month'). Schließen Sie den laufenden, noch nicht abgeschlossenen Monat aus.

P32. ytd-Modifikator mit GROUP BY auf Ebene der gesamten Periode #

Falsch: SELECT dt_year, AGG(Umsatz, 'ytd') FROM MODEL GROUP BY dt_year. Korrektur: ytd liefert einen kumulierten Wert. Verwenden Sie dt_date als Gruppierungsebene: SELECT dt_date, AGG(Umsatz, 'ytd') FROM MODEL WHERE dt_date = date(current_date) GROUP BY dt_date.

P33. Einen Datumsbereich für den kumulierten Wert bis zum Stichtag verwenden #

Falsch: WHERE dt_date BETWEEN date(current_date, 'start of year') AND date(current_date) für YTD. Korrektur: Verwenden Sie WHERE dt_date = date(current_date) mit AGG(Umsatz, 'ytd'). Der Modifikator bestimmt den Datumsbereich.

Kategorie: Kompilierung und Validierung #

P59. Vorjahresvergleich ohne Prüfung der Vergleichsspalte #

Falsch: AGG(Umsatz, 'yoy') verwenden, wenn die Summe von AbgabepreisbetragVorjahr null ergibt. Korrektur: Prüfen Sie SUM(AbgabepreisbetragVorjahr) mit einer Detailabfrage, bevor Sie eine Aussage zur Vorjahresentwicklung in Aussicht stellen.

Zusätzlicher Monat nach dem letzten Monat mit Quelldaten #

Legen Sie beim Vergleich von Perioden den Monatsbereich des Berichts ausdrücklich fest. Ein Full Outer Join kann auch Gruppen beibehalten, die nur in einer der beiden Perioden vorkommen. Wenn Dezemberumsätze dem Januar als Umsätze der Vorperiode zugeordnet werden, kann eine Abfrage ohne Datumsgrenzen den Januar enthalten, auch wenn er außerhalb des Berichtszeitraums liegt.

Das Beispiel verwendet Daten von Januar 2024 bis einschließlich Dezember 2025. In jedem Monat gibt es Verkäufe in allen fünf Kategorien. Das Modell definiert Erlös: SUM({Verkaufsbetrag}), eine Monatsdimension namens dt_month und revenue_mom: '{Erlös: pop}'.

SELECT dt_month, Kategorie, AGG(Erlös), AGG(revenue_mom)
FROM MODEL
WHERE dt_month >= '2024-01-01' AND dt_month < '2026-01-01'
GROUP BY dt_month, Kategorie

Mit den Beispieldaten liefert die Abfrage 120 Zeilen. Das Ergebnis stimmt mit dem von Hand geschriebenen SQL überein. Ohne Datumsfilter liefert die geprüfte Abfrage 125 Zeilen. In den fünf zusätzlichen Zeilen für Januar 2026 haben sowohl der Umsatz der aktuellen Periode als auch das Wachstum den Wert NULL, weil nur Dezemberumsätze in diese Gruppen eingehen.

Beide Perioden nach Kategorie abgleichen #

Wenn der Bericht die Gesamtumsätze zweier Perioden vergleicht, behalten Sie alle Kategorien bei, die innerhalb des Monatsbereichs des Berichts in mindestens einer der beiden Perioden Umsatz haben. Um beide Werte anzuzeigen, fügen Sie AGG({Erlös: pp}) AS previous_revenue zur SELECT-Liste hinzu.

Kategorie Umsatz der aktuellen Periode Umsatz der Vorperiode
A 120 100
B NULL 40
C 30 NULL
Summe 150 140

Wenn Sie in diesem Beispiel nur Kategorien mit Verkäufen in der aktuellen Periode anzeigen, entfällt Kategorie B und die angezeigte Summe der Vorperiodenumsätze sinkt auf 100. Verwenden Sie diesen Filter für einen Bericht, der sich gezielt auf die in der aktuellen Periode aktiven Kategorien bezieht, und verwenden Sie für seine Summen dieselbe Kategorieauswahl. Um einen vollständigen Vergleich zu prüfen, summieren Sie jede Umsatzspalte nach Berichtsmonat und gleichen Sie das Ergebnis mit der Quellsumme des jeweils zugehörigen Monats ab. Berechnen Sie das Gesamtwachstum aus den beiden Umsatzsummen.

Zeigen Sie einen fehlenden Wert nur dann als Null an, wenn die Daten für die betreffende Periode vollständig sind und nach den fachlichen Regeln ausbleibende Verkäufe als Null gelten. Das Auffüllen mit Null ändert den angezeigten Wert.
