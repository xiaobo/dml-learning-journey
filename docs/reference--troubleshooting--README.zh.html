错误与修复方法速查 #

错误或症状 修复方法 常见陷阱
UNION is not supported 独立的查询，或筛选条件不同的指标 P10
aggregation is not possible with MODEL.DATASET_* FROM MODEL + AGG(measure) P8, P45
subquery is not supported 使用 DML 指标，或将 +f / HAVING 与 AGG() 搭配使用 P10
JOIN is not supported 列宏中的 {DATASET}.column P11
ref {...} not defined 在模型中定义，在 SQL 中直接使用名称 P41
measure cannot be redefined 移除 AGG(measure_name) 上的 AS measure_name P40
use existing measure "X" instead of recreating… 仅使用 AGG(X) P40
... was referenced but not defined in sql 从模型查询的 SQL 中移除 {...}（AGG({…}) 内的修饰符形式除外） P41
file not found: SELECT ...（Windows） 在 CLI 中直接输入模型查询 SQL 时，将 / 运算符替换为 DIVIDE() P63
table … is owned by dataset … from {Dataset} / join {Dataset}，或 pk(...).{Dataset}.Col P22b
将指标用作维度时，缺少 +d、标签键不兼容，或同级指标无法安全上卷 为每个用作维度的指标显式指定完整的 +d 键。使用兼容的键和可聚合的输出指标。 P66–P68
对同一对象使用 {+d:x,-d:x} / {+d:x,-df:x} 时，会在没有提示的情况下变成单独的 {m} 或 {-f:x} 此写法不合法，必须明确报错。改写表达式，直接指定所需操作。 P79
-f / -df 分支移除了与分组粒度无关的查询筛选条件，导致 FOJ 另一侧的行混入结果 继续限制报表覆盖的数据范围（EXISTS / 半连接）。-f 不改变分组。 P80
月度查询中的 {m:{dimension:[dt_quarter]}} 被作为标量接入，或接入时使用了错误的粒度 通过日历关联较粗粒度的 CTE，将季度值分发到该季度的各行 P81
细粒度 CTE 中的 WHERE 及其外层的 SUM 被改写为粗粒度的 filters: "销售笔数 > 3" 在指标内部使用 SUMIF / SUM(iif)，并指定与之匹配的 {+d: …} P69
window functions are not allowed in atomic measures / GROUP BY 与 OVER 的非法组合 明细级的 OVER 放在 columns: 下。GROUP-BY 之后使用复合指标或 {-d:}。 P70–P71
… reference is not allowed in PARTITION BY 如果在指标的窗口函数中直接将 {col} 用于窗口定义，请将明细计算移到 columns:，或使用 {-d:} / {dimension:}。 P71
上卷时比率的分母算错（本应为 left × right，实际为 left²），且没有诊断信息 两个定义粒度的字段指向同一列。-df/dimension: 将第二个角色绑定到了第一个键。使用 pk() 引用已声明维度的 sql: 数据集。 P72
上卷的复合指标生成额外的行，或生成实际不存在的 left = right 行 跨数据集的 -df 会生成 FULL OUTER JOIN。使用 '{primary_measure} is not null': 限制结果。 P73
-df 上卷丢弃了定义粒度的一个字段，仅发出“skip dimension column”警告 基于同一物理表的两个 table: 数据集使用了不同的列集合。保持列集合完全一致，或避免使用让同一张表承担不同角色的数据集。 P74
重命名维度后，-df 报错 column(s) [x] … not in dimension -df 的参数应使用已声明的粒度字段名，而不是源列名。 P76
MAX(pk(…)) 报错 dataset must be specified … did you mean X 将 dataset: 设为使用方数据集 P77
