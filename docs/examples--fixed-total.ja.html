分母に含める月を選ぶ

このページの内容
  • 同じデータで比較する
  • 両方の定義を保存してからクエリを変更する
  • この例の適用範囲を守る
  • 検証を実行して結果を確認する

-dは月フィルターを維持し、-dfはその指標に対する月フィルターを解除します。どちらの場合も、1月の行だけを表示できます。分母の集計対象と、出力される行の範囲は別々に確認してください。

同じデータで比較する #

地域 a の売上は1月が10、2月が20です。地域 b の1月の売上は30です。1月を選択すると、結果は次のようになります。

地域 月 売上 -dによる地域別合計 -dfによる地域別合計
a 2024-01-01 10 10 30
b 2024-01-01 30 30 30

したがって、地域 a の割合は、業務上の定義に応じて10/10または10/30になります。月フィルターがない場合、どちらの地域も合計は30です。地域 a の1月と2月の行の売上は、それぞれ10と20のままです。

両方の定義を保存してからクエリを変更する #

モデルではregion_selected: '{sales: {-d: month}}'とregion_all_months: '{sales: {-df: month}}'を定義します。ここでのmonthはISO形式の通常の文字列であり、自動時間コンテキストのdim_dtではありません。

ファイル全体: fixed/model.dml 
dialect: duckdb
F:
  type: dataset
  table: FACT
  dimension: [id]
  columns:
    id:
    region:
    month:
    amount:
  measures:
    sales: SUM({amount})
region_selected:
  type: measure
  formula: '{sales: {-d: month}}'
region_all_months:
  type: measure
  formula: '{sales: {-df: month}}'
running_sales:
  type: measure
  formula: 'SUM({sales}) OVER (ORDER BY {month} ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)'
  dimensions:
    - [month]
ファイル全体: fixed/setup.sql 
CREATE TABLE FACT(id INTEGER,region VARCHAR, month VARCHAR,amount INTEGER); INSERT INTO FACT VALUES (1,'a','2024-01-01',10),(2,'a','2024-02-01',20),(3,'b','2024-01-01',30);
ファイル全体: fixed/january.sql 
SELECT region, month, AGG(sales), AGG(region_selected), AGG(region_all_months) FROM MODEL WHERE month='2024-01-01' GROUP BY region,month ORDER BY region,month
ファイル全体: fixed/unfiltered.sql 
SELECT region, month, AGG(sales), AGG(region_selected), AGG(region_all_months) FROM MODEL GROUP BY region, month ORDER BY region,month

クエリはモデルを変更せずに、表示する月を選びます。検証では、すべての列と行の集合全体を比較し、-dfによって2月の行が出力に戻らないことを確認します。

この例の適用範囲を守る #

この例では、地域と月による既知のグループ化を使用します。動的なピボット軸や自動小計のAPIは使用しません。通常のフィールドでの動作を確認しても、dim_dtの時間集計レベルが解除されることの検証にはなりません。時間を扱うクエリでフィールドを置き換える前に、累積KPIコンテキストを参照してください。

検証を実行して結果を確認する #

プロジェクトをダウンロードして、READMEの手順に従い、PowerShellでverify.ps1を実行します。dmlcにパスを通してください。新しい出力フォルダーに演習用データベースを作成し、結果と診断情報を保存します。

この例は DuckDB 上で dmlc 0.3.16（ビルド 2026-11-13）を使って確認しました。実行ファイルのフィンガープリントと各検証ケースのステータスは、ダウンロードに含まれる verification-summary.json に記載されています。データベースでの検証とその後の実行は独立した処理です。両方が同じスナップショットを使用する保証はありません。他のデータベースエンジンでは個別に確認してください。
