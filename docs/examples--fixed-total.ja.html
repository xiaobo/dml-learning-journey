分母に含める月を選ぶ

このページの内容
  • 同じデータで比較する
  • 両方の定義を保存してからクエリを変更する
  • この例の適用範囲を守る
  • 検証を実行して結果を確認する

-dは月フィルターを維持し、-dfはその指標に対する月フィルターを解除します。どちらの場合も、1月の行だけを表示できます。分母の集計対象と、出力される行の範囲は別々に確認してください。

同じデータで比較する #

地域 a の売上は1月が10、2月が20です。地域 b の1月の売上は30です。1月を選択すると、結果は次のようになります。

地域 月 売上 -dによる地域別合計 -dfによる地域別合計
a 2024-01-01 10 10 30
b 2024-01-01 30 30 30

したがって、地域 a の割合は、業務上の定義に応じて10/10または10/30になります。月を絞り込まない場合、地域 a の分母はどちらの計算でも30です。地域 a の売上は1月が10、2月が20です。

両方の定義を保存してからクエリを変更する #

モデルでは地域別選択月売上額: '{売上額: {-d: dt_month}}'と地域別全月売上額: '{売上額: {-df: dt_month}}'を定義します。時間ディメンションdt_monthはテーブルの列monthから日付を読み取ります。

ファイル全体: fixed/model.dml 
dialect: duckdb
売上明細:
  type: dataset
  table: FACT
  dimension: [番号]
  columns:
    番号:
      abbr: id
    地域:
      abbr: region
    dt_month:
      abbr: month
    注文金額:
      abbr: amount
  measures:
    売上額: SUM({注文金額})
地域別選択月売上額:
  type: measure
  formula: '{売上額: {-d: dt_month}}'
地域別全月売上額:
  type: measure
  formula: '{売上額: {-df: dt_month}}'
累計売上額:
  type: measure
  formula: 'SUM({売上額}) OVER (ORDER BY {dt_month} ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)'
  dimensions:
    - [dt_month]
ファイル全体: fixed/setup.sql 
CREATE TABLE FACT(id INTEGER,region VARCHAR, month DATE,amount INTEGER); INSERT INTO FACT VALUES (1,'a','2024-01-01',10),(2,'a','2024-02-01',20),(3,'b','2024-01-01',30);
ファイル全体: fixed/january.sql 
SELECT 地域, dt_month, AGG(売上額), AGG(地域別選択月売上額), AGG(地域別全月売上額) FROM MODEL WHERE dt_month='2024-01-01' GROUP BY 地域,dt_month ORDER BY 地域,dt_month
ファイル全体: fixed/unfiltered.sql 
SELECT 地域, dt_month, AGG(売上額), AGG(地域別選択月売上額), AGG(地域別全月売上額) FROM MODEL GROUP BY 地域, dt_month ORDER BY 地域,dt_month

クエリはモデルを変更せずに、表示する月を選びます。検証では、すべての列と行の集合全体を比較し、-dfによって2月の行が出力に戻らないことを確認します。

この例の適用範囲を守る #

この例では地域と月でグループ化します。動的なピボット軸や小計の自動計算用APIは扱いません。期間を指定して集計する方法は累計KPIの例を参照してください。

検証を実行して結果を確認する #

プロジェクトをダウンロードして、READMEの手順に従い、PowerShellでverify.ps1を実行します。dmlcにパスを通してください。新しい出力フォルダーに演習用データベースを作成し、結果と診断情報を保存します。

この例は DuckDB 上で dmlc 0.3.16（ビルド 2026-11-27）を使って確認しました。実行ファイルのフィンガープリントと各検証ケースのステータスは、ダウンロードに含まれる verification-summary.json に記載されています。データベースでの検証とその後の実行は独立した処理です。両方が同じスナップショットを使用する保証はありません。他のデータベースエンジンでは個別に確認してください。
