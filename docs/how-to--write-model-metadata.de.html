Modellmetadaten schreiben

Inhalt dieser Seite
  • Jeden Datensatz beschreiben
  • Spalten erläutern, die Entscheidungen beeinflussen

  • Abgeleitete Bezeichnungen und Schätzwerte dokumentieren

Helfen Sie Lesern mit Beschreibungen, vor der Abfrage des Modells den passenden Datensatz, die richtige Grundgesamtheit und die passende Kennzahl auszuwählen.

Jeden Datensatz beschreiben #

Geben Sie an, wofür eine einzelne Zeile in der Quelle steht und welche Felder sie identifizieren. Erläutern Sie die fachliche Bedeutung des zentralen Gesamtwerts, die erforderlichen Filter zur Eingrenzung des Geltungsbereichs und bekannte zeitliche oder geografische Grenzen.

description: |-
  Jede Zeile ist eine Transaktionsposition im Vertriebskanal; Belegnummer identifiziert den Quellsatz.
  SUM(Abgabepreisbetrag) ergibt den Nettokanalumsatz einschließlich Umlagerungen und Bewegungen des Zentrallagers. Kassenumsätze sind ausgenommen.
  Der offizielle UL-Bericht filtert auf InULBerücksichtigt = '是'.
  Der Kanal beschreibt den Vertriebsweg des Käufers.

Wenn zwei Datensätze dieselbe Quelle aus Verkäufer- und Käufersicht darstellen, beschreiben Sie die unterschiedlichen Zuordnungen für Partnernummer. Erwecken Sie nur dann den Eindruck, dass die Quellzeilen für die beiden Datensätze auf unterschiedlichen Ebenen definiert sind, wenn das tatsächlich der Fall ist.

Spalten erläutern, die Entscheidungen beeinflussen #

Verwenden Sie die Objektform, wenn der Spaltenname die Bedeutung der Spalte nicht erkennen lässt.

columns:
  Einkaufskanal:
    description: Vertriebsweg des Käufers. Im Modell heißt er Vertriebskanal.
  InULBerücksichtigt:
    description: Kennzeichnet die Datensätze des UL-Berichts. Bericht und Ursachenanalyse verwenden denselben Filter.
  AbgabepreisbetragVorjahr:
    description: Betrag der Quellzeile für den Vorjahreszeitraum. Vor dem Vergleich Vollständigkeit und fehlende Werte prüfen.

Beschreiben Sie vorrangig Spalten, die die Grundgesamtheit, Gruppierungen, Joins oder Vergleiche beeinflussen. Geben Sie bekannte Einschränkungen als Fakten über die Quelle an. Stellen Sie eine Beobachtung aus einer einzelnen Stichprobe nicht als dauerhafte Eigenschaft der Spalte dar.

Kennzahlnamen auf ihre Formeln abstimmen #

Verwenden Sie Fachbegriffe aus dem Geschäftsbereich als Kennzahlschlüssel. Geben Sie in der Beschreibung die Grundgesamtheit, die erforderliche Auswertungsdimension und das Verhalten bei NULL oder null an, wenn diese Angaben die Interpretation beeinflussen.

Wenn ein älterer Name die Formel falsch wiedergibt, benennen Sie die kanonische Kennzahl um. Behalten Sie einen Alias nur bei, wenn bestehende Nutzer oder Anwendungen ihn aus Kompatibilitätsgründen benötigen. Belassen Sie atomare Definitionen bei dem jeweils zuständigen Datensatz.

# Fragment under a dataset's measures mapping.
Nettokanalumsatz:
  description: Nettokanalumsatz einschließlich Umlagerungen und Bewegungen des Zentrallagers. Kassenumsätze sind ausgenommen.
  formula: SUM({Abgabepreisbetrag})

AktiveKäufer:
  description: Anzahl unterschiedlicher erfasster Käufer aller Käufertypen.
  formula: DISTINCTCOUNT({Käufernummer})

AktiveApotheken:
  description: Anzahl unterschiedlicher erfasster Käufer vom Typ Drugstore.
  formula: 'DISTINCTCOUNTIF({Käufernummer}, {Käufertyp} = ''Drugstore'')'

Kompensieren Sie einen irreführenden kanonischen Namen nicht mit einem Kommentar. Halten Sie eine dauerhaft geltende Einschränkung in description: fest, damit Werkzeuge, die Metadaten lesen, sie anzeigen können.

Den Spaltennamen aus der Quelltabelle angeben #

Wenn ein Datensatz aus einer Tabelle stammt, geben Sie unter table: den Tabellennamen an. DML liest die Spalte, die genauso heißt wie das Feld im Modell. Bei abweichenden Namen geben Sie unter abbr: den Spaltennamen aus der Quelltabelle an. In Abfragen verwenden Sie den Feldnamen aus dem Modell. Im folgenden Beispiel erhält eine Kennzahl einen kurzen internen Namen.

EinkaufswertOhneSteuer:
  abbr: SaleAmountNoTax
  type: measure
  dataset: Transaktionen
  description: Gültiger Einkaufsbetrag ohne Steuer.
  formula: SUM({GültigerUmsatz})

Prüfen Sie vor dem Umbenennen einer Kennzahl die Formelreferenzen und Abfragen sowie die Nutzer und Anwendungen, die materialisierte Ergebnisse verwenden. Ein abbr allein stellt nicht sicher, dass alle nachgelagerten Abhängigkeiten eine Umbenennung vertragen.

Abgeleitete Bezeichnungen und Schätzwerte dokumentieren #

Wenn die Bedeutung eines Spaltenmakros erklärt werden muss, geben Sie description: und formula: an.

# Fragment under a dataset's column-macros mapping.
EinkaufskanalDesKäufers:
  description: Vertriebsweg des Käufers aus Businesschannel.
  formula: '{Einkaufskanal}'

Wenn eine Bezeichnung aus fest codierten Regeln abgeleitet wird, geben Sie die betreffende Regel und ihre Grenzen an. Unterscheiden Sie eine im Modell definierte Kalenderbezeichnung vom offiziellen Geschäftskalender. Wenn eine Kennzahl Aktivitäten am Ende eines Prozesses anhand von Transaktionen in der Prozesskette schätzt, geben Sie an, welche Transaktionstypen sie einbezieht.

Metadaten anhand des Modells prüfen #

  1. Prüfen Sie, ob sich Name, Beschreibung und Formel jeweils auf dieselbe Kennzahl beziehen.
  2. Gleichen Sie die Datensatzbeschreibungen mit dem deklarierten Quellschlüssel und dem aktuellen Geltungsbereich ab.
  3. Prüfen Sie die Kompatibilitätsaliase und ermitteln Sie, wer oder was sie verwendet.
  4. Führen Sie den Linter für das geänderte Modell aus.
  5. Kompilieren Sie für jede geänderte Berechnung eine Abfrage, die sie verwendet, im strikten Modus.
  6. Prüfen Sie die generierten Aliase und die Ausgabespalten.
  7. Führen Sie die zutreffenden Live-Prüfungen anhand des CLI-Leitfadens durch.

Informationen zur Kennzahlsyntax und zu Auswertungsdimensionen finden Sie unter Kennzahlen. Folgen Sie für den vollständigen Ablauf von der Modellierung bis zur Abfrage der Anleitung Vorwärtsanalyse.
