結合における NULL の等価性

DML は、個別に集計した指標を、グループ化キー全体に基づいて対応付けます。この対応付けでは、キーの同じ位置にある NULL 値を等しいとみなします。そのため、レポートでは複数のソースにまたがる未分類のグループを 1 つにまとめて表示できます。

結合の目的別の等価性ルール #

用途 一般的な SQL ON での等価性 NULL を含むキーの扱い
独立した指標の結果からキーをまとめます。この方法を、キーの和集合による合成と呼びます。 FULL OUTER JOIN、または UNION と LEFT JOIN を使った重複のないキー集合 NULL セーフな等価比較 キー全体で値が一致し、NULL の位置も一致する場合、ソース間で対応付けられます。
基準となる行を保持して属性を付加します。内部の nullpk による属性の付加も含みます。 LEFT JOIN NULL セーフな等価比較 構造キーが一致する場合は、キーの構成要素が NULL でも属性を付加できます。

NULL セーフな等価比較には、方言に応じて <=>、IS NOT DISTINCT FROM、または両方の値が NULL の場合を明示的に扱う分岐を含む等価比較を使用できます。SQL の述語を a.地域 = b.地域 のように明示した場合は、データベースの通常の等価比較ルールが適用されます。明細行の結合では、その結合に使うキー固有の等価性ルールが適用されます。

対応付けに使うキーに NULL が含まれる場合の出力 #

未分類の地域について、売上の合計が 50、返金の合計が 8 だとします。地域 でグループ化すると、両方の指標を含む 1 行 (NULL, 50, 8) が返されます。この行はレポート上のグループを表します。元の売上レコードと返金レコードは、それぞれ個別のレコードとして識別されます。両方の指標値が NULL の場合も、グループは対応付けられます。

(地域, channel) のような複合キーでは、(NULL, 'online') と (NULL, 'online') が対応付けられます。(NULL, 'retail') は別のグループのままです。期間計算では、時間以外のグループ化キーに同じルールを適用し、時間の照合には従来どおりのルールを適用します。

レポートでラベル付きのグループが必要な場合は、coalesce(地域, 'UNKNOWN') のようなグループ化式を明示します。この式では、データに実際に含まれる 'UNKNOWN' 値も同じグループに入ります。

母集団、補完、行の密化 #

グループの有無を示す未補完の指標でフィルタリングすると、レポートを指定したソースのグループに限定できます。欠損値を許容する業務指標は、対応するグループがソースに存在していても NULL になることがあります。

欠落行の補完では、指標に代替値を設定します。密化では、欠落しているエンティティ行やカレンダー行を追加します。どちらの処理によっても、ソースの母集団への所属は確定しません。

コンパイラービルドの確認結果 #

この仕様は、2026 年 11 月 19 日のグループ化の変更を含むコンパイラービルドに適用されます。2026 年 10 月 16 日のビルドでは、確認したデータセット横断の例で通常の等価演算子 = が使われました。以前のビルドでコンパイルしたレポートを確認する場合は、生成された述語を調べ、キーに NULL を含む例で結果を比較してください。その後に確認した例でも、通常の等価比較が出力され、厳格モードでのコンパイルに成功しました。お使いのコンパイラーとデータで結果を確認してください。

コア仕様の「データセット間の自動結合」で、合成の方法を定義しています。モデルレビューでは、クエリを変更した場合の確認項目を示しています。
