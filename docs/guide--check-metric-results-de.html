Die folgenden Beispiele zeigen, wie Sie eine kumulierte Marge, einen Vergleich mit dem Vormonat und einen Suchschlüssel prüfen. Zu jedem Beispiel finden Sie ein Ergebnis oder eine Fehlermeldung zum Vergleich.

Seit Jahresbeginn beträgt die Marge 25 % #

In der Region Nord betrug der Umsatz im Januar 100, die Kosten lagen bei 60. Im Februar waren es 300 und 240. Die Monatsmargen betragen 40 % und 20 %. Ihr arithmetisches Mittel beträgt 30 %. Die Marge beider Monate zusammen ist (400 − 300) ÷ 400 = 25 %.

Im Modell verwendet gross_margin Umsatz und Kosten. Mit {gross_margin: ytd} werden Umsatz und Kosten für den gesamten Zeitraum summiert. Erst dann wird die Marge berechnet. Im Beispiel zur kumulierten Marge können Sie beide Ergebnisse und das Modell ansehen. Das Beispiel wurde auf DuckDB ausgeführt. Für SQL Server wurde das erzeugte SQL geprüft.

Im Februar bleibt der Januar zum Vergleich verfügbar #

Der Bericht zeigt nur den Februar. In der Region Nord beträgt der Februarumsatz 30, der Januarumsatz 20. Der Umsatz ist also um 50 % gestiegen. Entfernt ein SQL-Filter die Januarzeilen vor der Berechnung von LAG, fehlt der Vergleichswert. Das Modell liest den Vormonat mit {sales: pp}. Probieren Sie die Monatsauswahl in der Lektion zu Zeiträumen aus. Prüfen Sie dann den Vormonatsumsatz im DuckDB-Umsatzbericht.

Hat der Bericht einen festen Zeitraum, geben Sie Anfangs- und Endmonat an. Siehe zusätzliche Zeilen bei Zeitvergleichen.

Aus 30 können durch doppelte Schlüssel 60 werden #

Zwei Verkäufe in Nord ergeben zusammen 30. Enthält das Regionsverzeichnis zwei Einträge für Nord, findet der Join für jeden Verkauf zwei Treffer. Die Summe beträgt dann 60. Das Beispiel zum Regionsverzeichnis zeigt die zusätzlichen Zeilen. Im Beispiel zum zusammengesetzten Schlüssel prüfen Sie zuerst gültige Daten, fügen dann absichtlich ein Duplikat hinzu und beheben den Fehler. Suchen Sie im Fehlerbericht nach VALIDATION_ERROR. Den betroffenen Schlüssel finden Sie unter data.issues.

Mit --validate erhalten Sie einen Prüfbericht. Wenn die Abfrage bei einem ungültigen Schlüssel abbrechen soll, verwenden Sie bei der Ausführung --with-validation. Vergleichen Sie die Ergebnisse mit einer unabhängigen SQL-Abfrage auf denselben Daten. Siehe kompilieren, prüfen und Ergebnisse vergleichen.
