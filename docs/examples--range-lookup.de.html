Ein am Ereignisdatum gültiges Attribut nachschlagen

Inhalt dieser Seite
  • Das Datum an der Intervallgrenze prüfen
  • Die Zuordnungsregel im Modell definieren
  • Eine Überschneidung erkennen und beheben
  • Prüfung ausführen und Ergebnis lesen

Ordnen Sie das Ereignisdatum einem Gültigkeitsintervall desselben Objekts zu, das sich mit keinem anderen Gültigkeitsintervall dieses Objekts überschneidet. Dieses Beispiel verwendet [GültigAb, GültigBis). Der Beginn ist eingeschlossen, das Ende ausgeschlossen.

Das Datum an der Intervallgrenze prüfen #

Bezeichnung Gültigkeit Ereignisdatum Betrag
Jan [2024-01-01, 2024-02-01) 2024-01-01 10
Feb [2024-02-01, 2024-03-01) 2024-02-01 20

Der 1. Februar gehört zu Feb, nicht zu Jan. Die Abfrage gibt Feb 20 und Jan 10 zurück und liefert genau einen Treffer pro Ereignis.

Die Zuordnungsregel im Modell definieren #

Das Ziel deklariert dimension: [Kennung, 'range(GültigAb, GültigBis)']. Lassen Sie den Intervallausdruck in Anführungszeichen stehen, damit sein Komma Teil eines einzigen YAML-Listeneintrags bleibt. Der Ausdruck pk({Kennung}, {dt_date}).{Zuordnung}.Bezeichnung des Fakts liefert zuerst die Objekt-ID und dann das Ereignisdatum.

Vollständige Datei: range/model.dml 
dialect: duckdb
Zuordnung:
  type: dataset
  table: DIM
  dimension: [Kennung, 'range(GültigAb, GültigBis)']
  columns:
    Kennung:
      abbr: id
    GültigAb:
      abbr: valid_from
    GültigBis:
      abbr: valid_to
    Bezeichnung:
      abbr: label
Verkäufe:
  type: dataset
  table: FACT
  dimension: [Verkaufsnummer]
  columns:
    Verkaufsnummer:
      abbr: fid
    Kennung:
      abbr: id
    dt_date:
      abbr: event_date
    Bestellwert:
      abbr: amount
    Bezeichnung: 'pk({Kennung}, {dt_date}).{Zuordnung}.Bezeichnung'
  measures:
    Umsatz: SUM({Bestellwert})
Vollständige Datei: range/setup.sql 
CREATE TABLE DIM(id INTEGER, valid_from DATE,valid_to DATE,label VARCHAR); INSERT INTO DIM VALUES (1,'2024-01-01','2024-02-01','Jan'),(1,'2024-02-01','2024-03-01','Feb'); CREATE TABLE FACT(fid INTEGER,id INTEGER,event_date DATE,amount INTEGER); INSERT INTO FACT VALUES (1,1,'2024-01-01',10),(2,1,'2024-02-01',20);
Vollständige Datei: range/normal.sql 
SELECT Bezeichnung, AGG(Umsatz) FROM MODEL GROUP BY Bezeichnung ORDER BY Bezeichnung

Wenn Sie die Bezeichnung durch einen Preis oder eine Stufe ersetzen, legen Sie fest, was das Datum des Inkrafttretens und das Ereignisdatum bedeuten. Das Beispiel zeigt aneinandergrenzende, begrenzte Intervalle. Unbefristete Gültigkeit, beliebige n:m-Beziehungen oder Verteilungsregeln sind in diesem Beispiel ausgeschlossen.

Eine Überschneidung erkennen und beheben #

Die Prüfroutine verschiebt das Ende von Jan auf den 2. Februar. Dadurch fällt der 1. Februar in beide Intervalle. --validate meldet VALIDATION_ERROR. Wenn Sie das Ende wieder auf den 1. Februar setzen, sind sowohl die Validierung als auch die Prüfung des zweizeiligen Ergebnisses wieder erfolgreich.

Korrigieren Sie die fachliche Regel für die Gültigkeit. Wenn Sie willkürlich einen der passenden Datensätze beibehalten, verdecken Sie den Konflikt.

Prüfung ausführen und Ergebnis lesen #

Laden Sie das vollständige Projekt herunter und führen Sie verify.ps1 wie in der Datei README beschrieben in PowerShell aus. dmlc muss über den Suchpfad erreichbar sein. Das Skript legt die Übungsdatenbank im neuen Ausgabeordner an und speichert dort die Ergebnisse und Diagnosemeldungen.

Dieses Beispiel wurde auf DuckDB mit dmlc 0.3.16 (Build 2026-11-27) geprüft. Den Fingerabdruck der ausführbaren Datei und den Status der einzelnen Prüffälle finden Sie in der Datei verification-summary.json im Download. Die Datenbankvalidierung und die anschließende Ausführung sind voneinander unabhängige Vorgänge. Es ist daher nicht gewährleistet, dass beide denselben Datenbank-Snapshot verwenden. Prüfen Sie das Beispiel für andere Datenbank-Engines separat.
