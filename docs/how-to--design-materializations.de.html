Granularität einer Materialisierung wählen

Inhalt dieser Seite
  • Abfrageleistung und Gestaltungsprinzipien für materialize

Verwenden Sie eine Materialisierung, wenn wiederholt ausgeführte Abfragen gespeicherte Aggregate auf einer festen Granularitätsebene wiederverwenden können. Die Referenz zur Materialisierung definiert die Deklarationssyntax und die Voraussetzungen.

Abfrageleistung und Gestaltungsprinzipien für materialize #

Kurze Checkliste zur Verbesserung der Abfrageleistung:

  • Stellen Sie sicher, dass die Zeitspalten der Konvention dt_date/dt_week/dt_month/dt_quarter/dt_year folgen (erster Tag des Zeitraums).
  • Bevorzugen Sie wenige wiederverwendbare Kennzahlen (z. B. sales, qty) gegenüber vielen Kennzahlen für Einzelfälle.
  • Halten Sie SQL für Model Query einfach: Geben Sie FROM MODEL an, wählen Sie die Dimensionsfelder der Abfrage und AGG(measure) aus und gruppieren Sie anschließend mit GROUP BY.
  • Wenn wiederholte Aggregationen Abfragen verlangsamen, fügen Sie materialize auf der passenden Granularitätsebene hinzu.

Wann Sie materialize einsetzen sollten: wenn Abfragen dieselben Basisdaten wiederholt auf einer festen Granularitätsebene aggregieren (z. B. monatlich nach Produkt, Filiale oder Kategorie) und die Daten entweder nur durch Anhängen neuer Einträge erweitert oder je Zeitraum aktualisiert werden können. Verzichten Sie darauf, wenn die Datenmenge sehr klein ist, die Granularität je nach Abfrage festgelegt wird oder die Modellsemantik noch untersucht wird.

Grundsätze für die Wahl der Granularität:

  1. Die Granularität legt fest, auf welcher Ebene Zeilen oder Summen definiert sind. Wählen Sie sie fein genug für nachgelagerte Aggregationen, ohne dass die Zeilenzahl stark ansteigt. Üblich sind DWD (Tag und Schlüssel), DWS (Monat bzw. Quartal und Analysedimensionen) und ADS (direkt für Berichte nutzbar).
  2. Speichern Sie additive Kennzahlen wie Umsatz und Menge für nachgelagerte Aggregationen. Summieren Sie die Anzahl eindeutiger Kunden nur dann über mehrere Gruppen hinweg, wenn sich deren Kundenmengen nicht überschneiden. Behalten Sie den Entitätsschlüssel bei oder prüfen Sie, ob für die vorgesehene Aggregation eine unterstützte Darstellungsform verfügbar ist.
  3. Geben Sie die Felder, die eine Zeile eindeutig identifizieren, unter dimension: an. Geben Sie funktional abhängige Attribute, etwa das aus category_id abgeleitete category_name, unter dimension_columns: an. Siehe die Regeln für die Deklaration von Materialisierungen.
DWS_SALES_DATE_CATEGORY:
    type: materialize
    parameters:
        dt_date: date
    dimension:
        - dt_date
        - category_id
        - cust_id
    measures:
        - 销售额
        - 销售量

materialize ist ein Optimierungskonzept für die Modellierung. Das dauerhafte Speichern eines Datensatzes als physische Tabelle in DuckDB ist ein separater Vorgang. Durchgearbeitete Beispiele finden Sie unter Beispiele zur Materialisierung.

Folgen Sie dem Ablauf für die Materialisierung, um sie einzurichten, ihre Nutzung durch Abfragen zu prüfen, sie zu aktualisieren und die Ergebnisse zu kontrollieren.
