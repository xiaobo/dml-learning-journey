prepare 为本次查询准备所需数据，refresh 处理源数据变化。部署时执行 setup_sql，Query 的准备执行单元检查就绪后再查询，运维时通过 DML_MAZ_PROGRESS 查看全局进展。

根据任务选择入口 #

任务 操作 如何确认完成
打开报表、切换期间 执行 Query 的普通 prepare_sql prepare_sql 正常返回 data_ready=1 后执行业务 sql
核验报表，强制重新计算 prepare(force_update=1) 目标和必要上游强制重建；Query 准备正常返回后查询
加载后更新相关结果 refresh(invalidate_only=0，默认) 登记目标和受影响下游需求；读取报表时用 Query 准备等待就绪
补数后暂不重算 refresh(invalidate_only=1) 提交标记，不调用 runner，不新增主动需求，不取消既有待办
月结预热 提前执行指定 Query 的普通准备 该 Query 的 prepare_sql 正常返回
中断后继续已登记工作 执行无参 DML_REFRESH_MAZ 查看全局待办和本次 Query 的就绪状态

prepare 向上准备依赖，只接受精确名称。refresh 从变化入口向下处理影响，支持精确名称和 SQL LIKE。源变化未通知时可能复用旧数据；有效不等于源数据绝对最新。

差异刷新按分片选择工作，不是源行级 CDC。全量刷新指本次指定范围的强制重建，不是全部历史。每片的业务数据和成功状态共同提交，后片失败不撤销已提交片。

准备好本次数据再查询 #

共享 prepare 和带目标的 refresh 先提交刷新需求，再同步调用共享过程 DML_RUN_MAZ。仅失效分支提交后直接返回。取得执行权的调用处理全局待办；已有 runner 时，本次调用直接返回，不等待对方完成。普通 prepare 也可能因其他调用的全局工作而持续执行。

同一数据库最多一个 runner 执行实际构建。runner 负责依赖顺序、writer 调用和逐片提交。默认实现无需 Service Broker、SQL Server Agent 或后台应用服务；它不承诺调用返回或连接断开后继续在后台工作。

按同一请求及其参数执行以下顺序：

  1. 部署时执行 setup_sql，安装共享 runtime 和各 Maz 的 writer。
  2. 查询时执行生成的 prepare_sql。它集中完成普通准备、实际就绪检查和必要的重试，正常返回一行 data_ready=1。
  3. 正常返回后执行业务 sql。准备错误或等待超时后停止本次查询，排除原因后重试。

准备执行单元每 100 毫秒重试普通准备，五秒重试判断期限到且仍未就绪时抛错。这个期限不会中途打断已经执行的同步 writer 或目标锁等待；客户端超时与连接取消由集成端处理。重试不会自动改成强制刷新。

等待期间，可从另一连接执行同一请求的 prepare_status_sql，只观察本次 Query 的分片、日期和参数绑定。它不新增需求，也不要求普通调用方自己编写轮询。结果列为 data_ready。就绪检查与随后 SELECT 不提供共同快照。

直接调用低层共享 prepare 时仍可能返回 2，表示已登记但 runner 忙；1 表示本轮完成。refresh 的结果包括 accepted、runner_busy 和受影响分片。刷新受理或全局待办为零不能代替 Query 的实际就绪检查；Query 的生成准备单元会执行该检查。

prepare 参数 #

参数 规则
@_materialize 必填，精确 Maz 名称；不支持模式
@_range_start / @_range_end 日期型 Maz 必须提供两个闭区间边界，Query 可自动推导；相交完整片均纳入
@_force_update 默认 0；1 强制重建本次目标和必要上游；不接受 null
@_parameters / @_user 类型参数绑定与审计用途

强刷先使必要工作及受影响下游失效，主动需求限定于本次必要上游闭包；其他报表不会因此全部预热。Query 的共享依赖按分片和参数复用。普通准备对日期片和整表都复用有效且参数绑定相同的结果。缺失、无效、过期或绑定变化时重建；需要强制重算时显式使用 force_update=1。源变化仍须可靠通知。

EXEC dbo.DML_PREPARE_MAZ
    @_materialize=N'SALES_QUARTERLY',
    @_range_start='20250101', @_range_end='20250331', @_force_update=1;

refresh 参数与全匹配 #

参数 规则
@_materialize 精确名称或模式；与 @_source 互斥；两者均省略时只继续已有待办
@_source 已登记本地物理源表的 schema.table 精确名称；也接受同库 database.schema.table；不支持 like
@_match 默认 exact；可选 like，按数据库登记列的排序规则匹配
@_range_start / @_range_end 同时给出或同时省略；省略表示已有范围，不展开整个日历
@_invalidate_only 默认 0，登记主动需求并调用 runner；1 只提交失效标记，不调用 runner，保留既有待办；不接受 null
@_parameters / @_user 类型参数与审计；批量目标所需参数在失效前校验
匹配方式 示例
单个目标 exact + SALES_MONTHLY
前缀 like + SALES%
字面下划线前缀 like + SALES~_%
当前数据库全部已登记 Maz like + %

SQL LIKE 使用 %、_ 和方括号模式，~ 是转义符；* 不是全匹配。exact 不展开通配符。未知精确名称报错，模式零匹配返回 0 个目标。精确名称最多 128 个 UTF-16 代码单元，模式最多 512 个，不能截断后执行。

-- 源写入提交后，登记二月及已物化的受影响下游，并调用 runner。
EXEC dbo.DML_REFRESH_MAZ
    @_materialize=N'SALES_MONTHLY',
    @_range_start='20250201', @_range_end='20250228';

-- 全部已物化范围仅失效，随后按查询需要补齐。
EXEC dbo.DML_REFRESH_MAZ
    @_materialize=N'%', @_match=N'like', @_invalidate_only=1;

invalidate_only=1 不由本次调用执行 writer。其他连接已经运行的 runner 可以继续处理既有待办。

从 Maz 或源表选择变化范围 #

知道源表时可按已登记来源选择全部直接入口：

EXEC dbo.DML_REFRESH_MAZ
    @_source=N'dbo.TABLE_SALES',
    @_range_start='20250201', @_range_end='20250228';

来源 identity 标记证明日期与目标分片等同时按范围处理；无法证明时保守覆盖已有范围，不猜测冷日期分片。未知或跨库来源、缺少 schema、同时给出 source 与 materialize，以及 source 配合 like 都报错。来源选择不自动侦测源变化。

按 Maz 选择时，源表有多个独立直接入口须通知全部入口。只 refresh 季度不会发现未通知的旧月汇总；不知道缓存在哪层陈旧时，使用 Query 的强制 prepare。

日期边界采用闭区间，按相交完整分片展开，再计算下游影响；跨期移动覆盖旧、新期间。维表及不明影响选择足够大的范围。无法证明精确反向映射时，系统保守扩大已有下游范围。单边日期、反向日期、日历不完整拒绝，不静默裁剪。

有日期的默认 refresh 可以首次构建显式选中的 Maz；仅传播发现的冷下游不自动预建。缺状态的中间 Maz 不阻断已有下游传播。无日期只处理已有范围；全库首次预热需显式给出有限日期。整表型 Maz 按一个物理分片处理，传入日期也会扩大到整表。

日期分片不支持附带非日期值参数；整表只有一个当前参数绑定证明。

查看全局 runner 进展 #

执行当前构建生成的 setup_sql 后，查询共享视图：

SELECT pending_partitions, runner_running, estimated_seconds
FROM dbo.DML_MAZ_PROGRESS;

这是同一数据库全部 Maz 的进展，与具体 Query 无关，不加入 Query 编译结果。普通视图每次查询读取当前 STATE，固定统计最近 60 秒，不保存采样状态或历史批次。监控账号需要视图的 SELECT 权限，部署不会自动授权。

查看完整统计列与计算口径

完整列可用 SELECT * FROM dbo.DML_MAZ_PROGRESS; 查询。

列 含义
pending_partitions 当前待处理的物理分片数，包括正在构建但尚未发布的分片
runner_running 当前是否有 runner 持有单例执行权
completed_partitions / added_partitions 最近 60 秒内完成过 / 新登记过的不同物理分片数
completed_partitions_per_second / added_partitions_per_second 窗口覆盖数除以 60 秒
net_partitions_per_second 完成速度减去新增速度
estimated_seconds 按当前净消化速度估算的清空秒数
average_build_seconds 窗口内各片最新一次成功构建耗时的平均值
sample_start / sampled_at 本次统计窗口的开始和采样时间

物理分片按 Maz、分片类型和日期去重，整表的多个参数绑定只算一个分片。同一分片在窗口内完成多次仍只计一次，完成后再次失效也计入窗口完成数。因此速度表示分片覆盖数，不是实际 writer 执行次数。

没有待办时，预计秒数为 0。新增速度达到或超过完成速度，或 runner 已停止但仍有待办时，预计秒数为 NULL。成本不同的分片和移动窗口都会影响估算。

进展视图不能判断某个 Query 是否就绪。它读取已提交状态，发布事务可能造成短暂等待，不提供跨分片快照。需要其他窗口时，独立 Java 接口 MazRunner.progressSql("mssql", 300) 可生成最近五分钟的只读 SQL；直接执行该 SQL 需要 STATE 读取权限。

中断与重试 #

初始失效和需求登记在元数据事务提交或回滚，构建随后逐片提交。STATE 持久保留待主动刷新的分片及实际参数。中断时已提交片保留，当前片回滚，未完成需求等待下次调用。

情况 操作
runner 构建失败或连接断开 排除原因后调用普通 prepare 或无参 DML_REFRESH_MAZ，继续全局待办
只想继续已登记的剩余工作 执行下方无参 refresh，不重新声明刷新范围
再次 force_update=1 或默认 refresh 视为新刷新要求，可能重新失效并重做已完成片
普通无效或新需求尚未登记 执行相应 Query 的普通 prepare，再检查就绪状态
提交响应丢失 结果未知，重新检查状态，不推断未提交 
-- 继续当前数据库已登记的待办，不重新失效已完成片。
EXEC dbo.DML_REFRESH_MAZ;

客户端取消或超时可能绕过 SQL Server 的 CATCH，并在活连接上留下会话级 runner 锁。取消后关闭该物理连接，连接池应丢弃它；仅 ROLLBACK 不够。断开连接后，再次调用可推进持久待办。普通 SQL 用户也可在确认 runner 停止后，于原连接先回滚未结束事务，再显式释放 DML_MAZ_RUNNER 会话锁。

无参 refresh() 只继续待办，不表示全部历史重算；它不接受日期、like、仅失效或参数绑定选项。全部 Maz 仍用显式 % 和 like 选择。普通无效 state=0 不主动执行，state=3 表示无效且待主动刷新，state=1 表示已发布有效结果；state=2 只在发布事务内部暂存。源提交和通知之间仍有窗口，加载方需可靠执行通知并重试。

执行条件与结果边界 #

使用自动提交连接，IMPLICIT_TRANSACTIONS OFF 且无活动事务。入口检查本次目标和受影响 writer 的权限。runner 以调用者身份处理全局待办，因此执行账号也需具备其他待办涉及的 writer 权限；权限不足返回原始错误并保留需求。

运维参考：运行时对象与权限
对象 所属范围
各 Maz 的结果表和 writer（PROC_M__...） 单个 Maz
prepare_sql、prepare_status_sql、业务 sql 当前 Query 及本次参数
DML_MATERIALIZE_DEFINITION、DML_MATERIALIZE_DEPENDENCY、DML_MATERIALIZE_STATE 共享 runtime 表，按 Maz 和分片保存记录
DML_PREPARE_MAZ、DML_REFRESH_MAZ、DML_RUN_MAZ 共享 runtime 过程
DML_MAZ_IS_READY 共享就绪判断函数
DML_MAZ_PROGRESS 共享全局进展视图

日历及其维护例程由系统安装负责。重新部署前停止新请求并确认 runner 已退出，再执行生成的 setup。
