旅人が一つの疑問を持ってやってきます。地域ごとの売上はいくらだったのでしょうか。

図解付きのインタラクティブチュートリアルを開きます。現在は12章で構成され、採点付きの演習、進捗の保存機能、最終レポートの作成ツールが用意されています。演習ガイドでは、初心者向けプロジェクトの全手順を説明します。このページには、概念を簡潔に紹介する従来の内容を掲載しています。

販売は1件ずつ識別できる #

旅人は4件の販売を記録します。これらの行は説明用に作成したもので、データベースから取得したレコードではありません。

id region amount
1 North 10
2 North 20
3 South 30
4 South 40

ソースデータセットには dimension: [id] が定義されており、1行が1件の販売を表します。2件の販売が同じ地域に属することがあるため、region ではソース行を一意に識別できません。ただし、クエリでこれらの行を地域別にグループ化することはできます。

ディメンションの解説では、ソース行の識別とレポートでのグループ化について詳しく説明します。

再利用できる定義を DML で記述する #

旅人はノートに定義を書き留めます。DML はそのノートに相当するモデルで、YAML で記述します。次のコードは、販売データセットに対して2つのアトミック指標を宣言します。

FACT_SALES:
  type: dataset
  table: TABLE_SALES
  dimension: [id]
  columns:
    id:
    region:
    amount:
  measures:
    sales: SUM({amount})
    cnt: COUNT(1)

sales は金額を合計します。cnt はソース行の数を数えます。どちらもアトミック指標です。データセットとして FACT_SALES を継承します。直接集計する対象は、そのデータセットの行そのものか、列を使った式です。集計では他の指標を参照しません。行や合計を定義するレベルが指標の計算に適していれば、レポートでこれらの指標を再利用できます。

DMXで計算式を記述する #

ノートには、平均の計算方法も記載されています。

average_sale:
  type: measure
  formula: 'DIVIDE({sales}, {cnt})'

この YAML は指標を宣言します。その中の式は DMX で記述されています。{sales} と {cnt} は指標を参照し、DIVIDE は分母がゼロの場合に NULL を返します。average_sale は他の指標を参照するため複合指標であり、dataset: プロパティを持ちません。

DMX は、モデル定義とクエリ式で共通の式構文です。モデルとクエリの間に独立した処理ステップとして入るわけではありません。構文は式リファレンスで定義しています。

クエリで結果の1行が何を表すかを決める #

旅人は望遠鏡を各地域に向けます。

SELECT region, AGG(sales), AGG(average_sale)
FROM MODEL
GROUP BY region

AGG はモデルの指標を参照します。GROUP BY region を指定すると、地域ごとに結果が1行になります。架空の販売データ4件をもとに計算すると、次の値になります。

region sales average_sale
North 30 15
South 70 35

グループ化フィールドを指定しない場合、同じモデル指標から売上合計 100 と1件あたりの平均売上 25 が得られます。id でグループ化すると、販売1件につき結果が1行になります。どの場合もソース行の識別子は [id] のままです。

宣言されたソースキー [id] のレベルでは、検証対象のコンパイラが集計を行単位の式に簡略化し、厳格モードの指摘を報告します。この簡略化には、ソースデータ内で id が一意であることが前提となります。全体集計のクエリと地域別のクエリは、検証対象のビルドで厳格モードのコンパイルを通過します。

チュートリアルのコンパイラ検証記録には、インタラクティブプロジェクトで使用した実行ファイル、そのフィンガープリント、実施したチェックが記載されています。

インタラクティブページは、これらの小さなサンプル表の値をブラウザー内で計算します。DML の実行やデータベースへの接続は行いません。

コンパイルで SQL を生成する #

コンパイラはモデルとクエリを組み合わせて SQL を生成します。データベースは生成された SQL を実際のソーステーブルに対して実行します。

DML model + Model Query
          |
        dmlc
          |
     generated SQL
          |
       database
          |
       result rows

コンパイルが成功すれば、検証対象のコンパイラの動作を確認できます。元データのキーは実データで検証し、クエリの結果は別に求めた値と比較します。最初のクエリのチュートリアルでは、同じモデルで地域別のクエリをコンパイルし、生成された SQL を確認します。

詳しくは、基本概念、指標の宣言、またはモデルクエリ SQLを参照してください。
