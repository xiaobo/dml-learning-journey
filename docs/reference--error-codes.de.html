Anhand dieser Codes können Sie die fehlgeschlagene Phase ermitteln und eine passende Maßnahme wählen. Prüfen Sie neben dem Exitcode des Prozesses auch die Diagnoseinformationen und das generierte SQL.

Darstellung von Dateipfaden #

Angezeigte Dateipfade verwenden auf allen Plattformen Schrägstriche (/):

  • Eingaben wie ..\data oder ../data werden in Fehlermeldungen zur einheitlichen Schreibweise ../data normalisiert.
  • Pfade mit Arbeitsbereichsplatzhalter haben die Form <workspaceFolder>/relative/path. Hinter dem Platzhalter werden keine Backslashes verwendet.
  • Aufgelöste Dateisystempfade werden nach Möglichkeit relativ zum aktuellen Arbeitsverzeichnis angezeigt.

Fehlercodekategorien #

Kategorie Beschreibung CLI-Exitcode
INVALID_INPUT Eingabevalidierung fehlgeschlagen. Sie können die Eingabe korrigieren und es erneut versuchen. 64
VALIDATION Validierung auf Benutzerebene fehlgeschlagen (Parsing OK, aber die Argumente sind ungültig) 65
NOT_FOUND Angeforderte Ressource nicht gefunden 66
CONFIG Konfigurationsfehler (fehlende oder ungültige Konfiguration, unbekannte Verbindungs-ID usw.) 78
TIMEOUT Zeitlimit für den Vorgang überschritten. Versuchen Sie es mit anderen Parametern erneut. 69
COMPILE Kompilierung fehlgeschlagen (Syntax- oder Modellfehler) 2
EXECUTION Ausführung fehlgeschlagen. Ein erneuter Versuch kann erfolgreich sein. 70
INTERNAL Unerwarteter interner Fehler. Dieser Fehler sollte gemeldet werden. 70
BLOCKED Vorgang durch eine Richtlinie oder den aktuellen Zustand blockiert 77

Fehlercodes #

Fehler bei der Datei-Ein-/Ausgabe #

FILE_NOT_FOUND

  • Kategorie: NOT_FOUND
  • Code: FILE_NOT_FOUND
  • Häufige Ursachen: Der Dateipfad ist falsch, die Datei existiert nicht oder sie liegt außerhalb des Arbeitsbereichsordners.
  • Empfohlene Maßnahmen: Prüfen Sie, ob der Dateipfad korrekt ist und innerhalb des Arbeitsbereichsordners liegt.
  • Beispiel: File not found: /path/to/file.dml

FILE_ALREADY_EXISTS

  • Kategorie: BLOCKED
  • Code: FILE_ALREADY_EXISTS
  • Häufige Ursachen: Es wurde versucht, eine bereits vorhandene Datei zu erstellen, ohne das Überschreiben zu aktivieren.
  • Empfohlene Maßnahmen: Wählen Sie einen neuen Namen für die Ausgabedatei. Wenn Sie die vorhandene Datei ersetzen möchten, verwenden Sie die dafür vorgesehene Option des Befehls.
  • Beispiel: File already exists: /path/to/file.csv

UNSUPPORTED_FILE_TYPE

  • Kategorie: INVALID_INPUT
  • Code: UNSUPPORTED_FILE_TYPE
  • Häufige Ursachen: Es wurde versucht, ein nicht unterstütztes Dateiformat zu verwenden.
  • Empfohlene Maßnahmen: Verwenden Sie einen unterstützten Dateityp (parquet, csv, xlsx).
  • Beispiel: Unsupported file type: .txt. Supported types: .csv, .xlsx, .parquet

PATH_OUTSIDE_WORKSPACE

  • Kategorie: BLOCKED
  • Code: PATH_OUTSIDE_WORKSPACE
  • Häufige Ursachen: Der Dateipfad führt aus dem Arbeitsbereichsordner heraus, etwa über ../, über einen absoluten Pfad auf einem anderen Laufwerk oder über einen symbolischen Link, dessen Ziel außerhalb des Arbeitsbereichs liegt.
  • Empfohlene Maßnahmen: Verwenden Sie einen relativen Pfad, der innerhalb des Arbeitsbereichsordners bleibt.
  • Beispiel: File path must be within workspace: ../outside/file.csv. Workspace folder: <workspaceFolder>
  • Pfaddarstellung: In Fehlermeldungen und CLI-Ausgaben werden Pfade auf allen Plattformen mit Schrägstrichen (/) angezeigt. Das gilt auch für Pfade mit Platzhaltern wie <workspaceFolder>/relative/path.
  • Hinweise: Wenn in der CLI die Einstellung WORKSPACE_FOLDER gesetzt ist, müssen Ein- und Ausgabedateien innerhalb dieses Verzeichnisses liegen.

NO_SHEETS_IN_EXCEL

  • Kategorie: INVALID_INPUT
  • Code: NO_SHEETS_IN_EXCEL
  • Häufige Ursachen: Die Excel-Datei enthält keine Arbeitsblätter oder ist beschädigt.
  • Empfohlene Maßnahmen: Geben Sie eine gültige Excel-Datei mit mindestens einem Arbeitsblatt an.
  • Beispiel: Excel file has no sheets: /path/to/file.xlsx

Verbindungsfehler #

CONNECTION_NOT_FOUND

  • Kategorie: CONFIG
  • Code: CONNECTION_NOT_FOUND
  • Häufige Ursachen: Die Verbindungs-ID ist in connections.json nicht vorhanden.
  • Empfohlene Maßnahmen: Lassen Sie die verfügbaren Verbindungen auflisten und wählen Sie eine gültige Verbindungs-ID. Sie können die Verbindung auch zu connections.json hinzufügen.
  • Beispiel: Connection not found: production. Available connections: [dev, staging]

LIST_CONNECTIONS_ERROR

  • Kategorie: EXECUTION
  • Code: LIST_CONNECTIONS_ERROR
  • Häufige Ursachen: Aufgrund eines Datenbank- oder Konfigurationsfehlers konnten die verfügbaren Verbindungen nicht aufgelistet werden.
  • Empfohlene Maßnahmen: Prüfen Sie die Verbindungskonfiguration und ob die Datenbank erreichbar ist.
  • Beispiel: Failed to list connections: Connection refused

Fehler bei der Abfrageausführung #

EXECUTION_ERROR

  • Kategorie: EXECUTION
  • Code: EXECUTION_ERROR
  • Häufige Ursachen: Die Abfrage konnte wegen eines SQL-Fehlers, eines Problems mit den Daten oder der Datenbank oder eines nach Modelländerungen veralteten materialize-Caches nicht ausgeführt werden.
  • Empfohlene Maßnahmen: Prüfen Sie die Abfragesyntax, die Datentypen und die Verbindung zur Datenbank. Wenn die Meldung eine veraltete materialize-semver oder pls re-setup related model erwähnt, führen Sie dmlc -s <model.dml> --connection=<id> aus und starten Sie die Abfrage erneut mit demselben Wert für --model.
  • Beispiel: Execution failed: Column 'invalid_column' does not exist
  • Beispiel (materialize veraltet): materialize abort: procedure PROC_M__CACHED_SALES is obsolete since semver (...) is different from expect: ..., pls re-setup related model

EXECUTION_INTERRUPTED

  • Kategorie: EXECUTION
  • Code: EXECUTION_INTERRUPTED
  • Häufige Ursachen: Die Abfrage wurde vom Benutzer oder vom System unterbrochen.
  • Empfohlene Maßnahmen: Führen Sie die Abfrage erneut aus.
  • Beispiel: Query execution interrupted

TIMEOUT_ERROR

  • Kategorie: TIMEOUT
  • Code: TIMEOUT_ERROR
  • Häufige Ursachen: Die Ausführung der Abfrage hat zu lange gedauert.
  • Empfohlene Maßnahmen: Erhöhen Sie den Wert des Parameters timeoutSeconds oder vereinfachen Sie die Abfrage. Um die Leistung zu verbessern, können Sie auch materialize hinzufügen.
  • Beispiel: Query timed out after 30 seconds

Kompilierungsfehler #

COMPILE_ERROR

  • Kategorie: VALIDATION
  • Code: COMPILE_ERROR
  • Häufige Ursachen: DML-Syntaxfehler, Fehler bei der Modellvalidierung, Fehler bei der SQL-Generierung oder eine unzulässige Kombination von Modifikatoren. Ein Beispiel ist +d zusammen mit -d/-df für dieselbe Dimension in einem Modifikatorobjekt. Laut Sprachspezifikation muss die Kompilierung in diesem Fall mit einer Fehlermeldung abbrechen. Siehe Kombination von Modifikatoren und Fallstrick P79.
  • Empfohlene Maßnahmen: Beheben Sie die Kompilierungsfehler, prüfen Sie, ob model.dml im Arbeitsbereichsordner vorhanden ist, und kontrollieren Sie das generierte SQL in error.details.generatedSql. Formulieren Sie bei Konflikten zwischen +d/-d/-df die gewünschte Wirkung eindeutig in einer einzigen Angabe, ohne sich darauf zu verlassen, dass sich die Modifikatoren gegenseitig aufheben.
  • Beispiel: Compilation failed — see details.compilationErrors
  • Hinweise: Im aktuell geprüften Build führen die überprüften +d-Konflikte auf demselben Feld zu keiner Fehlermeldung. Geben Sie genau eine Auswertungsphase ausdrücklich an und prüfen Sie das generierte SQL. Verlassen Sie sich nicht darauf, dass sich die Modifikatoren gegenseitig aufheben.

COMPILE_TIMEOUT

  • Kategorie: TIMEOUT
  • Code: COMPILE_TIMEOUT
  • Häufige Ursachen: Die Kompilierung hat zu lange gedauert.
  • Empfohlene Maßnahmen: Vereinfachen Sie das DML-Modell, verringern Sie die Komplexität und erhöhen Sie das Zeitlimit.
  • Beispiel: Compilation timed out after 30 seconds

VALIDATION_ERROR

  • Kategorie: VALIDATION
  • Code: VALIDATION_ERROR
  • Häufige Ursachen: Deklarierte Einschränkungen für Dimensionen wurden verletzt. Prüfen Sie data.status und data.issues.
  • Empfohlene Maßnahmen: Korrigieren Sie ungültige Parameter oder die fehlerhafte Konfiguration.
  • Beispiel: Declared dimension constraints were violated; see data.issues.

Generierungsfehler #

MODEL_RESOLUTION_ERROR

  • Kategorie: NOT_FOUND
  • Code: MODEL_RESOLUTION_ERROR
  • Häufige Ursachen: <FROM>.dml wurde weder neben der SQL-Datei noch unter --model=<dir> oder im Modellsuchpfad gefunden. Weitere mögliche Ursachen sind die gemeinsame Verwendung von --model=acme.dml und FROM MODEL (die Datei stimmt nicht mit FROM überein, Exitcode 65) oder die Angabe eines Verzeichnisses für einen Vorgang, der nur Dateien akzeptiert.
  • Lösungsvorschläge: Übergeben Sie den Befehlen query, compile und validate ein Verzeichnis mit der passenden .dml-Datei oder eine Datei, deren Name mit FROM übereinstimmt. Übergeben Sie setup eine .dml-Datei.
  • Beispiel: model file "acme.dml" does not match FROM "MODEL" (expected "MODEL.dml").

FILTER_VALIDATION_ERROR

  • Kategorie: VALIDATION
  • Code: FILTER_VALIDATION_ERROR
  • Häufige Ursachen: Syntaxfehler im Filter oder ungültiger Feldname
  • Lösungsvorschläge: Korrigieren Sie den Feldnamen oder die Syntax im Filter.
  • Beispiel: Filter validation failed: invalid field 'dt_invalid'

Fehler bei der Dimensionsvalidierung #

Doppelte Schlüssel und überlappende Bereiche

  • Kategorie: VALIDATION
  • Code: VALIDATION_ERROR. Prüfen Sie den Problemtyp in data.issues.
  • Häufige Ursachen: Die vollständige Kombination der Dimensionswerte des Datensatzes kommt mehrfach vor oder eine bereichsbasierte Suche kann mehrere Quellzeilen mit überlappenden Bereichen finden.
  • Lösungsvorschläge: Korrigieren Sie den Quellschlüssel, die Feldliste unter dimension: im Datensatz, die überlappenden Bereiche oder die Quelldaten. Führen Sie anschließend --validate erneut aus. Weder DISTINCT/GROUP BY im kompilierten SQL noch DISTINCTCOUNT-Kennzahlen beheben eine nicht eindeutige Suche mit pk(...).
  • Beispiel: Declared DML dataset dimension is not unique in dataset 'Order Line' on this connection at validation time.

EXECUTION_ERROR

  • Kategorie: EXECUTION
  • Code: EXECUTION_ERROR
  • Häufige Ursachen: Die Validierungsabfrage konnte nicht ausgeführt werden.
  • Empfohlene Maßnahmen: Prüfen Sie die Verbindungskonfiguration und ob die Datenbank erreichbar ist.
  • Beispiel: Validation query failed: Connection refused

Arbeitsbereichs- und Vorgangsfehler #

NO_WORKSPACE

  • Kategorie: BLOCKED
  • Code: NO_WORKSPACE
  • Häufige Ursachen: Es ist kein Arbeitsbereichsordner festgelegt oder auf den Arbeitsbereich kann nicht zugegriffen werden.
  • Lösungsvorschläge: Legen Sie einen Arbeitsbereichsordner fest oder prüfen Sie die Zugriffsberechtigungen für den Arbeitsbereich.
  • Beispiel: No workspace folder configured

INVALID_PARAMS

  • Kategorie: VALIDATION
  • Code: INVALID_PARAMS
  • Häufige Ursachen: Ungültiger Parametername oder Parameterwert
  • Lösungsvorschläge: Korrigieren Sie den Parameternamen oder -wert und prüfen Sie die zulässigen Optionen für den Parameter.
  • Beispiel: Invalid parameter: 'invalid_param'. Valid options: ['param1', 'param2']

FILE_EXPORT_ERROR

  • Kategorie: EXECUTION
  • Code: FILE_EXPORT_ERROR
  • Häufige Ursachen: Der Export der Daten in eine Datei ist fehlgeschlagen.
  • Empfohlene Maßnahmen: Prüfen Sie den Ausgabepfad und die Schreibberechtigungen und wiederholen Sie den Export. Existiert die Zieldatei bereits, wählen Sie einen neuen Namen oder aktivieren Sie das Überschreiben, wenn Sie die vorhandene Datei ersetzen möchten.
  • Beispiel: File export failed: Permission denied

Allgemeine Fehler #

UNEXPECTED_ERROR

  • Kategorie: INTERNAL
  • Code: UNEXPECTED_ERROR
  • Häufige Ursachen: Ein unerwarteter interner Fehler ist aufgetreten.
  • Lösungsvorschläge: Erstellen Sie anhand der Support-Checkliste ein minimales Beispiel, mit dem sich der Fehler reproduzieren lässt. Senden Sie es über Ihren bestehenden Produktkontakt. Ein öffentlicher Supportkanal ist noch nicht aufgeführt.
  • Beispiel: Unexpected error: NullPointerException
