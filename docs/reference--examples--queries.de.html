Die einführenden Beispiele verwenden das gemeinsame Vertriebsmodell. Das Modell stellt Umsatz und die aufgeführten Transaktionsspalten bereit, erzeugt aber keine Quelldaten. Die Datumsbeispiele verwenden das aktuelle Datum. Mit historischen Testdaten liefern sie daher möglicherweise keine Zeilen.

Voraussetzungen für die Beispiele: Einfache Abfragen, zeitliche Umsatzvergleiche, Rangfolgen, Anteilsberechnungen und Produktzählungen verwenden dieses Modell. Die Ausgabenbeispiele benötigen zusätzlich die Kennzahl Ausgaben. Beispiele zu offenen Salden benötigen Kunde und OffenerBetrag, Beispiele zum Wachstum je Konto Konto und Erlös. Diese Fragmente müssen angepasst werden und lassen sich nicht als Ergänzungen zum gemeinsamen Modell ausführen. Einen ausführbaren Datensatz mit festen Datumswerten und erwarteten Ergebnissen finden Sie in der überprüften Vertriebsübung.

Einfache Abfragen #

Gesamtumsatz #

SELECT AGG(Umsatz) FROM MODEL

Umsatz nach Region #

SELECT Region, AGG(Umsatz) FROM MODEL GROUP BY Region

Umsatz im laufenden Monat #

SELECT AGG(Umsatz) FROM MODEL WHERE dt_month = date(current_date, 'start of month')

Umsatz im laufenden Monat nach Region #

SELECT Region, AGG(Umsatz)
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY Region

Detailabfrage zu bezahlten Transaktionen #

SELECT dt_date, TransaktionsID, Verkaufsbetrag, Bezahlt
FROM MODEL.Transaktionen
WHERE Bezahlt = 1
ORDER BY dt_date DESC

Zeitmodifikatoren #

Laufender Monat im Vergleich zum Vormonat #

SELECT dt_month,
       AGG(Umsatz) as UmsatzDiesenMonat,
       AGG(Umsatz, 'pp') as UmsatzImVormonat,
       AGG(Umsatz, 'pop') as WachstumZumVormonat
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY dt_month

Laufender Monat im Vergleich zum Vorjahresmonat #

SELECT dt_month,
       AGG(Umsatz) as UmsatzDiesenMonat,
       AGG(Umsatz, 'ya') as UmsatzImVorjahresmonat,
       AGG(Umsatz, 'yoy') as WachstumZumVorjahr
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY dt_month

Wachstum seit Jahresbeginn #

SELECT dt_date,
       AGG(Umsatz, 'ytd') as UmsatzLaufendesJahr,
       AGG(Umsatz, 'ytd', 'ya') as VorjahrKumuliert,
       AGG(Umsatz, 'ytd', 'yoy') as WachstumSeitJahresbeginn
FROM MODEL
WHERE dt_date = date(current_date)
GROUP BY dt_date

Beachten Sie die Kombination der Modifikatoren: 'ytd', 'ya' bezeichnet den Zeitraum vom Beginn des Vorjahres bis zum entsprechenden Vorjahresdatum.

Rollierende Summe über 12 Monate #

SELECT dt_month, AGG(Umsatz), AGG({Umsatz: mat}) AS GleitenderUmsatz
FROM MODEL
GROUP BY dt_month
ORDER BY dt_month DESC
LIMIT 12

Bestimmte Monate oder Quartale #

-- August this year
SELECT AGG(Ausgaben) FROM MODEL WHERE dt_month = date(current_date, 'start of year', '+7 months')

-- Q2 this year
SELECT AGG(Ausgaben) FROM MODEL WHERE dt_quarter = date(current_date, 'start of year', '+1 quarter')

Verschachtelte Modifikatoren in .dml #

# In model.dml
UmsatzSeitJahresbeginn:
    type: measure
    formula: '{Umsatz: ytd}'

VorjahresumsatzBisStichtag:
    type: measure
    formula: '{Umsatz: {ytd: ya}}'

-- In query
SELECT dt_date, AGG(UmsatzSeitJahresbeginn), AGG(VorjahresumsatzBisStichtag)
FROM MODEL
WHERE dt_date = date(current_date)
GROUP BY dt_date

Wichtige Punkte: Zeitmodifikatoren benötigen einen eindeutig bestimmten Zeitkontext und müssen die Voraussetzungen des Makros erfüllen. Auch Zeitfilter können den Zeitkontext liefern. yoy und pop geben Wachstumsraten als Dezimalzahlen zurück (0.15 = 15%). pp und ya geben den absoluten Wert des vorherigen Vergleichszeitraums zurück. Verwenden Sie nach Möglichkeit Modifikatoren anstelle manueller Datumsberechnungen.

Rangfolgen und Filter #

Die 10 umsatzstärksten Produkte #

SELECT Produkt, AGG(Umsatz)
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY Produkt
ORDER BY AGG(Umsatz) DESC
LIMIT 10

Den Rangmodifikator verwenden #

SELECT Produkt, AGG(Umsatz), AGG({Umsatz: rank}) AS Umsatzrang
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY Produkt

{Umsatz: rank} gibt für jedes Produkt den Rang seines Umsatzes im Abfrageergebnis zurück. Die Rangfolge richtet sich nach dem Umsatz in absteigender Reihenfolge.

Rang im ausgewählten Zeitraum #

SELECT Produkt,
       AGG(Umsatz) as Periodenumsatz,
       AGG({Umsatz: rank}) as RangImZeitraum
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY Produkt

Die Abfrage gruppiert bereits ausschließlich nach Produkt. Behalten Sie den Monatsfilter bei und bestimmen Sie den Rang direkt anhand von Umsatz. Die zeitliche Gruppierungsebene muss nicht entfernt werden. Das Entfernen eines Gruppierungsfelds ist nicht dasselbe wie das Entfernen des Zeitfilters.

Nach Rang filtern #

SELECT Produkt, AGG(Umsatz)
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY Produkt
HAVING AGG({Umsatz: rank}) <= 10

HAVING filtert nach der Aggregation. Daher steht rank in dieser Klausel zur Verfügung.

HAVING-Klausel für Kunden mit offenem Saldo #

SELECT Kunde, AGG(OffenerBetrag)
FROM MODEL
GROUP BY Kunde
HAVING AGG(OffenerBetrag) > 0

Wichtige Punkte: rank gibt RANK() OVER (ORDER BY measure DESC) zurück. rank_asc bestimmt den Rang in aufsteigender Reihenfolge. Verwenden Sie -d, um vor der Rangberechnung die Zeitdimension oder andere Dimensionen zu entfernen. Kombinieren Sie den Rangmodifikator mit HAVING, um dynamisch nach den ersten N Rängen zu filtern.

Anteil am Gesamtwert (pot) #

SELECT Produkt, AGG(Umsatz) AS Umsatz,
       AGG(Umsatz, 'rank') AS Umsatzrang,
       AGG({Umsatz: pot}) AS AnteilAnSumme
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY Produkt
ORDER BY AGG(Umsatz, 'rank')

pot entspricht measure / grand. Der kumulierte Pareto-Anteil ist kein System-fn-Makro. Wenn Sie eine laufende Summe benötigen, verwenden Sie OVER() in Model Query SQL.

RFM und Muster des gemeinsamen Auftretens #

Zur RFM-Analyse und zur Analyse des gemeinsamen Auftretens finden Sie ausgearbeitete Beispiele für Aggregationen auf einer detaillierten Ebene.

Dimension ohne dt #

Umsatz nach Region (gesamter Zeitraum) #

SELECT Region, AGG(Umsatz) FROM MODEL GROUP BY Region

Produktanteil nach Region (ohne zeitliche Gruppierung) #

SELECT Region, Produkt, AGG(Umsatz)
FROM MODEL
GROUP BY Region, Produkt

Ausgewählter Zeitraum im Vergleich zum gesamten historischen Zeitraum #

-- Selected month: retain the month filter.
SELECT Region, Produkt, AGG(Umsatz) AS UmsatzImZeitraum
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY Region, Produkt

-- All history: remove the month filter, retain the same grouping.
SELECT Region, Produkt, AGG(Umsatz) AS UmsatzÜberAlleJahre
FROM MODEL
GROUP BY Region, Produkt

Führen Sie diese Abfragen getrennt aus. -d entfernt die Gruppierung, lässt den Zeitfilter jedoch bestehen. Da diese Abfragen nicht nach Zeit gruppieren, benötigen sie -d: dim_dt nicht. Wenn Sie hier versuchen, die zeitliche Gruppierungsebene für einzelne Kennzahlen zu entfernen, lehnt der geprüfte Compiler dies ab. Wie Sie Gruppierungen und Filter gezielt für den Nenner entfernen, erfahren Sie unter Dimensions- und Filtermodifikatoren.

Zeitraumumrechnung #

SELECT dt_year,
       AGG({Umsatz: {dim_dt as quarter: pp}}) as UmsatzDesVorquartals
FROM MODEL
WHERE dt_year = '2024-01-01'
GROUP BY dt_year

dim_dt as quarter bewirkt, dass der Modifikator pp auf Quartalsebene arbeitet, obwohl die Abfrage nach Jahr gruppiert. Die Kennzahl wird auf der geänderten Ebene (Quartal) berechnet. Anschließend wird das Ergebnis per Join wieder mit den Daten auf der Gruppierungsebene der Abfrage (Jahr) verknüpft.

Hinweis: dim_dt as <grain> ist nur sinnvoll, wenn sich die geänderte Zeitebene von der zeitlichen Gruppierungsebene der Abfrage unterscheidet. Wenn die Abfrage bereits nach dt_quarter gruppiert, lehnt der Compiler dim_dt as quarter: pp als überflüssig ab. Verwenden Sie in diesem Fall direkt AGG({Umsatz: pp}).

Wichtige Punkte: Abfragen ohne Zeitfilter werten alle historischen Daten aus. -d: dim_dt entfernt das aktive Zeitfeld aus den Dimensionen, nach denen die Kennzahl ausgewertet wird. Adressieren Sie das aktive Zeitfeld mit dim_dt und nicht über ein bestimmtes Feld wie dt_date. Mit -d lassen sich nur Dimensionsfelder entfernen, die zur aktuellen Gruppierung der Abfrage gehören. dim_dt as <grain> ändert die zeitliche Auswertungsebene für eine einzelne Kennzahlreferenz. Beim Kombinieren ist Vorsicht geboten: Eine Kennzahl ohne Zeitdimension ist möglicherweise nicht mit einer Kennzahl mit Zeitdimension in derselben Zeile vergleichbar.

Vergleichsmuster #

Vergleich mit dem vorherigen Zeitraum #

SELECT AGG(Umsatz) as UmsatzDiesenMonat, AGG(Umsatz, 'pp') as UmsatzImVormonat
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')

Wachstumsrate nach Konto #

SELECT Konto, AGG(Erlös) as current, AGG(Erlös, 'pp') as previous
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY Konto
HAVING AGG(Erlös, 'pop') > 0.10  -- 10% growth

Seit Jahresbeginn im Vergleich zum Vorjahr #

SELECT AGG(Umsatz, 'ytd') as BisherigesJahr, AGG(Umsatz, 'ytd', 'ya') as VorjahrBisStichtag
FROM MODEL
WHERE dt_date = date(current_date)
GROUP BY dt_date

Bedingte Zählungen #

Modifikatoren gelten für Kennzahlen, nicht für Spalten. Wenden Sie {+d: Produkt} innerhalb der Bedingung auf die Kennzahl an:

-- Count of products with per-Produkt Umsatz above threshold
SELECT DISTINCTCOUNTIF(Produkt, AGG({Umsatz: {+d: Produkt}}) > 1000) as Produktzahl FROM MODEL

Alternativ können Sie die Kennzahl einmal in .dml mit formula: 'DISTINCTCOUNTIF({Produkt}, {Umsatz: {+d: Produkt}} > 1000)' definieren und anschließend mit SELECT AGG(high_sales_product_count) FROM MODEL abfragen.
