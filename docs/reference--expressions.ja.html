このページでは、参照形式と組み込み関数について説明します。修飾子の動作については、指標の修飾子を参照してください。クエリの文法とエイリアスについては、Model Query SQLを参照してください。例の関数は式の構文で記述しています。生成される SQL は、選択した方言によって異なります。

参照構文 #

.dml の式 #

参照の種類 構文 例
列 {column_name} SUM({amount})
指標 {measure_name} DIVIDE({sales}, {count})
別のデータセットの列 {DATASET}.column {products}.price
修飾子付きの指標 {measure: modifier} {sales: yoy}
入れ子になった修飾子を持つ指標 {measure: {modifier: sub}} {sales: {+d: customer}}

Model Query SQL 内 #

参照の種類 構文 例
列（ディメンション） 名前のみ SELECT product, dt_month
指標 AGG(measure_name) AGG(sales)
修飾子付きの指標 AGG({measure: modifier}) AGG({sales: yoy})
修飾子を位置引数で指定する指標 AGG(measure, 'modifier') AGG(sales, 'yoy')

基本ルール：波括弧 {...} は .dml 専用です。Model Query SQL では、ディメンションには名前だけを、指標には AGG(...) を使用します。唯一の例外は、修飾子を指定する形式 AGG({measure: modifier}) です。

pk(...) によるルックアップ #

ルックアップでは、単一キー、複合キー、有効期間付きキーを使用できます。ルックアップを使うクエリのグループ化フィールドではなく、参照先のキー全体を指定してください。このような属性のルックアップは、データセットの SQL でリレーションを準備する処理や、個別に集計した指標を組み合わせる処理とは異なります。詳しくは、ソースリレーション、ルックアップ、指標の合成を参照してください。

.dml の式で別のデータセットの列をルックアップする方法：

# Single PK
formula: 'SUM({amount} * pk(customer_id).{customers}.tier_discount)'

# Composite PK
formula: 'SUM(pk(brand_id, tag_id).{DATASET_PRODUCTS}.state)'

参照先のディメンションフィールドごとに 1 つの式を、宣言順に指定します。pk(1, tag_id) の引数の数は [brand_id, tag_id] に合っています。この例では意図的に brand_id を 1 に固定しています。このルックアップが正しいかどうかは、意図したキーと、ソースでそのキーが一意かどうかによって決まります。

複合キーと有効期間付きキー #

参照先の dimension: は、レポートのグループ化ではなく、ソースの完全なキーを表します。次の 2 つのルックアップパターンでは、参照先のフィールドを宣言順に指定します。

# Target with a compound key:
dimension: [id, region]
# Column in the referring dataset:
label: 'pk({id}, {region}).{D}.label'

# Target with an object key and validity interval:
dimension: [id, 'range(valid_from, valid_to)']
# Column in the referring dataset:
label: 'pk({id}, {event_date}).{D}.label'

カンマが YAML リストの 1 つの項目内に収まるように、'range(valid_from, valid_to)' の引用符を残してください。イベントの日付は [valid_from, valid_to) と照合されます。開始日は含まれ、終了日は含まれません。そのため、2 月 1 日のイベントは、2 月 1 日に始まる期間に一致し、その日に終わる期間には一致しません。これは、配列を生成するデータベース関数 range() とは別のものです。

複合キー全体が一意であれば、同じ ID が複数の地域に存在しても問題ありません。同じ ID の有効期間は重複してはいけません。コンパイルが成功しても、参照先の重複や有効期間の重なりによってクエリ結果の行が増えることがあります。--validate は、確認時点のデータがキーの要件を満たすかを検証します。データの修復や、後続の実行と同じスナップショットを使用することの保証は行いません。

複合キーと有効期間付きキーの演習には、完全なモデル、境界の日付、意図的に発生させた検証エラー、修正後の結果が含まれます。演習で扱うのは、有限で互いに隣接する区間です。片側に境界がない区間や、一般的な多対多の配分ルールは扱いません。ブリッジテーブルを使う分析や配分分析では、完全なキー、重み、想定される合計を別途定義してください。ルックアップの引数の数に関するエラーだけでは、その分析を表現できるかどうかは判断できません。

関数 #

基本的な集計関数 #

これらの関数は .dml と Model Query SQL の両方で使用できます。.dml では、元の列（SUM({amount})）または集計結果より細かい粒度の指標（SUM({sales: {+d: product}})）を集計します。Model Query SQL では、集計結果より細かい粒度の指標だけを集計できます。たとえば、SUM(AGG({sales: {+d: product}})) は製品ごとの売上を合算して総売上を求めます。指標を単に参照する場合は、AGG(measure) だけを使用します。

関数 構文 説明
SUM SUM({column}) 合計
COUNT COUNT({column}) NULL 以外の値の件数
COUNT(DISTINCT ...) COUNT(DISTINCT {column}) 重複を除いた件数
MAX MAX({column}) 最大値
MIN MIN({column}) 最小値
AVG AVG({column}) 平均値

DML 固有の関数 #

コンテキスト列は、有効な指標式の中で関数を使用できる箇所を示します。Model Query SQL では、引き続き AGG(...) を通じて指標を集計する必要があります。これらの関数を使っても、SELECT で元の列を集計することはできません。

関数 構文 コンテキスト 説明
AGG() AGG(measure) Model Query SQL のみ クエリ内で指標を参照する（集計関数ではない）
DIVIDE() DIVIDE({num}, {den}) 両方 安全な除算（ゼロで除算すると NULL を返す）
DISTINCTCOUNT() DISTINCTCOUNT({column}) 両方 重複を除いて値の件数を数える
SUMIF SUMIF({val}, {condition}) 両方 条件付き合計
COUNTIF COUNTIF({condition}) / COUNTIF({val}, {condition}) 両方 条件に一致する行／条件に一致する NULL 以外の値
AVGIF AVGIF({val}, {condition}) 両方 条件付き平均
MAXIF MAXIF({val}, {condition}) 両方 条件付き最大値
MINIF MINIF({val}, {condition}) 両方 条件付き最小値
DISTINCTCOUNTIF DISTINCTCOUNTIF({val}, {condition}) 両方 条件付きの重複除外カウント

条件付き集計の例：

# In .dml
completed_sales:
    type: measure
    formula: SUMIF({amount}, {status} = 'completed')

high_value_customers:
    type: measure
    formula: 'DISTINCTCOUNTIF({customer_id}, {sales: {+d: customer_id}} > 1000)'

-- In Model Query SQL (modifier form)
SELECT AGG(sales, '+f', region = 'North') FROM MODEL

条件関数とユーティリティ関数 #

関数 構文 説明
IIF IIF(condition, true_val, false_val) インライン条件式
ISNULL / IFNULL / COALESCE ISNULL({expr}, default) 最初の NULL 以外の値を返す
NULLIF NULLIF({a}, {b}) a = b の場合は NULL を返す

ユーティリティ関数は SQL の式レイヤーを使用します。式の構文として有効ですが、DML の正式な組み込みシンボルには含まれません。DML の関数カタログでは、この扱いは AGG、DIVIDE、SUMIF など、DML 自体が定義する関数に限られます。

指標の式の最外層が NULL 合体で、代替値がリテラルの場合、その指標を使用する箇所で欠落行の補完が有効になります。

daily_sales:
    type: measure
    formula: SUM(ISNULL({sales: {+d: dt_date}}, 0))

日付関数（SQLite 方言） #

関数 構文 説明
date() date(current_date) 現在の日付
date(current_date, 'start of month') — 今月の初日
date(current_date, 'start of month', '-1 month') — 先月の初日
date(current_date, 'start of year') — 今年の初日
date(current_date, '-N days') — N 日前

方言に関する注意：対象の方言に合わせて日付関数を選択してください。DML は SQLite 形式の日付式をサポートし、対応する式を選択した方言に変換します。生成された SQL を確認してください。対象のデータベースが元の式をそのまま受け付けるとは限りません。

Model Query SQL の修飾子構文 #

Model Query SQL では、次の 2 つの形式が等価です。

形式 構文 例
位置引数形式 AGG(measure, 'mod1', 'mod2') AGG(sales, 'yoy')
波括弧形式 AGG({measure: mod}) AGG({sales: yoy})

エイリアスのルール：正式なルールの一覧は、Model Query のエイリアスルールを参照してください。AGG(sales) にはエイリアスが自動で付き、AGG({sales: yoy}) には AS が必要です。

実行時変数 #

これらの変数は評価コンテキストのプレースホルダーであり、呼び出し元が指定するクエリパラメーターではありません。アプリケーションでのバインドについては、JDBC パラメーターとクエリの種類を参照してください。物理 SQL レベルでバインドを検証しても、Model Query のセマンティックレベルでバインドされるわけではありません。

変数 コンテキスト 意味
{dim_dt} 時間を考慮する式と修飾子 現在の評価コンテキストで解決された標準時間フィールド
{measure} fn-macro の式 マクロがラップする呼び出し元の指標
{dt_date}, {dt_week}, {dt_month}, {dt_quarter}, {dt_year} 標準時間フィールドの参照 名前で指定された標準時間フィールド

時間コンテキストでは、時間の分解能と期間の扱いを定めます。マクロの定義では、マクロの宣言と変数の使い方を説明します。

データベースで定義されたスカラー関数 #

スカラー関数の呼び出しは、アトミックな指標の内部にある場合や、集計済みの指標の結果に適用される場合も、生成されるSQLに残すことができます。指標のコンテキストはDMLが管理し、関数の実装と利用可否は対象データベースによって決まります。動作する例、評価段階の違い、検証要件については、検証済みのカスタム修飾子とデータベース関数を参照してください。この説明は、集約 UDF やテーブル値 UDF 全般に当てはまるわけではありません。

ルックアップの完全な例 #

pk()は対象データセットのディメンション順に引数を取り、単一のキーに限定されません。複合キーの例では、[id, region]を宣言し、validate-only を使って対象データセット内にキーの組み合わせの重複がないか確認します。範囲の例では、[id, 'range(valid_from, valid_to)']を使い、そのテストデータで開始値が範囲に含まれ、終了値が含まれず、互いに重なる範囲が拒否されることを検証します。これらの例は、任意の多対多の配分がサポートされることを示すものではありません。
