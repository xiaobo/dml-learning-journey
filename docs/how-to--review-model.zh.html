准备独立审查 #

向审查人员提供一套聚焦于审查所需内容的材料。其中应包含最终产物和报表约定，无需提供完整的对话记录。

材料包括以下内容。

  • 模型及其包含的文件，并标明已更改的定义。
  • 使用该模型的查询和原始报表约定。
  • 可执行文件的路径、版本、构建时间戳、指纹和方言。
  • 编译、实际运行验证和结果比较的证据。
  • 必需的语义检查及其假设。
  • 已知的审查发现和缺失的先决条件。

对于大规模变更，将模型复用、使用模型的查询和结果检查分别交给不同的审查人员。明确每个人的职责。作者负责实施已接受的修复，并作出最终交付决定。

6.1 核对报表约定 #

将每条使用模型的查询与第 2 阶段的草稿进行比较。

  1. 检查结果中每行所对应的粒度，以及结果涵盖的总体。
  2. 确认所有必需的指标都解析到预期的定义。
  3. 检查时间范围、对比期间和报表切片。
  4. 检查输出列、别名、类型和实际顺序。
  5. 移除交付报表不需要的调试列。

6.2 审查模型定义 #

逐一检查每个新指标能否在其他报表中复用。

  • 仅当总体、粒度、筛选条件和 NULL 的处理行为均一致时，才合并重复公式。
  • 将报表特有的切片移到查询中，除非该切片定义了业务指标。
  • 保留体现必要计算维度的中间指标。
  • 如果具名派生指标是可复用的业务指标，或物化过程依赖该指标，则保留它。
  • 检查名称、描述和公式是否一致。
  • 在判定两个定义冗余之前，先检查有关相似指标的警告。

合并或重命名后，对更改的模型运行 lint 检查，并以严格模式编译受影响的查询。

6.3 审查使用模型的查询 #

确认分组方式和指标修饰符能够表达所要求的报表。

  • 为每个带修饰符的指标引用保留各自独立的显式别名。
  • 如果下游使用方不需要这些别名，请移除未加修饰的 AGG(measure) 上的冗余别名。
  • 如果结果含义或下游使用方的约定依赖于 ORDER BY 和 LIMIT，请保留它们。
  • 检查解析后的时间上下文和宏的先决条件。
  • 检查连接的等值条件、数据的来源归属、填充行为和投影列。
  • 在保存的文件中保持 SQL 易于阅读。如果工具要求使用字符串格式，请将其编码为字符串。

6.4 根据明确的假设检查结果 #

编辑模型或查询后，重新运行受影响的结果检查。

  1. 对于子集计数，确认两个计数基于可比较的总体。
  2. 对于子集金额，在应用不等式之前，先考虑负值的影响。
  3. 对于比率，检查分母为零和输入缺失时的既定处理行为。
  4. 对于时间比较，检查前一期间的数据覆盖情况，以及已声明的 NULL 处理规则或填充规则。
  5. 如果有独立得出的结果，请选取有代表性的行进行比较。

不要一概规定上年数据缺失时结果为零。检查公式和生成的 SQL。缺少实际运行验证的证据时，记录为 not run。

6.5 重新检查受影响的产物 #

修复后，对更改的模型运行 lint 检查，并以严格模式编译更改的查询。如果修复改变了实际运行验证或结果检查的输入，则重新运行适用的验证和检查。检查 SQL 和汇总值，尤其是在变更粒度或合并指标之后。

如果严格模式下仍有警告，请报告该问题。生成 SQL 产物并不代表严格模式检查已通过。

6.6 交付产物和审查证据 #

提交模型、使用模型的查询、审查发现、已接受的变更和检查结果。区分已通过的检查、已复现的缺陷和未运行的检查。

对于导出和仪表板，请保持指标为数值类型，并根据下游使用方的要求核对输出名称。

6.7 处理审查发现 #

在更新后的模型和受影响的查询中重新检查已接受的修复。记录尚未解决的问题及其对结果的影响。

如果拟议的优化会改变业务定义，请返回第 4 阶段，并明确记录这项变更。

6.8 单独核实分析中的各项主张 #

在建模过程中和执行后检查业务假设。仅凭技术审查无法确认业务结论能否从数据中得出。
