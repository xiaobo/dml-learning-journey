Typische Fehler bei der Modellerstellung

Inhalt dieser Seite
  • P1. Darstellungslogik in DML aufnehmen
  • P2. Abgeleitete Spalten, die nur eine Abfrage benötigt, in DML aufnehmen
  • P5. Nicht prüfen, ob das Ergebnis des kompilierten SQL mit dem Ergebnis des Referenz-SQL übereinstimmt
  • P6. Eigene Kennzahlen für einzelne Filter oder Kombinationen von Abfragedimensionen anlegen
  • P7. Aggregationsformeln mehrfach definieren
  • Kategorie: Model Query SQL

Legen Sie wiederverwendbare Definitionen im Modell ab und treffen Sie Entscheidungen zur Darstellung in der Abfrage- oder Berichtsschicht.

P1. Darstellungslogik in DML aufnehmen #

Fehler: FORMAT(...), CONCAT(...) und CAST(... AS VARCHAR) in Kennzahlformeln verwenden. Korrektur: Entfernen Sie die Formatierung aus .dml. Nehmen Sie sie im Dashboard oder in der Darstellungsschicht vor.

P2. Abgeleitete Spalten, die nur eine Abfrage benötigt, in DML aufnehmen #

Fehler: Kennzahlen für Berechnungen anlegen, die nur in einer bestimmten Abfrage sinnvoll sind. Korrektur: Legen Sie abfragespezifische Ausdrücke im Model Query SQL ab, nicht in .dml.

P5. Nicht prüfen, ob das Ergebnis des kompilierten SQL mit dem Ergebnis des Referenz-SQL übereinstimmt #

Fehler: Allein aus der erfolgreichen Kompilierung schließen, dass die Ausgabe von -c korrekt ist. Korrektur: Führen Sie sowohl das ursprüngliche SQL als auch das kompilierte SQL aus und vergleichen Sie die Ergebnismengen.

P6. Eigene Kennzahlen für einzelne Filter oder Kombinationen von Abfragedimensionen anlegen #

Fehler: sales_north, sales_south und sales_east anlegen oder sales_north anlegen, obwohl WHERE Region = 'North' ausreicht. Korrektur: Definieren Sie eine allgemeine Kennzahl Umsatz und verwenden Sie WHERE Region = 'North' in den Abfragen.

P7. Aggregationsformeln mehrfach definieren #

Fehler: Erlös: SUM({Verkaufsbetrag}) und total_revenue: SUM({Verkaufsbetrag}) definieren. Korrektur: Definieren Sie eine einzige atomare Kennzahl und referenzieren Sie sie überall.

Kategorie: Model Query SQL #

SQL, für das sich Entwürfe erzeugen lassen #

Im Testlauf im November 2026 erzeugte --to-dml Entwürfe für standardkonformes CAST(... AS type), GROUP BY mit CASE, ROW_NUMBER() in einem CTE, LIMIT/OFFSET, EXTRACT, DATE_TRUNC, ILIKE, GENERATE_SERIES, NULLS LAST und EXCEPT. Jeder Entwurf muss noch kompiliert werden. Anschließend müssen die Ergebnisse verglichen werden.

Eingaben, die sich im Testlauf nicht konvertieren ließen Vor der Konvertierung umschreiben
sale_date::date AS d, DATE '2025-01-01' Verwenden Sie CAST(sale_date AS date) AS d oder CAST('2025-01-01' AS date).
SUM(Verkaufsbetrag) FILTER (WHERE paid) Verwenden Sie SUM(CASE WHEN paid THEN Verkaufsbetrag END).
QUALIFY ROW_NUMBER() ... = 1 oder DISTINCT ON Berechnen Sie ROW_NUMBER() in einem CTE mit derselben Partitionierung und Sortierung. Filtern Sie in der äußeren Abfrage nach rn = 1.
$$hello$$ Schließen Sie die Zeichenfolge in einfache Anführungszeichen ein und verdoppeln Sie jedes einfache Anführungszeichen innerhalb der Zeichenfolge.
INTERVAL '1 day', LATERAL, STRING_AGG(... ORDER BY ...) oder JSON ->> Passen Sie den Ausdruck an den vorgesehenen Parser und Dialekt an oder stellen Sie ihn als Spalte einer Quellansicht bereit. Prüfen Sie vor der Konvertierung die Sortierung, das Verhalten bei NULL und welche Zeilen im Ergebnis enthalten sind.

Nach der Konvertierung

  1. Fügen Sie den Eintrag dialect: für die Zieldatenbank hinzu, falls er im Entwurf fehlt.
  2. Der Dateiname ohne Erweiterung und der in der Datei angegebene Abfragename müssen übereinstimmen. Wenn zwei Definitionen denselben Kennzahlnamen verwenden, behalten Sie eine Definition bei oder benennen Sie die abfragelokale Berechnung um und aktualisieren ihre Referenzen.
  3. Setzen Sie die Grenzen des Berichtszeitraums in der Abfrage. Stellen Sie sicher, dass der Kennzahl die von pp, pop oder ytd benötigten historischen Quelldaten zur Verfügung stehen.

Prüfen Sie den bearbeiteten Entwurf mit dem Linter und kompilieren Sie ihn im strikten Modus. Vergleichen Sie anschließend seine Ergebnisse mit denen des ursprünglichen SQL auf denselben Daten.
