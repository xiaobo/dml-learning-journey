モデルを組み合わせるときの名前の参照

このページの内容
  • 同じファイルで定義した名前
  • ほかのファイルを読み込む
  • SQL で使うモデル上の名前とデータベース上の名前
  • クエリファイルを直接コンパイルする

同じファイルや読み込んだファイルで使える名前と、データセットの SQL でモデル上の名前とデータベース上の名前を書き分ける方法を説明します。

同じファイルで定義した名前 #

確認に使用したコンパイラでは、同じファイルの後で定義する名前も参照できます。指標は、それが使うデータセットや別の指標より先に書けます。計算列が参照する列や、pk() の参照先データセットも後で定義できます。参照先を先に書くと読みやすくなります。定義が見つからない場合や参照が循環する場合はエラーになります。

ほかのファイルを読み込む #

各ファイルで使えるのは、そのファイル内の定義と、自分で読み込んだファイルの定義です。読み込み元だけにあるデータセットを、読み込まれる側から参照することはできません。読み込みに失敗すると、読み込み元のモデルも無効になります。相対パスは、まず読み込みを指定したファイルの場所を基準に解決されます。環境で設定したモデルの検索パスとは別に、依存するファイルをモデルで指定してください。

同じセッションで以前に読み込んだモデルの定義が、自動的に使えるようになることはありません。共通のデータセットと指標を一つのモデルに定義し、各レポートでそのモデルを読み込むと再利用できます。

SQL で使うモデル上の名前とデータベース上の名前 #

データセットの sql: で FROM {Customers} はモデル上のデータセットを、FROM Customers はデータベース上の表などを参照します。列の式で {net_amount} と書くと、そのモデル列の定義が展開されます。net_amount とだけ書くと、データベースに渡す SQL の列名になります。逆変換で生成される SQL に、データベース上の名前がそのまま残る場合もあります。

クエリファイルを直接コンパイルする #

DML を直接コンパイルする場合、クエリ名は拡張子を除くファイル名と一致させます。たとえば report.dml に report: {type: query, ...} を記述します。クエリを含まないモデルを再利用するには Model Query SQL を使います。FROM に指定する名前はモデルのファイル名に基づきます。詳しくはクエリの検索を参照してください。

レポートを実行する前に、使用するコンパイラで読み込み先、名前、生成された SQL を確認してください。
