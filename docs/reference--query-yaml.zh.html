本页介绍 type: query、列、筛选器、物化方式的选择以及 after:。此查询使用的模型指标与模型查询 SQL 相同。

文件名约束：使用 dmlc -c 编译 .dml 文件时，type: query 块的名称必须与去掉扩展名 .dml 后的文件名一致。例如，名为 my_report.dml 的文件必须包含 my_report: type: query，不能使用 some_other_name: type: query。如果名称不一致，编译器会拒绝编译并报错：query name should be <filename> (the same as filename) instead of <block_name>。

基本结构 #

my_report:
    type: query
    allows: ALL              # optional: consider compatible materializations

    columns:
        dimension:
            - dt_month
            - 商品
        销售额:               # measure reference (no AGG needed)
        销售额同比:
            formula: '{销售额: yoy}'

columns: 为必填项。除维度键外，其中的每个键都表示一个输出列名，对应的值是公式或对指标的直接引用。可选键 dataset: 用于选择数据集查询形式，不能与 columns.dimension 同时使用。

查询筛选器有以下形式。每个键都是一个筛选器的名称，指标引用修饰符可以通过该名称指定筛选器。

值的形式 含义
<column>: <数值> 对同名列应用等值条件
<column>: [a, b] 判断值是否在列表中
<name>: {column: <column>, 数值: <数值>} 对显式指定的列应用命名等值筛选器
<name>: {column: <column>, range: [lo, hi]} 对显式指定的列应用命名范围筛选器，包含上下限
<name>: {visibility: hidden, default: on} 已启用默认值的隐藏筛选器

筛选器放置规则决定每个谓词在哪个阶段应用。

明细与聚合 #

模式 指定方式 约束
聚合 无 dataset: 键 允许使用指标，由编译器进行聚合
明细 dataset: DATASET_NAME 不允许使用指标，仅允许使用原始列 
# Detail query
商品清单:
    type: query
    dataset: DATASET_PRODUCTS
    columns:
        dimension:
            - 商品

自动联接多个数据集中的指标 #

聚合查询引用不同数据集中的指标时，按 FULL OUTER JOIN 的语义在共有的维度字段上联接。仅存在于一个数据集中的行也会保留，另一个数据集的指标值为 NULL。

生成的联接类型取决于已证实的行保留规则。编译器以 FULL OUTER JOIN 为起点，将每个联接收紧为查询筛选条件能够证实的最严格类型。在 filters: 中使用 "{primary_measure} is not null":，会排除仅存在于次侧的行，并将生成的联接改为 LEFT JOIN。如果两侧都有要求值存在的条件，则生成 INNER JOIN。只有在有效的主侧分组中，主指标不可能为 NULL 时，这个条件的结果才与作为基准的 SQL LEFT JOIN 一致。请证实这项关于 NULL 和空分组的约束，并检查生成的联接类型和输出。否则，筛选器也会删除有效分组。请将此条件写在 after: 之外，以便在追踪数据血缘、审查和复用时都能看到它。

必须使用公式作为键，即写成 "{expr}":，并将值留空。name: {condition: …} 不符合架构定义。

DML 格式的列引用 #

列类型 语法 示例
同一数据集中的维度字段 直接使用名称 商品:
其他数据集中的维度字段 "{DATASET}.column" 商品编号: "{DATASET_PRODUCTS}.商品编号"
指标 直接使用名称 销售额:
带修饰符的指标 formula: 销售额同比: {销售额: yoy}

注意：在未指定 dataset: 的聚合查询中，如果列属于某个特定数据集，仅使用列名会报错。请使用 "{DATASET}.column" 形式。

自动别名与直接引用 #

如果名称匹配，没有公式的查询列可以解析为指标或数据集列。这称为自动别名。共有三个层级：

层级 机制 示例 结果
column（直接引用） 数据集的 columns: 下的条目不含公式，且该条目在 DML 中的名称与表中的列名相同。 prod_amount: SUM(prod_amount)，原样传递名称，不使用别名
查询列 → 指标（自动别名） 查询列没有公式，列名与指标名相同 收入:（指标 收入 已存在） 编译器代入该指标的 formula: 表达式
查询列 → 数据集列（自动别名） 查询列没有公式，列名与数据集列名相同，且该数据集列可从查询维度推导 prod_name:（通过 pk({商品编号}) 链找到的数据集列） 编译器根据数据集定义解析该列

主要行为：

  • dmlc -c 不会根据表结构检查数据集列是否存在。列名不匹配时，编译仍会通过，但执行时会出现 SQL 错误。请使用 validateOnly 检查列名是否匹配。此选项需要数据库连接。
  • 如果查询列名与任何指标名或可推导的数据集列名都不匹配，则会报错 not defined, add formula?。
  • 如果查询列名与指标名不同，请添加显式公式（display_name: '{measure_name}'），或使用 abbr: 重命名该指标。
  • 如果数据集列无法从查询维度推导，例如原始事实列不依赖任何维度字段，则会报错 cannot be derived from dimension [门店编号]。
  • 直接传递的列（无 formula:）可以用对象形式添加元数据属性（description:、visibility:），无需指定 formula:。例如，收入: { description: 'Total revenue' } 会通过自动别名引用指标 收入，同时添加描述。

visibility: hidden #

从最终查询输出中隐藏列，同时让该列在中间临时表中仍然可用。

项目 行为
最终的 SELECT 隐藏列通常不会出现在输出中，但如果筛选器或 HAVING 子句引用了隐藏列，该列可能会进入最终输出。确定具体输出列之前，请检查生成的 SQL。
中间临时表 隐藏列仍可用于 JOIN 条件和 filters:
引用隐藏维度字段的 filters: 可以通过编译，但可能会收紧可选联接，也可能强制物化辅助结果。请检查生成的 SQL。
after: 中按名称引用隐藏维度字段的 SQL 失败 — query columns refer to nonexistence source column
PK 链 保持完整 — 仅设置 visibility: hidden 不会触发 PK 警告

指导： 如果 after: 按名称引用维度字段，请移除 visibility: hidden。如果 after: 仅使用指标列，请保留该设置。如果输出受契约约束，请编译查询，确认最终结果中没有隐藏的辅助列。只有输出契约明确允许时，才能包含额外的列。

有效的 YAML 写法： 使用 - dim: {visibility: hidden}，或使用键位于 dim 条目下一级的嵌套映射。将 visibility: 与 dim 键并列在同一缩进层级会因缩进不足而触发架构检查错误。请使用内联或嵌套写法。仅使用 dmlc -c 时，务必检查编译生成的 SELECT（架构检查在编辑器中或通过 dmlc --lint 运行）。

查询维度格式 #

columns:
    dimension:
        - dt_month
        - 商品
        # Correct: list dimension field names only

错误：不要将跨数据集的列映射放入查询的维度字段中。请将这些公式定义为单独的查询列：

# Wrong
columns:
    dimension:
        - f_tag_id: {DATASET_PT}.销售明细编号

# Correct
columns:
    dimension:
        - f_tag_id
    f_tag_id: "{DATASET_PT}.销售明细编号"

例外：将指标用作维度。 查询维度条目可以绑定一个指标（通常使用 +d），使查询按该指标值对行分组，并以此确定查询粒度：

columns:
    dimension:
        - 首次购买月份: '{首次购买月份: {+d: 门店编号}}'
    销售额:

使用 +d（首选）或 dimension: 显式声明分类实体的键。只有完整键一致时，才允许使用多个独立字段。常规输出指标必须能够从 Q ∪ K 所定义的层级正确向上汇总。标签通道过滤器（公式的 filters: 或 Model Query 的 HAVING）在标签生成之后才生效。请参阅将指标用作维度。请勿将此例外用于物理映射或 {DATASET}.col 映射。

过滤器的放置层级 #

过滤器的放置位置决定查询语义，并非语法偏好：

层 位置 此处填写的内容
查询的 filters: 查询块 特定于报表的数据切片（渠道、品牌、日期范围）
中间列或中间指标 .dml 数据集或顶层指标 指标专属的纳入条件，适用于被排除的行可以留在指标值为 NULL 的组中的情况
数据集中的 sql: 数据集定义 源数据行集合中始终成立的不变条件，或 DML 无法以声明方式表达的结构

将源数据的 WHERE 条件移到指标输入的筛选条件中，会改变结果中是否存在相应的行，除非仅由被排除行构成的组不可能出现，或按契约，这类组与结果中实际存在且指标值为 NULL 的组等价。请明确证明这一例外成立。如果例外不成立或无法确定，请保留会移除行的写法。

结构化范围的语义： 查询的 filters: 中，range: [start, end] 按 dt_<grain> 声明的时间粒度包含两个端点。对于 2025 年的日度数据，使用 ['2025-01-01', '2025-12-31']；对于月度数据，使用 ['2025-01-01', '2025-12-01']。SQL 方言可以使用 < dateadd(day, 1, end) 之类的不包含上界的物理条件来实现该范围，但 DML 输入的结束值仍是范围内最后一个包含的值。

列表与范围的常见误用： 直接使用列表值 dim: ['a', 'b'] 会编译为 WHERE dim IN ('a', 'b')（精确匹配两个值之一），不会编译为包含端点的范围。对于日期维度，这可能导致数据在没有提示的情况下被遗漏。dt_date: ['2024-01-01', '2025-12-31'] 只返回指定两天的行，不会返回整个 2 年时间跨度内的行。需要指定包含端点的区间时，请始终使用 range: [start, end]：

# Wrong — only 2 days of data
filters:
    dt_date: ['2024-01-01', '2025-12-31']

# Right — full inclusive range
filters:
    dt_date:
        range: ['2024-01-01', '2025-12-31']

常见过滤问题：

症状 修复方法
[dataset …] [filters]: not supported 移至查询的 filters:、指标公式或 sql: 中的 WHERE
查询过滤器中出现 referred column {DATASET}.col is undefined 使用字符串形式："{DATASET}.col = 数值":
日期维度上的双元素列表仅返回 2 天的数据 使用 range: [start, end] 代替直接填写的列表。dim: [a, b] 会编译为 IN (a, b)，而非 BETWEEN。
查询的 filters: 中存在复杂的 EXISTS / PK 链 仅在条件用于判断行是否应纳入特定指标时，才在指标输入阶段筛选。如果条件用于选择源数据行，请将其保留在处理源数据行的阶段。将条件移入指标可能改变报表所涵盖的数据范围。请检查生成的谓词和连接。

pk 链式查找 #

# Single PK lookup
formula: 'pk(客户编号).{DATASET_CUSTOMERS}.tier'

# Composite PK — all columns required
formula: 'pk(brand_id, tag_id).{DATASET_PRODUCTS}.state'

键数量规则：pk(...) 中的键数量必须与目标数据集的 dimension: 中的维度字段数量一致。如果不一致，则会产生 expect N expr(s) to query dataset X using pk, but got M（参阅故障排查索引中的 P65）。

嵌套的查找链：从一条 pk() 查找链派生的列可以用作另一条 pk() 查找链的键。编译器会追踪派生链，并生成对应的嵌套 LEFT JOIN。这是直接表达“查找一个属性，再用该属性查找另一个属性”的原生方式，无需使用 sql: 或 after:。

# fact dataset
columns:
    门店编号:
    # First hop: store_id → Dim Customer → hq_id
    总部编号: pk({门店编号}).{客户名录}.总部编号
    # Second hop: hq_id (itself a pk chain result) → Dim Customer → store_code
    总部代码: pk({总部编号}).{客户名录}.store_code
    # Third hop: hq_id → Dim Customer → org_id, then org_id → Dim Org → emp_name
    总部组织编号: pk({总部编号}).{客户名录}.组织编号
    总部联系人姓名: pk({总部组织编号}).{组织名录}.员工姓名

在已检查的构建版本中，支持同一文件内的前向引用，包括列依赖和 pk() 的目标。为便于阅读，请将被依赖项写在前面。包含文件有独立的可见性边界，请参阅模型组合。

after: 子句 #

after: 是可选的。省略时，编译器会解析出代表查询维度字段的可见输出列，并按解析后的维度字段顺序依次使用这些列作为排序键，对结果行进行升序排序。因此，隐藏维度字段可能通过可见查询列的别名参与排序，而不使用定义中写明的字段名。如果没有有效的输出维度，则不保证行顺序。省略 NULL 的排序修饰符时，使用目标 SQL 方言的默认规则。

只要存在 after: 块，最终结果的顺序就由该块决定。具体而言，select * from {QUERY} 如果没有自己的 ORDER BY，就会取消编译器的默认排序。只有当具有业务意义的自定义设置与默认行为不同时，才使用 after:。这些设置包括排序方向、NULL 的排序位置、排序值相同时的次级排序规则、按指标或表达式排序，以及 TOP 或 LIMIT。请勿再次聚合：

my_report:
    type: query
    columns:
        dimension: [商品]
        销售额:
    after: 'select * from {QUERY} ORDER BY 销售额 DESC LIMIT 10'

存在 after: 时，必须使用 {QUERY} 指代编译后的查询结果，供查询后语句使用。“仅排序”表示除这层包装和 ORDER BY/TOP/LIMIT 外，不包含任何业务逻辑。如果显式指定的排序与查询的默认输出顺序一致，上游编译器会发出 redundant ORDER BY 警告。请按该警告针对当前位置给出的提示操作。如果 after: 中还有其他重要处理，只删除冗余的 ORDER BY 子句。只有没有其他处理时，才删除整个块。

错误：在标准指标查询的 after: 中使用 group by 进行二次聚合。应由查询块聚合指标。

allows: ALL #

要让编译器考虑所有兼容的物化结果，请使用以下配置：

my_report:
    type: query
    allows: ALL
    columns:
        dimension:
            - dt_date
        销售额:

allows: 控制哪些物化结果可以作为候选项。ALL 允许使用候选项，NONE 禁止使用物化结果。显式指定名称会将候选范围限制在这些名称内。候选项是否可用，仍取决于其定义行或汇总值的粒度和筛选条件是否都与查询兼容。此设置不会放宽指标的 dimensions: 约束，也不允许任意指定查询粒度。请参阅物化声明。

YAML 语法常见问题 #

  • 如果公式包含 :、{ 或 -，请用引号括起公式：formula: 'SUMIF(...)'
  • 在 measures: 下声明维度字段：错误。维度字段只能在 dimension: 下声明。
  • 为复合指标指定 dataset:：错误。如果公式引用了其他指标，请省略 dataset:。
  • 不同数据集中的维度字段名称不一致：统一为同一个名称（例如 tag_id），并在 columns: 中配置映射。

YAML 查询速查 #

用 type: query 定义查询。用 dimension: 指定结果分组，用 columns: 指定输出。筛选条件的位置决定它作用于源行、单个指标还是聚合后的结果。跨数据集组合时，先确认关联键、值为 NULL 的键以及仅在一侧出现的分组。用 after: 处理最终排序等查询操作。
