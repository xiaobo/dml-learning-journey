複数の地域に同じ ID があるときの検索

行を特定するために必要な項目をすべてキーに含め、検索時には定義と同じ順序で値を渡します。東部と西部に同じ 番号=1 があっても、(番号, 地域) の組み合わせで 1 行に絞れれば検索できます。

元データと集計結果 #

参照先のテーブルでは (1,east) が東部、(1,west) が西部に対応します。売上は東部が 10、西部が 20 です。クエリは次の結果を返します。

地域名 売上
East 10
West 20

ID だけで結合すると、この 2 行を区別できません。

参照方法をモデルに定義する #

参照先のテーブルに dimension: [番号, 地域] を定義します。売上データの地域名は pk({番号}, {地域}).{対応表}.名称 で取得します。引数の順序は参照先のディメンションで定義した順序と同じです。

ファイル全体：compound/model.dml 
dialect: duckdb
対応表:
  type: dataset
  table: DIM
  dimension: [番号, 地域]
  columns:
    番号:
      abbr: id
    地域:
      abbr: region
    名称:
      abbr: label
売上明細:
  type: dataset
  table: FACT
  dimension: [売上明細番号]
  columns:
    売上明細番号:
      abbr: fid
    番号:
      abbr: id
    地域:
      abbr: region
    注文金額:
      abbr: amount
    名称: 'pk({番号}, {地域}).{対応表}.名称'
  measures:
    売上額: SUM({注文金額})
ファイル全体：compound/setup.sql 
CREATE TABLE DIM(id INTEGER, region VARCHAR, label VARCHAR); INSERT INTO DIM VALUES (1,'east','East'),(1,'west','West'); CREATE TABLE FACT(fid INTEGER,id INTEGER,region VARCHAR,amount INTEGER); INSERT INTO FACT VALUES (1,1,'east',10),(2,1,'west',20);
ファイル全体：compound/normal.sql 
SELECT 名称, AGG(売上額) FROM MODEL GROUP BY 名称 ORDER BY 名称

地域名で集計するときは、モデルに定義した参照方法が使われます。各クエリに結合条件を書く必要はありません。番号, 地域 を自分のデータに合わせる前に、どの項目を組み合わせれば行を特定できるか確認してください。

どの売上が二重に集計されたか #

地域テーブルに (1,east) の行をもう 1 行追加します。東部の売上 10 が 2 行に一致します。通常の SQL で結合して合計すると、東部は 20 になります。西部は 20 のままです。注文データは変わっていません。

このデータに対して --validate を実行すると、検証結果に duplicate_key が表示されます。(1,east) の行を 1 行だけ残して再度検証し、元のクエリを実行します。東部は 10 に戻り、西部は 20 のままです。ダウンロードできるスクリプトでは、重複があるときの SQL の集計結果、検証時のエラー、修正後の 2 行を確認できます。

検証では、宣言したキーで現在のデータの行を特定できるかを確認します。その後のデータ追加で新たな重複が生じることはあります。重複の原因に応じて元データやキーの定義を修正してください。最後に DISTINCT を追加しても、二重に集計された金額を正しく戻せるとは限りません。

検証を実行して結果を確認する #

プロジェクトをダウンロードして、READMEの手順に従い、PowerShellでverify.ps1を実行します。dmlcにパスを通してください。新しい出力フォルダーに演習用データベースを作成し、結果と診断情報を保存します。

この例は DuckDB で実行しました。使用したコンパイラのバージョンと検証結果は、ダウンロードに含まれる verification-summary.json で確認できます。検証とクエリの実行は別々に行われるため、その間にデータが変わる可能性があります。他のデータベースで使う場合は個別に確認してください。
