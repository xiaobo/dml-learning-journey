报表将业务定义与分组、筛选和呈现方式的选择结合起来。DML 将可复用的定义保存在模型中。只要定义行或汇总值的层级（粒度）彼此相容，报表就可以使用相同的指标。

指标可以引用其他指标，每处引用的求值方式取决于分析上下文。因此，同一个利润率定义既可用于地区报表，也可用于统计当年年初至分析截止日的 KPI。时间转换会重新计算利润和收入，再做除法，而不是对各月的利润率取平均值。来自不同数据集的指标也可以在行或汇总值的粒度相容时组合。输出键和仅在一侧有数据的分组仍须符合报表预期覆盖的数据范围。盈利能力示例通过组合、累积和比较展示了这一过程。DML 模型、DMX 表达式和编译器可以构成分析语义层的计算核心。业务定义仍由相关人员协商确定。

图解DML 简明入门使用四笔销售示例和一个分组探索工具介绍这些概念。

如需完整的可执行示例，请参阅编译第一个模型查询。DML 核心规范定义了该语言的规则。

1. 模型层、查询层和表达式层 #

层 语言 内容 位置
模型 DML（Dato Measure Language） 数据集、指标和列宏 .dml YAML
查询 Model Query 指标选择、分组和报表筛选条件 .sql 或指定了 type: query 的 DML
表达式 DMX（Dato Measure eXpression） 公式、引用和修饰符 模型公式和查询表达式

DML 是独立的语义层编译器。它处理模型文件，并生成由数据库执行的 SQL。数据库权限和应用授权负责控制访问，仪表板和调度由外围系统负责。模型筛选条件本身不能作为访问控制策略。

DML 检查声明结构和分析兼容性，例如粒度和时间上下文。它不会对 SQL 表达式进行完整的静态类型检查。物理值类型由数据库负责，模型校验所用的模式会拒绝列的 type: 声明。因此，无效的类型转换或函数参数可能通过编译，却在数据库执行时出错。请参阅列元数据和值类型。

数据集将列绑定到物理表或 SQL 关系。数据集的 dimension: 声明源行的完整键。

交易明细:
  type: dataset
  table: fact_transactions
  dimension: [交易编号]
  columns:
    交易编号:
      abbr: transaction_id
    销售金额:
      abbr: amount
    折扣金额:
      abbr: discount
    净额: 销售金额 - 折扣金额
  measures:
    销售额: SUM({净额})
    交易笔数: COUNT(1)

每笔平均交易额:
  type: measure
  formula: 'DIVIDE({销售额}, {交易笔数})'

销售额 和 交易笔数 是原子指标。它们继承定义所在的数据集，直接聚合其中的行或列表达式，且不引用其他指标。虽然这两个原子指标都使用 交易明细，但 每笔平均交易额 的公式引用了其他指标，因此它是复合指标。复合指标没有 dataset: 属性。

在模型公式中，不带花括号的 销售金额 指向物理 SQL 列。{净额} 则展开为模型中计算列的表达式。即使逻辑名称和物理名称相同，花括号也能区分这两种引用。

列宏定义可复用的列表达式或跨数据集查找。列宏可以让指标访问属性，无需在每个使用该指标的查询中编写联接。查找参数由目标数据集的完整键决定。请参阅源关系与查找。

Model Query 通过 AGG(...) 引用指标。模型公式直接使用 SUM 和 COUNT 等聚合函数。AGG 是查询引用指标的接口，不能替代模型公式中的 SUM。

一次性使用的指标可以先定义在查询文件的内联 DML 块中。探索时无需先修改共享模型。将有用的定义纳入共享指标之前，请先审查这些定义。

2. 源关系、查找与指标组合 #

DML 在不同阶段组合数据。所选阶段决定了需要检查哪些键、筛选条件和行集合。

任务 机制 结果约定
通过完整键复用属性 在模型公式中使用 pk(...) 查找 每个查找键对应一条目标行。支持单列键和复合键。
查找在事件日期有效的属性 使用 pk(销售明细编号, dt_date) 对照 [销售明细编号, 'range(valid_from, valid_to)'] 查找 校验的有限区间采用 [start,end) 的形式。同一 id 的区间不得重叠。
比较销售额和预算等独立的事实数据 按对齐的维度求值的指标 常规组合使用两侧键的并集，保留任一侧出现的所有组。仅在一侧出现的组，其另一侧的值仍为缺失。
准备桥接、联接、并集或子查询关系 数据集的 sql: 或数据库视图 预先准备的关系需要有自己的完整键。如果一条源行可能匹配多条记录，请定义分摊权重并核对总计。

使用模型的 Model Query 中，SQL 不直接支持 JOIN、UNION 或子查询。这项限制并不妨碍在数据集的 SQL 中准备受支持的关系。源 SQL 中的筛选条件仍会限制源关系包含的行，不会自动变成能响应每个使用方上下文的规则。

支持复合键查找和按指定日期查找当日有效的值，并不意味着存在可以任意选择路径的通用关系图，也不意味着支持自动多对多分摊。独立聚合指标也无法修复重复的查找键或错误的对齐规则。复合键查找和按指定日期查找有效值的示例提供了完整模型，并展示如何故意触发和修复键错误。有关未匹配的组和 NULL 键，请参阅组合语义。有关源关系的归属和派生关系的验证，请参阅数据集 SQL。

3. 维度的作用与粒度 #

维度字段是一个有名称的 DML 字段。维度是一个字段列表。维度的作用取决于它在何处声明。

声明 含义
数据集中的 dimension: 完整标识源行的信息
公式中的维度修饰符 单个指标引用的求值维度
查询中的 GROUP BY 或 columns.dimension 结果分组
物化中的 dimension: 存储的分组和键
指标中的 dimensions: 允许使用的备选求值维度，每个内层列表对应一个维度

粒度描述在特定上下文中一行代表什么。例如，[交易编号] 标识一笔交易，[地区, dt_month] 则按地区和月份对报表分组。一个报表分组可以包含许多源行，因此不能替代源键。

修饰符 dimension: [] 清空求值维度，以计算总计。它不声明用于标识数据集行的键。+d 为中间计算添加字段。当公式需要更粗粒度的结果时，由显式指定的外层聚合汇总这些中间值。

编译器依赖已声明的源键。即使编译成功，如果 pk(...) 的参照表中有重复键，同一条源记录也可能在关联时被匹配多次。校验可以检查当前数据中的键是否唯一。要确认查询结果是否符合预期，还需另行核对结果。

维度语义更详细地介绍了这些作用及其影响。

4. 时间上下文与 dim_dt #

dim_dt 表示指标的查询上下文中当前生效的时间字段。公式可以用它引用当前时间粒度，无需直接指定 dt_date、dt_month 或 dt_quarter。宏接受的粒度仍受该宏的前置条件限制。

用于分组的时间字段或时间筛选条件都可以提供上下文。请查看严格模式的诊断信息并检查生成的连接，这两项检查应独立于语法是否被接受。仅有时间比较或基于键并集的连接，并不意味着严格模式会发出警告。

声明 dt_date 等细粒度的标准时间字段后，便可通过系统日历使用受支持的更粗粒度时间字段。这些虚拟字段无需另行声明为物理字段。在编辑器中对派生字段 dt_month 使用“转到定义”，会跳转到显式声明的源时间列。

单个 KPI 仍需要明确指定统计截止点。在可运行示例中，按二月筛选时，基于一月和二月数据计算的 YTD 利润率为 20%，而同一查询中的普通收入指标只计算二月。缺少时间上下文时，查询会失败。使用日历分组的查询也可能返回有累计值但当月收入为 NULL 的月份，因此请根据需要选择输出期间。执行查询的连接所使用的日历必须覆盖目标日期。

时间上下文规范定义了 dim_dt 和标准时间字段。系统宏提供时间宏和公式宏的定义供参考。

5. 复用与集成 #

自定义 fn-macro 定义会包裹调用方的指标公式，而 dt-macro 定义会改变该公式的时间上下文。两者可以通过修饰符语法组合使用，无需修改编译器。数据库标量函数调用复用执行连接上已安装的函数。扩展指南展示了实际执行的示例和因缺少函数而失败的示例。这些机制既不构成通用模块系统，也不为所有类型的 UDF 提供跨环境支持。

请显式设置模型的 SQL 方言。方言能被识别，并不能证明所有功能都已在该数据库引擎上成功执行。生成的 SQL 可能包含多条语句、中间关系和日历依赖项，因此也要验证执行环境。

经过验证的 JDBC 驱动程序会在物理 SQL 中绑定位置参数。对于 Model Query，该驱动程序会在筛选条件和指标表达式中绑定位置参数。请参阅 JDBC 参数示例。物化参数和内部字面量参数化是不同的机制。

编译、验证和执行各自检查不同的事情。在实际数据上校验键，可以提前发现会让同一条记录在关联时被匹配多次的重复键。校验和随后的执行可能读到不同的数据快照。数据库接受 EXPLAIN 并不能证明数值正确。请在相同的数据范围内，与独立得出的结果逐项核对完整键、每行出现的次数、NULL 和舍入前的数值。

时间比较与结果行的纳入条件 #

查询中处理上一期的分支可以借助日历，将上一期的分组带入没有当月事实数据的月份。该分组是否纳入报表，取决于查询的时间窗口以及仅保留当期有数据的分组的筛选条件。请参阅比较中额外出现的月份。
