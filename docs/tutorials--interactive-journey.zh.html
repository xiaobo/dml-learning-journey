我们将创建一份 2 月销售报表，其中包含已完成交易的销售额、与上月的对比、每位客户的平均销售额以及各区域的销售额占比。在浏览器中打开一段探索 DML 的小小旅程。如需离线使用，请将页面及其同级文件保存在同一目录中。

使用简介下方的按钮开始教程，或从下一个未完成的章节继续。

教程在浏览器中使用虚构的数据行进行计算。它不会编译任意 DML，也不会连接数据库。预先记录的配套查询包含编译器的实际输出。最后，我们将下载一个完整的项目。

选择答案后，点击提交答案。仅选择选项不会完成该章节。将指针悬停在带点线标记的代码名称或结果标题上，或用键盘将焦点移到这些元素上，即可查看简短提示。点击或轻触这些元素可查看其定义。

1. 标识每条源数据行 #

查看第 1 章中的四笔销售记录，找出 North 对应的两行。选择 [id] 作为源维度，然后检查答案。

反馈会说明为什么区域是分组字段，无法用作唯一源键。进度指示器现在显示已完成一章。

2. 找出原子指标 #

阅读第 2 章的模型声明。选出对源列求和的指标，然后检查答案。现在，我们有了可复用的销售额和行数定义。

3. 在公式中复用指标 #

查看第 3 章中的 DIVIDE({sales}, {cnt})。对 North 计算 30 ÷ 2 = 15，然后检查答案。将四笔销售记录作为一组，用同一公式计算，得到 100 ÷ 4 = 25。指标引用的值取决于报表当前的分组和筛选条件。

展开完整声明，查看复合指标如何在自身不声明 dataset: 属性的情况下复用原子指标。

4. 更改分组 #

在第 4 章中依次选择全部销售、按地区和按销售记录。观察查询、结果表和平均值计算如何同步变化。选择“全部销售”时，销售总额为 100，平均值为 25。按区域查看时，North 为 30，South 为 70。

点击查询中的 average_sale，查看其模型声明。在引用下，依次打开 sales 和 amount 可追溯到源列，打开 cnt 可查看行数计算公式。点击分组字段可查看它映射到哪一列。点击×或按 Escape 键可关闭定义。后续章节的公式和结果标题也提供这些提示。

回答关于源维度的问题。源维度始终是 [id]。当结果行定义在源键层级时，用于验证的编译器会指出聚合可以简化。此简化以声明的键具有唯一性为前提。

5. 区分编译和执行 #

沿着第 5 章的模型与查询示意图查看流程。选出编译成功时生成的内容，然后检查答案。接着逐项查看各项检查：检查编译生成的 SQL，通过连接验证查询所涉及的源键和 SQL 执行计划，并将执行结果与独立得出的答案进行比较。

6. 比较报表筛选条件和指标筛选条件 #

打开第 6 章中包含八行数据的源表。原来的四笔销售现在归入 2 月。1 月的四行数据用于历史对比。查看扩展后的完整模型。

选择 North 作为报表区域。结果显示 sales = 30 和 completed_sales = 10，North 的两笔销售中有一笔是退货（returned）。在 completed_sales 的定义中找到 +f，然后检查本章练习的答案。

在 {sales: ...} 中，冒号前的名称表示指标，冒号后的设置会调整本次引用的计算方式。f 表示筛选。+f 为本次引用添加筛选条件，同时保留 sales 的原始定义。展开修饰符的两种写法，比较命名修饰符和配置对象。

7. 选择分母 #

在第 7 章中选择 North。使用 -d: region 时，分母为 30，占比为 100%。切换到 -df: region 后，分母变为 100，占比变为 30%。

d 表示维度，f 表示筛选。-d 从本次引用求值时使用的分组中移除一个字段。-df 还会移除与该字段相关的筛选条件。月份筛选条件、源键和报表分组保持不变。在此示例中，如果没有相关的区域筛选条件，两种修饰符得到的分母相同。

查看记录中由编译器生成的查询，以及关于如何分组和纳入哪些行的说明。检查有关如何让分母继续涵盖所有区域的练习答案。报表仍选中 North，分母中的指标引用使用不同的筛选上下文。

8. 按客户粒度计算 #

在第 8 章中选择 AVG。在阶段 1 中找到 South 区域客户 C 的销售总额 70。阶段 2 对这一个客户的总额求平均，得到 70。平均交易金额为 35，因为它是对源数据中两笔交易的金额求平均。

将外层聚合切换为 SUM，再切换为 MAX。观察两个阶段以及公式。切回 AVG，然后检查练习答案。

+d: customer 将客户加入求值维度。外层聚合显式地将各客户的总额汇总回查询维度所定义的粒度。源维度仍用于标识源行，查询维度仍用于对结果行分组。

9. 比较相邻月份 #

阅读第 9 章中显示的两个模型定义。previous_sales 使用 {sales: pp} 获取上月值，sales_change 使用 {sales: pop} 计算增长率。选择 2025 年 2 月。North 的销售额为 30，上月销售额为 20，增长率为 50%。South 的销售额为 70，上月销售额为 50，增长率为 40%。

将 {sales: pp} 理解为“上一期间的销售额”。这里以月份为单位，因此指上月的销售额。pop 返回小数形式的增长率，页面将 0.5 显示为 50%。

选择2025 年 1 月。示例中没有 12 月的事实记录，因此上一期间的销售额和增长率均为 NULL。检查 pp 请求的是哪个期间。

调整查询时，请设置报表涵盖的月份范围。要完整比较两个期间，请保留在任一期间有销售额的所有地区，这样每列的合计就等于对应期间的销售总额。参见月环比示例。

10. 制造并修复重复的查找键 #

在第 10 章中，启用加入一条无效的重复 North 目录记录。四条事实记录联接后变为六行。此时 North 的金额合计为 60。

禁用重复记录。四条事实记录联接后恢复为四行，North 的合计为 30。查看有关源数据唯一性的练习。编译器快照不会检查这些实际存储的记录。

要通过数据库连接检查键，请展开第 10 章中的用 dmlc 检出重复键。将其中用于查找经理的查询保存为 lookup.sql，与下载的模型放在同一目录。只有查询能够通过其依赖关系到达 DIM_REGION，验证才会检查该维度。将 default 替换为包含示例表的连接，然后运行以下命令：

dmlc.exe --validate lookup.sql --model=model.dml --connection=default --json

如果该连接中的 TABLE_REGION 同时包含两条 North 记录，则应看到针对 DIM_REGION 的 DIMENSION_NOT_UNIQUE。修正数据集的维度声明或源数据，然后重新运行验证。浏览器中的开关只会更改本页虚构的示例数据。验证会读取连接中的数据，检查查询通过依赖关系到达的数据集维度，并用 EXPLAIN 检查主查询，而不会执行主查询来获取结果行。

11. 明确如何处理缺失值 #

在第 11 章中，从保留 NULL切换到用字面量 0 填补。1 月的结果分组保持不变。只有上一期间的值从 NULL 变为 0。

查看补全后的指标公式，检查 1 月的结果有何变化。备用值会在使用该指标的地方提供一个值。它不会生成新的日历行，也不会决定历史数据缺失在业务上意味着什么。

12. 构建并下载最终报表 #

在第 12 章的试一试练习中，为两个地区做一张二月报表。选择“2025 年 2 月”“按地区”和“全部地区”。勾选 completed_sales、previous_sales、average_customer_sales 和 all_region_share。sales 已经选中。

在报表控件下方，对照查看模型笔记 · model.dml和报表问题 · query.sql。笔记本摘录显示所选指标及其依赖项。展开完整笔记本或下载 model.dml，查看源数据集的声明。结果表位于这两个窗格下方。

选择报表控件旁的提交答案。如果缺少某项设置，请按反馈调整后重试，或选择查看提示获取指导。完成此练习后，教程的第 12 步会标记为已完成。配置完成后，报表将显示以下预期示例值：

region sales completed_sales previous_sales average_customer_sales all_region_share
North 30 10 20 15 0.3
South 70 70 50 70 0.7

浏览器将占比显示为百分比。模型和下载的预期结果 CSV 文件均以小数表示占比。

选择下载已检查的项目。将项目压缩包解压到可写目录，然后打开其中的 START-HERE.txt。压缩包包含完整模型、最终查询、源 CSV 文件、预期结果、已记录的编译器输出，以及包含日历表的可选 SQL Server 设置。

要保存其他报表配置，请选择下载我的 query.sql。随附的编译记录仅适用于已记录的配套查询。对于在构建器中选择的其他组合，仍需编译并检查生成的 SQL。

编译下载的项目 #

确保 dmlc.exe 可用后，在解压目录中打开终端并运行以下命令：

dmlc.exe --lint model.dml --json
dmlc.exe --compile --strict query.sql --model=model.dml --json --artifacts=gen

检查诊断信息和生成的 SQL。在经过检查的构建中，综合练习返回 status: ok，退出码为 0。关于键并集的诊断是提示信息。联接结果可能包含只在对比月份出现的地区。检查这些地区是否应纳入报表，再检查客户级别的汇总和最终投影。生成 SQL 并不能证明数据库结果正确。

如果要做可选的数据库练习，请使用一个新建的空 SQL Server 数据库，并查看 setup-mssql.sql。该脚本会创建源表以及期间比较 SQL 所需的日历表。通过该连接运行模型查询（Model Query）并启用验证，然后将每个结果值与 expected.csv 对照。

dmlc.exe --query query.sql --model=model.dml --connection=default --with-validation --json

将 default 替换为练习用连接的 ID。文档检查期间未在实际数据库上运行此练习。

有关连接和验证命令，请参阅编译并验证查询。完成此入门项目后，可查阅语言参考，进一步了解窗口、分类器、物化和模型组合。

要用同一份示例数据完成一次独立的 DuckDB 运行，请参照已检查的销售额练习。

完成第 12 章后，如需尝试在 SQL Server 中进行物化，请参照从月度切换到季度的 Maz 练习。此练习包含查询就绪检查和运行器的全局进度视图。准备和刷新约定说明了调用返回后在哪些情况下仍可能有待处理的工作。

继续学习或重新开始 #

使用固定页眉中的地球图标和语言选择器，可在 English、中文、日本語和 Deutsch 之间切换。每种语言都以该语言的名称显示，即使看不懂当前页面的语言，也能找到所需的选项。全部 12 节课程以及题目、讲解、导航和反馈会同步切换语言。你的答案、报表设置和章节完成状态都会保留。浏览器会分别保存语言设置和学习进度。代码、字段名称、源数据值和可下载的项目均保留原有标识符。

固定页眉会显示当前章节。使用页眉中的箭头可以切换课程，点击章节标题可以查看全部 12 章和已完成的章节数。已完成的章节带有勾选标记。在最后一章，点击返回箭头会打开导言。

在该菜单中打开符号速查，可查阅修饰符以及源维度、查询维度和求值维度各自的作用。指南位于第 12 章之后，不计为额外章节。示例模型使用 FACT_SALES 和 DIM_REGION 作为逻辑数据集名称，使用 TABLE_SALES 和 TABLE_REGION 作为物理表名称，并使用 lower_snake_case 为字段和指标命名。

如果浏览器的本地存储可用，答对练习题后，学习进度会保存在当前浏览器中。在章节菜单中选择继续学习，即可找到下一个尚未完成的章节。学习进度保留在此设备上，页面不会向服务器发送任何学习者数据。

在章节菜单底部选择重置进度，即可清除练习完成记录。如果浏览器存储不可用，当前页面会话期间仍可正常学习课程。
