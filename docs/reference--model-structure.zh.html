本页介绍模型级字段、数据集、列宏和通用元数据。有关包含文件的可见性和名称解析，请参阅模型组合。

模型级字段 #

字段 类型 说明
includes string[] 要合并的其他 .dml 文件的路径（对各文件的符号取并集）
dialect string 目标 SQL 方言。请显式设置。有关可识别的名称、默认值和执行支持范围，请参阅 SQL 方言。
column-macros object 多个数据集共享的列定义
<name> object | string 数据集、指标、dt-macro、fn-macro、materialize 或查询

对象名称规则：可使用除保留关键字以外的任意字符串。保留关键字包括 includes、column-macros、datasets、measures、columns、dimensions[dt]、dt-macros、fn-macros、materializes、queries、dialects 及其单数形式。

指标定义的简写：如果顶层映射项的值只是一个字符串，则将该值视为指标公式的简写：

销售额: SUM({销售金额})
# equivalent to:
销售额:
    type: measure
    formula: SUM({销售金额})

SQL 方言 #

经检查的编译器可识别 adb_mysql、duckdb、mssql、mysql、postgres 和 sqlite。如果被检查的模型未声明方言，当前编译器会拒绝该模型。请显式声明目标方言。配置 DuckDB 连接不会改变模型的目标方言。以 DuckDB 为目标时，请声明 dialect: duckdb。

在这项检查中，BigQuery、Snowflake、Databricks 和 ClickHouse 均无法识别为目标。如果部署要求使用无法识别的引擎，必须先解决该要求，再在该部署中使用 dmlc。

方言识别与执行验证覆盖范围是两回事。可运行的示例主要验证 DuckDB 的结果，概述中另行记录了面向 SQL Server 的编译情况。这些检查无法证明全部六种引擎的功能一致。请验证生成的 SQL，并在目标数据库上比较结果。生成的 SQL 可能需要多条语句、中间关系和日历对象。

数据集定义（type: dataset） #

<name>:
    type: dataset
    table: <table_name>          # required (or sql:)
    # sql: <SELECT ...>          # alternative to table: — derived dataset
    dimension: [col1, col2]      # dataset grain dimensions
    materialize: <name>          # optional, declare a materialize table for this dataset
    # or:
    # materialize:
    #     name: <name>
    #     parameters:
    #         <param>: <value>
    columns:                     # required
        col1:                    # direct column (pass-through)
        col2: expr               # calculated column (inline expression)
        col3:                    # full column definition
            abbr: <source_column> # optional when the names match
            description: <text>
            formula: expr        # calculated column (block form)
            # source: expr       # alternative to formula: data-source verification formula
            prerequisite: <expr> # column-level grain constraint
    dimensions[dt]:              # optional explicit time metadata; coarser standard dt_* fields may be system-derived
        dt_date: date
        dt_month: month
    measures:                    # atomic measures (inherit enclosing dataset; no dataset:)
        <measure_name>: <formula or full definition>
            abbr: <short>
            description: <text>

约束：

  • 必须且只能指定 table: 和 sql: 中的一项（两者互斥）。
  • table: 声明独占的表归属。 table: policy 表示该物理表归数据集 Policy 所有。其他数据集不得在 sql: 中通过 FROM 或 JOIN 引用物理表名。请写成 from {Policy} 或 join {Policy}（编译器会替换为数据集的查询名称），也可以使用 pk(...).{Policy}.Col 查询属性并省去该连接。要共享表而不声明归属，请用 sql: select * from <table> 代替 table:。
  • 事实表模式： 维度数据集（Claim、Policy）使用 table:。仅需要这些属性的事实数据集可以继续使用未声明归属的源表，通过 pk() 查询属性，无需在 sql: 中连接已有归属的表。
  • 可见性： 经检查的构建版本支持在同一文件中向前引用后续定义的数据集、指标和列。被包含的文件必须通过自己的定义或包含项解析名称，不能依赖包含它的父文件。请参阅模型组合。
  • 直接编译文件时，请使用去掉扩展名的文件名作为查询名称（report.dml → report）。
  • allows: 用于指定哪些物化项可以使用（ALL、NONE 或显式指定的名称）。它不会覆盖指标的维度。
  • 示例所示的指标查询形式必须指定 columns:。
  • dimensions[dt] 的值为枚举值：year、quarter、month、week、date、hour。
  • materialize: 接受标量名称，也接受包含必填项 name: 和可选项 parameters: 的对象。两种写法在同一数据集内标识同一个物化项。

数据集的 SQL 可以在计算指标前通过受支持的连接、集合合并和子查询来准备数据。UNION ALL 保留每行出现的次数。在各个输入中能唯一标识行的键，在合并后的结果中未必仍然唯一。请为合并后的关系定义行标识，不要假定某个分支原有的键仍然唯一。经检查的示例通过 {DATASET} 引用使用仅定义了列的源数据集。当前可执行程序可以验证这些派生关系，无需依赖不可用的中间表。请检查派生关系的完整键。键唯一时验证通过；键重复时，验证报告会通过 data.issues[].kind: duplicate_key 标明违规；补上缺失的键组成部分后，验证可重新通过。物理数据源缺失会产生 EXECUTION_ERROR，不会报告为键重复。验证不能替代对业务结果的检查。

列定义形式：

写法 YAML 含义
直接引用 销售金额:（null） 直接使用底层表中的列
计算（行内） net: 销售金额 - 折扣金额（字符串） 通过表达式派生的列
计算（块） net: { formula: 销售金额 - 折扣金额 } 带元数据的派生列
带验证公式 net: { source: 销售金额 - 折扣金额 } 声明用于验证数据源的公式。仅凭编译无法确认源数据值相等。

公式中花括号对名称绑定的影响：

formula: 中的写法 绑定为 示例
仅 销售金额 物理（原生）表列。编译器将名称原样传入 SQL。 两列均为直接引用时的 net: 销售金额 - 折扣金额
{calc_amt} 计算列（或指标、列宏）。DMX 会展开其定义。 两倍值: '{calc_amt} * 2'

在计算列的公式中，不加花括号的名称会被视为原生 SQL 列。SELECT 中别名的顺序可能让这种写法看起来有效，但它不会展开计算列的定义。要在公式中复用该定义，请用花括号括住名称。

先定义被依赖的对象是为了便于阅读。在经检查的版本中，使用 pk() 引用同一文件中稍后定义的目标可以成功编译。名称无法解析可能是因为缺少包含项、名称拼写有误，或违反了包含文件的可见性规则。请参阅模型组合。

列宏 #

列宏定义多个数据集共用的列：

column-macros:
    datasets: [tx, orders]       # scoped datasets
    columns:                     # shared column definitions
        地区: '{门店数}.地区' # cross-dataset lookup
    dimensions[dt]:
        dt_month: month

    # OR per-dataset scope:
    <dataset_name>:
        <col>: <formula>

通用元数据字段 #

支持的元数据因对象类型而异。请参阅相应的架构定义：

字段 类型 说明
abbr string 数据集字段名和源表列名不同时，在这里填源表列名。指标也可以用它指定内部简称。查询结果使用业务名称，或你通过 AS 指定的别名。
description string 便于阅读的说明
tags string[] 可自由指定的标签
prerequisite string（公式） 限制可在哪些层级定义行或汇总值（适用于度量值、列、dt 宏和 fn 宏）

列元数据不是 SQL 类型声明 #

列属性必须符合 DML 架构。请将属性嵌套在目标列下。如果在 columns: 中将 type: text 写在与目标列同级的位置，就会定义另一个名为 type 的列。因此，即使模型通过验证，也无法据此判断目标列的类型。在已验证的构建版本中，写在列下的 type: text 和 type: banana 都会因属性不受支持而被拒绝。这属于元数据架构验证，无法证明系统会对表达式执行完整的静态类型检查。请在数据库中定义物理列的类型。需要转换类型时，请使用受支持的表达式或类型转换。顶层的 type: dataset 和 type: measure 用于标识 DML 对象的种类，并不声明 SQL 值的类型。

系统日历 #

对于某些连接，首次使用该连接进行需要访问数据库的验证，或首次使用该连接执行查询时，会初始化 DML_CALENDAR，即使查询中没有时间修饰符也是如此。试用的 DuckDB 连接为 2016 年至 2036 年的每一天初始化了一行，包含起止年份（共 7,671 行）。用于初始化的账户需要有权在目标架构中创建表并写入数据。后续查询需要对该表的读取权限。

如果运行时账户无法创建表，请先让数据库管理员使用相同的 dmlc 构建版本、连接方言和架构初始化日历，再使用运行时账户执行验证。请确认日历覆盖报表期间和比较期间。
