Ein Reisender kommt mit einer Frage an: Wie hoch war der Umsatz in jeder Region?

Öffnen Sie das illustrierte interaktive Tutorial. Es umfasst jetzt zwölf Kapitel, bewertete Übungen, eine Fortschrittsspeicherung und einen Assistenten zum Erstellen des Abschlussberichts. Die Übungsanleitung führt durch das gesamte Einstiegsprojekt. Auf dieser Seite bleibt die kürzere Einführung in die Konzepte erhalten.

Jeder Verkauf ist eindeutig identifizierbar #

Der Reisende erfasst vier Verkäufe. Die Zeilen wurden für dieses Beispiel erfunden und stammen nicht aus einer Datenbank.

id region amount
1 North 10
2 North 20
3 South 30
4 South 40

Für den Quelldatensatz ist dimension: [VerkaufspositionID] definiert: Jede Zeile steht für einen Verkauf. Zwei Verkäufe können zur selben Region gehören. Daher lässt sich eine Quellzeile anhand von Region nicht eindeutig identifizieren. Eine Abfrage kann diese Zeilen dennoch nach Region gruppieren.

Die Einführung in Dimensionen erläutert im Detail, wie Quellzeilen identifiziert und für Berichte gruppiert werden.

DML hält wiederverwendbare Definitionen fest #

Der Reisende hält seine Definitionen in einem Notizbuch fest. DML ist dieses Modell und wird in YAML geschrieben. Der folgende Ausschnitt deklariert zwei atomare Kennzahlen für den Verkaufsdatensatz:

Verkaufspositionen:
  type: dataset
  table: TABLE_SALES
  dimension: [VerkaufspositionID]
  columns:
    VerkaufspositionID:
      abbr: id
    Region:
      abbr: region
    Verkaufsbetrag:
      abbr: amount
  measures:
    Umsatz: SUM({Verkaufsbetrag})
    Verkaufsanzahl: COUNT(1)

Umsatz summiert die Beträge. Verkaufsanzahl zählt die Quellzeilen. Beide sind atomare Kennzahlen. Sie übernehmen Verkaufspositionen als Datensatz und aggregieren direkt dessen Zeilen oder Ausdrücke über dessen Spalten, ohne auf andere Kennzahlen zu verweisen. Berichte können sie wiederverwenden, sofern die Ebene, auf der Zeilen oder Summen definiert sind, mit der Berechnung der Kennzahlen vereinbar ist.

DMX beschreibt eine Berechnung #

Im Notizbuch steht auch, wie ein Durchschnitt berechnet wird:

DurchschnittsumsatzJeVerkauf:
  type: measure
  formula: 'DIVIDE({Umsatz}, {Verkaufsanzahl})'

Der YAML-Abschnitt deklariert eine Kennzahl. Die darin enthaltene Formel ist in DMX geschrieben. {Umsatz} und {Verkaufsanzahl} verweisen auf Kennzahlen, und DIVIDE gibt bei einem Nenner von null NULL zurück. DurchschnittsumsatzJeVerkauf ist eine zusammengesetzte Kennzahl, weil sie auf andere Kennzahlen verweist. Sie hat keine Eigenschaft dataset:.

DMX ist die gemeinsame Ausdruckssyntax für Modelldefinitionen und Abfrageausdrücke. Zwischen Modell und Abfrage gibt es dafür keinen eigenen Verarbeitungsschritt. Die Ausdrucksreferenz legt die Syntax fest.

Die Abfrage legt fest, wofür eine Ergebniszeile steht #

Der Reisende richtet sein Fernrohr auf die Regionen:

SELECT Region, AGG(Umsatz), AGG(DurchschnittsumsatzJeVerkauf)
FROM MODEL
GROUP BY Region

AGG verweist auf eine Kennzahl aus dem Modell. Mit GROUP BY Region liefert die Abfrage eine Ergebniszeile pro Region. Aus den vier erfundenen Verkäufen ergeben sich diese Werte:

region sales average_sale
North 30 15
South 70 35

Ohne Gruppierungsfelder ergeben dieselben Modellkennzahlen einen Gesamtumsatz von 100 und einen durchschnittlichen Verkaufsbetrag von 25. Bei einer Gruppierung nach VerkaufspositionID gibt es ein Ergebnis pro Verkauf. In allen Fällen identifiziert [VerkaufspositionID] die Quellzeilen.

Auf der Ebene des deklarierten Quellschlüssels [VerkaufspositionID] vereinfacht der geprüfte Compiler die Aggregation zu einem Ausdruck pro Zeile und meldet einen Befund der strikten Prüfung. Diese Vereinfachung setzt voraus, dass VerkaufspositionID in den Quelldaten eindeutig ist. Die Abfragen für den Gesamtwert und die Werte pro Region bestehen mit dem geprüften Build die strikte Kompilierung.

Das Compilerprotokoll des Tutorials dokumentiert die für das interaktive Projekt verwendete ausführbare Datei, ihren Fingerabdruck und die durchgeführten Prüfungen.

Die interaktive Seite berechnet diese kleinen Beispieltabellen im Browser. Sie führt weder DML aus noch stellt sie eine Verbindung zu einer Datenbank her.

Die Kompilierung erzeugt SQL #

Der Compiler führt Modell und Abfrage zusammen und erzeugt daraus SQL. Die Datenbank führt das erzeugte SQL auf der tatsächlichen Quelltabelle aus.

DML model + Model Query
          |
        dmlc
          |
     generated SQL
          |
       database
          |
       result rows

Eine erfolgreiche Kompilierung bestätigt das Verhalten des geprüften Compilers. Die Prüfung der Schlüssel anhand der tatsächlichen Daten und der Vergleich der Ergebnisse liefern gesonderte Nachweise für die Quelldaten und das Abfrageergebnis. Im Tutorial zur ersten Abfrage kompilieren Sie dieselbe regionale Abfrage mit diesem Modell und sehen sich das erzeugte SQL an.

Weitere Informationen finden Sie unter Grundkonzepte, Kennzahlendeklarationen oder Model Query SQL.
