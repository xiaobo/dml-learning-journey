Troubleshoot duplicate keys

Look up the dataset and key named in the validation report. The model requires that key to be unique, but the check found more than one record with the same key.

Find the repeated key

The region table DIM uses id and region together as its key. ID 1 can occur once in East and once in West. Check for duplicates of the pair.

SELECT id, region, COUNT(*) AS matches
FROM DIM
GROUP BY id, region
HAVING COUNT(*) > 1;
idregionmatches
1east2

How does this affect the report?

East has one sale of 10. With two (1, east) rows in the region table, a SQL join matches that sale twice and reports 20. West stays at 20.

Check again after the repair

First check whether the two records should be distinct. If both are valid, review the key declared in the model. Here the second East row was added by mistake. Correct the region table, validate again and rerun the report. Expect 10 for East and 20 for West.
