本页介绍指标的属性和公式形式。设计指标介绍定义指标时需要做出的选择。公式示例提供常见业务场景的写法。

基本语法 #

measure_name:
    type: measure
    description: Business description
    dataset: dataset_name
    formula: aggregation_expression
    dimensions:                # optional allowed evaluation dimensions
        - [客户编号]
        - [客户编号, ...]   # listed fields remain required
    prerequisite: validity_expression

formula: 为必填项。dataset: 将顶层原子指标绑定到其数据源。在数据集的 measures: 块中声明的指标会继承该数据集。复合指标引用其他指标，并省略 dataset:。

dimensions: 是一个由数组组成的数组。每个内部列表代表一组允许用于求值的维度。使用平铺列表会报错 string found, array expected。省略号允许出现其他字段，但列出的每个字段仍然必需。此属性约束求值，不声明数据集的标识，也不定义查询的分组。

prerequisite: 添加一个表达式，用于判断定义数据行或汇总值的粒度是否有效。常用元数据字段 description、abbr 和 tags 见模型元数据字段。有关如何选择这些约束，请参见设计指标。

注意事项

  • 在模型查询中设置查询专用的筛选和分组（使用 SQL 的 WHERE/GROUP BY，或使用 DML 格式的 filters: / columns: dimension:），不要为此定义一次性指标。模型查询的规则见模型查询（SQL）。
  • dataset: 仅用于原子指标。原子指标的公式直接聚合该数据集的行或列表达式，不引用其他指标。复合指标引用其他指标，不得声明 dataset:。即使引用的指标都使用同一个数据集，也适用此规则。请参见指标引用和常见问题 P39。
  • 指标可以返回数值、日期值或分类值。显示格式由使用方设置，聚合方式和数据类型应与业务定义一致。
  • 对于存储金额或对精度敏感的原始字段，建议在原子指标中进行一次类型转换（例如 SUM(CAST({销售金额} AS DECIMAL(38, 2)))），并在后续处理中复用该指标。
  • 如果业务规则依赖 > 0 / < 0 比较，请先确保基础指标已具有预期的数据类型（例如 DECIMAL），再将其用于 MINIF/MAXIF/DISTINCTCOUNTIF 的条件。

简单聚合 #

COUNT #

交易笔数:
    type: measure
    dataset: 交易明细
    formula: count(distinct 交易编号)

商品数:
    type: measure
    dataset: 交易明细
    formula: count(distinct 商品)

SUM #

销售金额:
    type: measure
    dataset: 交易明细
    formula: SUM(CAST({原始金额} AS DECIMAL(38, 2)))

交易数量:
    type: measure
    dataset: 交易明细
    formula: SUM(数量)

MAX/MIN #

最近下单日期:
    type: measure
    dataset: 交易明细
    formula: MAX(dt_date)

AVG #

每张发票平均数量:
    type: measure
    formula: 'AVG({开票数量: {+d: 交易编号}})'

带筛选条件的指标 #

使用 {+f: condition} 指定内联筛选条件。修饰符的语法见函数修饰符。

费用:
    type: measure
    dataset: 交易明细
    formula: |-
        {借方金额: {+f: {账户类型: ['Expense', 'Other Expense']}}}

销售额:
    type: measure
    description: Sales revenue from income accounts
    formula: |-
        {贷方金额: {+f: {账户类型: ['Income', 'Other Income']}}}

餐饮费用:
    type: measure
    formula: |-
        {费用: {+f: "instr(账户, 'Food & drink') > 0"}}

信用卡交易笔数:
    type: measure
    formula: |-
        {交易笔数: {+f: {credit_card : 'yes'}}}

未付发票数:
    type: measure
    formula: |-
        {发票数: {+f: '未结余额 > 0'}}

指标引用 #

在公式中引用其他指标的写法如下。

复合指标不得声明 dataset:。 如果 formula: 引用了其他指标，请省略 dataset:。原子指标使用 dataset: 绑定要聚合的源数据行或列表达式，且不引用其他指标。下方的原子指标示例（贷方金额 / 借方金额）保留 dataset:，复合指标 利润 则省略该属性。请参见常见问题 P39。

# Base measures
贷方金额:
    type: measure
    dataset: 交易明细
    formula: SUM(贷方金额)

借方金额:
    type: measure
    dataset: 交易明细
    formula: SUM(借方金额)

# Derived measure (composite — no dataset:)
利润:
    type: measure
    formula: |-
        {贷方金额: {+f: {交易类型: ['Income','Other Income','Expense','Other Expense']}}} -
        {借方金额: {+f: {交易类型: ['Income','Other Income','Expense','Other Expense']}}}

复杂公式 #

条件聚合 #

使用 SUMIF / DISTINCTCOUNTIF / MINIF / MAXIF 且引用其他指标的指标是复合指标，不得声明 dataset:，即使公式中的某一列“属于”某个已知数据集也是如此。如果需要在列的范围内进行聚合，只在单独的原子指标上使用 dataset:。请参见指标引用和常见问题 P39。

收款:
    type: measure
    formula: |-
        SUMIF({payment: {+d: 客户}}, {客户} is not null)

付款:
    type: measure
    formula: |-
        SUMIF({payment: {+d: 供应商}}, {供应商} is not null)

嵌套聚合 #

发票最高金额:
    type: measure
    formula: |-
        MAX({销售额: {+d: 交易编号}})

日均销售额:
    type: measure
    formula: |-
        divide(sum({销售额: {+d: dt_date}}), distinctcount({dt_date}))

周均销售额:
    type: measure
    formula: |-
        divide(sum({销售额: {+d: dt_week}}), distinctcount({dt_week}))

每笔平均销售额:
    type: measure
    formula: |-
        divide(sum({销售额: {+d: 交易编号}}), distinctcount({交易编号}))

窗口函数 #

窗口函数的放置位置。完整规则见窗口函数的放置位置。以下为概要。

用途 位置
明细层级的 OVER（无 GROUP BY，作为行属性供后续的 DISTINCTCOUNTIF 或外层的 SUM / LAG 条件使用） 在 columns: 下定义计算列，然后进行原子聚合
GROUP-BY 之后的排名 / 占比 / 累计值 过渡用法是将原子聚合与使用窗口函数 / {-d:} / {-df:} / grand 的复合指标搭配使用（无 dataset:）。

原子指标不接受 OVER（window functions are not allowed in atomic measures）。常见问题见 P70 和 P71。

明细层级（在 columns: 下直接引用分区列）

交易记录:
    type: dataset
    table: FACT_SALES
    columns:
        门店编号:
            abbr: store_id
        商品编号:
            abbr: prod_id
        数量:
            abbr: qty
        净数量: 'SUM({数量}) over (partition by {门店编号}, {商品编号})'
    measures:
        净数量合计: 'SUM({净数量})'

聚合后（在复合指标上引用汇总值的定义粒度）

销售总额:
    type: measure
    dataset: 交易记录
    formula: SUM({数量})

地区排名:
    type: measure
    formula: 'rank() over (partition by {-d: 商品} order by {销售总额} desc)'

在模型查询（SQL）中，如果 system_macros.dml 中的函数宏（rank、rank_asc、pot、grand）适用于当前场景，请优先使用。

SELECT 商品, AGG(销售额, 'rank') AS 销售排名
FROM MODEL GROUP BY 商品

SELECT 商品, AGG({销售额: pot}) AS 占比
FROM MODEL GROUP BY 商品

宏的类别及其行为见函数修饰符。

ISNULL 和 IIF #

所有商品销售额:
    type: measure
    description: Product sales including products with zero sales
    formula: |-
        SUM(isnull({销售额: {+d: 商品}}, 0) * iif({DATASET_PRODUCT_SERVICE}.商品 is not null, 1, 0))

所有客户销售额:
    type: measure
    description: Customer sales including customers with zero sales
    formula: |-
        SUM(isnull({销售额: {+d: 客户}}, 0) * iif({DATASET_CUSTOMER}.客户 is not null, 1, 0))

缺少行时填充默认值 #

功能。当连接、FOJ 或物化操作中缺少行时，填充默认值，防止空值传播到后续计算。

要启用此功能，请用 isnull / ifnull / coalesce(公式, 字面量) 中的一种在最外层包裹整个指标公式。

当该指标的使用位置（查询列、重命名、{m: pp} / 其他 dt 修饰符，或嵌入另一个公式的位置）可能缺行时，才应用默认值（FOJ / nullpk / 物化时的外层包裹）。

请区分以下两条规则。

  1. 不会自动添加外层包裹。 在复合指标中引用已启用默认值填充的指标，这一引用本身不会包裹该复合指标的结果列。如果缺行时该复合指标自身的结果列必须为非空值，请对结果启用填充。
  2. 嵌入时仍会展开填充逻辑。 当复合指标直接或通过一连串公式引用嵌入已启用填充的依赖指标时，在可能缺行的 FOJ 使用位置，填充逻辑仍会在发起嵌入调用的位置展开。例如，deep = {q2fp1} * 3 依赖 q2fp1 = {q2f} + 1 和 q2f = isnull(SUM(...), 0) 时，如果缺少匹配行，结果为 (coalesce(dep, 0) + 1) * 3，而不是 NULL。填充作用于已启用该功能的依赖指标，不会自动应用 isnull(deep, …)。
上期:
    type: measure
    formula: 'isnull({销售额: pp}, 0)' # activate

上上期:
    type: measure
    formula: '{上期: pp}' # use site → 0

本期减上期:
    type: measure
    formula: '{销售额} - {上期}' # 上期 use site → 0 (no contagion)

本期减上期_fill:
    type: measure
    formula: 'isnull({销售额} - {上期}, 0)' # activate on result

# Nested embed (activation on q2f; deep expands fill of q2f at FOJ)
q2f:   { dataset: secondary, formula: 'isnull(SUM({q2}), 0)' }
q2fp1: { formula: '{q2f} + 1' }
deep:  { formula: '{q2fp1} * 3' }

不构成激活（缺少该行时，值仍可能为 null）：

写法 原因
仅 {销售额: pp} 未激活
isnull({a}, {b}) / coalesce(a, b, 0) 指标的补充项，而非 (公式, 字面量)
将 isnull(…, 0) + 1 本身作为激活的指标 在输入为 null 时对该指标求值（通常 → 1）。这并不表示缺少行时就返回该指标的单位元（“缺少行 → 0”）。
结果列始终不会被激活 依赖指标的空值可能会在公式内部填补。后续引用结果列本身时，只有该列已激活，系统才会自动在引用外层加上填补逻辑。

原理与 MetricFlow 的 fill_nulls_with 或 Looker 在聚合后使用的 COALESCE 相同：在指标上声明填充值，使用该指标时应用填充值。DML 不会创建缺失的日历行，只会在联接后的列值为 null 时填补。请单独补齐缺失的日期，可使用日历表或按 FOJ 定义的粒度补齐。常见问题见故障排查索引中的 P28b。编译器说明（dmlc）见 docs/fill-default-when-row-missing.md。

可复用的按时间顺序累计的指标 #

命名的复合指标可以包含在聚合后求值的窗口函数。累计销售额示例按声明的 [month] 粒度定义 SUM({销售额}) OVER (ORDER BY {month} ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)。计算不按区域分区，筛选到 2 月会改变累计的起点。可加总金额的累计和既不是累计去重计数，也不是累计比率。示例包含完整的模型、查询和预期结果行。dimension: [] 会在计算总计时清除求值分组。它既不指定排序，也不要求进行累计计算。若要取最后一次观测时的余额，请明确日期是按实体分别确定还是在全局统一确定，并定义如何处理缺失的观测以及日期并列的情况。按指定顺序求和或采用某一种取最后日期的方法，无法涵盖所有半可加性计算。
