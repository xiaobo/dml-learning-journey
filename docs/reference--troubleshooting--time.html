These entries cover period values, comparison context, and missing history. Evaluation semantics owns the time-context contract.

P29. Non-first-day time filters #

Wrong: dt_month = '2024-01-15' or dt_month = 'Jan 2024'. Fix: dt_month = '2024-01-01' — always first day.

P30. Missing current day in past-N-days #

Wrong: dt_date BETWEEN date(current_date, '-7 days') AND date(current_date, '-1 day'). Fix: dt_date BETWEEN date(current_date, '-6 days') AND date(current_date) — 7 days including today.

P31. Including current period in past-N-months #

Wrong: dt_month BETWEEN date(current_date, 'start of month', '-12 months') AND date(current_date, 'start of month'). Fix: dt_month BETWEEN date(current_date, 'start of month', '-12 months') AND date(current_date, 'start of month', '-1 month') — exclude current (incomplete) month.

P32. Using ytd modifier with full-period GROUP BY #

Wrong: SELECT dt_year, AGG(sales, 'ytd') FROM MODEL GROUP BY dt_year. Fix: ytd is cumulative. Use dt_date grain: SELECT dt_date, AGG(sales, 'ytd') FROM MODEL WHERE dt_date = date(current_date) GROUP BY dt_date.

P33. Period-to-date with date range #

Wrong: WHERE dt_date BETWEEN date(current_date, 'start of year') AND date(current_date) for YTD. Fix: WHERE dt_date = date(current_date) with AGG(sales, 'ytd') — modifier handles the range.

Category: Compilation and Validation #

P59. YoY without column probe #

Wrong: AGG(销售额, 'yoy') when 去年同期出厂价金额 sums to zero. Fix: Detail query SUM(去年同期出厂价金额) before promising YoY narrative.

Extra month after the latest source data

Set the report's month range explicitly when you compare periods. A full outer join can keep groups from either period. When December sales align to January as prior sales, an unbounded query can include January even if it is outside your report.

This example uses data from January 2024 through December 2025, with sales in each of five categories every month. The model defines revenue: SUM({amount}), a month dimension named dt_month, and revenue_mom: '{revenue: pop}'.

SELECT dt_month, category, AGG(revenue), AGG(revenue_mom)
FROM MODEL
WHERE dt_month >= '2024-01-01' AND dt_month < '2026-01-01'
GROUP BY dt_month, category

On the example data, this returns 120 rows and matches the hand-written SQL. Without the date filter, the checked query returns 125 rows. The five extra January 2026 rows have NULL current revenue and growth because only December sales contribute to those groups.

Reconcile both periods by category

For a report that compares total revenue across periods, keep categories that have revenue in either period within the report's month range. To see both values, add AGG({revenue: pp}) AS previous_revenue to the select list.

Category Current revenue Previous revenue
A 120 100
B NULL 40
C 30 NULL
Total 150 140

In this example, filtering to categories with current sales drops B and reduces the visible previous-revenue sum to 100. Use that filter for a report specifically about current active categories and apply the same category selection to its totals. To check a full comparison, sum each revenue column by report month and compare it with the corresponding month's source total. Calculate total growth from the two revenue totals.

Show a missing value as zero only if the data is complete for that period and the business treats no sales as zero. A zero fill changes the displayed value.
