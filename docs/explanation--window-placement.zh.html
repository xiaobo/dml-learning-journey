窗口计算的位置

窗口计算取决于其求值阶段可用的行。明细窗口在后续的指标聚合之前计算。复合公式中的窗口以聚合后的指标结果为输入。

支持的计算位置 #

计算 位置 输入行
每个源行的属性 数据集的 columns: 下定义的计算列 明细行
分组聚合后指标值的排名或占比 不含 dataset: 的复合公式 聚合后的行
包含 OVER 的原子指标 经验证的构建版本会拒绝此写法 无受支持的位置

检查生成的 SQL，确认各窗口在哪个阶段计算。编译、在数据库中执行和比较结果是三项独立的检查。

明细窗口 #

交易记录:
  type: dataset
  table: FACT_SALES
  dimension: [销售明细编号]
  columns:
    销售明细编号:
      abbr: id
    客户:
      abbr: customer
    地区:
      abbr: region
    销售金额:
      abbr: amount
    客户交易额: 'SUM({销售金额}) OVER (PARTITION BY {客户})'
  measures:
    逐行客户交易额: 'SUM({客户交易额})'

窗口会在同一客户的每个明细行中重复写入该客户的总额。对计算列求和时，每个源行都会计入一次该行上的客户总额。结果并非按客户去重后的总额，因此此示例仅用于说明窗口的位置，不作为推荐的销售额指标。

对行顺序敏感的窗口还取决于排序、窗口帧、用于确定并列行顺序的键，以及参与计算的源行集合。改变过滤器的应用阶段，可能会改变一个分区内的所有窗口结果。

明细窗口也可以在聚合前选取最后一条观测记录。对于包含 dt_month 和 收入金额 的数据源，经验证的写法会添加以下列和指标。

# Under the dataset's columns:
是否上月: 'IIF({dt_month} = MAX({dt_month}) OVER (), 1, 0)'
# Under the same dataset's measures:
上月收入: 'SUM({收入金额} * {是否上月})'

MAX(...) OVER () 从明细窗口的输入中选出唯一一个最近月份。指标只汇总该月的金额。窗口不按实体分区。如果某个实体在该月没有观测记录，其最后一个已知余额不会结转至该月。对于库存或账户余额，采用公式前，请先明确“最后”是按实体确定还是在全局范围内确定、如何处理缺失的观测记录，以及哪些过滤器限定窗口的输入范围。

聚合后的窗口 #

给定原子指标 销售额: SUM({销售金额})，此复合公式对聚合后的销售额进行排名。

客户排名:
  type: measure
  formula: 'rank() over (partition by {-d: 客户} order by {销售额} desc)'

当查询行按 [地区, 客户] 的粒度定义时，分区表达式保留查询中的其他字段，此处为 地区。经验证的 SQL 先按地区和客户分组，再在每个地区内对 SUM(amount) 进行排名。排名的输入不包括物理事实行。

+d 建立一个粒度更细的聚合阶段。它不会将分组值变成明细窗口的属性。源数据过滤器、窗口结果过滤器和最终报表过滤器可能会选出不同的行集合。

Model Query 也接受经过验证的直接编写窗口表达式的形式。查询参考介绍了可用的查询接口。接受其中一种写法，并不代表支持任意窗口帧或方言。

行窗口与日历期间 #

聚合后的行窗口使用在其计算阶段仍保留的行，并按顺序处理这些行。如果在窗口计算前将累计销售额查询筛选为仅包含二月，一月的数据就会被排除。使用命名查询计算累计总额的示例验证了这种筛选情况和一个可复用的窗口指标。

如果业务定义采用截至明确截止日期的日历期间，请使用 ytd 等时间宏。如果定义采用所选行按顺序排列后的窗口帧，请使用行窗口。月份缺失、过滤器的应用阶段以及并列行的排序方式都可能改变行窗口帧。SUM 窗口可以运行，并不能证明累计去重计数或累计比率也能运行，请分别测试这些定义。
