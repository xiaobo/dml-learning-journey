Join NULL equality

On this page

  • Population, fill, and densification

DML aligns independently aggregated measures by their complete grouping key. NULL values in the same key position compare equal for this alignment. A report can therefore show one shared unclassified group across sources.

Equality by join purpose #

Purpose Typical SQL Equality in ON NULL-key behavior
Combine keys from independent measure results, called key-union composition FULL OUTER JOIN, or a deduplicated key set with UNION and LEFT JOIN NULL-safe equality Full keys with matching values and NULL positions align across sources
Attach attributes while preserving a driving row, including internal nullpk attachment LEFT JOIN NULL-safe equality Matching structural keys can attach even when a component is NULL

NULL-safe equality can use <=>, IS NOT DISTINCT FROM, or an equality test with an explicit both-NULL branch, depending on the dialect. An explicit SQL predicate such as a.region = b.region keeps the database's ordinary equality semantics. Detail joins use the equality rules for their own keys.

Output with NULL alignment keys #

Suppose sales totals 50 and refunds totals 8 for the unclassified region. Grouping by region returns one row (NULL, 50, 8), with both measures. This row represents a reporting group. The underlying sales and refund records keep their own identities. The group still aligns when both measure values are NULL.

For a composite key such as (region, channel), (NULL, 'online') aligns with (NULL, 'online'). (NULL, 'retail') remains a separate group. Period calculations use the same rule for non-time grouping keys and keep their time matching rules.

Use an explicit grouping expression such as coalesce(region, 'UNKNOWN') when the report calls for a labeled bucket. The expression adds any real 'UNKNOWN' values to that same bucket.

Population, fill, and densification #

A presence filter based on an unfilled presence measure can restrict the report to groups from a chosen source. A nullable business measure can be NULL even when its source group exists.

Missing-row fill supplies a fallback measure value. Densification supplies missing entity or calendar rows. Neither operation establishes membership in a source population.

Build evidence #

This contract applies to compiler builds that include the November 19, 2026 grouping change. The October 16, 2026 build used ordinary = in the checked cross-dataset example. When checking a report compiled with an older build, inspect the generated predicate and compare results using a NULL-key example. A later checked example also emitted ordinary equality and passed strict compilation. Check the result with your compiler and data.
