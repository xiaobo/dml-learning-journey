この独立した例では、収益性をモデル化します。インタラクティブガイドの売上モデルを補完する例です。定義同士の関係は、概要アニメーションで確認できます。

定義をすり合わせる #

業務チームとデータチームは、純売上高と売上原価に何を含めるかを取り決めます。モデルはこれらの計算に名前を付け、粗利益を導出し、粗利益を売上高で割って粗利益率を求めます。DMLとDMXでルールを記述し、コンパイラがデータベース向けのSQLを生成します。これらを組み合わせることで、分析用セマンティックレイヤーの計算の中核を構成できます。

モデル #

論理データセットは FACT_PROFITABILITY、その物理ソースは TABLE_PROFITABILITY です。参照先が一意に決まるように、ソースのフィールド名とメジャー名は異なります。ソースの完全なキーは [id] です。物理テーブルでは、revenue_amount と cost_amount に十進数型を使用してください。CSV には SQL の列の型情報が含まれず、整数除算では利益率の小数部分が失われます。

dialect: mssql

売上と原価:
  type: dataset
  table: TABLE_PROFITABILITY
  dimension: [売上明細番号]
  columns:
    売上明細番号:
      abbr: id
    地域:
      abbr: region
    dt_month:
    売上金額:
      abbr: revenue_amount
    原価金額:
      abbr: cost_amount
  measures:
    純売上高: SUM({売上金額})
    売上原価: SUM({原価金額})

粗利益:
  type: measure
  formula: '{純売上高} - {売上原価}'

粗利率:
  type: measure
  formula: 'DIVIDE({粗利益}, {純売上高})'

年初来粗利率:
  type: measure
  formula: 'DIVIDE({純売上高: ytd} - {売上原価: ytd}, {純売上高: ytd})'

前年同期の年初来粗利率:
  type: measure
  formula: 'DIVIDE({純売上高: {ytd, ya}} - {売上原価: {ytd, ya}}, {純売上高: {ytd, ya}})'

粗利率の前年差ポイント:
  type: measure
  formula: '100 * ({年初来粗利率} - {前年同期の年初来粗利率})'

model.dmlをダウンロードするか、CSV形式のソースデータまたはJSON形式のソースデータをダウンロードできます。

コンテキストを変える #

North の 2025 年 2 月の売上高は 300、原価は 240 で、利益率は 20% です。1 月の売上高は 100、原価は 60 で、利益率は 40% です。年初来の売上高は 400、原価は 300 です。累計利益率は 25% で、月別利益率の単純平均である 30% にはなりません。

ダウンロードできるモデルでは、純売上高と売上原価の両方に ytd を適用します。累計の純売上高から累計の売上原価を引き、累計の純売上高で割ります。前年同期を計算するときは両方の金額に {ytd, ya} を適用します。

SELECT 地域, dt_month, AGG(年初来粗利率)
FROM MODEL
WHERE dt_month = '2025-02-01'
GROUP BY 地域, dt_month

同じ期間で比較する #

North の 2024 年 1～2 月の売上高は 200、原価は 160 で、累計利益率は 20% です。現在の累計利益率は 25% で、前年同期より 5 パーセントポイント高くなっています。相対的な増加率は 25% になります。これは別の計算であり、表示される差ではありません。

SELECT 地域, dt_month, AGG(年初来粗利率), AGG(前年同期の年初来粗利率), AGG(粗利率の前年差ポイント)
FROM MODEL
WHERE dt_month = '2025-02-01'
GROUP BY 地域, dt_month

月次クエリ、累計クエリ、または比較クエリをダウンロードできます。標準の時間計算には、対象の接続先にコンパイラの DML_CALENDAR も必要です。

検証結果を確認する #

コンパイラの記録には、使用した実行ファイルの識別情報、クエリの正確な内容、プロセスの終了結果、ステータス、診断情報、生成された SQL が含まれます。確認した 3 つのクエリはいずれも厳格なコンパイルを通過します。生成結果を確認すると、累計を求める分岐では売上高と原価をそれぞれ合計してから除算し、前年を求める分岐では累計期間を 1 年前にずらしています。

これらの確認結果は、この例と、このコンパイラビルドに適用されます。これらの短い式を別途 DuckDB で実行確認した際は、厳格なコンパイルとソースキーの検証を通過しました。独立した SQL による確認では、2 月時点の YTD 利益率は North が 25%、South が 33⅓% で、前年の YTD 利益率はどちらも 20% でした。この結果だけでは、SQL Server で同じ実行結果が得られることは確認できません。ブラウザーは架空のデータ行をもとに独自に計算し、DML は実行しません。分母の売上高が 0 の場合は NULL になります。比較対象の過去期間にデータがない場合は、0 で補わず欠損のまま扱います。
