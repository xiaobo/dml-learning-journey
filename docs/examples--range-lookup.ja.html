イベント日に有効な属性を取得する

このページの内容
  • 有効期間の境界日を確認する
  • 照合ルールをモデルで定義する
  • 有効期間の重複を検出して修正する
  • 検証を実行して結果を確認する

イベント日を、同じオブジェクトの重複しない有効期間に照合します。この例では [適用開始日, 適用終了日) を使い、開始日を含め、終了日を除外します。

有効期間の境界日を確認する #

地域名 有効期間 イベント日 金額
Jan [2024-01-01, 2024-02-01) 2024-01-01 10
Feb [2024-02-01, 2024-03-01) 2024-02-01 20

2月1日は Jan ではなく Feb に属します。クエリは Feb 20 と Jan 10 を返し、各イベントに一致するレコードは1件です。

照合ルールをモデルで定義する #

参照先では dimension: [番号, 'range(適用開始日, 適用終了日)'] を宣言します。範囲式は引用符で囲んだままにしてください。式内のカンマは、YAML のリストの1つの要素に含まれます。ファクト側の pk({番号}, {dt_date}).{対応表}.名称 は、オブジェクト ID、イベント日の順に値を渡します。

完全なファイル: range/model.dml 
dialect: duckdb
対応表:
  type: dataset
  table: DIM
  dimension: [番号, 'range(適用開始日, 適用終了日)']
  columns:
    番号:
      abbr: id
    適用開始日:
      abbr: valid_from
    適用終了日:
      abbr: valid_to
    名称:
      abbr: label
売上明細:
  type: dataset
  table: FACT
  dimension: [売上明細番号]
  columns:
    売上明細番号:
      abbr: fid
    番号:
      abbr: id
    dt_date:
      abbr: event_date
    注文金額:
      abbr: amount
    名称: 'pk({番号}, {dt_date}).{対応表}.名称'
  measures:
    売上額: SUM({注文金額})
完全なファイル: range/setup.sql 
CREATE TABLE DIM(id INTEGER, valid_from DATE,valid_to DATE,label VARCHAR); INSERT INTO DIM VALUES (1,'2024-01-01','2024-02-01','Jan'),(1,'2024-02-01','2024-03-01','Feb'); CREATE TABLE FACT(fid INTEGER,id INTEGER,event_date DATE,amount INTEGER); INSERT INTO FACT VALUES (1,1,'2024-01-01',10),(2,1,'2024-02-01',20);
完全なファイル: range/normal.sql 
SELECT 名称, AGG(売上額) FROM MODEL GROUP BY 名称 ORDER BY 名称

ラベルを価格や区分に置き換える場合は、適用日とイベント日が何を意味するかを定義してください。この例で扱うのは、開始日と終了日がある隣接した有効期間です。終了日を設けない有効期間、任意の多対多の関係、配賦ルールは対象外です。

有効期間の重複を検出して修正する #

検証処理は Jan の終了日を2月2日に変更します。その結果、2月1日は両方の有効期間に該当します。--validate は VALIDATION_ERROR を報告します。終了日を2月1日に戻すと、検証と、結果が2行であることの確認が再び通ります。

業務上の有効期間のルールを修正してください。一致したレコードのうち任意の1件だけを残すと、矛盾が見えなくなります。

検証を実行して結果を確認する #

プロジェクトをダウンロードして、READMEの手順に従い、PowerShellでverify.ps1を実行します。dmlcにパスを通してください。新しい出力フォルダーに演習用データベースを作成し、結果と診断情報を保存します。

この例は DuckDB 上で dmlc 0.3.16（ビルド 2026-11-27）を使って確認しました。実行ファイルのフィンガープリントと各検証ケースのステータスは、ダウンロードに含まれる verification-summary.json に記載されています。データベースでの検証とその後の実行は独立した処理です。両方が同じスナップショットを使用する保証はありません。他のデータベースエンジンでは個別に確認してください。
