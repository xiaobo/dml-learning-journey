Eine ID in der richtigen Region nachschlagen

Inhalt dieser Seite
  • Ausgangsdaten und Ergebnis
  • Den Schlüssel im Modell festlegen
  • Welcher Verkauf wurde doppelt gezählt?
  • Prüfung ausführen und Ergebnis lesen

Geben Sie den vollständigen fachlichen Schlüssel an. Übergeben Sie die Werte beim Nachschlagen in der Reihenfolge der Deklaration. Kennung=1 kann im Osten und im Westen vorkommen. Eindeutig sein muss die Kombination (Kennung, Region).

Ausgangsdaten und Ergebnis #

Die Nachschlagetabelle ordnet (1,east) dem Osten und (1,west) dem Westen zu. Die Umsätze betragen 10 im Osten und 20 im Westen. Die Abfrage liefert:

Bezeichnung Umsatz
East 10
West 20

Werden die Tabellen allein über die ID verknüpft, lassen sich die beiden Zeilen nicht unterscheiden.

Den Schlüssel im Modell festlegen #

Die Nachschlagetabelle deklariert dimension: [Kennung, Region]. Die Bezeichnung wird für jede Verkaufszeile mit pk({Kennung}, {Region}).{Zuordnung}.Bezeichnung ermittelt. Die Argumente stehen in derselben Reihenfolge wie in der Zieldimension.

Vollständige Datei: compound/model.dml 
dialect: duckdb
Zuordnung:
  type: dataset
  table: DIM
  dimension: [Kennung, Region]
  columns:
    Kennung:
      abbr: id
    Region:
    Bezeichnung:
      abbr: label
Verkäufe:
  type: dataset
  table: FACT
  dimension: [Verkaufsnummer]
  columns:
    Verkaufsnummer:
      abbr: fid
    Kennung:
      abbr: id
    Region:
    Bestellwert:
      abbr: amount
    Bezeichnung: 'pk({Kennung}, {Region}).{Zuordnung}.Bezeichnung'
  measures:
    Umsatz: SUM({Bestellwert})
Vollständige Datei: compound/setup.sql 
CREATE TABLE DIM(id INTEGER, region VARCHAR, label VARCHAR); INSERT INTO DIM VALUES (1,'east','East'),(1,'west','West'); CREATE TABLE FACT(fid INTEGER,id INTEGER,region VARCHAR,amount INTEGER); INSERT INTO FACT VALUES (1,1,'east',10),(2,1,'west',20);
Vollständige Datei: compound/normal.sql 
SELECT Bezeichnung, AGG(Umsatz) FROM MODEL GROUP BY Bezeichnung ORDER BY Bezeichnung

Wenn Sie nach der Bezeichnung gruppieren, verwendet die Abfrage den im Modell definierten Schlüssel. Die Verknüpfungsbedingung muss dadurch nur einmal angegeben werden. Klären Sie vor dem Anpassen von Kennung, Region, welche Felder in Ihren Daten einen Eintrag eindeutig kennzeichnen.

Welcher Verkauf wurde doppelt gezählt? #

Fügen Sie der Regionstabelle eine zweite Zeile für (1,east) hinzu. Der Verkauf im Osten über 10 passt jetzt zu zwei Zeilen. Nach einer gewöhnlichen SQL-Verknüpfung ergibt die Summe für den Osten 20. Der Westen bleibt bei 20. Die Bestellungen sind dieselben.

Führen Sie --validate mit diesen Daten aus. Im Prüfbericht erscheint duplicate_key. Behalten Sie nur eine Zeile für (1,east), prüfen Sie die Daten erneut und führen Sie den ursprünglichen Bericht aus. Der Osten liegt wieder bei 10, der Westen weiterhin bei 20. Das Skript im Download prüft die SQL-Summen mit der doppelten Zeile, die Fehlermeldung und beide Ergebniszeilen nach der Korrektur.

Die Prüfung zeigt, ob der deklarierte Schlüssel zu den aktuellen Daten passt. Spätere Schreibvorgänge können neue Duplikate erzeugen. Korrigieren Sie die Quelldaten oder die Schlüsseldeklaration. Ein nachträgliches DISTINCT im Ergebnis kann eine zu hohe Summe nicht zuverlässig korrigieren.

Prüfung ausführen und Ergebnis lesen #

Laden Sie das vollständige Projekt herunter und führen Sie verify.ps1 wie in der Datei README beschrieben in PowerShell aus. dmlc muss über den Suchpfad erreichbar sein. Das Skript legt die Übungsdatenbank im neuen Ausgabeordner an und speichert dort die Ergebnisse und Diagnosemeldungen.

Dieses Beispiel wurde mit DuckDB ausgeführt. Die verwendete Compilerversion und die Prüfergebnisse stehen im Download unter verification-summary.json. Zwischen der Prüfung und der Ausführung können sich die Daten ändern. Prüfen Sie andere Datenbanksysteme gesondert.
