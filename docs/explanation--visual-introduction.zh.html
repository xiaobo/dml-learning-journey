一位旅人带着一个问题而来：每个地区的销售额是多少？

打开带插图的交互式教程。教程现在包含十二章，提供有评分的练习、进度保存功能和最终报表创建工具。练习指南涵盖整个入门项目。本页保留较简短的概念介绍。

每笔销售都有自己的标识 #

旅人记录了四笔销售。这些行是为说明而虚构的，并非从数据库获取的记录。

id region amount
1 North 10
2 North 20
3 South 30
4 South 40

源数据集定义了 dimension: [id]，每行代表一笔销售。两笔销售可能属于同一个地区，因此 region 无法唯一标识源数据中的一行。查询仍然可以按地区对这些行分组。

维度说明详细介绍了如何标识源数据中的行，以及如何在报表中分组。

DML 记录可复用的定义 #

旅人用笔记本记录各项定义。DML 就是这个模型，用 YAML 编写。以下代码片段为销售数据集声明了两个原子指标：

FACT_SALES:
  type: dataset
  table: TABLE_SALES
  dimension: [id]
  columns:
    id:
    region:
    amount:
  measures:
    sales: SUM({amount})
    cnt: COUNT(1)

sales 对金额求和。cnt 统计源数据的行数。两者都是原子指标，均继承 FACT_SALES 作为数据集，直接对其中的行或列表达式进行聚合，不引用其他指标。如果报表定义行或汇总值的层级适用于这些指标的计算，就可以复用它们。

DMX 表达计算逻辑 #

笔记本还记录了如何计算平均值：

average_sale:
  type: measure
  formula: 'DIVIDE({sales}, {cnt})'

这段 YAML 声明了一个指标，其中的公式用 DMX 编写。{sales} 和 {cnt} 引用指标，分母为零时，DIVIDE 返回 NULL。average_sale 引用了其他指标，因此是复合指标。它没有 dataset: 属性。

DMX 是模型定义和查询表达式共用的表达式语法。它不是模型与查询之间的独立处理步骤。语法以表达式参考为准。

查询决定每行结果代表什么 #

旅人把望远镜转向各个地区：

SELECT region, AGG(sales), AGG(average_sale)
FROM MODEL
GROUP BY region

AGG 引用模型中的一个指标。GROUP BY region 指定每个地区对应一行结果。根据示例中虚构的四笔销售，可以算出以下数值：

region sales average_sale
North 30 15
South 70 35

不指定分组字段时，同一组模型指标得出的总销售额为 100，平均每笔销售额为 25。按 id 分组时，每笔销售对应一行结果。无论如何分组，源数据的行标识始终是 [id]。

在声明的源键 [id] 所定义的层级上，经过检查的编译器将聚合简化为逐行表达式，并报告一条严格模式下的诊断信息。这项简化以 id 在源数据中唯一为前提。总计查询和按地区分组的查询均在经过检查的构建版本中通过严格模式编译。

教程的编译器验证记录列出了交互式项目使用的可执行文件、该文件的指纹以及执行过的检查。

交互页面在浏览器中计算这些小型示例表中的值。它不会运行 DML，也不会连接数据库。

编译生成 SQL #

编译器结合模型和查询，生成 SQL。数据库针对实际的源表执行生成的 SQL。

DML model + Model Query
          |
        dmlc
          |
     generated SQL
          |
       database
          |
       result rows

编译成功可以确认受检编译器的行为。源数据的键需要在实际数据上校验，查询结果需要与独立算出的结果核对。首个查询教程使用同一个模型，带你编译按地区汇总的查询，并查看生成的 SQL。

如需了解更多内容，请参阅核心概念、指标声明或模型查询 SQL。
