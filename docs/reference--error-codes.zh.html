使用这些代码确定发生错误的阶段，并选择相应的解决方法。除了进程退出码，还要检查诊断信息和生成的 SQL。

路径显示规则 #

在所有平台上，向用户显示的文件路径均使用正斜杠（/）：

  • 在错误消息中，..\data 或 ../data 等用户输入会规范化为 ../data。
  • 含工作区占位符的路径使用 <workspaceFolder>/relative/path 格式。占位符之后的路径中不得使用反斜杠。
  • 解析后的文件系统路径尽可能以相对于当前工作目录的形式显示。

错误代码类别 #

类别 说明 CLI 退出码
INVALID_INPUT 输入验证失败。用户可以修正输入后重试。 64
VALIDATION 用户级验证失败（解析结果为 OK，但参数无效） 65
NOT_FOUND 找不到请求的资源 66
CONFIG 配置错误（缺少配置、配置无效、连接 ID 未知等） 78
TIMEOUT 操作超时。请更改参数后重试。 69
COMPILE 编译失败（语法错误或模型错误） 2
EXECUTION 执行失败，重试可能成功。 70
INTERNAL 发生意外的内部错误，应报告此错误。 70
BLOCKED 操作因策略或当前状态而受阻 77

错误代码 #

文件 I/O 错误 #

FILE_NOT_FOUND

  • 类别：NOT_FOUND
  • 代码：FILE_NOT_FOUND
  • 常见原因：文件路径不正确、文件不存在，或文件位于工作区文件夹之外。
  • 建议的解决方法：确认文件路径正确，且位于工作区文件夹内。
  • 示例：File not found: /path/to/file.dml

FILE_ALREADY_EXISTS

  • 类别：BLOCKED
  • 代码：FILE_ALREADY_EXISTS
  • 常见原因：尝试创建已存在的文件，但未指定覆盖。
  • 解决方法：换一个输出文件名。如果确实要替换现有文件，请使用该命令支持的覆盖选项。
  • 示例：File already exists: /path/to/file.csv

UNSUPPORTED_FILE_TYPE

  • 类别：INVALID_INPUT
  • 代码：UNSUPPORTED_FILE_TYPE
  • 常见原因：尝试使用不受支持的文件格式。
  • 建议的解决方法：使用受支持的文件类型（parquet、csv、xlsx）。
  • 示例：Unsupported file type: .txt. Supported types: .csv, .xlsx, .parquet

PATH_OUTSIDE_WORKSPACE

  • 类别：BLOCKED
  • 代码：PATH_OUTSIDE_WORKSPACE
  • 常见原因：文件路径位于工作区文件夹之外，例如通过 ../ 跳出该文件夹的路径、指向其他驱动器的绝对路径，或解析到工作区之外的符号链接。
  • 建议的解决方法：使用指向工作区文件夹内的相对路径。
  • 示例：File path must be within workspace: ../outside/file.csv. Workspace folder: <workspaceFolder>
  • 路径显示：在所有平台上，错误消息和 CLI 输出中向用户显示的路径均使用正斜杠（/），包括 <workspaceFolder>/relative/path 这类含占位符的路径。
  • 说明：如果在 CLI 中配置了 WORKSPACE_FOLDER，输入和输出文件必须位于该目录内。

NO_SHEETS_IN_EXCEL

  • 类别：INVALID_INPUT
  • 代码：NO_SHEETS_IN_EXCEL
  • 常见原因：Excel 文件不含工作表，或文件已损坏。
  • 建议的解决方法：提供至少包含一张工作表的有效 Excel 文件。
  • 示例：Excel file has no sheets: /path/to/file.xlsx

连接错误 #

CONNECTION_NOT_FOUND

  • 类别：CONFIG
  • 代码：CONNECTION_NOT_FOUND
  • 常见原因：connections.json 中不存在该连接 ID。
  • 建议的解决方法：列出可用连接并选择有效的连接 ID，或将连接添加到 connections.json。
  • 示例：Connection not found: production. Available connections: [dev, staging]

LIST_CONNECTIONS_ERROR

  • 类别：EXECUTION
  • 代码：LIST_CONNECTIONS_ERROR
  • 常见原因：由于数据库或配置错误，无法列出可用连接。
  • 建议的解决方法：检查连接配置，并确认能否访问数据库。
  • 示例：Failed to list connections: Connection refused

查询执行错误 #

EXECUTION_ERROR

  • 类别：EXECUTION
  • 代码：EXECUTION_ERROR
  • 常见原因：查询执行失败，原因可能是 SQL 错误、数据问题、数据库问题，或模型变更后 materialize 缓存已过时。
  • 建议的解决方法：检查查询语法、数据类型和数据库连接。如果消息提到 materialize 的 semver 已过时，或包含 pls re-setup related model，请运行 dmlc -s <model.dml> --connection=<id>，然后使用相同的 --model 值重试查询。
  • 示例：Execution failed: Column 'invalid_column' does not exist
  • 示例（materialize 已过时）：materialize abort: procedure PROC_M__CACHED_SALES is obsolete since semver (...) is different from expect: ..., pls re-setup related model

EXECUTION_INTERRUPTED

  • 类别：EXECUTION
  • 代码：EXECUTION_INTERRUPTED
  • 常见原因：查询被用户或系统中断。
  • 建议的解决方法：重试查询。
  • 示例：Query execution interrupted

TIMEOUT_ERROR

  • 类别：TIMEOUT
  • 代码：TIMEOUT_ERROR
  • 常见原因：查询执行耗时过长。
  • 建议的解决方法：增大 timeoutSeconds 参数的值，或简化查询。可以考虑添加 materialize 来提高性能。
  • 示例：Query timed out after 30 seconds

编译错误 #

COMPILE_ERROR

  • 类别：VALIDATION
  • 代码：COMPILE_ERROR
  • 常见原因：DML 语法错误、模型验证错误、SQL 生成错误，或修饰符组合非法。例如，在同一个修饰符对象中，对同一维度同时使用 +d 和 -d/-df。语言规范要求对此类组合明确报错。请参阅修饰符组合和常见问题 P79。
  • 建议的解决方法：修复编译错误，确认 model.dml 位于工作区文件夹内，并检查 error.details.generatedSql 中生成的 SQL。如果 +d/-d/-df 之间存在冲突，请改写为单一、明确的操作，不要依赖修饰符相互抵消。
  • 示例：Compilation failed — see details.compilationErrors
  • 说明：在当前已验证的构建版本中，已检查的同一字段上的 +d 冲突不会报错。请明确指定一个求值阶段，并检查生成的 SQL。不要依赖修饰符相互抵消。

COMPILE_TIMEOUT

  • 类别：TIMEOUT
  • 代码：COMPILE_TIMEOUT
  • 常见原因：编译耗时过长。
  • 建议的解决方法：简化 DML 模型、降低复杂度并延长超时时间。
  • 示例：Compilation timed out after 30 seconds

VALIDATION_ERROR

  • 类别：VALIDATION
  • 代码：VALIDATION_ERROR
  • 常见原因：违反了已声明的维度约束。请检查 data.status 和 data.issues。
  • 建议的解决方法：修正无效的参数或配置。
  • 示例：Declared dimension constraints were violated; see data.issues.

生成错误 #

MODEL_RESOLUTION_ERROR

  • 类别：NOT_FOUND
  • 代码：MODEL_RESOLUTION_ERROR
  • 常见原因：在 SQL 文件所在目录、--model=<dir> 指定的目录或模型搜索路径中均找不到 <FROM>.dml。其他可能的原因包括同时使用了 --model=acme.dml 和 FROM MODEL（文件与 FROM 不匹配，退出码为 65），或向仅接受文件的操作传入了目录。
  • 建议的修复方法：对于 query、compile 和 validate 命令，请传入包含匹配的 .dml 文件的目录，或传入文件名与 FROM 匹配的文件。对于 setup 命令，请传入 .dml 文件。
  • 示例：model file "acme.dml" does not match FROM "MODEL" (expected "MODEL.dml").

FILTER_VALIDATION_ERROR

  • 类别：VALIDATION
  • 代码：FILTER_VALIDATION_ERROR
  • 常见原因：筛选器语法错误或字段名无效
  • 建议的修复方法：修正筛选器中的字段名或语法。
  • 示例：Filter validation failed: invalid field 'dt_invalid'

维度验证错误 #

重复的键和重叠的范围

  • 类别：VALIDATION
  • 错误码：VALIDATION_ERROR。请在 data.issues 中查看问题类型。
  • 常见原因：数据集的完整维度值组合出现多次，或按范围查找时可能匹配到范围相互重叠的源数据行。
  • 建议的修复方法：修正源键、数据集的 dimension: 字段列表、重叠的范围或源数据，然后重新运行 --validate。无论是在编译生成的 SQL 中使用 DISTINCT/GROUP BY，还是使用 DISTINCTCOUNT 指标，都无法解决 pk(...) 查找结果不唯一的问题。
  • 示例：Declared DML dataset dimension is not unique in dataset 'Order Line' on this connection at validation time.

EXECUTION_ERROR

  • 类别：EXECUTION
  • 代码：EXECUTION_ERROR
  • 常见原因：验证查询执行失败。
  • 建议的解决方法：检查连接配置，并确认能否访问数据库。
  • 示例：Validation query failed: Connection refused

工作区和操作错误 #

NO_WORKSPACE

  • 类别：BLOCKED
  • 代码：NO_WORKSPACE
  • 常见原因：未设置工作区文件夹，或无法访问工作区。
  • 建议的修复方法：设置工作区文件夹，或检查工作区的访问权限。
  • 示例：No workspace folder configured

INVALID_PARAMS

  • 类别：VALIDATION
  • 代码：INVALID_PARAMS
  • 常见原因：参数名或参数值无效。
  • 建议的修复方法：修正参数名或参数值，并检查该参数允许的选项。
  • 示例：Invalid parameter: 'invalid_param'. Valid options: ['param1', 'param2']

FILE_EXPORT_ERROR

  • 类别：EXECUTION
  • 代码：FILE_EXPORT_ERROR
  • 常见原因：数据导出到文件失败。
  • 解决方法：检查输出路径和写入权限，再重新导出。如果目标文件已存在，请换一个文件名；确实要替换它时，再启用覆盖。
  • 示例：File export failed: Permission denied

常规错误 #

UNEXPECTED_ERROR

  • 类别：INTERNAL
  • 代码：UNEXPECTED_ERROR
  • 常见原因：发生了意外的内部错误。
  • 建议的修复方法：按照支持检查清单准备一个最小复现示例，并通过您现有的产品联系人提交。目前尚未列出公开的支持渠道。
  • 示例：Unexpected error: NullPointerException
