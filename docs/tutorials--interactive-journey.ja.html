2月の売上レポートを作成します。レポートには、完了した取引の売上、前月との比較、顧客あたりの平均売上、地域別の売上構成比を含めます。ブラウザーでDML をめぐる小さな旅を開きます。オフラインで使う場合は、ページと関連ファイルを同じフォルダーに保存してください。

導入部の下にあるボタンでチュートリアルを開始するか、次の未完了の章から再開します。

チュートリアルでは、架空のデータ行を使ってブラウザー内で計算します。任意のDMLをコンパイルしたり、データベースに接続したりすることはありません。記録済みの関連クエリには、コンパイラーの実際の出力が含まれます。最後に、プロジェクト一式をダウンロードします。

回答を選び、答え合わせをクリックします。選択肢を選ぶだけでは章は完了しません。点線が付いたコード内の名前や結果の見出しにポインターを合わせるか、キーボードでフォーカスを移すと、短いヒントが表示されます。クリックまたはタップすると定義を確認できます。

1. 各ソース行を識別する #

第1章の4件の売上取引を確認します。North の2行を見つけます。ソースディメンションとして[id]を選択し、回答を確認します。

フィードバックでは、地域がグループ化フィールドとして使われ、一意のソースキーにはならない理由を説明します。進捗インジケーターには、完了した章が1つと表示されます。

2. アトミック指標を見つける #

第2章のモデル宣言を読みます。ソース列の値を合計する指標を選び、回答を確認します。これで、売上と行数の定義を再利用できます。

3. 数式で指標を再利用する #

第3章のDIVIDE({sales}, {cnt})を確認します。North について 30 ÷ 2 = 15 と計算し、回答を確認します。4件の取引をまとめて同じ数式で計算すると、100 ÷ 4 = 25 になります。指標参照の値は、レポートの現在のグループ化とフィルターに基づいて決まります。

宣言全体を展開し、複合指標が自分の定義に dataset: プロパティを含めずにアトミック指標を再利用する方法を確認します。

4. グループ化を変更する #

第4章で、全売上、地域別、売上明細別を順に選択します。クエリ、結果テーブル、平均の計算が連動して変わることを確認します。「全売上」の売上合計は100、平均は25です。地域別の表示では North が30、South が70です。

クエリ内のaverage_saleをクリックすると、モデル宣言が表示されます。参照でsales、続いてamountを開くとソース列をたどれます。cntを開くと行数の数式を確認できます。グループ化フィールドをクリックすると、対応する列を確認できます。×または Escape キーで定義を閉じます。以降の章でも、数式や結果の見出しで同じようにヒントを確認できます。

ソースディメンションについての設問に答えます。ソースディメンションは一貫して[id]です。行がソースキー単位で定義される場合、確認に使ったコンパイラーは集計を簡略化できると報告します。この簡略化には、宣言されたキーが一意であることが必要です。

5. コンパイルと実行を区別する #

第5章のモデルとクエリの図で処理の流れをたどります。コンパイルに成功すると何が生成されるかを選び、回答を確認します。続いて、個別の確認手順をたどります。コンパイルで生成されたSQLを確認します。データベース接続を使って、クエリの対象となるソース行のキーとSQLの実行計画を検証します。実行結果を、独立に求めた結果と比較します。

6. レポートフィルターと指標フィルターを比較する #

第6章で、8行のソーステーブルを開きます。最初の4件の取引は、ここでは2月の取引です。1月の4行は比較用の過去データです。拡張したモデルの全体を確認します。

レポートの地域としてNorthを選択します。結果には sales = 30 と completed_sales = 10 が表示され、North の 2 件のうち 1 件は返品（returned）です。completed_sales の定義で +f を見つけ、この章の演習の回答を確認します。

{sales: ...} では、コロンの前の名前が指標を表し、後ろの設定がこの参照の計算方法を変更します。f はフィルターを表します。+f は、元の sales の定義を維持したまま、この参照にフィルターを追加します。修飾設定の2つの書き方を展開し、名前付き修飾子と設定オブジェクトを比較します。

7. 分母を選ぶ #

第7章でNorthを選択します。-d: region を使うと、分母は30、構成比は100%です。-df: region に切り替えると、分母は100、構成比は30%になります。

d はディメンション、f はフィルターを表します。-d は、この参照の評価時に使うグループ化からフィールドを外します。-df は、そのフィールドに関連するフィルターも外します。月のフィルター、ソースキー、レポートのグループ化はそのままです。関連する地域フィルターがなければ、この例ではどちらの修飾子でも同じ分母になります。

コンパイラーが生成したクエリの記録と、グループ化や対象となる行についての注記を確認します。全地域を分母に含めたままにする演習の回答を確認します。レポートでは引き続き North が選択されています。分母の参照には異なるフィルターコンテキストが適用されます。

8. 顧客単位で計算する #

第8章でAVGを選択します。ステージ1で、South の顧客 C の売上合計70を確認します。ステージ2では、その1件の顧客別売上合計を平均して70を得ます。取引あたりの平均額は、ソースの2件の取引金額を平均するため、35になります。

外側の集計をSUMに切り替え、次にMAXに切り替えます。両方のステージと数式を確認します。AVGに戻し、演習の回答を確認します。

+d: customer は顧客を評価ディメンションに追加します。外側の集計は、顧客ごとの合計を明示的に集約し、クエリディメンションの粒度に戻します。ソースディメンションは引き続きソース行を識別し、クエリディメンションは引き続き結果行をグループ化します。

9. 連続する月を比較する #

第9章に表示される2つのモデル定義を読みます。previous_sales は前月の値を取得するために {sales: pp} を使い、sales_change は前月比の増減率を求めるために {sales: pop} を使います。2025 年 2 月を選択します。North の売上は30、前月の売上は20、増減率は50%です。South の売上は70、前月の売上は50、増減率は40%です。

{sales: pp} は「前の期間の売上」と読みます。ここでは月を基準にしているため、前月の売上を指します。pop は増減率を小数で返し、ページでは 0.5 を 50% と表示します。

2025 年 1 月を選択します。この例には12月のファクトレコードがないため、前の期間の売上と売上の増減率は NULL になります。pp がどの期間を参照するか確認してください。

クエリを変更する際は、レポートの対象月の範囲を設定します。比較対象を漏れなく含めるには、2つの期間のうち少なくとも一方に売上がある地域をすべて残します。これにより、各列の合計がそれぞれの期間の売上総額と一致します。前月比較の例を参照してください。

10. ルックアップキーを重複させてから修正する #

章 10 で、無効な 2 件目の North を一覧に追加を有効にします。4件のファクトを結合すると6行になります。North の金額の合計は 60 になります。

重複行を無効にします。4件のファクトを結合した結果は再び4行になり、North の合計は 30 になります。ソースデータの一意性に関する演習を確認してください。コンパイラのスナップショットでは、実際に格納されているこれらのレコードは検査されません。

データベース接続先のキーを検査するには、第 10 章のdmlc で重複キーを検出を展開します。そこにあるマネージャーを検索するクエリを、ダウンロードしたモデルと同じディレクトリに lookup.sql という名前で保存します。ディメンションが検査されるには、クエリが DIM_REGION に到達する必要があります。default をサンプルテーブルがある接続に置き換え、次のコマンドを実行します。

dmlc.exe --validate lookup.sql --model=model.dml --connection=default --json

その接続先の TABLE_REGION に North のエントリが両方含まれている場合、DIM_REGION に対して DIMENSION_NOT_UNIQUE が返るはずです。データセットのディメンション宣言またはソースデータを修正し、検証を再実行します。ブラウザーの切り替えで変わるのは、このページ用に作成されたサンプルデータだけです。検証では接続先のデータを読み取り、クエリが到達するデータセットのディメンションを検査します。また、EXPLAIN でメインクエリを調べますが、結果行を取得するための実行は行いません。

11. 欠損値の扱いを明示する #

章 11 で、NULL を保持から定数 0 で補うに切り替えます。1月の結果のグループは変わりません。前の期間の値だけが NULL から 0 に変わります。

補完後の指標の式を読み、1月の結果がどう変わるかを確認します。代替値は、その指標が使われる箇所に値を補います。カレンダーに新しい行を追加したり、過去データの欠損を業務上どう解釈するかを決めたりするものではありません。

12. 最終レポートを作成してダウンロードする #

第 12 章のやってみようでは、両方の地域を含む 2 月のレポートを作ります。「2025 年 2 月」「地域別」「全地域」を選びます。completed_sales、previous_sales、average_customer_sales、all_region_share にチェックを入れます。sales は選択済みです。

設定欄の下にあるモデルのノート · model.dmlとレポートの問い · query.sqlを比較します。ノートブックの抜粋には、選択した指標とその依存関係が表示されます。ソースデータセットの宣言を確認するには、ノートブック全体を展開するか、model.dml をダウンロードします。結果テーブルは両方のペインの下に表示されます。

レポート設定欄の横にある答え合わせを選択します。設定が不足している場合は、フィードバックに従ってやり直すか、ヒントを見るを選択してヒントを確認します。この演習を完了すると、12番目のステップが完了済みになります。設定を完了すると、サンプルの結果として次の値が表示されます。

region sales completed_sales previous_sales average_customer_sales all_region_share
North 30 10 20 15 0.3
South 70 70 50 70 0.7

ブラウザーは割合をパーセントで表示します。モデルと、ダウンロードした期待結果の CSV では、割合は小数で表されます。

確認済みプロジェクトをダウンロードを選択します。プロジェクトアーカイブを書き込み可能なディレクトリに展開し、展開先の START-HERE.txt を開きます。アーカイブには、完全なモデル、最終クエリ、ソース CSV、期待結果、記録済みのコンパイラ出力、およびカレンダーテーブルを含むオプションの SQL Server セットアップが含まれています。

別のレポート設定を保存するには、自分の query.sql をダウンロードを選択します。同梱のコンパイル記録は、記録の対象となった付属クエリにのみ対応します。ビルダーで作成したほかの組み合わせについては、コンパイルして、生成された SQL を確認する必要があります。

ダウンロードしたプロジェクトをコンパイルする #

dmlc.exe が使える状態で、展開先のディレクトリでターミナルを開き、次のコマンドを実行します。

dmlc.exe --lint model.dml --json
dmlc.exe --compile --strict query.sql --model=model.dml --json --artifacts=gen

診断情報と生成された SQL を確認します。確認済みのビルドでは、総仕上げの演習で status: ok が返り、終了コードは 0 になります。キーの和集合に関する診断は情報メッセージです。結合結果には、比較対象月にのみ存在する地域が含まれる場合があります。そうした地域をレポートに含めるべきか確認してから、顧客単位の集計と最終的な射影を確認します。SQL の生成だけでは、データベースで得られる結果が正しいことの確認にはなりません。

オプションのデータベース演習では、新規の空の SQL Server データベースを使い、setup-mssql.sql の内容を確認します。このスクリプトは、ソーステーブルと、期間比較用の SQL に必要なカレンダーを作成します。その接続でモデルクエリ（Model Query）を検証付きで実行し、結果の値をすべて expected.csv と比較します。

dmlc.exe --query query.sql --model=model.dml --connection=default --with-validation --json

default を練習用接続の ID に置き換えます。実際のデータベースを使うこの演習は、ドキュメントの確認作業では実行していません。

接続と検証のコマンドについては、クエリをコンパイルして検証するを参照してください。この入門プロジェクトの次に学ぶ内容として、言語リファレンスでは、ウィンドウ、分類子、マテリアライズ、モデルの合成に関する発展的なトピックを扱います。

同じサンプルデータを使って DuckDB で単独実行するには、確認済みの売上演習を使います。

第 12 章の後で SQL Server でのマテリアライズを試すには、月単位から四半期単位に切り替える Maz 演習に進みます。この演習には、クエリの準備状況の確認と、ランナー全体の進捗表示が含まれます。準備と更新の仕様では、呼び出しから戻った後も処理が残る場合について説明しています。

再開または最初からやり直す #

固定ヘッダーにある地球儀アイコンと言語選択メニューを使って、English、中文、日本語、Deutsch を切り替えられます。各言語はその言語での名称で表示されるため、現在のページの言語が読めなくても選べます。12 のレッスンすべてと、問題、解説、ナビゲーション、フィードバックの表示言語が一緒に切り替わります。回答、レポート設定、章の完了状況は保持されます。ブラウザーは言語設定を学習の進捗とは別に保存します。コード、フィールド名、ソースの値、ダウンロードできるプロジェクトでは、元の識別子がそのまま使われます。

固定ヘッダーには現在の章が表示されます。矢印でレッスンを移動できます。章のタイトルを選択すると、全 12 章の一覧と完了した章の数が表示されます。完了した章にはチェックマークが付きます。最後の章で戻る矢印を選択すると、イントロダクションが開きます。

そのメニューの記号早見表を開くと、修飾子と、ソースディメンション、クエリディメンション、評価ディメンションの各役割を確認できます。ガイドは第 12 章の後にあり、追加の章としては数えません。サンプルモデルでは、論理データセット名に FACT_SALES と DIM_REGION、物理テーブル名に TABLE_SALES と TABLE_REGION を使用し、フィールド名と指標名には lower_snake_case を使用します。

ブラウザーのローカルストレージが利用できる場合、練習問題に正解すると進捗がこのブラウザーに保存されます。章メニューで学習を続けるを選択すると、次に取り組む未完了の章を確認できます。進捗はこの端末に保存され、ページからサーバーに学習者のデータが送信されることはありません。

章メニューの一番下にある進捗をリセットを選択すると、完了した練習問題の記録が消去されます。ブラウザーのストレージを利用できない場合でも、現在のページセッション中はレッスンを利用できます。
