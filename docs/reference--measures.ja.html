このページでは、指標のプロパティと数式の形式を説明します。指標の設計では、指標を定義する際の判断基準を説明します。数式の例では、業務でよく使われるパターンを紹介します。

基本構文 #

measure_name:
    type: measure
    description: Business description
    dataset: dataset_name
    formula: aggregation_expression
    dimensions:                # optional allowed evaluation dimensions
        - [customer_id]
        - [customer_id, ...]   # listed fields remain required
    prerequisite: validity_expression

formula: は必須です。dataset: は、最上位で宣言するアトミック指標をデータソースに紐付けます。データセットの measures: ブロック内にある指標は、そのデータセットを継承します。複合指標は他の指標を参照し、dataset: を省略します。

dimensions: は配列の配列です。各内側のリストは、評価に使用できるディメンションの組み合わせを1つ定義します。入れ子にせず単一のリストを指定すると、string found, array expected エラーが発生します。省略記号を指定すると追加のフィールドを使用できますが、列挙したフィールドはすべて必須です。このプロパティは評価を制約するもので、データセットの識別やクエリのグループ化は定義しません。

prerequisite: は、行や集計値を定義する粒度が有効かどうかを判定する式を追加します。共通のメタデータフィールド description、abbr、tags については、モデルのメタデータフィールドを参照してください。制約の選び方は、指標の設計で説明します。

注意事項

  • クエリ固有のフィルタリングやグループ化は、そのクエリ専用の指標ではなく、モデルクエリで指定します（SQL の WHERE/GROUP BY、または DML 形式の filters: / columns: dimension:）。モデルクエリの規則については、モデルクエリ（SQL）を参照してください。
  • dataset: はアトミック指標専用です。その数式は、他の指標を参照せず、データセットの行や列の式を直接集計します。複合指標は他の指標を参照し、dataset: を宣言してはいけません。参照先の指標がすべて同じデータセットを使用している場合も同様です。指標の参照と、よくある落とし穴 P39 を参照してください。
  • 指標は数値、日付、または分類値を返すことができます。表示形式は利用側で設定し、集計方法と型は業務上の定義に合わせて選択します。
  • 金額や精度が重要な元データのフィールドは、アトミック指標で一度だけ型変換し（例 SUM(CAST({amount} AS DECIMAL(38, 2)))）、後続の処理ではその指標を再利用することを推奨します。
  • 業務ルールが > 0 / < 0 の比較に依存する場合は、MINIF/MAXIF/DISTINCTCOUNTIF の条件で再利用する前に、ベースとなる指標が意図した型（例 DECIMAL）になっていることを確認してください。

COUNT #

number_of_transactions:
    type: measure
    dataset: transactions
    formula: count(distinct transaction_id)

number_of_products:
    type: measure
    dataset: transactions
    formula: count(distinct product)

    type: measure
    dataset: transactions
    formula: SUM(CAST({raw_amount} AS DECIMAL(38, 2)))

    type: measure
    dataset: transactions
    formula: SUM(quantity)

last_order_date:

avg_invoice_quantity:

フィルター付き指標 #

インラインフィルターには {+f: condition} を使用します。修飾子の構文については、関数修飾子を参照してください。

expense:
    type: measure
    dataset: transactions
    formula: |-
        {debit: {+f: {account_type: ['Expense', 'Other Expense']}}}

sales:
    type: measure
    description: Sales revenue from income accounts
    formula: |-
        {credit: {+f: {account_type: ['Income', 'Other Income']}}}

food_and_drink_expense:
    type: measure
    formula: |-
        {expense: {+f: "instr(account, 'Food & drink') > 0"}}

number_of_credit_card_transactions:
    type: measure
    formula: |-
        {number_of_transactions: {+f: {credit_card : 'yes'}}}

number_of_unpaid_invoices:
    type: measure
    formula: |-
        {number_of_invoices: {+f: 'open_balance > 0'}}

指標の参照 #

数式内で他の指標を参照するには、次のように記述します。

複合指標では dataset: を宣言してはいけません。 formula: が他の指標を参照する場合は、dataset: を省略します。アトミック指標は dataset: を使って、他の指標を参照せずに集計する元の行や列の式を紐付けます。以下のアトミック指標の例（credit / debit）では dataset: を指定し、複合指標 profit では省略しています。よくある落とし穴 P39 を参照してください。

# Base measures
credit:
    type: measure
    dataset: transactions
    formula: SUM(credit)

debit:
    type: measure
    dataset: transactions
    formula: SUM(debit)

# Derived measure (composite — no dataset:)
profit:
    type: measure
    formula: |-
        {credit: {+f: {transaction_type: ['Income','Other Income','Expense','Other Expense']}}} -
        {debit: {+f: {transaction_type: ['Income','Other Income','Expense','Other Expense']}}}

指標の別名 #

既存の指標に別名を付けるには、次のように記述します。

revenue: |-
    {sales}

income: |-
    {sales}

outgoing: |-
    {expense}

複雑な数式 #

条件付き集計 #

SUMIF / DISTINCTCOUNTIF / MINIF / MAXIF を使って他の指標を参照する指標は複合指標です。数式内の列が既知のデータセットに「属する」場合でも、dataset: を宣言してはいけません。列を対象とした集計が必要な場合は、別のアトミック指標でのみ dataset: を使用します。指標の参照と、よくある落とし穴 P39 を参照してください。

incoming_payment:
    type: measure
    formula: |-
        SUMIF({payment: {+d: customer}}, {customer} is not null)

outgoing_payment:
    type: measure
    formula: |-
        SUMIF({payment: {+d: vendor}}, {vendor} is not null)

入れ子の集計 #

max_amount_per_invoice:
    type: measure
    formula: |-
        MAX({sales: {+d: transaction_id}})

daily_avg_sales:
    type: measure
    formula: |-
        divide(sum({sales: {+d: dt_date}}), distinctcount({dt_date}))

weekly_avg_sales:
    type: measure
    formula: |-
        divide(sum({sales: {+d: dt_week}}), distinctcount({dt_week}))

avg_sales_per_trx:
    type: measure
    formula: |-
        divide(sum({sales: {+d: transaction_id}}), distinctcount({transaction_id}))

ウィンドウ関数 #

ウィンドウ関数の配置。ルールの詳細はウィンドウ関数の配置を参照してください。概要は以下のとおりです。

目的 配置
明細レベルの OVER（GROUP BY なし。後続の DISTINCTCOUNTIF や外側の SUM / LAG の条件で使う行属性） columns: に計算列を定義し、その後アトミック集計
GROUP-BY 後の順位 / 割合 / 累計 移行時は、アトミック集計と、ウィンドウ関数 / {-d:} / {-df:} / grand を使う複合指標を組み合わせます（dataset: なし）。

アトミック指標では OVER を使用できません（window functions are not allowed in atomic measures）。よくある落とし穴については、P70、P71 を参照してください。

明細レベル（columns: 内でパーティション分けに使う列を直接参照する場合）

fact:
    type: dataset
    table: FACT_SALES
    columns:
        store_id:
        prod_id:
        qty:
        net_qty: 'SUM({qty}) over (partition by {store_id}, {prod_id})'
    measures:
        sum_net_qty: 'SUM({net_qty})'

集計後（複合指標で集計値を定義する粒度を参照する場合）

total_sales:
    type: measure
    dataset: fact
    formula: SUM({qty})

region_rank:
    type: measure
    formula: 'rank() over (partition by {-d: product} order by {total_sales} desc)'

モデルクエリ（SQL）では、目的に合うものがあれば、system_macros.dml の関数マクロ（rank、rank_asc、pot、grand）を優先して使用します。

SELECT product, AGG(sales, 'rank') AS sales_rank
FROM MODEL GROUP BY product

SELECT product, AGG({sales: pot}) AS share
FROM MODEL GROUP BY product

マクロの分類と動作については、関数修飾子を参照してください。

ISNULL と IIF #

all_product_sales:
    type: measure
    description: Product sales including products with zero sales
    formula: |-
        SUM(isnull({sales: {+d: product}}, 0) * iif({DATASET_PRODUCT_SERVICE}.product is not null, 1, 0))

all_customer_sales:
    type: measure
    description: Customer sales including customers with zero sales
    formula: |-
        SUM(isnull({sales: {+d: customer}}, 0) * iif({DATASET_CUSTOMER}.customer is not null, 1, 0))

行が欠けている場合に既定値を補う #

機能 結合、FOJ、またはマテリアライズで行が欠けている場合に既定値を補い、後続の計算への NULL の伝播を防ぎます。

この機能を有効にするには、指標の数式を最外層で isnull / ifnull / coalesce(公式, 字面量) のいずれかで囲みます。

既定値は、その指標の使用箇所（クエリの列、名前の変更、{m: pp} / その他の dt 修飾子、別の数式への埋め込み）で行が欠ける可能性がある場合に適用されます（FOJ / nullpk / マテリアライズ時のラップ）。

次の2つのルールを混同しないでください。

  1. 外側のラップは自動で追加されません。 複合指標の中で既定値補完を有効にした指標を参照するだけでは、その複合指標の結果列はラップされません。行が欠けている場合もその複合指標自身の結果列が NULL 以外の値を返す必要があるなら、結果に対して補完を有効にします。
  2. 埋め込み時も既定値補完は展開されます。 複合指標が、補完を有効にした依存先の指標を直接または数式参照の連鎖を通じて埋め込む場合、行が欠ける可能性のある FOJ の使用箇所では、埋め込みを呼び出す側で補完処理が展開されます。たとえば、deep = {q2fp1} * 3 が q2fp1 = {q2f} + 1 と q2f = isnull(SUM(...), 0) に依存する場合、結合相手の行が欠けているときの結果は NULL ではなく (coalesce(dep, 0) + 1) * 3 になります。この補完は有効化済みの依存先に対するもので、isnull(deep, …) が自動で適用されるわけではありません。
上期:
    type: measure
    formula: 'isnull({销售额: pp}, 0)'   # activate

上上期:
    type: measure
    formula: '{上期: pp}'                # use site → 0

本期减上期:
    type: measure
    formula: '{销售额} - {上期}'         # 上期 use site → 0 (no contagion)

本期减上期_fill:
    type: measure
    formula: 'isnull({销售额} - {上期}, 0)'  # activate on result

# Nested embed (activation on q2f; deep expands fill of q2f at FOJ)
q2f:   { dataset: secondary, formula: 'isnull(SUM({q2}), 0)' }
q2fp1: { formula: '{q2f} + 1' }
deep:  { formula: '{q2fp1} * 3' }

有効化には当たらない（行が存在しない場合、値は依然として null になることがあります）：

記述形式 理由
{销售额: pp} 単独 有効化されない
isnull({a}, {b}) / coalesce(a, b, 0) 指標の補完であり、(公式, 字面量) ではない
isnull(…, 0) + 1 自体を有効化された指標とする場合 その指標を null で評価します（多くの場合 → 1）。この指標の単位元を「行がない → 0」として補うわけではありません。
結果列は一切有効化されない 依存先の指標の null は、式の内部で補完されることがあります。結果列自体が後続の処理で参照される箇所では、その列が有効化されている場合に限り、参照に補完処理が自動で適用されます。

MetricFlow の fill_nulls_with や Looker の集計後の COALESCE と同じ考え方です。補完値を指標に定義し、その指標が使われるときに適用します。DML は欠けているカレンダー行を作成せず、結合後の列の値が null の場合にだけ補完します。欠けている日付は、カレンダーを使うか、FOJ で定義される粒度で別途補ってください。注意点はトラブルシューティング索引の P28b を参照してください。コンパイラに関する補足（dmlc）は docs/fill-default-when-row-missing.md を参照してください。

時系列順に累積する再利用可能な指標 #

名前付きの複合指標には、集計後に評価するウィンドウ関数を含めることができます。累計売上の例では、SUM({sales}) OVER (ORDER BY {month} ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) を宣言済みの [month] の粒度で定義します。計算は地域別にパーティション分割されません。2 月に絞り込むと、計算の開始点が変わります。加算可能な金額の累計は、重複を除いた件数の累計でも、累積比率でもありません。この例には、モデル全体、クエリ、期待される結果行が含まれます。dimension: [] は、総計を評価する際にグループ化を解除します。並び順の指定や累積計算の要求は行いません。最終観測時点の残高を求める場合は、日付をエンティティごとに決めるか全体で決めるかを定義し、観測値がない場合や同じ日付に複数の観測値がある場合の扱いも定義してください。順序を指定した合計や、最終日付を使う単一の計算方法で、すべての半加算計算を定義できるわけではありません。
