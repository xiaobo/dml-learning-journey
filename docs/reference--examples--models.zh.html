维度修饰符 #

业务问题：每种产品在所属类别中的占比是多少？

产品在所属类别中的占比 #

SELECT category, product,
       AGG(sales) as product_sales,
       AGG({sales: {dimension: [category]}}) as category_total
FROM MODEL
GROUP BY category, product

这里，{sales: {dimension: [category]}} 移除 product 和 region，因此 sales 仅按类别计算。

使用 pot（占总计的百分比） #

pot 移除所有维度，从而计算每行占总计的比例：

SELECT category, product,
       AGG(sales) as product_sales,
       AGG({sales: pot}) as share_of_grand_total
FROM MODEL
GROUP BY category, product

如果要计算在上级维度内的占比（例如产品值除以类别总计），请改用 dimension 修饰符：

-- Share of category (product / category total)
SELECT category, product,
       AGG(sales) as product_sales,
       DIVIDE(AGG(sales), AGG({sales: {dimension: [category]}})) as category_share
FROM MODEL
GROUP BY category, product

隐藏的维度字段 #

数据集有时包含仅供内部计算使用、不应向最终用户显示的维度。

transactions:
    type: dataset
    dimension:
        - dt_date
        - product
        - region
    columns:
        dt_date:
        product:
        region:
        transaction_id:          # internal dimension, not for analysis
        amount:

transaction_id 仍可用于 +d 修饰符，但不会显示在 MODEL 表中。

滚动年度总计（MAT） #

SELECT dt_month, AGG(sales), AGG({sales: mat})
FROM MODEL
WHERE dt_month BETWEEN date(current_date, 'start of month', '-12 months')
                   AND date(current_date, 'start of month', '-1 month')
GROUP BY dt_month

mat 计算截至每个 dt_month（含当月）的滚动 12 个月总计。

要点：+d 执行下钻：向计算维度追加一个维度字段，在更细的粒度上聚合，再汇总回原来的粒度。-d 移除维度字段（上卷）。dimension: [list] 替换整个计算维度。可使用这些修饰符计算占比、父子层级之间的比值，以及在调整粒度后进行比较。

组合列 #

业务问题：如何按产品显示已支付发票中的最小开票数量？

条件聚合 #

min_paid_qty:
    type: measure
    dataset: transactions
    formula: MINIF({quantity}, {is_paid} = 1)

SELECT product, AGG(min_paid_qty)
FROM MODEL
GROUP BY product

补齐日历日期与填充默认值的区别 #

补齐日期（显示每个日期）：先确保日历或连续日期序列具备所需粒度，例如在 Dim Calendar 上设置标志，然后按该粒度查询。

Dim Calendar:
    type: dataset
    table: DML_CALENDAR
    dimension:
        - dt_date
    columns:
        dt_date:
        has_data:
            source: '1'

行缺失时填充默认值（防止连接 / FOJ 后 NULL 传播）：在表达式最外层使用 isnull / ifnull / coalesce(公式, 字面量) 启用填充。填充仅在该指标的使用处生效。请参阅缺失行填充。

daily_sales:
    type: measure
    formula: 'isnull(SUM({sales: {+d: dt_date}}), 0)'   # activate

对于后续组合计算，不要仅依赖 SUM(isnull({sales: {+d: dt_date}}, 0)) 来处理连接后缺失的行。请为将要引用的指标启用填充，或为组合计算的结果启用填充。

要点：使用 MINIF / MAXIF / AVGIF 进行返回单个值的条件聚合。日期有缺失时，补齐日期；连接后的指标行有缺失时，在使用处填充默认值（P28b）。

使用 allows: ALL 选择物化结果 #

有关语法和示例，请参阅 allows: ALL。allows: ALL 允许将兼容的物化结果纳入候选范围，指标的粒度约束仍然适用。

物化 #

业务问题：某个仪表板每小时查询一次过去 24 个月的月度销售额、同比增长率和 MAT。底层数据集非常大。

解决方案：物化 #

先定义指标，再定义一个物化对象，按固定粒度预聚合这些指标：

sales:
    type: measure
    dataset: transactions
    formula: SUM({amount})

sales_yoy:
    type: measure
    formula: '{sales: yoy}'

sales_mat:
    type: measure
    formula: '{sales: mat}'

DWS_SALES_DATE_PRODUCT:
    type: materialize
    parameters:
        dt_date: date
    dimension:
        - dt_date
        - product
    measures:
        - sales
        - sales_yoy
        - sales_mat

数据集也可以在自身定义中直接声明物化（在数据集上指定 materialize: <name>）。请参阅数据集定义（type: dataset）。有关独立对象形式，请参阅物化声明。

⚠️ 指标级别没有 materialize: true 标志。编译器会拒绝该标志并报错 undefined modifier 'materialize'（已用 dmlc -c 验证）。物化通过 type: materialize 或数据集级别的 materialize: <name> 声明，不能在指标上声明。

工作原理 #

  1. 编译器会注册物化，并按 dimension: 声明的粒度预聚合列出的指标。
  2. 以兼容粒度引用这些指标的查询可以考虑从物化表获取结果，无需扫描原始数据。是否可用取决于 allows:，请参阅查询定义（type: query）。
  3. 物化通过对应的存储过程（parameters:）刷新，不会实时更新。

使用未物化维度筛选的查询 #

SELECT dt_month, product, region, AGG(sales)
FROM MODEL
WHERE region = 'North'
GROUP BY dt_month, product, region

如果物化粒度为 dt_date + product（不含 region），则无法用该物化结果处理此查询。必要时可以考虑按多个粒度分别物化。

何时使用物化 #

场景 是否物化？
频繁扫描指标，且原始数据量很大 是
指标用于有严格 SLA 要求的仪表板 是
仅偶尔临时查询该指标 否（收益不足以抵消额外开销）
指标粒度 = 原始数据粒度 否（聚合无法带来收益）
指标涉及复杂的窗口函数 是

要点：使用 type: materialize 对象声明物化（用 dimension: 指定粒度，用 measures: 指定指标）。不能直接在指标上声明物化。查询仍按常规方式引用已物化的指标（AGG(sales)）。请参阅物化定义（type: materialize）和物化设计。

使用物化替代 ETL #

业务问题：一个存储过程构建事实表（INSERT INTO RPT_X SELECT ... FROM raw LEFT JOIN dim1 LEFT JOIN dim2 ...），随后报表使用 RPT_X。能否用 DML 替代这个存储过程？

解决方案：将 ETL 流水线建模为物化对象 #

请对整个流水线建模，而不是将 RPT_X 视为外部构建的 table: 数据集。将原始数据源定义为 table: 数据集，通过链式调用 pk() 补充数据，再将 RPT_X 定义为 type: materialize 对象，从补充后的数据源进行预聚合。

# 1. Dimension datasets (the stored procedure's #temp tables)
Dim Customer:
    type: dataset
    table: MDM_STORE
    dimension: [store_id]
    columns:
        store_id:
        store_name:
        hq_id:

Dim Org:
    type: dataset
    table: MDM_ORG
    dimension: [org_id]
    columns:
        org_id:
        emp_name:

# 2. Source fact dataset with pk() chain enrichment
#    (replaces the stored procedure's SELECT ... LEFT JOIN ...)
raw_sales:
    type: dataset
    table: RAW_SALES
    dimension: [dt_month, store_id, prod_id]
    columns:
        dt_month:
        store_id:
        prod_id:
        amt:
        # pk() chain enrichment replaces LEFT JOINs
        store_name: pk({store_id}).{Dim Customer}.store_name
        hq_id: pk({store_id}).{Dim Customer}.hq_id
        # nested pk() chain: hq_id → Dim Customer → ... (hq_id is itself a pk result)
        hq_name: pk({hq_id}).{Dim Customer}.store_name
        # three-hop chain: store → hq_id → org_id → emp_name
        hq_org_id: pk({hq_id}).{Dim Customer}.org_id
        hq_emp: pk({hq_org_id}).{Dim Org}.emp_name
    measures:
        sales: SUM({amt})

# 3. Materialize replaces INSERT INTO RPT_X
#    Grain keys (dt_month, store_id, prod_id) go in dimension:.
#    Functionally dependent attributes (store_name, hq_name, hq_emp) go in
#    dimension_columns: — the compiler rejects derivable attributes in dimension:.
RPT_X:
    type: materialize
    parameters:
        dt_month: range
    dimension:
        - dt_month
        - store_id
        - prod_id
    dimension_columns:
        store_name:
        hq_name:
        hq_emp:
    measures:
        - sales

# 4. Report query consumes the materialize
report:
    type: query
    allows:
        - RPT_X
    filters:
        dt_month: { range: ['2024-01-01', '2024-03-01'] }
    columns:
        dimension: [dt_month, store_name]
        sales: '{sales}'

何时使用此模式：

  • 作为基准的 SQL 实现是一个包含 INSERT INTO ... SELECT ... FROM raw JOIN dims 的存储过程。
  • 存储过程的临时表可直接映射为通过 pk() 链查找的维度数据集。
  • 存储过程中通过 INNER JOIN 限定参与计算的行的条件，会转换为控制哪些行参与指标计算的条件。请保留原有的行集合，并检查生成的谓词。

注意事项：

  • 使用 @month（最后一个余额月份）刷新所有历史月份主数据的存储过程，无法用基于 archive_month（各月各自的主数据）进行联接的 pk() 链精确复现。请将其记录为已知限制，并注明需要使用同一份源数据快照比较结果。
  • 通过 CROSS APPLY 使用表值函数以及通过 CASE WHEN 重映射键时，需要在维度数据集中使用 sql: 转义写法。请声明所得的键并验证其唯一性。

维度不一致 #

业务问题：比较按地区划分的销售额和按仓库划分的库存。两者共有 dt_date 和 product，但 region 和 warehouse 都不是共有维度。

比较的难点 #

如果数据集的维度完全不同，必须先对齐维度，才能直接比较其中的指标。

sales:
    type: dataset
    table: fact_sales
    dimension:
        - dt_date
        - product
        - region
        - customer
    columns:
        dt_date:
        product:
        region:
        customer:
        amount:

inventory:
    type: dataset
    table: fact_inventory
    dimension:
        - dt_date
        - product
        - warehouse
    columns:
        dt_date:
        product:
        warehouse:
        units:

total_sales:
    type: measure
    dataset: sales
    formula: SUM({amount})

total_inventory:
    type: measure
    dataset: inventory
    formula: SUM({units})

共同粒度：按产品和日期 #

SELECT dt_date, product, AGG(total_sales), AGG(total_inventory)
FROM MODEL
WHERE dt_date = date(current_date)
GROUP BY dt_date, product

两项指标共有 dt_date 和 product，因此可以这样比较。模型会隐式处理缺少的维度。

同一查询中需要同时使用地区和仓库时 #

通常不能同时按 region 和 warehouse 分组，因为 total_inventory 没有 region，而 total_sales 没有 warehouse。

方案 1：使用两个独立查询

-- Sales by region
SELECT dt_date, region, AGG(total_sales) FROM MODEL GROUP BY dt_date, region

-- Inventory by warehouse
SELECT dt_date, warehouse, AGG(total_inventory) FROM MODEL GROUP BY dt_date, warehouse

方案 2：使用修饰符移除不兼容的维度

SELECT dt_date, region,
       AGG(total_sales) as sales,
       AGG({total_inventory: {-d: warehouse}}) as inventory_dropped_warehouse
FROM MODEL
GROUP BY dt_date, region

{-d: warehouse} 将 warehouse 从定义库存粒度的维度中移除。这样，库存按 dt_date + product 粒度计算，并可与 dt_date + region + product 粒度的销售额联接。不过，这种联接在业务含义上通常值得商榷，请谨慎使用。

所选期间与全部历史的合计 #

-d 会取消分组。如果仍有月份筛选条件，取消分组并不意味着查询涵盖全部历史。对于这些模型片段，请使用各自明确指定范围的独立查询：

-- Selected month
SELECT product, region, AGG(total_sales) AS period_sales
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY product, region

-- All history
SELECT product, region, AGG(total_sales) AS all_time_sales
FROM MODEL
GROUP BY product, region

请使用本页要求的模型定义，分别执行这些语句。有关在同一份报表中实际执行完整比较的示例，请参阅固定轴分母。该示例中的常规分组字段 month 有别于时间上下文 dim_dt。

要点：如果不同数据集中的指标有足够多的共有维度，就可以在同一查询中查询这些指标。如果维度不一致，请使用独立查询，或谨慎使用 -d 修饰符。为强行兼容而移除维度可能产生误导性结果，请记录这样做的目的。
