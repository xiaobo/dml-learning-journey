指標をディメンションとして使用する場合に、+d がない、ラベルのキーに互換性がない、または同じ階層の別の指標を正しくロールアップできない ディメンションとして使う各指標に、完全な +d キーを明示する。互換性のあるキーと、集計可能な出力指標を使う。 P66–P68
同じオブジェクトに対する {+d:x,-d:x} / {+d:x,-df:x} が、通知なしに {m} または {-f:x} だけになる 無効な指定であり、明示的なエラーにする必要がある。意図した操作を直接指定する形に書き換える。 P79
-f / -df の分岐がグループ化の粒度に関係しないクエリフィルターを外すため、FOJ の相手側の行が結果に混入する レポートの対象範囲を引き続き絞り込む（EXISTS / セミジョイン）。-f でグループ化は変わらない。 P80
月単位のクエリで {m:{dimension:[dt_quarter]}} がスカラー値として、または誤った粒度で結合される 粗い粒度の CTE をカレンダー経由で結合し、四半期の値をその四半期に属する各行に展開する P81
細かい粒度の CTE 内の WHERE と外側の SUM が、粗い粒度の filters: "売上件数 > 3" に書き換えられる 指標の中で、対応する {+d: …} とともに SUMIF / SUM(iif) を使う P69
window functions are not allowed in atomic measures / GROUP BY と OVER の無効な組み合わせ 明細レベルの OVER は columns: に置く。GROUP-BY の後は複合指標または {-d:} を使う。 P70–P71
… reference is not allowed in PARTITION BY 指標のウィンドウ関数で、ウィンドウ定義に {col} を直接指定している場合は、明細の計算を columns: に移すか、{-d:} / {dimension:} を使う。 P71
ロールアップ時に比率の分母が誤って計算される（left × right ではなく left²）。診断メッセージは出ない。 粒度を定める 2 つのフィールドが同じ列を参照する。-df/dimension: は 2 番目の役割を最初のキーに結び付けた。pk() を使って、ディメンションを宣言した sql: データセットを参照する。 P72
ロールアップする複合指標から余分な行や、本来存在しない left = right の行が出力される データセットをまたぐ -df は FULL OUTER JOIN を生成する。'{primary_measure} is not null': で結果を絞り込む。 P73
-df のロールアップが粒度を定めるフィールドを除外し、警告は「skip dimension column」のみ 同じ物理テーブルを参照する 2 つの table: データセットで列の集合が異なる。列の集合を同一にするか、同じテーブルを異なる役割で参照するデータセットを避ける。 P74
ディメンションの名前を変更した後、-df で column(s) [x] … not in dimension が発生する -df の引数には、粒度を定めるフィールドの宣言名を指定する。ソース列の名前は指定しない。 P76
MAX(pk(…)) で dataset must be specified … did you mean X が発生する dataset: に参照先を利用する側のデータセットを指定する P77
