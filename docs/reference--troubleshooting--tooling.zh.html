P34. 在需要可靠结果时跳过验证 #

错误：在可以进行数据库验证的情况下，写完查询就直接执行，跳过验证。处理方法：在计划使用的连接上通过 --with-validation 运行查询，或使用 --validate 生成报告。验证会发现编译错误，根据实际观测到的数据检查查询涉及的数据集的完整维度，并通过 EXPLAIN 检查主查询。验证无法证明结果正确，也无法证明将来仍满足唯一性要求。前提条件：验证需要支持 --validate 的可执行文件以及已配置的连接。请检查 --help 和 --advanced-help。如果缺少任一前提条件，请将数据库验证记录为未运行。参见「连接数据库进行验证」。

P35. 忽略列说明 #

错误：说明写着「仅供内部使用，请改用 customer」，却仍使用 customer_name。处理方法：阅读并遵循列说明。将内部字段替换为对应的公开别名。

P36. 方言不匹配 #

错误：以为所有 SQLite 日期表达式都能在 MSSQL 中原样使用。处理方法：DML 会将受支持的 SQLite 风格日期表达式转换为目标方言。检查生成的 SQL，并测试实际使用的表达式。对于不受支持的写法，需要使用适合目标方言的替代写法。参见「日期表达式」。

类别：编译器、YAML 和命名 #

P53. 在 PowerShell 中用 && 串联命令 #

错误：cd path && dmlc --model=model.dml query.sql 修正：cd path; dmlc --model=model.dml query.sql

P53b. FROM 中的名称 ≠ --model= 指定的文件名 #

错误：用 dmlc q.sql --model=acme.dml 执行 SQL SELECT AGG(x) FROM MODEL。
→ model file "acme.dml" does not match FROM "MODEL" (expected "MODEL.dml")（退出码 65）。
处理方法：改为 FROM acme，或使用 --model=model.dml 并保留 FROM MODEL，也可以指定包含正确 .dml 文件的目录（--model=<dir> 会在其中找到 <FROM>.dml）。
注意：dmlc -e 不接受目录，必须指定一个 .dml 文件。参见「模型查询 SQL」中的「查询类型」一节。

P63. Windows 上直接传给 CLI 的模型查询 SQL 中的 / 运算符 #

现象：file not found: SELECT ...。a / b 中的 / 会使 CLI 将 SQL 字符串视为文件路径。处理方法：通过命令行参数直接向 CLI 传入查询时，请使用 DIVIDE(a, b)，也可以改用 .sql 文件传入查询。

P54. 通过 PowerShell 管道传递含 CJK 字符的 JSON #

错误：处理中文字段名时使用 dmlc ... | Out-File result.json，或捕获标准输出。处理方法：使用 dmlc ... --output=result.json --replace，或在 Node 中使用 execSync(..., { encoding: 'utf8' })。

各构建版本的 CLI 选项 #

根据可执行文件的构建时间戳和帮助信息，确定该构建版本的命令用法和行为。

旧选项 已检查的构建版本
--output-format=json 使用 --json 生成结构化的 CLI 报告
--output-dir=gen 使用 --artifacts=gen 输出编译器产物
对模型查询使用 --validate-only 使用 --validate 生成独立的验证报告

Explain-change 仍使用自己的 --validate-only 进行预检查。执行查询时使用 --with-validation，可在验证失败时停止执行，避免返回任何行。

SQL 语法检查 #

在 2026-11-23 构建版本中，即使解析失败，--check --json 也可能报告成功，例如使用 QUALIFY 时。请以所需操作的退出状态和诊断信息为准，例如对模型查询进行严格编译，或使用 --to-dml 进行转换。

验证时日历设置失败 #

如果遇到 DML_CALENDAR 的权限错误，请检查选定的模式和连接所用的角色。按照「设置系统日历」的步骤，使用有权创建表和插入行的角色初始化系统日历。然后使用运行时角色重新执行验证。
