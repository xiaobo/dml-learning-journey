DML 根据完整的分组键对齐各自独立聚合的指标。对齐时，分组键中相同位置的 NULL 值视为相等。因此，报表可以将多个来源中未分类的数据呈现在同一个分组中。

按连接用途划分的等值规则 #

用途 典型的 SQL 写法 ON 中的等值规则 含有 NULL 的键如何处理
合并各自独立的指标结果中的键，这种方式称为键并集组合。 FULL OUTER JOIN，或使用 UNION 和 LEFT JOIN 的去重键集合 NULL 安全的等值比较 完整键的值一致且 NULL 出现在相同位置时，这些键会在不同来源之间对齐。
在保留驱动行的同时附加属性，包括通过内部 nullpk 附加属性。 LEFT JOIN NULL 安全的等值比较 结构键匹配时，即使其中一个组成部分为 NULL，也可以附加属性。

NULL 安全的等值比较可以使用 <=>、IS NOT DISTINCT FROM，或使用包含显式分支的等值判断来处理两侧均为 NULL 的情况，具体取决于所用方言。显式 SQL 谓词（如 a.地区 = b.地区）遵循数据库的常规等值语义。明细连接使用各自键的等值规则。

使用含 NULL 的键对齐时的输出 #

假设未分类地区的销售总额为 50，退款总额为 8。按 地区 分组会返回一行 (NULL, 50, 8)，其中包含两个指标。这一行代表报表中的一个分组。底层销售记录和退款记录各自保留其标识。即使两个指标值都是 NULL，该分组仍会对齐。

对于 (地区, channel) 这样的复合键，(NULL, 'online') 与 (NULL, 'online') 对齐。(NULL, 'retail') 仍是单独的分组。期间计算对非时间分组键应用相同的规则，并沿用自身的时间匹配规则。

如果报表需要一个带标签的分组，请使用 coalesce(地区, 'UNKNOWN') 这样的显式分组表达式。该表达式也会将数据中实际存在的 'UNKNOWN' 值归入同一分组。

总体、填充和行密集化 #

使用基于未填充的存在性指标的筛选器，可以将报表限定为来自指定来源的分组。即使对应分组在来源中存在，允许空值的业务指标也可能是 NULL。

缺失行填充为指标提供备用值。行密集化补齐缺失的实体行或日历行。这两项操作都无法确定某个分组是否属于来源总体。

编译器构建版本的验证结果 #

这项规则适用于包含 2026 年 11 月 19 日分组变更的编译器构建版本。在已检查的跨数据集示例中，2026 年 10 月 16 日的构建版本使用了常规等值运算符 =。检查使用旧版编译器构建版本编译的报表时，请查看生成的谓词，并使用键中含有 NULL 的示例比较结果。后来检查的另一个示例也生成了常规等值比较，并通过了严格模式编译。请使用自己的编译器和数据检查结果。

核心规范中的跨数据集自动连接定义了组合方式。模型审查列出了查询变更后的检查项。
