Modelle einbinden und Namen auflösen

Welche Namen stehen in derselben Datei und in eingebundenen Dateien zur Verfügung? Wie unterscheiden sich im SQL eines Datensatzes Verweise auf das Modell von Verweisen auf die Datenbank?

Definitionen in derselben Datei #

In der geprüften Compilerversion dürfen Sie Namen verwenden, bevor Sie sie in derselben Datei definieren. So kann eine Kennzahl vor dem Datensatz oder der Kennzahl stehen, die sie verwendet. Dasselbe gilt für berechnete Spalten und den Zieldatensatz von pk(). Für Leser ist es oft einfacher, zuerst die benötigten Namen zu definieren. Fehlt eine Definition oder hängen Definitionen im Kreis voneinander ab, meldet der Compiler einen Fehler.

Dateien einbinden #

Jede Datei kann ihre eigenen Definitionen und die von ihr eingebundenen Dateien verwenden. Ein Datensatz, der nur in der übergeordneten Datei definiert ist, ist in der eingebundenen Datei nicht verfügbar. Schlägt das Einbinden fehl, ist auch das übergeordnete Modell ungültig. Der Compiler sucht relative Pfade zuerst im Verzeichnis der Datei, die den Pfad angibt. In der Umgebung konfigurierte Modellpfade geben Suchorte an. Abhängigkeiten müssen Sie weiterhin im Modell angeben.

Eine frühere Abfrage in derselben Sitzung macht keine zusätzlichen Namen verfügbar. Gemeinsam genutzte Datensätze und Kennzahlen können Sie in einem Basismodell definieren und dieses in jeden Bericht einbinden.

Modellnamen und Datenbanknamen in SQL #

In der Datensatzeigenschaft sql: verweist FROM {Customers} auf den Datensatz im Modell. FROM Customers verweist auf die Relation in der Datenbank. In einer Spaltenformel setzt der Compiler für {net_amount} die Definition der Modellspalte ein. Der unmarkierte Name net_amount bleibt als Spaltenname im SQL stehen. Beim Rückübersetzen können solche Datenbankverweise im erzeugten SQL erhalten bleiben.

Abfragedateien direkt kompilieren #

Wenn Sie eine DML-Datei direkt kompilieren, muss die Abfrage wie die Datei ohne Erweiterung heißen. In report.dml steht also report: {type: query, ...}. Ein wiederverwendbares Modell ohne eigene Abfrage sprechen Sie über Model Query SQL an. Der Name nach FROM richtet sich nach dem Dateinamen des Modells. Siehe Abfragen finden.

Prüfen Sie die eingebundenen Dateien, die Namen und das erzeugte SQL mit Ihrer installierten Compilerversion, bevor Sie den Bericht ausführen.
