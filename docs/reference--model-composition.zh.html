模型里的名称可以在哪里引用？

本页目录
  • 同一文件中的定义
  • 引入其他文件
  • SQL 中的模型名称和数据库名称
  • 直接编译查询文件

本文说明同一文件和引入的文件中可以引用哪些定义，以及在数据集的 SQL 里如何区分模型中的名称和数据库里的名称。

同一文件中的定义 #

在已验证的编译器版本中，可以先引用一个名称，再在同一文件里定义它。例如，可以先写指标，再写它依赖的数据集或另一个指标。计算列引用的列、pk() 指向的数据集也可以写在后面。先写被引用的定义通常更容易阅读。找不到定义或出现循环依赖时，编译器会报错。

引入其他文件 #

每个文件都可以使用自己的定义，以及它自己引入的定义。如果某个数据集只在上层文件中定义，被引入的文件就无法使用它。引入失败会使上层模型也失效。编译器会先按引入方所在的目录解析相对路径。环境中配置的模型路径指定搜索位置，文件依赖仍需在模型里声明。

同一会话中先前用过的名称，不会因此出现在当前模块里。可以把共用的数据集和指标定义在一个基础模型中，再让各个报表引入这个模型。

SQL 中的模型名称和数据库名称 #

在数据集的 sql: 中，FROM {Customers} 引用模型定义的数据集，FROM Customers 引用数据库里的表或视图。在列公式中，{净额} 会展开成模型中该列的定义；直接写 净额 时，它是数据库 SQL 中的列名。反向生成的 SQL 可能会保留对数据库对象的引用。

直接编译查询文件 #

直接编译 DML 文件时，查询名必须与去掉扩展名的文件名一致。例如，report.dml 中的查询写作 report: {type: query, ...}。可以使用 Model Query SQL 读取不含查询的可复用模型。FROM 后的名称由模型文件名决定，详见查找查询。

运行报表前，用实际安装的编译器检查引入的文件、引用的名称和生成的 SQL。
