扣除退款后，月报和地区报表会怎么变？ #

假设团队以前按订单金额报收入，现在决定扣除退款。两张报表都引用模型里的净收入指标 net_revenue。月报按月汇总，地区报表按地区汇总。

月份 地区 订单金额 退款
一月 东区 100 10
二月 东区 150 30
二月 西区 80 0

只改模型里的一行。用原来的两条查询重新生成 SQL，在同一份数据上再跑一次。

报表 行 原来 扣除退款后
月报 一月 100 90
月报 二月 230 200
地区报表 东区 250 210
地区报表 西区 80 80

东区一共退了 40，两笔退款分别扣在一月和二月。西区没有退款，仍是 80。如果报表已经导出，要重新运行查询，再导出一份。

对照公式和查询。

原来

net_revenue: SUM({amount})

扣除退款后

net_revenue: SUM({amount}) - SUM({refund})
完整文件 / Complete file: net-revenue/monthly.sql 
SELECT report_month, AGG(net_revenue) FROM MODEL GROUP BY report_month ORDER BY report_month DESC
完整文件 / Complete file: net-revenue/regional.sql 
SELECT region, AGG(net_revenue) FROM MODEL GROUP BY region ORDER BY region

下载示例，按包内说明运行 verify.py。打开输出目录的 net-revenue 文件夹，比较 monthly-rows.json 和 after-monthly-rows.json；地区报表对应的文件以 regional 和 after-regional 开头。

先确认集成需要的能力 #

已测 JDBC 物理 SQL 和 FROM MODEL 查询都能绑定位置参数 ?；示例覆盖筛选条件和指标表达式。物化参数和内部字面量参数化是不同机制；不要拼接不可信输入。

按目标数据库显式设置 dialect:；当前编译器在缺少方言的测试模型中报错，连接配置不会代替该声明。识别方言不等于各引擎所有功能都执行验证过。列值类型由数据库定义，已测列声明不接受 type:，编译通过仍可能出现数据库类型错误。

累计指标要区分时间范围与筛选后行窗口。二月的窗口累计不会自动包含一月；日历累计则要明确截止点和输出期间。键验证也不保证与后续执行使用同一数据快照。根据上表的对应指南验证边界，再对照完整结果。

扩展自己的计算规则 #

可以扩展修饰符，也可以调用数据库中的标量函数。 自定义 fn-macro 包装指标公式，dt-macro 调整时间上下文，并按同一语法组合。数据库函数的实现、部署和权限由数据库负责；编译通过不代表函数存在，应在目标连接上验证。
