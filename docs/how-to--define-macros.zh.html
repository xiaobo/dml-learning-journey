DML 可在两个不同的层面扩展：可以在 DML 中定义可复用的指标或时间转换，也可以调用目标数据库中已安装的标量函数。自定义修饰符可与指标引用组合使用。数据库函数的计算逻辑由相应的数据库实现。

要复用时间转换，或复用应用于调用方所选指标的公式，请使用自定义宏。有关调用和组合规则，请参阅修饰符参考。

自定义宏定义（dt-macro 和 fn-macro） #

用户可以在 .dml 中定义自己的宏，包括 dt-macro（用于偏移时间范围）和 fn-macro（用于将指标嵌入公式）。只需定义一次，即可像引用内置修饰符一样，在任意指标或查询中按名称引用。

两种宏类型

类型 用途 关键属性 {measure} 占位符
dt-macro 偏移或扩大时间窗口 数值:（单点偏移）或 range: [start, end] 否。宏作用于时间上下文。
fn-macro 将指标嵌入派生公式 使用 {measure} 的 formula: 是。占位符会替换为调用方提供的指标。

使用 数值: 偏移时间点，使用 range: [start, end] 指定时间窗口。fn-macro 使用 {measure} 引用调用方提供的指标，dt-macro 使用 {dim_dt} 引用解析得到的时间字段。可通过可选的 prerequisite: 限制求值时允许在哪些层级定义行或汇总值。

选择扩展方式 #

目标 使用方式 维护内容
将同一计算应用于多个指标 fn-macro 基于 {measure} 的 DML 公式
复用时间偏移或时间窗口 dt-macro DML 时间转换
复用数据库中的现有计算 数据库标量函数调用 数据库函数及其权限和部署

自定义修饰符将分析逻辑保留在模型中，调用语法与内置修饰符相同。数据库函数可在数据所在的数据库中复用逻辑，但会引入对该数据库函数实现的依赖。无论使用哪种方式，都需要正确选择求值时定义行或汇总值的层级。

经过验证的组合示例 #

自定义修饰符的引用形式与内置修饰符相同，无需修改编译器。

先在隔离的 DuckDB 练习数据库中准备两条销售记录：

CREATE TABLE sales(id INTEGER, dt_month DATE, amount DECIMAL(12,2));
INSERT INTO sales VALUES
  (1, DATE '2025-01-01', 20),
  (2, DATE '2025-02-01', 30);

将以下完整模型保存为 model.dml：

dialect: duckdb
S:
  type: dataset
  table: sales
  dimension: [销售明细编号]
  columns:
    销售明细编号:
      abbr: id
    dt_month:
    销售金额:
      abbr: amount
  measures:
    销售额: SUM({销售金额})
两倍金额:
  type: fn-macro
  formula: '{measure} * 2'
上月:
  type: dt-macro
  数值: date({dim_dt}, '-1 month')

当 1 月销售额为 20、2 月销售额为 30 时：

SELECT AGG({销售额: 两倍金额}) AS 两倍值,
       AGG({销售额: 上月}) AS previous,
       AGG({销售额: {两倍金额, 上月}}) AS 上期两倍值
FROM MODEL
WHERE dt_month = '2025-02-01'

将查询保存为 query.sql。将练习数据库配置为 default 后，运行：

dmlc --compile --strict query.sql --model=model.dml --json
dmlc --validate query.sql --model=model.dml --connection=default --json
dmlc query.sql --model=model.dml --connection=default

执行得到的值为 60、20、40。在所检查的 DuckDB 连接上，严格编译、validate-only 和执行均成功。模型声明了 dialect: duckdb、源数据中唯一的 销售明细编号、dt_month 和 销售额: SUM({销售金额})。

这是语言层面可复用的组合方式。宏接收调用方提供的指标及其求值上下文。这并不是可任意扩展编译器的插件 API。粒度规则、时间前提条件和修饰符顺序仍然适用。自定义名称无法绕过这些规则。

调用数据库中定义的函数 #

DML 可以在生成的 SQL 中保留标量函数调用，函数由数据库实现。例如，在运行 DML 之前，先在 DuckDB 练习数据库中安装以下函数：

CREATE FUNCTION business_net(x) AS x * 0.8;

DuckDB 将这种形式实现为持久化的 SQL 标量宏。此示例验证的是数据库中定义的标量函数调用，不涉及 Python UDF 注册、聚合 UDF 或表值函数。

在 S.measures 下添加以下条目，使其与 销售额 并列，以便在聚合前对源数据值调用该函数：

# Under the sales dataset's measures:
净销售额: SUM(business_net({销售金额}))

然后，将该指标与对聚合结果调用函数所得到的值进行比较：

SELECT AGG(净销售额), business_net(AGG(销售额)) AS 净额合计
FROM MODEL
WHERE dt_month = '2025-02-01'

2 月销售额为 30 时，两种方式均返回 24。生成的 SQL 保留了 SUM(business_net(销售金额)) 和 business_net(SUM(销售金额))。两种方式在不同阶段求值。此处结果相同，是因为函数是线性的。舍入、阈值判断或其他非线性函数可能产生不同的结果，因此请根据所需结果选择求值阶段。

在计划使用的连接上验证函数 #

DML 不会安装函数，也不会在不同数据库之间转换其实现。执行查询的连接必须能够访问该函数，函数必须接受生成的参数类型，且该数据库用户必须有权调用函数。函数命名、架构限定、部署和可移植性仍取决于具体数据库。

对一个故意未提供的函数的调用通过了严格编译，但随后在 validate-only 的 EXPLAIN 阶段失败（退出码 65）；直接执行也失败了（退出码 70）。因此，仅凭编译成功无法确认 UDF 是否存在或能否调用。请先编译和验证，再比较实际结果。

验证范围 #

以上示例使用 dmlc 0.3.16（可执行文件的 SHA-256 校验值为 c019a84c3208aee31cb5fa068232fa24d3258e9cdc83dfc2a91584a86a5ba091）和 DuckDB 1.5.5 运行。验证范围包括自定义 fn-macro、自定义 dt-macro、两者的组合、对源数据值和聚合结果的标量函数调用，以及缺失函数的诊断。此处未测试其他数据库引擎、架构限定名称、过程式或原生 UDF、聚合 UDF 和表函数。
