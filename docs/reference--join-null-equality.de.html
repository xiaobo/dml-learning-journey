Gleichheit von NULL bei Joins

DML führt unabhängig aggregierte Kennzahlen anhand ihres vollständigen Gruppierungsschlüssels zusammen. NULL-Werte an derselben Schlüsselposition gelten dabei als gleich. Ein Bericht kann daher eine gemeinsame nicht klassifizierte Gruppe für mehrere Quellen anzeigen.

Gleichheitsregeln nach Join-Zweck #

Zweck Typisches SQL Gleichheit in ON Verhalten bei Schlüsseln mit NULL
Schlüssel aus unabhängigen Kennzahlergebnissen zusammenführen. Dieses Verfahren heißt Komposition über die Vereinigungsmenge der Schlüssel. FULL OUTER JOIN oder eine Schlüsselmenge ohne Duplikate mit UNION und LEFT JOIN NULL-sichere Gleichheit Vollständige Schlüssel werden quellenübergreifend einander zugeordnet, wenn ihre Werte übereinstimmen und NULL jeweils an denselben Positionen steht.
Attribute hinzufügen und dabei die Zeile der führenden Seite beibehalten, auch bei der internen Attributzuordnung über nullpk LEFT JOIN NULL-sichere Gleichheit Bei übereinstimmenden strukturellen Schlüsseln lassen sich Attribute auch dann hinzufügen, wenn eine Schlüsselkomponente NULL ist.

Für NULL-sichere Gleichheit kann je nach Dialekt <=>, IS NOT DISTINCT FROM oder eine Gleichheitsprüfung mit einem expliziten Zweig verwendet werden, der prüft, ob beide Werte NULL sind. Bei einem expliziten SQL-Prädikat wie a.Region = b.Region gelten die üblichen Gleichheitsregeln der Datenbank. Joins auf Detailebene verwenden die Gleichheitsregeln ihrer eigenen Schlüssel.

Ausgabe bei der Zuordnung über Schlüssel mit NULL #

Angenommen, für die nicht klassifizierte Region beträgt der Gesamtumsatz 50 und die Summe der Rückerstattungen 8. Die Gruppierung nach Region liefert eine Zeile (NULL, 50, 8) mit beiden Kennzahlen. Diese Zeile steht für eine Berichtsgruppe. Die zugrunde liegenden Umsatz- und Rückerstattungsdatensätze behalten jeweils ihre eigene Identität. Die Gruppe wird auch dann quellenübergreifend zugeordnet, wenn beide Kennzahlwerte NULL sind.

Bei einem zusammengesetzten Schlüssel wie (Region, channel) wird (NULL, 'online') mit (NULL, 'online') zusammengeführt. (NULL, 'retail') bleibt eine eigene Gruppe. Periodenberechnungen verwenden dieselbe Regel für Gruppierungsschlüssel ohne Zeitbezug und behalten ihre Regeln für den Zeitabgleich bei.

Wenn der Bericht eine Gruppe mit eigener Bezeichnung erfordert, verwenden Sie einen expliziten Gruppierungsausdruck wie coalesce(Region, 'UNKNOWN'). Der Ausdruck ordnet auch alle tatsächlich vorhandenen Werte 'UNKNOWN' derselben Gruppe zu.

Grundgesamtheit, Ersatzwerte und Vervollständigung von Zeilen #

Ein Filter, der auf einer Kennzahl zur Erkennung vorhandener Gruppen basiert, kann den Bericht auf Gruppen aus einer ausgewählten Quelle beschränken. Für diese Kennzahl werden keine Ersatzwerte eingesetzt. Eine Geschäftskennzahl, die fehlende Werte zulässt, kann auch dann NULL sein, wenn ihre Gruppe in der Quelle vorhanden ist.

Beim Auffüllen fehlender Zeilen wird ein Ersatzwert für die Kennzahl eingesetzt. Die Vervollständigung ergänzt fehlende Zeilen für Entitäten oder Kalenderzeiträume. Keiner der beiden Vorgänge bestimmt, ob eine Gruppe zur Grundgesamtheit einer Quelle gehört.

Prüfergebnisse zu Compiler-Builds #

Diese Zusicherung gilt für Compiler-Builds, die die Änderung der Gruppierung vom 19. November 2026 enthalten. Der Build vom 16. Oktober 2026 verwendete im geprüften Beispiel für einen Join über mehrere Datenbestände den üblichen Gleichheitsoperator =. Wenn Sie einen Bericht prüfen, der mit einem älteren Build kompiliert wurde, untersuchen Sie das generierte Prädikat und vergleichen Sie die Ergebnisse anhand eines Beispiels mit NULL im Schlüssel. Auch bei einem später geprüften Beispiel generierte der Compiler einen gewöhnlichen Gleichheitsvergleich und die strikte Kompilierung war erfolgreich. Prüfen Sie das Ergebnis mit Ihrem Compiler und Ihren Daten.

Der Abschnitt Automatische Joins zwischen Datenbeständen in der Kernspezifikation definiert die Komposition. Modellprüfung listet die Prüfschritte für geänderte Abfragen auf.
