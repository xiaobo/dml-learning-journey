P21. 在指标公式中使用 AGG() #

错误：在 .dml 中使用 销售额: AGG({销售金额})。修正：销售额: SUM({销售金额})。在 .dml 中使用 SQL 聚合函数。

P22. 未使用查找的跨数据集引用 #

错误：跨数据集使用 利润: SUM({销售额.销售金额} - {成本.销售金额})。修正：使用通过 {DATASET}.column 或 pk(...) 查找的列宏。

P22b. 在另一个数据集的 sql: 中连接通过 table: 归属于某个数据集的物理表 #

错误：Policy 定义了 table: policy，另一个数据集却在 sql: 中使用 from policy 或 join policy。修正：用 from {Policy} 或 join {Policy} 引用数据集，而不是物理表。若要在不使用 SQL 连接的情况下引用属性，请使用 pk(...).{Policy}.Col。sql: 中的 {Policy} 用于替换表来源，并非列表达式。编译器会将它改写为数据集的查询名称。请参阅数据集定义（type: dataset）。

P23. 原子指标缺少 dataset: #

错误：销售额: type: measure, formula: SUM({销售金额})，未指定数据集。修正：销售额: type: measure, dataset: 交易明细, formula: SUM({销售金额})

P24. 指标名称过于具体 #

错误：sales_q1_2024_north、sales_john_doe。修正：将通用指标与查询筛选条件结合使用。

P25. 未记录边界情况 #

错误：指标说明中未写明“排除退货”或“包含零值”。修正：对于不易从定义看出的行为，始终添加 description:。记录数据集维度、每行的含义、适用范围标志以及容易引起误解的名称。请参阅编写模型元数据。

P27. 在不兼容的查询中使用有维度限制的指标 #

错误：在查询维度为 [dt_month] 的查询中选择 商品销售额（允许的维度为 [商品]）和 销售总额。修正：确保每个指标都允许使用该查询维度，且各指标定义行的粒度相互兼容，或者使用独立的查询。

P28. 在 GROUP BY 已足够时使用 +d #

错误：创建 sales_by_region: SUM({销售额: {+d: 地区}})。修正：定义 销售额: SUM({销售金额})，并使用查询 SELECT 地区, AGG(销售额) FROM MODEL GROUP BY 地区。

P28b. 连接缺行时的 NULL 传播 #

错误：利润: '{收入} - {成本}'。如果任意一侧在当前数据切片中缺行（FOJ 或稀疏的 dt），该侧的输入为 NULL，差值也会变为 NULL。

修正：缺行时填充默认值（缺行填充）：

  1. 将 isnull、ifnull 或 coalesce(公式, 字面量) 用作最外层函数，为稀疏输入启用填充：
收入: 'isnull(SUM({销售金额}), 0)' # or wrap the existing measure formula outermost
成本: 'isnull(SUM({成本金额}), 0)'
利润: '{收入} - {成本}' # use sites of revenue/costs → 0
  1. 如果结果粒度下缺少对应的行，而结果列本身必须为非 NULL，请直接对结果启用填充：
利润: 'isnull({收入} - {成本}, 0)'

以下做法不够，或无法启用填充：使用 isnull({a}, {b})、coalesce(a, b, 0)，单独使用 {m: pp}，或期待外层无关的复合指标自动套用 isnull。将已启用填充的依赖指标嵌入复合指标后，在稀疏 FOJ 中引用该依赖指标时，其填充表达式仍会展开。请参阅measures.md 填充默认值。

P28c. 跨数据集组合指标时的 NULL 分组键 #

现象。 报表中有一行的地区为 NULL，其中包含来自多个来源的指标。该行代表这些来源共有的报表分组。如果使用复合键，其他所有维度也必须匹配。

检查。 比较完整的分组键，并检查生成的谓词。包含 2026 年 11 月 19 日变更的构建版本使用 NULL 安全的等值比较来匹配分组。较旧的构建版本可能无法匹配含 NULL 的键。若只保留主来源中的分组，请使用未经填充、用于指示主来源中是否存在对应行的指标进行筛选。请参阅连接中的 NULL 等值比较。

P37. 列上的修饰符 #

错误：在公式中使用 {客户编号: {+d: 客户编号}}。修正：在要计算的指标上指定下钻，例如 {销售额: {+d: 客户编号}}。输入修饰符 +f 等其他修饰符也有适用于列的写法。这一限制并非适用于所有列修饰符。

P38. YAML 公式未加引号 #

错误：formula: SUMIF({销售额: {+d: dt_month}}, {dt_month} = {首次购买月份}) 的值包含 :、{ 或 -，但未加引号。修正：formula: 'SUMIF(...)'

P39. 在复合指标上指定 dataset: #

错误：引用其他指标的复合指标仍指定了 dataset:。修正：公式引用其他指标时，省略 dataset:。仅在原子指标中保留 dataset:。

P40. 无法重新定义指标或公式重复 #

错误：当 销售额 或 x 已是现有指标时，分别使用 SELECT AGG(销售额) AS 销售额 或 AGG(x) AS x。修正：使用 SELECT AGG(销售额)，省略别名，或指定一个与现有指标名称不同的别名（AS sales_value）。如果编译器提示“use existing measure "X"”，请使用 AGG(X)，无需重新写出公式。

P41. 在模型查询的 SQL 中使用 DML 的 {...} 语法 #

错误：SELECT {dt_month}, AGG({销售额}) FROM MODEL。花括号仅用于 .dml 公式。修正：SELECT dt_month, AGG(销售额) FROM MODEL。在查询中，仅在使用修饰符的写法中使用 AGG({销售额: pop})。

P42. .dml 公式中不带花括号的列名与 {col} 的区别 #

错误理解： 把 formula: calc_amt * 2 当成“漏写花括号”或“编译器漏检”。不带花括号的 calc_amt 会绑定到表中的物理列（原样传递给 SQL）。修正： 要引用计算列的定义，请用花括号括住列名，例如 formula: '{calc_amt} * 2'。引用物理列时直接写列名，例如 net: 销售金额 - 折扣金额。请参阅数据集定义（type: dataset）。

模型排错 #

先检查入口模型中的 dialect: 设置，以及 includes: 中的路径和名称。确认数据集的 dimension: 能唯一标识源行，并按声明顺序向 pk(...) 传入完整的键。先修复第一条明确报告的缺失引用或冲突，再重新运行 lint。
