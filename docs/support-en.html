Troubleshooting: first locate the failing step

On this page
  • Prepare reproducible material
  • Versions and known limits

Save the complete diagnostics first, then narrow down to one measure. A successful compile does not prove the source keys match the data; a passing validation does not replace checking business results.

Symptom Next step
Model not found Check the file name and the FROM name; query discovery rules
Compilation error Keep the exit code and JSON; error code reference
VALIDATION_ERROR Fix the keys or the data and retest; duplicate-key validation
Totals, shares, or historical values look wrong Check input rows, filters, and grouping; modifiers
Materialized result is stale Materialization lifecycle

Prepare reproducible material #

Save dmlc --version, the command, the exit code, the complete diagnostics, a minimal model/query, sanitized inputs, and the expected result. Remove passwords, tokens, real connection strings, and personal information. Give feedback through your existing product contact; this site does not list a public support channel yet, so do not submit private data to unrelated repositories.

Versions and known limits #

Observations of a specific build apply only to that recorded build and its fixtures. Historical issues are not a defect list for the current version. When you see a difference, reproduce it with the current compiler and keep the generated SQL. Start with the sales exercise for its validation status; mark other dialects or unexecuted scenarios as "not verified".
