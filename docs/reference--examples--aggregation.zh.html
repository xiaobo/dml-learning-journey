细粒度聚合示例

本页目录
  • 使用 +d 进行多级聚合
  • 先在细粒度上筛选，再用 +d 汇总

这些模式先在中间粒度上计算指标，再聚合或筛选所得值。各代码片段均注明了所需的额外模型依赖项。指标修饰符定义了修饰符参数的语法。

使用 +d 进行多级聚合 #

+d 支持两阶段聚合：先在中间粒度上定义指标，再汇总到查询粒度。编译器会生成 CTE（WITH ... AS (SELECT ... GROUP BY ...) SELECT ...）。

模式：限定维度的指标 → 汇总指标 → 查询

# Step 1: require customer_id during evaluation
客户销售额:
    type: measure
    dataset: 交易明细
    formula: SUM({销售金额})
    dimensions:
        - [客户编号, ...]  # customer required; additional query fields allowed

# Step 2: evaluate with dimension [customer_id], then roll up to the query dimension
客户销售总额:
    type: measure
    formula: SUM({客户销售额: {+d: 客户编号}})

-- Step 3: use any compatible query dimension ([品牌], [地区], 合计, etc.)
SELECT 品牌, AGG(客户销售总额) FROM MODEL GROUP BY 品牌

RFM 分析：结合使用 +d 和 fn 宏的完整示例：

# .dml: customer-grain measures for RFM
最近购买月份:
    type: measure
    formula: 'MAXIF({dt_month}, {销售额: {+d: dt_month}} > 0)'
    dimensions:
        - [客户编号]

购买月数:
    type: measure
    dataset: 交易明细
    formula: 'COUNT(DISTINCT CASE WHEN {销售金额} > 0 THEN {dt_month} ELSE NULL END)'
    dimensions:
        - [客户编号]

-- Model Query SQL: RFM with ranks
SELECT AGG(销售额) AS M, AGG(销售额, 'rank') AS M_rank,
       AGG(购买月数) AS F, AGG(购买月数, 'rank') AS F_rank,
       AGG(最近购买月份) AS R, AGG(最近购买月份, 'rank_asc') AS R_rank
FROM MODEL GROUP BY 客户编号

内联指标：通过 /** dml ... **/ 注释块直接在模型查询的 SQL 中定义临时指标，无需修改 .dml。完整语法和规则见内联指标（/** dml ... **/）。

/** dml
客户销售额中间值:
    type: measure
    dataset: 交易明细
    formula: SUM({销售金额})
    dimensions:
        - [客户编号, ...]

客户平均销售额中间值:
    type: measure
    formula: 'AVG({客户销售额中间值: {+d: 客户编号}})'
**/
SELECT 品牌, AGG(客户平均销售额中间值) AS 客户平均销售额
FROM MODEL GROUP BY 品牌

先在细粒度上筛选，再用 +d 汇总 #

SQL 中的常见做法是：在细粒度上聚合 → 用 WHERE 在该粒度上筛选 → 用 SUM 汇总到较粗的报表粒度。

WITH sales AS (
  SELECT product, region, SUM(amount) AS total, COUNT(*) AS cnt
  FROM fact GROUP BY product, region
)
SELECT product, SUM(total) AS grand_total
FROM sales
WHERE cnt > 3                -- filter fine-grain rows
GROUP BY product
HAVING SUM(total) > 500      -- report-level HAVING

推荐的 DML 写法：将细粒度的筛选条件放在汇总公式内部。查询中的 filters: 仅用于限定报表范围或指定 HAVING：

DATASET_SALES:
    type: dataset
    table: FACT
    columns:
        商品:
            abbr: product
        地区:
            abbr: region
    measures:
        合计: SUM(销售金额)
        销售笔数: COUNT(1)

总计:
    type: measure
    formula: |-
        SUMIF({合计: {+d: 地区}}, {销售笔数: {+d: 地区}} > 3)
    # No qualifying fine rows -> NULL. Use an explicit fill only if required.

report:
    type: query
    filters:
        "{总计} > 500":
    columns:
        dimension:
            - 商品
        总计:

理解这个示例：{销售笔数: {+d: 地区}} 和 {合计: {+d: 地区}} 都在相同的细粒度 (商品, 地区) 上计算。iif 或 SUMIF 决定该粒度下哪些行参与外层的 SUM 聚合。查询维度仍为 商品。

应避免的写法 原因
在 columns.dimension 中只指定 商品，并使用 filters: "销售笔数 > 3" 查询 销售笔数 脱离了其定义粒度。编译或合并时，条件可能被错误地改写为产品级的 HAVING COUNT(1) > 3。
filters: "{销售笔数: {+d: 地区}} > 3" 有时可以编译，但这种写法颠倒了理解查询的逻辑，把下钻到细粒度的操作藏在了报表筛选条件里。
SUM({合计: {+d: 地区, +f: '{销售笔数} > 3'}}) 该条件引用了聚合指标，而 +f 要求对输入行进行筛选。

如果希望按 SQL 的步骤逐步编写，可以采用以下备选方案：保留细粒度查询（dimension: [商品, 地区]、filters: "销售笔数 > 3"），再在展示层的 after: 中重新聚合。整理和维护模型时，优先采用上文的指标写法。

另请参阅指标设计和常见陷阱 P69。

+d 的限制：

  • 仅靠 +d 无法为同一个维度引入两个独立的别名。要构建完整的 N×N 共现矩阵，可以改用带 sql: 的数据集。按客户对已声明的数据源执行自连接，选取去重后的 (客户, brand_from, brand_to) 组合，将这组字段整体声明为键，再按两个品牌字段分组统计客户数。经检查，包含两个品牌的测试数据可通过编译和验证，并返回 A–A: 2、A–B: 1、B–A: 1、B–B: 1。这种写法要求显式定义表示品牌配对的关系，+d 不会自动完成这一转换。

当 +d 出现在查询的维度绑定（columns.dimension: - name: '{m: {+d: K}}'）中时，这是将指标用作维度，并非上述汇总模式。参见将指标用作维度。

共现分析（1×N 模式）：结合使用 +d、-d 和 +f，逐一统计同时购买目标品牌与各个其他品牌的客户数：

/** dml
目标品牌客户数:
    type: measure
    formula: 'MAXIF(1, {销售额: {+d: 客户编号, -d: 品牌, +f: {品牌: ''BrandA''}}} > 0)'
    dimensions:
        - [..., 客户编号]

当前品牌客户数:
    type: measure
    formula: 'MAXIF(1, {销售额: {+d: [品牌, 客户编号]}} > 0)'
    dimensions:
        - [品牌, 客户编号]

共同出现次数:
    type: measure
    formula: 'SUM({当前品牌客户数: {+d: [品牌, 客户编号]}} * {目标品牌客户数: {+d: 客户编号}})'
**/
SELECT 品牌, AGG(共同出现次数) AS 与品牌A重合的客户数
FROM MODEL GROUP BY 品牌 ORDER BY AGG(共同出现次数) DESC

-d: 品牌 从目标指标的计算维度中移除维度字段 品牌，只保留 [客户]。+f 将数据筛选到目标品牌，两个标志值的乘积用于统计同时购买两种品牌的客户。

指标的 dimensions: 始终是一个由数组组成的数组。每个内层列表定义一个允许的维度，外层列表包含这些备选维度：

当月活跃标记:
    type: measure
    formula: 'ISNULL(MAXIF(1, {当月数量: {+d: [商品编号, dt_month]}} > 0), 0)'
    dimensions:
      - [门店编号, dt_month, ...]

在允许的维度中，...（省略号）允许包含未列出的其他维度字段，但引用该指标时，计算维度仍必须包含所有列出的字段。
