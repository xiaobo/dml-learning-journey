本页介绍引用形式和内在函数。修饰符的行为见指标修饰符。查询语法和别名规则见Model Query SQL。示例中的函数采用表达式语法，生成的 SQL 取决于所选方言。

引用语法 #

在 .dml 公式中 #

引用类型 语法 示例
列 {column_name} SUM({amount})
指标 {measure_name} DIVIDE({sales}, {count})
其他数据集中的列 {DATASET}.column {products}.price
带修饰符的指标 {measure: modifier} {sales: yoy}
带嵌套修饰符的指标 {measure: {modifier: sub}} {sales: {+d: customer}}

在 Model Query SQL 中 #

引用类型 语法 示例
列（维度） 直接使用名称 SELECT product, dt_month
指标 AGG(measure_name) AGG(sales)
带修饰符的指标 AGG({measure: modifier}) AGG({sales: yoy})
以位置参数指定修饰符的指标 AGG(measure, 'modifier') AGG(sales, 'yoy')

基本规则：花括号 {...} 仅用于 .dml。在 Model Query SQL 中，维度直接使用名称，指标使用 AGG(...)。唯一的例外是修饰符写法 AGG({measure: modifier})。

使用 pk(...) 查找 #

查找支持单字段键、复合键和带生效日期的键。请提供目标的完整键，而不是使用该查找的查询的分组字段。此类属性查找不同于在数据集 SQL 中准备关系，也不同于组合独立聚合的指标。参见源关系、查找与指标组合。

在 .dml 公式中查找其他数据集的列：

# Single PK
formula: 'SUM({amount} * pk(customer_id).{customers}.tier_discount)'

# Composite PK
formula: 'SUM(pk(brand_id, tag_id).{DATASET_PRODUCTS}.state)'

按声明顺序为目标的每个维度字段提供一个表达式。对于 [brand_id, tag_id]，pk(1, tag_id) 的参数个数正确，并且有意将 brand_id 固定为 1。此查找是否正确，取决于预期使用的键以及该键在源数据中是否唯一。

复合键和带生效日期的键 #

目标的 dimension: 定义其完整的源键，而不是报表的分组方式。以下两种查找写法均按声明顺序使用目标字段：

# Target with a compound key:
dimension: [id, region]
# Column in the referring dataset:
label: 'pk({id}, {region}).{D}.label'

# Target with an object key and validity interval:
dimension: [id, 'range(valid_from, valid_to)']
# Column in the referring dataset:
label: 'pk({id}, {event_date}).{D}.label'

请保留 'range(valid_from, valid_to)' 的引号，使逗号留在同一个 YAML 列表项中。事件日期按 [valid_from, valid_to) 匹配，包含起始日期，排除结束日期。因此，2 月 1 日的事件匹配从 2 月 1 日开始的区间，而不匹配当天结束的区间。这与数据库中用于生成数组的 range() 函数不同。

只要整个复合键唯一，同一 ID 就可以出现在多个地区。同一 ID 的有效日期区间不得重叠。即使编译成功，目标记录重复或区间重叠仍可能使查询产生额外的行。--validate 验证所观察到的数据是否满足键约束，但不会修复数据，也不保证后续执行使用同一数据快照。

复合键和带生效日期的键练习提供了完整的模型、边界日期、特意构造的验证失败以及修正后的结果。练习演示的是有限且相邻的区间，不涉及无界区间或通用的多对多分摊规则。对于使用桥接表的分析或分摊分析，请单独定义完整键、权重和预期总计。仅凭查找参数个数错误，无法判断该分析能否表达。

函数 #

基本聚合函数 #

这些函数在 .dml 和 Model Query SQL 中均可使用。在 .dml 中，它们可以聚合原始列（SUM({amount})）或更细粒度的指标（SUM({sales: {+d: product}})）。在 Model Query SQL 中，它们只能聚合更细粒度的指标。例如，SUM(AGG({sales: {+d: product}})) 将各产品的销售额相加，得出销售总额。仅引用指标时，单独使用 AGG(measure)。

函数 语法 说明
SUM SUM({column}) 求和
COUNT COUNT({column}) 统计非空值的个数
COUNT(DISTINCT ...) COUNT(DISTINCT {column}) 去重计数
MAX MAX({column}) 最大值
MIN MIN({column}) 最小值
AVG AVG({column}) 平均值

DML 特有的函数 #

上下文列说明函数可以出现在有效指标表达式的哪些位置。Model Query SQL 仍要求通过 AGG(...) 聚合指标。这些函数不允许在 SELECT 中聚合原始列。

函数 语法 上下文 说明
AGG() AGG(measure) 仅限 Model Query SQL 在查询中引用指标（不是聚合函数）
DIVIDE() DIVIDE({num}, {den}) 两者均适用 安全除法（除数为零时返回 NULL）
DISTINCTCOUNT() DISTINCTCOUNT({column}) 两者均适用 统计不同值的个数
SUMIF SUMIF({val}, {condition}) 两者均适用 条件求和
COUNTIF COUNTIF({condition}) / COUNTIF({val}, {condition}) 两者均适用 满足条件的行／满足条件的非空值
AVGIF AVGIF({val}, {condition}) 两者均适用 条件平均值
MAXIF MAXIF({val}, {condition}) 两者均适用 条件最大值
MINIF MINIF({val}, {condition}) 两者均适用 条件最小值
DISTINCTCOUNTIF DISTINCTCOUNTIF({val}, {condition}) 两者均适用 条件去重计数

条件聚合示例：

# In .dml
completed_sales:
    type: measure
    formula: SUMIF({amount}, {status} = 'completed')

high_value_customers:
    type: measure
    formula: 'DISTINCTCOUNTIF({customer_id}, {sales: {+d: customer_id}} > 1000)'

-- In Model Query SQL (modifier form)
SELECT AGG(sales, '+f', region = 'North') FROM MODEL

条件函数和辅助函数 #

函数 语法 说明
IIF IIF(condition, true_val, false_val) 内联条件表达式
ISNULL / IFNULL / COALESCE ISNULL({expr}, default) 返回首个非空值
NULLIF NULLIF({a}, {b}) 当 a = b 时返回 NULL

辅助函数使用 SQL 表达式层。它们可以在公式中使用，但不属于 DML 的正式内在符号。DML 函数目录只将 DML 自身定义的函数列为此类符号，例如 AGG、DIVIDE 和 SUMIF。

如果指标公式的最外层是以字面量作为后备值的 NULL 合并操作，则该指标的各个引用位置会启用缺失行填充。

daily_sales:
    type: measure
    formula: SUM(ISNULL({sales: {+d: dt_date}}, 0))

日期函数（SQLite 方言） #

函数 语法 说明
date() date(current_date) 当前日期
date(current_date, 'start of month') — 本月第一天
date(current_date, 'start of month', '-1 month') — 上月第一天
date(current_date, 'start of year') — 本年第一天
date(current_date, '-N days') — N 天前

方言说明：请使用与目标方言匹配的日期函数。DML 支持 SQLite 风格的日期表达式语言，并将支持的写法转换为所选方言。请检查生成的 SQL。目标数据库不一定能直接接受原样的表达式文本。

Model Query SQL 中的修饰符语法 #

Model Query SQL 中的两种等价写法：

形式 语法 示例
位置参数写法 AGG(measure, 'mod1', 'mod2') AGG(sales, 'yoy')
花括号写法 AGG({measure: mod}) AGG({sales: yoy})

别名规则：正式规则表见Model Query 别名规则。AGG(sales) 会自动获得别名，AGG({sales: yoy}) 则必须使用 AS。

运行时变量 #

这些变量是求值上下文的占位符，而非调用方提供的查询参数。有关应用程序中的绑定，请参见JDBC 参数和查询类型。物理 SQL 层的绑定即使通过检查，也不会建立 Model Query 的语义绑定。

变量 上下文 含义
{dim_dt} 感知时间的表达式和修饰符 在当前求值上下文中解析出的标准时间字段
{measure} fn-macro 公式 调用该宏且由该宏包裹的指标
{dt_date}, {dt_week}, {dt_month}, {dt_quarter}, {dt_year} 标准时间字段引用 按名称指定的标准时间字段

时间上下文定义时间分辨率和时间段的约定。定义宏介绍如何声明宏和使用变量。

数据库定义的标量函数 #

标量函数调用可以保留在生成的 SQL 中，包括在原子指标内部调用函数，或将函数应用于指标的聚合结果。DML 负责管理指标上下文，目标数据库决定函数的实现及其是否可用。有关可运行的示例、求值阶段的差异和验证要求，请参阅经过验证的自定义修饰符和数据库函数。这一说明并不普遍适用于聚合 UDF 或返回表的 UDF。

完整的查找示例 #

pk() 按目标数据集中维度的顺序接收参数，并不限于单个键。复合键示例声明 [id, region]，并使用 validate-only 检查目标数据集中的键组合是否重复。范围示例使用 [id, 'range(valid_from, valid_to)']，并通过该示例的测试数据验证范围包含起点、排除终点，且重叠的范围会被拒绝。这些示例并不能证明支持任意多对多分配。
