这个独立示例对盈利能力进行建模，可作为交互式指南中销售模型的补充。观看概览动画，了解各项定义之间的关系。

商定定义 #

业务团队和数据团队共同确定净收入和销售成本包含哪些项目。模型为这些计算命名，据此推导出毛利润，再用毛利润除以收入，得到毛利率。DML 和 DMX 记录这些规则，编译器为数据库生成 SQL。三者可共同构成分析语义层的计算核心。

模型 #

逻辑数据集为 FACT_PROFITABILITY，其物理数据源为 TABLE_PROFITABILITY。源字段名与度量名称不同，以确保引用无歧义。源数据的完整键为 [id]。在物理表中，将 revenue_amount 和 cost_amount 定义为十进制数值类型。CSV 不包含 SQL 列类型信息，而整数除法会丢失利润率的小数部分。

dialect: mssql

FACT_PROFITABILITY:
  type: dataset
  table: TABLE_PROFITABILITY
  dimension: [id]
  columns:
    id:
    region:
    dt_month:
    revenue_amount:
    cost_amount:
  measures:
    net_revenue: SUM({revenue_amount})
    sales_cost: SUM({cost_amount})

gross_profit:
  type: measure
  formula: '{net_revenue} - {sales_cost}'

gross_margin:
  type: measure
  formula: 'DIVIDE({gross_profit}, {net_revenue})'

gross_margin_ytd:
  type: measure
  formula: 'DIVIDE({net_revenue: ytd} - {sales_cost: ytd}, {net_revenue: ytd})'

gross_margin_prior_ytd:
  type: measure
  formula: 'DIVIDE({net_revenue: {ytd, ya}} - {sales_cost: {ytd, ya}}, {net_revenue: {ytd, ya}})'

margin_change_pp:
  type: measure
  formula: '100 * ({gross_margin_ytd} - {gross_margin_prior_ytd})'

更改计算上下文 #

2025 年 2 月，North 的收入为 300，成本为 240，利润率为 20%。1 月的收入为 100，成本为 60，利润率为 40%。年初至今的累计收入为 400，累计成本为 300，因此累计利润率为 25%，而非各月利润率的简单平均值 30%。

将时间修饰符直接应用于已命名的比率：formula: '{gross_margin: ytd}'。这样会根据毛利率所依赖的收入和成本，重新计算整个累计期间的毛利率。各月的百分比既不相加，也不取平均值。上年同期的 YTD 使用 '{gross_margin: {ytd, ya}}'。

SELECT region, dt_month, AGG(gross_margin_ytd)
FROM MODEL
WHERE dt_month = '2025-02-01'
GROUP BY region, dt_month

比较同期数据 #

2024 年 1 至 2 月，North 的收入为 200，成本为 160，累计利润率为 20%。当前累计利润率为 25%，比上年同期高 5 个百分点。相对增长率为 25%。它采用不同的计算方式，并非界面显示的差值。

SELECT region, dt_month, AGG(gross_margin_ytd), AGG(gross_margin_prior_ytd), AGG(margin_change_pp)
FROM MODEL
WHERE dt_month = '2025-02-01'
GROUP BY region, dt_month

查看验证记录 #

编译器记录包含可执行文件的标识、查询原文、进程退出结果、状态、诊断信息以及生成的 SQL。检查的三个查询均通过严格编译。检查确认，累计分支先分别汇总收入和成本，再进行除法。上年同期分支将累计期间移至上一年的对应期间。

这些观察结果适用于本示例和所用的编译器构建版本。另行在 DuckDB 中对这些简短公式进行执行检查时，公式通过了严格编译和源键验证。独立的 SQL 验证确认，截至 2 月的 YTD 利润率，North 为 25%，South 为 33⅓%，两者上年同期的 YTD 利润率均为 20%。这些结果不能证明在 SQL Server 上执行时会得到一致的结果。浏览器根据虚构的示例数据行独立进行计算，不执行 DML。作为分母的收入为零时，结果为 NULL。前期数据缺失时保留缺失状态，不填入人为设定的零值。
