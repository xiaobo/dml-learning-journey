两种查询编写方式 #

语法 格式 适用场景
Model Query SQL .sql 文件或内联字符串 熟悉 SQL 的用户、CLI、仪表板
DML 格式 .dml 文件的 YAML 内容中的 type: query 以 YAML 为原生格式的环境、dmlc --to-dml 的输出

查询类型 #

聚合查询 #

使用 FROM …，并通过 AGG() 引用至少一个指标。

FROM 后的名称是去掉扩展名 .dml 的模型文件名，不区分大小写。大多数教程使用惯用的对应关系 FROM MODEL ↔ model.dml。

模型文件 SQL 中的写法
model.dml FROM MODEL
acme.dml FROM acme
渠道表现模型.dml FROM 渠道表现模型

对于查询、编译和仅验证，--model= 对该名称的解析有以下影响。

传入的值 行为
--model=some/dir dmlc 会在该目录中查找 <FROM>.dml（FROM MODEL → dir/model.dml，FROM acme → dir/acme.dml）。
--model=acme.dml 该文件即为模型。SQL 中必须写 FROM acme，不能写 FROM MODEL。
省略 在 SQL 文件所在的目录或模型搜索路径中按相同规则查找。

FROM 子句中不要带扩展名 .dml。如果 queries/ 采用嵌套目录结构，请将 .dml 文件与 SQL 文件放在同一目录，或通过 --model= 指定模型文件所在的目录。

setup（dmlc -s）接受.dml 文件，不接受目录。

-- Query SQL using model.dml
SELECT product, dt_month, AGG(sales)
FROM MODEL
WHERE dt_month = date(current_date, 'start of month', '-1 month')
GROUP BY product, dt_month

-- Query SQL using acme.dml (dmlc --model=acme.dml …  or  --model=<dir containing acme.dml>)
SELECT product, dt_month, AGG(sales)
FROM acme
GROUP BY product, dt_month

在 IDE 中，如果固定了模型，导航功能仍可能将 FROM MODEL 解析为指向该模型。在 CLI 中，请确保 FROM 后的名称与所用文件对应，或者与在 --model=<dir> 下找到的 .dml 文件对应。

明细查询 #

使用 FROM <model>.<dataset> 获取数据集的行。查询会拒绝直接使用 GROUP BY。要获取分组指标，请定义可复用的指标并查询模型。在模型聚合查询中使用 AGG()。

-- Query SQL using model.dml
SELECT dt_date, transaction_id, raw_amount
FROM MODEL.transactions
WHERE dt_month = date(current_date, 'start of month')

-- Query SQL using acme.dml
SELECT ClaimNumber, ClaimOpenDate
FROM acme.Claim

明细查询返回数据集的行，也接受经检查的非分组聚合表达式和窗口表达式。查询会拒绝直接使用 GROUP BY。聚合查询按请求的分组粒度返回可复用的模型指标。

模型查询 SQL 规范 #

基本限制 #

禁止用法 原因 替代方法
子查询 模型查询 SQL 不支持 用指标对计算建模，或在数据集的 sql: 中准备所需的关系。
UNION / UNION ALL 模型查询 SQL 不支持 在数据集的 sql: 或数据库视图中准备通过 UNION 合并得到的关系。
JOIN 模型查询 SQL 不支持 使用 pk(...) 对属性查找建模，或在数据集的 sql: 中准备所需的关系。
直接在列名外使用 {...} 花括号仅用于 .dml，在此处使用时会被移除且不提示。 直接使用名称，例如 SELECT product, AGG(sales)。

这些面向使用方查询的限制并不意味着整个 DML 都禁止使用 SQL。可在数据集的 sql: 中使用受支持的连接、UNION 和子查询来准备关系。请用 {DATASET} 引用已声明的数据集，并遵循物理表的归属关系。该关系必须显式定义正确的键。数据集参考介绍如何验证纳入检查范围的派生关系。写入数据集 SQL 的过滤条件仍决定哪些行属于该数据集。将 SQL 移到模型中，并不会自动让每条规则都能随使用方的上下文而变化。请参阅数据集定义。

模型查询 SQL 允许使用窗口函数（OVER()）。编译器会将其原样写入生成的 SQL。对于常见用法，优先使用 system_macros.dml 中的函数宏（rank、rank_asc、pot、grand）。请参阅函数修饰符。有关 OVER 在 .dml 模型中的写法（窗口函数的放置位置），请参阅窗口函数的放置位置。

SELECT 规则 #

  • 聚合查询中，每个指标都使用 AGG(measure)。维度直接使用名称。
  • 明细查询中，所有列都直接使用列名。列出不重复的值时，添加 DISTINCT。
-- Aggregation
SELECT product, dt_month, AGG(sales), AGG({sales: yoy}) AS sales_yoy FROM MODEL GROUP BY product, dt_month

-- Detail
SELECT DISTINCT product FROM MODEL.transactions

别名规则 #

模式 是否需要别名？
AGG(sales) 不需要。系统会自动使用 sales 作为别名。
AGG(sales) AS sales 允许，但属于冗余写法（原样传递）。
AGG({sales: yoy}) 需要，请使用 AS sales_yoy。
AGG(sales, 'pop') AS sales 错误。这会产生循环引用，请使用 AS sales_mom。
AGG({sales: yoy}) AS sales 错误。这会产生循环引用，请使用 AS sales_yoy。

选择列表中前面定义的别名指向SQL 结果列，不指向指标。如果后续表达式使用该名称，例如在 AGG(sales) AS current_value 之后使用 AGG(current_value)，该名称就指向前面定义的结果列。名称解析不会回退到不相关的同名 DML 指标。

如果为带修饰符的指标引用指定与该指标同名的别名，例如 AGG(sales, 'pop') AS sales，编译器会将该别名视为对指标的重新定义，从而产生循环引用。请使用不同的别名，例如 AS sales_mom。没有修饰符时，AGG(sales) AS sales 是允许的冗余写法，值会原样传递。

AGG 的第一个参数指定指标名称。使用 AGG(sales) 获取指标的常规值，或使用 AGG({sales: yoy}) 修饰此次引用。在模型查询 SQL 的其他位置，直接使用列名。

WHERE 规则 #

  • 直接使用列名，例如 WHERE customer = 'John Doe'。
  • 语法不限制谓词的顺序。
  • 时间筛选条件使用期间首日的日期，例如 dt_month = '2024-01-01'。
  • 筛选单个期间时，优先使用 =，而非 BETWEEN。
  • 除非明确要求，否则不要添加冗余的 NULL 筛选条件。

GROUP BY 规则 #

  • SELECT 中每个未聚合的字段都必须出现在 GROUP BY 中。
  • 如果输出顺序很重要，请让 GROUP BY 中的字段顺序与 SELECT 一致。经检查的编译器接受不同的顺序，并可能重新排列可见列。请检查 artifacts.sql 和 effectiveOutputOrder。
  • 时间修饰符需要已解析的时间上下文。用于分组的时间字段或时间筛选条件都可以提供该上下文。对于多期间报表，优先显式按时间分组。筛选单个期间的条件可以提供隐藏的时间上下文。
-- Correct: time modifier + matching time field in GROUP BY
SELECT dt_month, AGG(sales), AGG({sales: yoy}) AS sales_yoy
FROM MODEL
GROUP BY dt_month

-- Wrong: yoy with neither a grouped time field nor a time filter
SELECT product, AGG(sales), AGG({sales: yoy}) FROM MODEL GROUP BY product

ORDER BY / LIMIT #

  • 始终指定 ASC/DESC
  • 仅在查询语义需要时添加（前 N 项、极值）
  • 不要仅因为排序有些好处就添加排序。

指标引用规则 #

  • 在查询中使用 AGG(measure)，始终用 AGG() 包裹指标引用。
  • 带修饰符的写法：AGG({measure: modifier}) 或 AGG(measure, 'modifier')
  • 在 Model Query SQL 中，切勿用 {...} 包裹裸列名，AGG 内带修饰符的写法除外。裸列名外的花括号会被静默移除，只留下列名。请直接使用列名。
  • 如果编译器提示 use existing measure "X"，请使用 AGG(X)，不要另写公式来表达同一计算。

时间处理 #

字段命名：dt_date、dt_week、dt_month、dt_quarter、dt_year，均以相应周期的第一天表示。

系统派生：如果模型显式声明了 dt_date 等较细粒度的标准时间字段，该数据集会自动提供 dt_month 等受支持的较粗粒度字段。请直接使用派生字段名。不要仅为满足查询或筛选条件，或消除编辑器诊断而添加重复的物理列。对派生字段名执行转到定义操作时，会跳转到显式声明的源时间列。

筛选：WHERE dt_month = '2024-01-01'（使用周期的第一天，筛选单个周期时用 =，不用 BETWEEN）。

日期函数参考介绍了 SQLite 风格的表达式写法。编译器会将受支持的写法转换为所选方言。

对于同时请求 dt_year 和 dt_month 的受检查询，由于生成的输出中缺少 dt_year，编译器会拒绝该查询。不要将此组合视为可成功生成双字段报表的写法。如果年份仅用于显示标签，请按所需的月粒度查询，再根据月键生成标签，并单独验证结果行所处的粒度。此结果不能说明所有包含多个时间字段的查询都不受支持。

HAVING #

-- Customers with outstanding balance
SELECT customer, AGG(outstanding)
FROM MODEL
GROUP BY customer
HAVING AGG(outstanding) > 0

-- Products selling less than last month
SELECT product, AGG(sales) as this_month, AGG(sales, 'pp') as last_month
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY product
HAVING AGG(sales) < AGG(sales, 'pp')

将指标用作维度时的注意事项： 针对分类标签和/或同一标签粒度下其他指标的谓词，属于标签生成后应用的筛选条件。Model Query 文本中可能使用 HAVING，但语义上，筛选必须在标签生成后进行。编译生成的 SQL 通常在标签生成后的 CTE 上以 WHERE 应用此筛选条件。不要因为文档示例使用了 HAVING，就认为可以在分类之前筛选。参见分类标签筛选条件。

快速参考 #

模式 SQL
总计 SELECT AGG(sales) FROM MODEL
按维度汇总 SELECT product, AGG(sales) FROM MODEL GROUP BY product
带筛选条件 SELECT AGG(sales) FROM MODEL WHERE region = 'North'
前 N 项 SELECT product, AGG(sales) FROM MODEL GROUP BY product ORDER BY AGG(sales) DESC LIMIT 10
增长率 SELECT dt_month, AGG(sales, 'yoy') AS sales_yoy FROM MODEL GROUP BY dt_month
周期对比 SELECT dt_month, AGG(sales), AGG(sales, 'pp') AS sales_pp FROM MODEL GROUP BY dt_month
占总计的比例 SELECT product, AGG({sales: pot}) AS sales_share FROM MODEL GROUP BY product
排名 SELECT product, AGG(sales, 'rank') AS sales_rank FROM MODEL GROUP BY product
多级聚合 SELECT brand, AGG(total_customer_sales) FROM MODEL GROUP BY brand（需要在 .dml 或内联 /** dml ... **/ 中定义 +d 指标）
内联指标 /** dml temp_m: ... **/ SELECT AGG(temp_m) FROM MODEL
带筛选条件的指标 SELECT AGG(sales, '+f', region = 'North') FROM MODEL

在已检查的构建版本中，时间比较语法可能对基于键并集的联接产生严格的诊断结果。这些示例展示了查询写法。执行前请阅读诊断信息并检查生成的联接。

聚合速查表 #

Model Query SQL（FROM MODEL）要求所有聚合都通过指标进行。这些指标定义在 model.dml 或内联 /** dml ... **/ 块中（内联指标）。直接对原始列聚合会被拒绝。

目标 错误写法（会失败） 正确写法
总行数 COUNT(*) 先在 model.dml 或内联块中定义 笔数: COUNT({ID})，再使用 AGG(笔数)
原始列的总和 SUM(出厂价金额) 先在 model.dml 或内联块中定义 销售额: SUM({出厂价金额})，再使用 AGG(销售额)
原始列的平均值 AVG(销售数量) 先在 model.dml 或内联块中定义 均价: DIVIDE(SUM({出厂价金额}), NULLIF(SUM({销售数量}),0))，再使用 AGG(均价)
维度的标量 MIN/MAX SELECT MIN(dt_month) FROM MODEL 使用明细数据集：SELECT MIN(dt_month) FROM MODEL.<dataset>
按行数筛选分组 HAVING COUNT(*) > 100 先在 model.dml 或内联块中定义 行数: COUNT({ID})，再使用 HAVING AGG(行数) > 100

唯一的例外是在明细数据集（FROM MODEL.<dataset>）上进行标量聚合以查看元数据。此例外不适用于业务指标仪表板。

内联指标（/** dml ... **/） #

可以直接在 Model Query SQL 中定义临时指标，无需编辑 .dml 文件。编译器会加载 FROM 指定的 .dml 文件（FROM MODEL → model.dml；FROM acme → acme.dml），合并内联定义，然后编译查询。

/** dml
temp_sales:
    type: measure
    dataset: transactions
    formula: SUM({amount})
**/
SELECT product, AGG(temp_sales) FROM MODEL GROUP BY product

相关人员就探索性计算的业务含义达成共识后，请将同一公式以固定名称移入 .dml 模型。使用者可以继续按名称引用该指标，无需重复编写公式。无论采用内联定义还是在模型中定义，由多个分项计算的利润率都可以写为 DIVIDE({net_revenue} - {sales_cost}, {net_revenue})。对该指标应用 ytd 时，会在累计范围内重新计算各分项。此计算不会对显示的月度比率求平均值。

适用场景：

  • 无需修改 .dml 即可进行临时聚合（满足使用指标的要求）
  • 使用 +d 和 dimensions 进行多级聚合，并内联定义中间指标。
  • RFM 分析：内联定义客户粒度的指标，并使用 rank 函数宏查询。

规则：

  • 必须使用多行 YAML 格式（每行一个属性）
  • 内联指标可以引用 .dml 中已有的指标和数据集
  • 内联指标可以引用同一块中先前定义的其他内联指标
  • 语法与 .dml 中的指标定义相同（type、formula、dataset、dimensions）

查询筛选与指标语义 #

写入 Model Query SQL 的 WHERE 子句 写入 .dml 的指标定义
与查询结果行处于同一粒度的渠道、区域和数据质量标记 队列基准点、实体纳入条件
按查询结果行的粒度定义的时间窗口（dt_period、dt_month） 按客户粒度定义的跨周期标记

JDBC 参数与查询类型 #

经检查的 JDBC 发行版可在物理 SQL 和 Model Query 中绑定位置参数 ?。在任务测试用例中，将 2 分别绑定到筛选条件和指标表达式时，两种查询均分别返回 20 和 60。任务示例项目包含复现步骤。

物化参数与内部字面量参数化是两种独立的机制。对于应用程序输入，请在调用方绑定参数。不要将不受信任的值拼接到 SQL 中。

时间筛选条件也会限定同一查询中的其他指标 #

查询级别的月份筛选条件可以为 YTD 指标提供时间基准，同时也会限定同一查询中普通指标的数据范围。在单个 KPI 的示例中，2 月的 YTD 利润率使用 1 月和 2 月的数据，而普通收入只使用 2 月的数据。缺少时间基准的查询会失败。按日历期间分组的查询可能返回有累计值但没有当期收入的月份。哪些行会出现在结果中，以及哪些数据会用于计算指标，是两个独立的问题。请勿隐式选用当天日期或事实数据中的最新日期作为时间基准。

Model Query SQL 速查 #

FROM MODEL 绑定 model.dml。用 AGG(sales) 引用指标，用 GROUP BY region 指定每个地区输出一行。用 WHERE 限定查询范围，用 HAVING AGG(sales) > 0 筛选聚合后的组。用 AS 指定输出列名。
