将可复用的定义放在模型中，将显示方式交由查询层或报表层决定。

P1. 在 DML 中加入显示逻辑 #

错误：在指标公式中使用 FORMAT(...)、CONCAT(...)、CAST(... AS VARCHAR)。修正：从 .dml 中移除格式设置，在仪表板或渲染层处理。

P2. 在 DML 中加入仅特定查询使用的派生列 #

错误：为仅在某个特定查询中有意义的计算创建指标。修正：将查询专用表达式写在 Model Query 的 SQL 中，不要写在 .dml 中。

P5. 未验证编译生成的 SQL 与基准 SQL 的结果是否一致 #

错误：仅凭编译成功就认定 -c 的输出正确。修正：分别执行原始 SQL 和编译生成的 SQL，比较结果集。

P6. 为特定筛选条件或查询维度组合创建专用指标 #

错误：分别创建 sales_north、sales_south、sales_east，或在 WHERE region = 'North' 已足够时仍创建 sales_north。修正：定义一个通用指标 sales，并在查询中使用 WHERE region = 'North'。

P7. 重复定义聚合公式 #

错误：同时定义 revenue: SUM({amount}) 和 total_revenue: SUM({amount})。修正：只定义一个原子指标，所有需要该计算的地方都引用它。

类别：Model Query 的 SQL #

可转换为草稿的 SQL #

在 2026 年 11 月的试验中，--to-dml 为以下用法生成了草稿：标准的 CAST(... AS type)、带有 CASE 的 GROUP BY、在 CTE 中使用的 ROW_NUMBER()，以及 LIMIT/OFFSET、EXTRACT、DATE_TRUNC、ILIKE、GENERATE_SERIES、NULLS LAST 和 EXCEPT。生成草稿后，仍需编译并比较结果。

试验中转换失败的输入 转换前的改写方法
sale_date::date AS d, DATE '2025-01-01' 使用 CAST(sale_date AS date) AS d 或 CAST('2025-01-01' AS date)。
SUM(amount) FILTER (WHERE paid) 使用 SUM(CASE WHEN paid THEN amount END)。
QUALIFY ROW_NUMBER() ... = 1 或 DISTINCT ON 在 CTE 中使用相同的分区和排序规则计算 ROW_NUMBER()。在外层查询中按 rn = 1 筛选。
$$hello$$ 用单引号括起字符串，并将字符串内部的每个单引号写成两个连续的单引号。
INTERVAL '1 day'、LATERAL、STRING_AGG(... ORDER BY ...) 或 JSON 的 ->> 将表达式规范化为目标解析器和方言支持的形式，或从源视图中将其作为列投影出来。转换前，确认行的排序、NULL 的处理方式以及结果包含哪些行。

转换后的操作

  1. 如果草稿缺少 dialect: 条目，请按目标数据库补充该条目。
  2. 确保不含扩展名的文件名与文件内的查询名称一致。如果两个定义使用了同一个指标名称，请只保留一个定义，或重命名仅在该查询中使用的计算并更新对它的引用。
  3. 在查询中设置报表期间的起止范围。确保指标仍可使用 pp、pop 或 ytd 所需的历史源数据。

对修改后的草稿运行静态检查，并在严格模式下编译，然后在相同数据上比较其结果与原始 SQL 的结果。
