如果编译失败、出现严格模式警告，或生成的 SQL 与查询意图不符，请按此流程排查。如果不确定实际行为，请使用所选的 dmlc.exe 进行确认。

调试流程（Model Query SQL） #

如果编译报告 COMPILE_ERROR，或消息中提到 UNION、JOIN、subquery、aggregation is not possible、ref {...} not defined、measure cannot be redefined 或 use existing measure，请使用此流程。

  1. 阅读完整的错误信息，包括消息载荷中生成的 -- dialect: … SQL。
  2. 确定查询类型：明细查询（存在性检查、列表、单条记录）或聚合查询。聚合使用 FROM MODEL + AGG()。如果模型文件名为 <name>.dml，则使用 FROM <name> 作为查询来源。
  3. 选择合适的 FROM 子句。聚合查询使用 FROM MODEL，文件名为 <name>.dml 时使用 FROM <name>。明细查询使用 FROM MODEL.<dataset> 或 FROM <name>.<dataset>，不使用 AGG 或 GROUP BY。名称应与 .dml 文件对应（model.dml ↔ FROM MODEL）。
  4. 移除不受支持的 SQL。不得使用子查询、UNION 或 JOIN。需要可移植的窗口操作时，使用 system_macros.dml 中的 fn 宏（rank、pot、grand）。多级聚合使用 +d 指标，复杂逻辑使用 .dml 定义（参见指标设计和修饰符叠加）。手写 OVER 时，有关数据集中窗口操作的放置位置，请参见窗口操作的放置位置。如果没有 fn 宏支持所需的写法，可以在 Model Query 中直接编写 OVER()。
  5. 区分指标和列。在查询中使用 AGG(measure)，在 .dml 文件中使用 {column} 或 '{measure: modifier}'。在 Model Query SQL 中，除 AGG({measure: modifier}) 外，不要对直接引用的列使用 {...}。
  6. 逐步调试。先验证 SELECT AGG(one_measure) FROM MODEL，再添加 GROUP BY 和筛选条件。使用 dmlc --validate <query.sql> --model=<model> --connection=<id> --json 进行验证。

阅读编译错误 #

结合生成的 SQL 阅读编译器消息。如果原因不明，请先将查询简化为一个指标，再逐个添加列和筛选条件。

问题预防检查清单 #

提交任何 DML 或 Model Query SQL 前，请检查以下各项：

  1. 指标使用业务名称，不使用技术名称。
  2. .dml 文件中的指标公式不含 AGG()。
  3. 直接使用的 AGG(measure) 没有多余的别名。
  4. 时间修饰符的时间上下文已确定，并满足宏的前置条件。
  5. 时间筛选条件采用相应时间段首日的日期格式。
  6. 为便于阅读，可以将时间筛选条件放在最后。语法不要求谓词按特定顺序排列。
  7. 不使用子查询、JOIN 或 UNION。
  8. 将易于阅读的 Model Query SQL 保存到 .sql 文件中。
  9. 查询类型（明细或聚合）符合查询意图。
  10. 在预定的数据库连接上，--validate 验证通过。
  11. 不要用 GROUP BY 直接对 MODEL.DATASET_* 聚合。请使用 FROM MODEL + AGG()，或导出明细数据。
  12. 对于涉及稀疏数据或 FOJ 的复合指标，请为引用的输入启用默认值填充，将 isnull、ifnull 或 coalesce(公式, 字面量) 放在最外层（P28b）。嵌入已启用填充的依赖项时，填充逻辑仍会展开。
  13. 将指标用作维度时，每个从指标派生的维度都必须有完整、显式的实体键（优先使用 +d）。如果有多个标签，各标签的键彼此独立且相同。每个输出指标都必须能从 Q ∪ K 所定义的粒度正确向上汇总。标签筛选条件在标签生成后应用（P66–P68）。
  14. 如果要先在细粒度 CTE 中应用 WHERE，再在外层执行 SUM，请使用 SUMIF 或 SUM(iif)，并指定匹配的 {+d: …}。不要在粗粒度查询中直接按指标筛选（P69）。
  15. 窗口操作的放置位置：将明细级 OVER 放在 columns: 下，然后执行原子聚合。GROUP-BY 之后，将窗口操作放在复合指标、{-d:} 或 {-df:} 中。切勿在原子指标上使用 OVER（P70–P71）。
  16. 如果两个定义粒度的字段是同一物理列的别名，请检查生成的每个汇总 ON 子句是否使用了正确的键（P72）。需要显式键时，可改用 pk() 将数据导入已声明维度的 sql: 数据集（P77）。
  17. 跨数据集的 -df 复合汇总采用 FULL OUTER。使用 '{primary_measure} is not null': 排除仅存在于对侧的行（P73）。对侧的临时结果可能包含由 max() 填充的键，因此“额外的行”可能看起来像与自身匹配的有效行对。
  18. 切勿对同一对象编写 {+d:x,-d:x} 或 {+d:x,-df:x}。遇到这种写法应明确报错，并显式改写表达式（P79）。
  19. -f 不会移除限定查询总体的筛选条件。受阻且不涉及粒度字段的筛选条件需要使用 EXISTS（P80）。
  20. 跨粒度替换时间 dimension: 时，需要通过日历建立映射，并将值广播到目标行（P81）。
  21. 单独使用 {m:{+d:x}} 时，结果仅处于细粒度。要汇总回原粒度，必须在外层使用 SUM、AVG 等聚合函数，MAD 标签绑定除外。
