Beispiele für fortgeschrittene Kennzahlen

Inhalt dieser Seite
  • Gewichtete Distribution (Multiplikation auf mehreren Granularitätsebenen)
  • Produktlebenszyklus verfolgen
  • RFM-Segmentierung mit percent_rank
  • Produktrangliste anhand der kumulierten Verteilung

Diese Codeausschnitte veranschaulichen Verteilung, Lebenszyklus, Segmentierung und kumulative Rangbildung. Jedes Muster setzt die jeweils genannten Quellkennzahlen und Dimensionen voraus. Die Ausschnitte dienen nicht als feste Prüffälle für Abnahmetests.

Gewichtete Distribution (Multiplikation auf mehreren Granularitätsebenen) #

Die gewichtete Distribution misst den nach Bedeutung der Verkaufsstellen gewichteten Umsatzanteil einer Marke. Dazu müssen Kennzahlen auf unterschiedlichen Granularitätsebenen berechnet und miteinander multipliziert werden. Anschließend wird das Ergebnis auf einer höheren Ebene aggregiert.

# Store-level sales (restricted to store + category grain)
store_cat_sales:
  type: measure
  formula: 'IIF({sales} > 0, {sales}, 0)'
  dimensions:
    - [dim_dt, store_id, category]

# Category-level sales (drop store)
cat_sales:
  type: measure
  formula: 'SUM({store_cat_sales: {+d: store_id}})'
  dimensions:
    - [dim_dt, category]

# Store weight = store sales / category sales (store + category grain)
store_weight:
  type: measure
  formula: 'DIVIDE({store_cat_sales}, {cat_sales: {-d: store_id}})'
  dimensions:
    - [dim_dt, store_id, category]

# Brand distribution flag (store + category + brand grain)
brand_dist_flag:
  type: measure
  formula: 'IIF({sales} > 0, 1, 0)'
  dimensions:
    - [dim_dt, store_id, category, brand]

# Weighted distribution = SUM(store_weight * brand_flag) at brand grain
weighted_distribution:
  type: measure
  formula: |-
    SUM({store_weight: {dimension: [dim_dt, store_id, category]}}
        * {brand_dist_flag: {dimension: [dim_dt, store_id, category, brand]}})
  dimensions:
    - [dim_dt, category, brand]

Zentrale Technik: Der Modifikator dimension: erzwingt, dass jede Teilkennzahl innerhalb von SUM() auf der jeweils erforderlichen Granularitätsebene berechnet wird. Der Compiler erzeugt für jede Ebene CTEs und verknüpft sie per Join.

Produktlebenszyklus verfolgen #

Bestimmen Sie das Produktalter seit dem ersten Verkauf, ordnen Sie Produkte einer Lebenszyklusphase zu und berechnen Sie gleitende Durchschnitte, die das kürzere Verkaufsalter neuer Produkte berücksichtigen.

# First sale date per product (restricted to product grain)
first_sale_raw:
  type: measure
  formula: 'MINIF({dt_date}, {sales: {+d: dt_date}} > 0)'

# First sale date, looking back up to 6 years
first_sale:
  type: measure
  formula: '{first_sale_raw: p6y}'
  dimensions:
    - [dt_week, product]

# Weeks since launch
weeks_since_launch:
  type: measure
  formula: 'datediff(week, {first_sale}, {Dim Calendar}.dt_week)'
  dimensions:
    - [dt_week, product]

# Flag: product has 2+ years of sales data
has_2yr_data:
  type: measure
  formula: 'IIF(MAX({weeks_since_launch: {+d: dt_week}}) > 104, 1, 0)'
  dimensions:
    - [product]

# Total sales in first 2 years
first_2yr_sales:
  type: measure
  formula: |-
    SUMIF({sales: {+d: dt_week}},
          {weeks_since_launch: {+d: dt_week}} >= 0
          AND {weeks_since_launch: {+d: dt_week}} < 104)
  dimensions:
    - [product]

# Rolling 4-week average, adjusted for product age
weekly_avg_4w:
  type: measure
  formula: |-
    DIVIDE({sales: p4w},
           IIF({weeks_since_launch: {dimension: [product, dt_week]}} >= 3,
               4,
               {weeks_since_launch: {dimension: [product, dt_week]}} + 1))

Zentrale Techniken:

  • MINIF mit {+d: dt_date} ermittelt den ersten Verkauf auf Tagesebene. Die Berechnung ist auf [dt_week, product] beschränkt.
  • Das benutzerdefinierte dt-macro p6y begrenzt den Rückblickzeitraum (siehe Mehrstufige Aggregation mit +d, Abschnitt „Benutzerdefinierte Makrodefinitionen“).
  • datediff verwendet {Dim Calendar}.dt_week als Bezugswert, um das Produktalter anhand des Kalenderdatensatzes zu berechnen.
  • SUMIF mit {+d: dt_week} berücksichtigt nur die Wochen innerhalb der ersten 104 Wochen (2 Jahre).
  • Der Nenner des gleitenden Durchschnitts wird für Produkte angepasst, deren erster Verkauf weniger als 4 Wochen zurückliegt.

RFM-Segmentierung mit percent_rank #

Vollständige RFM-Segmentierung nach Zeit seit dem letzten Kauf, Kaufhäufigkeit und Kaufbetrag. Die Kennzahlenformeln verwenden percent_rank(), die Bewertung erfolgt mit CASE.

# Monetary: MAT sales (moving annual total)
monetary:
  type: measure
  formula: '{sales: mat}'
  dimensions:
    - [dim_dt, customer_id]

# Recency: last purchase date
recency:
  type: measure
  formula: 'MAXIF({dt_date}, {monetary: {+d: dt_date}} > 0)'
  dimensions:
    - [dim_dt, customer_id]

# Frequency: number of active sales days
frequency:
  type: measure
  formula: 'DISTINCTCOUNTIF({dt_date}, {monetary: {+d: dt_date}} > 0)'
  dimensions:
    - [dim_dt, customer_id]

# Percentile ranks
recency_pct:
  type: measure
  formula: 'percent_rank() over (order by {recency} desc)'
  dimensions:
    - [dim_dt, customer_id]

frequency_pct:
  type: measure
  formula: 'percent_rank() over (order by {frequency} asc)'
  dimensions:
    - [dim_dt, customer_id]

monetary_pct:
  type: measure
  formula: 'percent_rank() over (order by {monetary} asc)'
  dimensions:
    - [dim_dt, customer_id]

# Scores (1-5 scale)
recency_score:
  type: measure
  formula: |-
    CASE
      WHEN {recency_pct} >= 0.8 THEN 5
      WHEN {recency_pct} >= 0.6 THEN 4
      WHEN {recency_pct} >= 0.4 THEN 3
      WHEN {recency_pct} >= 0.2 THEN 2
      ELSE 1
    END
  dimensions:
    - [dim_dt, customer_id]

# (frequency_score and monetary_score follow the same pattern)

# Segment classification
rfm_segment:
  type: measure
  formula: |-
    CASE
      WHEN {recency_score} <= 2 AND {frequency_score} <= 2 THEN 'Hibernating'
      WHEN {recency_score} <= 2 AND {frequency_score} <= 4 THEN 'At Risk'
      WHEN {recency_score} <= 2 AND {frequency_score} <= 5 THEN 'Cannot Lose Them'
      WHEN {recency_score} <= 3 AND {frequency_score} <= 2 THEN 'About to Sleep'
      WHEN {recency_score} <= 3 AND {frequency_score} <= 3 THEN 'Need Attention'
      WHEN {recency_score} <= 4 AND {frequency_score} <= 1 THEN 'Promising'
      WHEN {recency_score} <= 4 AND {frequency_score} <= 3 THEN 'Potential Loyalists'
      WHEN {recency_score} <= 4 AND {frequency_score} <= 5 THEN 'Loyal Customers'
      WHEN {recency_score} <= 5 AND {frequency_score} <= 1 THEN 'New Customers'
      WHEN {recency_score} <= 5 AND {frequency_score} <= 3 THEN 'Potential Loyalists'
      ELSE 'Champions'
    END
  dimensions:
    - [dim_dt, customer_id]

Zentrale Techniken:

  • percent_rank() over (...) kann in Kennzahlenformeln verwendet werden. Fensterfunktionen sind in .dml-Formeln zulässig.
  • Alle RFM-Kennzahlen sind auf die Granularitätsebene [dim_dt, customer_id] beschränkt. Die Systemvariable dim_dt ermöglicht die Berechnung auf jeder zeitlichen Granularitätsebene.
  • MAXIF und DISTINCTCOUNTIF werden mit {+d: dt_date} verwendet, um die Zeit seit dem letzten Kauf und die Kaufhäufigkeit zu berechnen.
  • CASE-Ausdrücke kombinieren die Punktwerte und ordnen Kunden anhand dieser Werte benannten Segmenten zu.

Produktrangliste anhand der kumulierten Verteilung #

Ordnen Sie Produkte anhand von kumulierten Summen, die mit Fensterfunktionen berechnet werden, in Stufen ein (Top 50%, Top 80%, Top 95%).

# Product rank by total first-2-year sales
product_power_rank:
  type: measure
  formula: 'rank() over (order by {first_2yr_sales} desc)'
  dimensions:
    - [product]

# Tier classification via cumulative distribution
product_tier:
  type: measure
  formula: |-
    CASE
      WHEN SUM({first_2yr_sales}) over (order by {first_2yr_sales} desc)
           <= 0.50 * SUM({first_2yr_sales}) over () THEN 'Top 50%'
      WHEN SUM({first_2yr_sales}) over (order by {first_2yr_sales} desc)
           <= 0.80 * SUM({first_2yr_sales}) over () THEN 'Top 80%'
      WHEN SUM({first_2yr_sales}) over (order by {first_2yr_sales} desc)
           <= 0.95 * SUM({first_2yr_sales}) over () THEN 'Top 95%'
      ELSE 'Others'
    END
  dimensions:
    - [product]

Zentrale Technik: SUM() over (order by ... desc) berechnet die laufende Summe. SUM() over () berechnet die Gesamtsumme. Das Verhältnis der laufenden Summe zur Gesamtsumme ergibt die kumulierte Verteilung für die Klassifizierung nach dem Pareto-Prinzip. Alle Berechnungen sind auf die Granularitätsebene [product] beschränkt.
