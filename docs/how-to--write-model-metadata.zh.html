通过说明帮助读者在查询模型前选出合适的数据集、统计总体和指标。

说明每个数据集 #

说明源数据中的一行代表什么，以及哪些字段可用于标识该行。解释主要汇总值的业务含义、限定范围所需的筛选条件，以及已知的时间或地域限制。

description: |-
  一行代表一条管道交易明细，transaction_id 标识源记录。
  SUM(出厂价金额) 为管道净额，包含调拨和总仓流转，不代表终端 POS 销售。
  官方 UL 报告使用 是否统计UL = '是'。
  渠道表示购买方侧业务渠道，与卖出方渠道不同。

如果两个数据集分别从卖方和买方视角呈现同一数据源，请说明 合作方编号 的映射有何不同。除非两个数据集的源数据行确实定义在不同层级，否则不要暗示它们的源数据粒度不同。

说明影响决策的列 #

如果列名无法体现该列的含义，请使用对象形式。

columns:
  购买渠道:
    description: 购买方侧业务渠道。模型别名为渠道，与卖出方渠道不同。
  是否统计UL:
    description: 官方 UL 报告范围标志。报告和归因分析使用相同筛选。
  去年同期出厂价金额:
    description: 行级去年同期金额。计算同比前检查数据覆盖及缺失值。

优先说明影响统计总体、分组、联接和比较的列。将已知限制作为有关数据源的事实来说明。不要把单个样本中的发现当作该列的长期属性。

使指标名称与公式一致 #

使用业务术语作为指标键。如果统计总体、必需的求值维度以及遇到 NULL 或零时的处理方式会影响解读，请在说明中写明这些信息。

如果旧名称无法准确反映公式，请重命名规范指标。仅当现有使用方需要兼容时才保留别名。原子定义仍应归属原数据集。

# Fragment under a dataset's measures mapping.
管道净额:
  description: 管道净额包含调拨和总仓流转，不代表终端 POS 销售。
  formula: SUM({出厂价金额})

活跃购买方数:
  description: 有记录的不同购买方代码数量，包含全部购买方类型。
  formula: DISTINCTCOUNT({购买方代码})

活跃药店数:
  description: 有记录且类型为 Drugstore 的不同购买方代码数量。
  formula: 'DISTINCTCOUNTIF({购买方代码}, {购买方客户类型} = ''Drugstore'')'

不要用注释弥补容易误导的规范名称。将长期适用的限制写入 description:，以便读取元数据的工具显示该限制。

对应源表列名 #

如果数据集来自一张表，table: 填源表名，abbr: 填源表列名。写查询时用业务名称。指标也可以指定内部简称，见下例。

进货额(不含税):
  abbr: SaleAmountNoTax
  type: measure
  dataset: 交易明细
  description: 不含税的有效进货金额。
  formula: SUM({有效销售额})

重命名指标前，请检查公式中的引用、查询和物化结果的使用方。仅设置 abbr 并不能保证所有下游依赖都能安全地重命名。

记录派生标签和估算值 #

如果需要解释列宏的含义，请提供 description: 和 formula:。

# Fragment under a dataset's column-macros mapping.
购买方渠道:
  description: 购买方侧业务渠道，来源为 Businesschannel。
  formula: '{购买渠道}'

如果标签来自硬编码规则，请说明所用规则及其限制。区分模型定义的日历标签与正式业务日历。如果某个指标根据流程中的交易估算末端活动，请说明它涵盖哪些交易类型。

使用模型验证元数据 #

  1. 检查每组名称、说明和公式是否描述同一个指标。
  2. 根据声明的源键和当前范围核对数据集说明。
  3. 检查兼容性别名及其使用方。
  4. 对修改后的模型运行 lint 检查。
  5. 对于每项已更改的计算，使用严格模式编译一条引用该计算的查询。
  6. 检查生成的别名和输出列。
  7. 按照CLI 指南，在实际运行环境中执行适用的检查。

有关指标语法和求值维度，请参阅指标。有关从建模到查询的完整流程，请遵循正向分析中的步骤。
