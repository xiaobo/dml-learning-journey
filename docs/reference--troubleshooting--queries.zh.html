P8. 聚合查询中遗漏 AGG() #

错误：SELECT 商品, 销售额 FROM MODEL GROUP BY 商品 修正：SELECT 商品, AGG(销售额) FROM MODEL GROUP BY 商品

P9. 为 AGG() 添加多余的别名 #

错误：SELECT AGG(销售额) as 销售额 修正：SELECT AGG(销售额) 会自动使用别名 销售额。

P10. 使用子查询 #

错误：SELECT * FROM MODEL WHERE 销售额 > (SELECT AVG(销售额) FROM MODEL) 修正：将 HAVING 与指标一起使用，例如 HAVING AGG(销售额) > AGG(avg_sales)。

P11. 使用 JOIN #

错误：SELECT a.*, b.* FROM MODEL a JOIN MODEL b ON a.销售明细编号 = b.销售明细编号 修正：在 .dml 文件中使用跨数据集的列宏，或通过 pk(...) 查找。

P12. 时间修饰符缺少时间上下文 #

错误：SELECT 商品, AGG({销售额: yoy}) FROM MODEL GROUP BY 商品（既没有用于分组的时间字段，也没有时间筛选条件）

规则：确定时间上下文，并满足宏的前置条件。最清楚的做法是显式指定用于分组的时间字段。时间筛选条件也可以提供上下文。为便于阅读，建议以同一时间粒度定义行或汇总值。

时间上下文参考：时间修饰符。

正确示例（按月计算同比）：

SELECT dt_month, AGG(销售额), AGG({销售额: yoy}) FROM MODEL GROUP BY dt_month

正确示例（日粒度的 YTD）：

SELECT dt_date, AGG(销售额, 'ytd') FROM MODEL WHERE dt_date = date(current_date) GROUP BY dt_date

P13. 混用不同的时间粒度 #

建议：优先使用单一时间粒度。经验证的构建版本接受同时指定 dt_year, dt_month。支持多个字段并不能保证每种宏组合都能获得预期的时间上下文。请检查解析得到的时间粒度。

P14. 添加不必要的空值筛选条件 #

错误：未明确要求时仍添加 WHERE 客户 is not null。修正：仅在问题明确要求时排除空值。

P15. 用 BETWEEN 筛选单个时间段 #

建议：dt_month = '2024-01-01' 明确选中 1 月。如果确实需要选择某个日期区间，可以使用该区间。请显式指定边界，并检查时间戳和区间最后一天的处理方式。

P16. 时间筛选条件的顺序属于书写约定 #

两种谓词顺序都能通过编译。引擎对谓词顺序没有要求，可按可读性选择顺序。

P17. 在不需要时使用 ORDER BY #

错误：为每个查询添加 ORDER BY。修正：仅在获取排名前 N 的结果或问题明确要求排名时使用 ORDER BY。

P18. 手动计算增长率 #

错误：DIVIDE(AGG(销售额), AGG(销售额, 'ya')) - 1 修正：使用带有内置修饰符的 AGG(销售额, 'yoy')。

P20. 仅用 DISTINCT 检查记录是否存在 #

错误：用 SELECT DISTINCT 客户 FROM MODEL.交易明细 回答“有客户吗？”。修正：用 SELECT 客户, dt_date, 交易编号 FROM MODEL.交易明细 LIMIT 1 返回一条具体记录。

P45. 在明细查询中使用指标 #

错误：在选择指标 total_cost: 的查询中指定 dataset: DATASET_PRODUCTS。修正：删除 dataset: 以使用聚合模式，或从明细查询中移除该指标。

P46. 在聚合查询中使用未限定的列名 #

错误：列属于 DATASET_PRODUCTS 时，直接写 商品编号: 而未指定 dataset:。修正：商品编号: "{DATASET_PRODUCTS}.商品编号"。

P47. 不同数据集中的维度字段名不一致 #

错误：DATASET_PT 使用维度 销售明细编号，DATASET_MC 使用维度 tag_id。修正：统一使用一个名称（例如 tag_id），并在 columns: 中映射数据仓库中的列（tag_id: 销售明细编号）。

P48. 在 dimension: 中将映射用作维度字段 #

错误：在 columns: dimension: 下写入 - f_tag_id: {DATASET_PT}.销售明细编号。修正：只列出 - f_tag_id，并单独定义公式 f_tag_id: |- …。

P49. 在 measures: 下定义维度字段 #

错误：在数据集的 measures: 下为 tag_id: 定义公式。修正：在数据集的 dimension: 下声明定义数据行的粒度。指标仅用于聚合。

P50. 在查询的 filters: 中使用复杂筛选条件 #

错误：在查询的 filters: 中使用 EXISTS 子查询或涉及多个字段的 PK 链。修正：将谓词移到事实数据集的 sql: 中的 WHERE 子句。

P51. PK 链式调用的参数数量不匹配 #

错误：DATASET_PRODUCTS 的复合 PK 为 (brand_id, tag_id) 时，使用 pk(1, tag_id).{DATASET_PRODUCTS}.state。修正：使用 pk(brand_id, tag_id).{DATASET_PRODUCTS}.state，传入 PK 的所有列。

P52. 在 after: 中手动指定 GROUP BY #

错误：在标准指标查询的 after: 中使用 group by 再次聚合。修正：由查询块聚合指标。省略 after: 可按维度自动排序。如果自定义排序或行数限制需要使用该块，请引用 {QUERY}，并仅用该块控制结果的呈现（select * from {QUERY} 加上 ORDER BY／TOP／LIMIT），除非文档明确记录了无法避免的自定义后处理 SQL。

有关命令和结果检查方法，请参阅编译和验证查询。

P60. 在聚合查询中使用子查询获取 MAX 日期 #

错误写法：WHERE dt_month = (SELECT MAX(dt_month) FROM MODEL ...) 修正方法：将用于验证的月份写为固定值，或使用明细查询 SELECT MAX(dt_month) FROM MODEL.<dataset>。

P61. 使用 GROUP BY 直接在数据集上聚合 #

错误写法：SELECT 购买方代码, 品牌, SUM(出厂价金额) FROM MODEL.DATASET_X GROUP BY 购买方代码, 品牌 现象：cannot aggregate directly on dataset MODEL.DATASET_X using GROUP BY 修正方法：任选一种方式：(a) 在 model.dml 中定义指标，并将 FROM MODEL 与 AGG() 搭配使用；(b) 对于临时查询，通过 /** dml ... **/ 格式的注释块使用内联指标，无需修改 .dml（参见内联指标（/** dml ... **/））。

查询排错 #

先用只含一个指标的查询确认模型和连接，再逐个加回维度、筛选和指标。行数偏多时检查数据集键重复、连接后的行数以及只在对比期间出现的键。数值不符时，用相同时间范围和数据快照运行独立 SQL，逐组比对键、NULL 和指标值。
