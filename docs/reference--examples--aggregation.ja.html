細かい粒度での集計例

このページの内容
  • +dを使った多段階集計
  • 細かい粒度でフィルタリングしてから +d で集約

これらのパターンでは、中間の粒度で指標を評価し、その値を集計またはフィルタリングします。各コード断片には、追加で依存するモデル要素を明記しています。指定内容の構文は「指標の修飾子」を参照してください。

+dを使った多段階集計 #

+dを使うと、2 段階の集計ができます。中間の粒度で指標を定義し、次にクエリの粒度まで集約します。コンパイラは CTE（WITH ... AS (SELECT ... GROUP BY ...) SELECT ...）を生成します。

パターン：ディメンションを限定した指標 → 上位の粒度に集約する指標 → クエリ

# Step 1: require customer_id during evaluation
顧客別売上高:
    type: measure
    dataset: 取引明細
    formula: SUM({売上金額})
    dimensions:
        - [顧客番号, ...]  # customer required; additional query fields allowed

# Step 2: evaluate with dimension [customer_id], then roll up to the query dimension
顧客売上高合計:
    type: measure
    formula: SUM({顧客別売上高: {+d: 顧客番号}})

-- Step 3: use any compatible query dimension ([ブランド], [地域], 合計, etc.)
SELECT ブランド, AGG(顧客売上高合計) FROM MODEL GROUP BY ブランド

RFM 分析：+d と fn マクロを使った完全な例：

# .dml: customer-grain measures for RFM
最終購入月:
    type: measure
    formula: 'MAXIF({dt_month}, {売上高: {+d: dt_month}} > 0)'
    dimensions:
        - [顧客番号]

購入月数:
    type: measure
    dataset: 取引明細
    formula: 'COUNT(DISTINCT CASE WHEN {売上金額} > 0 THEN {dt_month} ELSE NULL END)'
    dimensions:
        - [顧客番号]

-- Model Query SQL: RFM with ranks
SELECT AGG(売上高) AS M, AGG(売上高, 'rank') AS M_rank,
       AGG(購入月数) AS F, AGG(購入月数, 'rank') AS F_rank,
       AGG(最終購入月) AS R, AGG(最終購入月, 'rank_asc') AS R_rank
FROM MODEL GROUP BY 顧客番号

インライン指標：.dmlを変更せずに、/** dml ... **/のコメントブロックを使って、モデルクエリの SQL に一時的な指標を直接定義できます。構文とルールの詳細は「インライン指標（/** dml ... **/）」を参照してください。

/** dml
顧客売上高中間値:
    type: measure
    dataset: 取引明細
    formula: SUM({売上金額})
    dimensions:
        - [顧客番号, ...]

顧客平均売上高中間値:
    type: measure
    formula: 'AVG({顧客売上高中間値: {+d: 顧客番号}})'
**/
SELECT ブランド, AGG(顧客平均売上高中間値) AS 顧客平均売上高
FROM MODEL GROUP BY ブランド

細かい粒度でフィルタリングしてから +d で集約 #

SQL では、細かい粒度で集計 → その粒度で WHERE による絞り込み → SUM でより粗いレポートの粒度に集約、という手順をよく使います。

WITH sales AS (
  SELECT product, region, SUM(amount) AS total, COUNT(*) AS cnt
  FROM fact GROUP BY product, region
)
SELECT product, SUM(total) AS grand_total
FROM sales
WHERE cnt > 3                -- filter fine-grain rows
GROUP BY product
HAVING SUM(total) > 500      -- report-level HAVING

DML で推奨する方法：細かい粒度で適用する条件は、集約式の中に記述します。クエリの filters: は、レポートの対象範囲の指定または HAVING にのみ使います。

DATASET_SALES:
    type: dataset
    table: FACT
    columns:
        商品:
            abbr: product
        地域:
            abbr: region
    measures:
        合計: SUM(売上金額)
        売上件数: COUNT(1)

総計:
    type: measure
    formula: |-
        SUMIF({合計: {+d: 地域}}, {売上件数: {+d: 地域}} > 3)
    # No qualifying fine rows -> NULL. Use an explicit fill only if required.

report:
    type: query
    filters:
        "{総計} > 500":
    columns:
        dimension:
            - 商品
        総計:

例の読み方： {売上件数: {+d: 地域}} と {合計: {+d: 地域}} は、どちらも同じ細かい粒度 (商品, 地域) で評価されます。iif または SUMIF によって、その粒度のどの行を外側の SUM に含めるかが決まります。クエリのディメンションは 商品 のままです。

避けるべき書き方 理由
columns.dimension に 商品 だけを指定して filters: "売上件数 > 3" でクエリする 売上件数 が定義時の粒度とは異なる粒度で参照されています。コンパイル時やクエリの統合時に、商品レベルの HAVING COUNT(1) > 3 へ誤って書き換えられることがあります。
filters: "{売上件数: {+d: 地域}} > 3" コンパイルできる場合もありますが、処理の捉え方が逆になります。細かい粒度への掘り下げが、レポートのフィルターに埋め込まれているためです。
SUM({合計: {+d: 地域, +f: '{売上件数} > 3'}}) この条件は集計済みの指標を参照しています。+f が受け付けるのは入力行を絞り込む条件です。

SQL と同じ手順を明示したい場合の代替策として、細かい粒度のクエリ（dimension: [商品, 地域]、filters: "売上件数 > 3"）を残し、表示用の after: で再集計します。モデルを整備する際は、上記の指標による書き方を優先してください。

「指標の設計」と、注意点「P69」も参照してください。

+d の制限：

  • +d だけでは、同じディメンションに独立した別名を 2 つ導入できません。完全な N×N の共起行列には、代わりに sql: を使ったデータセットを使用できます。宣言済みのソースを顧客で自己結合し、一意な (顧客, brand_from, brand_to) の組み合わせを選択します。そのフィールドの組み合わせ全体をキーとして宣言し、2 つのブランドフィールドでグループ化して顧客数を数えます。確認済みの 2 ブランドのテストデータは、コンパイルと検証に成功し、A–A: 2、A–B: 1、B–A: 1、B–B: 1 を返します。この方法には、ブランドの組を表すリレーションを明示的に定義する必要があります。+d による自動変換ではありません。

+d がクエリのディメンションバインディング（columns.dimension: - name: '{m: {+d: K}}'）にある場合は、上記の集約パターンではなく、指標をディメンションとして使うパターンです。「指標をディメンションとして使う」を参照してください。

共起分析（1×N パターン）：+d、-d、+f を使って、対象ブランドともう一方のブランドの両方を購入した顧客数を、他のブランドごとに集計します。

/** dml
対象ブランド顧客数:
    type: measure
    formula: 'MAXIF(1, {売上高: {+d: 顧客番号, -d: ブランド, +f: {ブランド: ''BrandA''}}} > 0)'
    dimensions:
        - [..., 顧客番号]

現在のブランドの顧客数:
    type: measure
    formula: 'MAXIF(1, {売上高: {+d: [ブランド, 顧客番号]}} > 0)'
    dimensions:
        - [ブランド, 顧客番号]

共起回数:
    type: measure
    formula: 'SUM({現在のブランドの顧客数: {+d: [ブランド, 顧客番号]}} * {対象ブランド顧客数: {+d: 顧客番号}})'
**/
SELECT ブランド, AGG(共起回数) AS ブランドA共通顧客数
FROM MODEL GROUP BY ブランド ORDER BY AGG(共起回数) DESC

-d: ブランド は、対象指標の評価ディメンションからディメンションフィールド ブランド を取り除きます。評価ディメンションには [顧客] だけが残ります。+f で対象ブランドに絞り込み、2 つのフラグの積で両方のブランドを購入した顧客を数えます。

指標の dimensions: は常に配列の配列です。内側の各リストは許可するディメンションを 1 つ定義し、外側のリストはそれらを選択肢としてまとめます。

当月利用フラグ:
    type: measure
    formula: 'ISNULL(MAXIF(1, {当月数量: {+d: [商品番号, dt_month]}} > 0), 0)'
    dimensions:
      - [店舗番号, dt_month, ...]

許可するディメンションの定義で ...（省略記号）を使うと、指標参照の評価ディメンションに、列挙されていないディメンションフィールドも含められます。ただし、列挙されたフィールドはすべて評価ディメンションに含める必要があります。
