細かい粒度での集計例

このページの内容
  • +dを使った多段階集計
  • 細かい粒度でフィルタリングしてから +d で集約

これらのパターンでは、中間の粒度で指標を評価し、その値を集計またはフィルタリングします。各コード断片には、追加で依存するモデル要素を明記しています。指定内容の構文は「指標の修飾子」を参照してください。

+dを使った多段階集計 #

+dを使うと、2 段階の集計ができます。中間の粒度で指標を定義し、次にクエリの粒度まで集約します。コンパイラは CTE（WITH ... AS (SELECT ... GROUP BY ...) SELECT ...）を生成します。

パターン：ディメンションを限定した指標 → 上位の粒度に集約する指標 → クエリ

# Step 1: require customer_id during evaluation
customer_sales:
    type: measure
    dataset: transactions
    formula: SUM({amount})
    dimensions:
        - [customer_id, ...]  # customer required; additional query fields allowed

# Step 2: evaluate with dimension [customer_id], then roll up to the query dimension
total_customer_sales:
    type: measure
    formula: SUM({customer_sales: {+d: customer_id}})

-- Step 3: use any compatible query dimension ([brand], [region], total, etc.)
SELECT brand, AGG(total_customer_sales) FROM MODEL GROUP BY brand

RFM 分析：+d と fn マクロを使った完全な例：

# .dml: customer-grain measures for RFM
last_purchase_month:
    type: measure
    formula: 'MAXIF({dt_month}, {sales: {+d: dt_month}} > 0)'
    dimensions:
        - [customer_id]

purchase_months:
    type: measure
    dataset: transactions
    formula: 'COUNT(DISTINCT CASE WHEN {amount} > 0 THEN {dt_month} ELSE NULL END)'
    dimensions:
        - [customer_id]

-- Model Query SQL: RFM with ranks
SELECT AGG(sales) AS M, AGG(sales, 'rank') AS M_rank,
       AGG(purchase_months) AS F, AGG(purchase_months, 'rank') AS F_rank,
       AGG(last_purchase_month) AS R, AGG(last_purchase_month, 'rank_asc') AS R_rank
FROM MODEL GROUP BY customer_id

インライン指標：.dmlを変更せずに、/** dml ... **/のコメントブロックを使って、モデルクエリの SQL に一時的な指標を直接定義できます。構文とルールの詳細は「インライン指標（/** dml ... **/）」を参照してください。

/** dml
temp_customer_sales:
    type: measure
    dataset: transactions
    formula: SUM({amount})
    dimensions:
        - [customer_id, ...]

temp_avg_customer_sales:
    type: measure
    formula: 'AVG({temp_customer_sales: {+d: customer_id}})'
**/
SELECT brand, AGG(temp_avg_customer_sales) AS avg_customer_sales
FROM MODEL GROUP BY brand

細かい粒度でフィルタリングしてから +d で集約 #

SQL では、細かい粒度で集計 → その粒度で WHERE による絞り込み → SUM でより粗いレポートの粒度に集約、という手順をよく使います。

WITH sales AS (
  SELECT product, region, SUM(amount) AS total, COUNT(*) AS cnt
  FROM fact GROUP BY product, region
)
SELECT product, SUM(total) AS grand_total
FROM sales
WHERE cnt > 3                -- filter fine-grain rows
GROUP BY product
HAVING SUM(total) > 500      -- report-level HAVING

DML で推奨する方法：細かい粒度で適用する条件は、集約式の中に記述します。クエリの filters: は、レポートの対象範囲の指定または HAVING にのみ使います。

DATASET_SALES:
    type: dataset
    table: FACT
    columns:
        product:
        region:
    measures:
        total: SUM(amount)
        cnt: COUNT(1)

grand_total:
    type: measure
    formula: |-
        SUMIF({total: {+d: region}}, {cnt: {+d: region}} > 3)
    # No qualifying fine rows -> NULL. Use an explicit fill only if required.

report:
    type: query
    filters:
        "{grand_total} > 500":
    columns:
        dimension:
            - product
        grand_total:

例の読み方： {cnt: {+d: region}} と {total: {+d: region}} は、どちらも同じ細かい粒度 (product, region) で評価されます。iif または SUMIF によって、その粒度のどの行を外側の SUM に含めるかが決まります。クエリのディメンションは product のままです。

避けるべき書き方 理由
columns.dimension に product だけを指定して filters: "cnt > 3" でクエリする cnt が定義時の粒度とは異なる粒度で参照されています。コンパイル時やクエリの統合時に、商品レベルの HAVING COUNT(1) > 3 へ誤って書き換えられることがあります。
filters: "{cnt: {+d: region}} > 3" コンパイルできる場合もありますが、処理の捉え方が逆になります。細かい粒度への掘り下げが、レポートのフィルターに埋め込まれているためです。
SUM({total: {+d: region, +f: '{cnt} > 3'}}) この条件は集計済みの指標を参照しています。+f が受け付けるのは入力行を絞り込む条件です。

SQL と同じ手順を明示したい場合の代替策として、細かい粒度のクエリ（dimension: [product, region]、filters: "cnt > 3"）を残し、表示用の after: で再集計します。モデルを整備する際は、上記の指標による書き方を優先してください。

「指標の設計」と、注意点「P69」も参照してください。

+d の制限：

  • +d だけでは、同じディメンションに独立した別名を 2 つ導入できません。完全な N×N の共起行列には、代わりに sql: を使ったデータセットを使用できます。宣言済みのソースを顧客で自己結合し、一意な (customer, brand_from, brand_to) の組み合わせを選択します。そのフィールドの組み合わせ全体をキーとして宣言し、2 つのブランドフィールドでグループ化して顧客数を数えます。確認済みの 2 ブランドのテストデータは、コンパイルと検証に成功し、A–A: 2、A–B: 1、B–A: 1、B–B: 1 を返します。この方法には、ブランドの組を表すリレーションを明示的に定義する必要があります。+d による自動変換ではありません。

+d がクエリのディメンションバインディング（columns.dimension: - name: '{m: {+d: K}}'）にある場合は、上記の集約パターンではなく、指標をディメンションとして使うパターンです。「指標をディメンションとして使う」を参照してください。

共起分析（1×N パターン）：+d、-d、+f を使って、対象ブランドともう一方のブランドの両方を購入した顧客数を、他のブランドごとに集計します。

/** dml
target_brand_customers:
    type: measure
    formula: 'MAXIF(1, {sales: {+d: customer_id, -d: brand, +f: {brand: ''BrandA''}}} > 0)'
    dimensions:
        - [..., customer_id]

current_brand_customers:
    type: measure
    formula: 'MAXIF(1, {sales: {+d: [brand, customer_id]}} > 0)'
    dimensions:
        - [brand, customer_id]

co_occurrence:
    type: measure
    formula: 'SUM({current_brand_customers: {+d: [brand, customer_id]}} * {target_brand_customers: {+d: customer_id}})'
**/
SELECT brand, AGG(co_occurrence) AS overlap_with_brandA
FROM MODEL GROUP BY brand ORDER BY AGG(co_occurrence) DESC

-d: brand は、対象指標の評価ディメンションからディメンションフィールド brand を取り除きます。評価ディメンションには [customer] だけが残ります。+f で対象ブランドに絞り込み、2 つのフラグの積で両方のブランドを購入した顧客を数えます。

指標の dimensions: は常に配列の配列です。内側の各リストは許可するディメンションを 1 つ定義し、外側のリストはそれらを選択肢としてまとめます。

month_active_flag:
    type: measure
    formula: 'ISNULL(MAXIF(1, {month_qty: {+d: [prod_id, dt_month]}} > 0), 0)'
    dimensions:
      - [store_id, dt_month, ...]

許可するディメンションの定義で ...（省略記号）を使うと、指標参照の評価ディメンションに、列挙されていないディメンションフィールドも含められます。ただし、列挙されたフィールドはすべて評価ディメンションに含める必要があります。
