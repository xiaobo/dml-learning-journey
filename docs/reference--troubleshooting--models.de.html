Diese Einträge behandeln Definitionen, Namen, Lookups und Metadaten. Die Deklarationssyntax wird unter Modellstruktur und Kennzahldeklarationen beschrieben.

P21. AGG() in Kennzahlformeln #

Falsch: sales: AGG({amount}) in .dml. Korrektur: sales: SUM({amount}). Verwenden Sie in .dml Aggregatfunktionen aus SQL.

P22. Datasetübergreifende Referenzen ohne Lookup #

Falsch: profit: SUM({sales.amount} - {costs.amount}) über Datasetgrenzen hinweg verwenden. Korrektur: Verwenden Sie Spaltenmakros mit Lookups über {DATASET}.column oder pk(...).

P22b. Eine über table: einem Dataset zugeordnete physische Tabelle in sql: eines anderen Datasets verknüpfen #

Falsch: Policy enthält table: policy, und ein anderes Dataset verwendet in sql: die Angabe from policy oder join policy. Korrektur: Referenzieren Sie das Dataset statt der physischen Tabelle mit from {Policy} oder join {Policy}. Verwenden Sie für Attribute ohne SQL-Join den Ausdruck pk(...).{Policy}.Col. {Policy} in sql: dient als Platzhalter für eine Tabellenquelle und ist kein Spaltenausdruck. Der Compiler ersetzt den Platzhalter durch den Namen der Datasetabfrage. Siehe Datasetdefinition (type: dataset).

P23. Fehlendes dataset: bei atomaren Kennzahlen #

Falsch: sales: type: measure, formula: SUM({amount}). Das Dataset fehlt. Korrektur: sales: type: measure, dataset: transactions, formula: SUM({amount})

P24. Zu spezifische Kennzahlnamen #

Falsch: sales_q1_2024_north, sales_john_doe. Korrektur: Kombinieren Sie allgemein definierte Kennzahlen mit Abfragefiltern.

P25. Sonderfälle bleiben undokumentiert #

Falsch: Bei einer Kennzahl fehlt der Hinweis „schließt Retouren aus“ oder „berücksichtigt Nullwerte (0)“. Korrektur: Ergänzen Sie bei Verhalten, das sich nicht von selbst erschließt, immer description:. Dokumentieren Sie die Datasetdimension, die Bedeutung einer Zeile, Flags zum Geltungsbereich und irreführende Namen. Siehe Modellmetadaten verfassen.

P27. Kennzahlen mit Dimensionseinschränkungen in inkompatiblen Abfragen verwenden #

Falsch: sales_by_product (zulässige Dimension [product]) und total_sales in einer Abfrage mit der Abfragedimension [dt_month] auswählen. Korrektur: Stellen Sie sicher, dass jede Kennzahl die Abfragedimension zulässt und dass die Ebenen, auf denen die Zeilen der Kennzahlen definiert sind, zueinander passen. Alternativ verwenden Sie getrennte Abfragen.

P28. +d verwenden, obwohl GROUP BY ausreicht #

Falsch: sales_by_region: SUM({sales: {+d: region}}) anlegen. Korrektur: Definieren Sie sales: SUM({amount}) und verwenden Sie die Abfrage SELECT region, AGG(sales) FROM MODEL GROUP BY region.

P28b. Weitergabe von NULL bei einer fehlenden Join-Zeile #

Falsch: profit: '{revenue} - {costs}'. Fehlt auf mindestens einer Seite eine Zeile für den betrachteten Ausschnitt (FOJ oder lückenhafte dt), ist der entsprechende Eingabewert NULL und die Differenz wird ebenfalls NULL.

Korrektur bei fehlender Zeile: Standardwert einsetzen (Fehlende Zeilen auffüllen):

  1. Aktivieren Sie die Auffüllung für lückenhafte Eingaben, indem Sie isnull, ifnull oder coalesce(公式, 字面量) als äußerste Funktion verwenden:
revenue: 'isnull(SUM({amount}), 0)'   # or wrap the existing measure formula outermost
costs: 'isnull(SUM({cost}), 0)'
profit: '{revenue} - {costs}'         # use sites of revenue/costs → 0
  1. Wenn die Ergebnisspalte selbst auch dann einen Wert ungleich NULL liefern muss, wenn die Zeile auf ihrer Granularitätsebene fehlt, aktivieren Sie die Auffüllung direkt für das Ergebnis:
profit: 'isnull({revenue} - {costs}, 0)'

Reicht nicht aus oder aktiviert die Auffüllung nicht: isnull({a}, {b}), coalesce(a, b, 0), {m: pp} allein oder die Annahme, dass eine unbeteiligte äußere zusammengesetzte Kennzahl automatisch von isnull umschlossen wird. Wenn eine zusammengesetzte Kennzahl eine Abhängigkeit einbindet, für die die Auffüllung bereits aktiviert ist, wird deren Auffüllausdruck an den Stellen expandiert, an denen die Abhängigkeit in lückenhaften FOJ-Kontexten verwendet wird. Siehe measures.md Standardwert einsetzen.

P28c. Gruppierungsschlüssel mit NULL beim Kombinieren von Kennzahlen aus mehreren Datasets #

Symptom. Ein Bericht zeigt eine Zeile mit NULL als Region und Kennzahlen aus mehreren Quellen. Diese Zeile steht für eine gemeinsame Berichtsgruppe. Bei einem zusammengesetzten Schlüssel müssen auch alle übrigen Dimensionen übereinstimmen.

Prüfung. Vergleichen Sie die vollständigen Gruppierungsschlüssel und prüfen Sie das generierte Prädikat. Builds mit der Änderung vom 19. November 2026 verwenden für diese Zuordnung einen NULL-sicheren Gleichheitsvergleich. Ältere Builds können Schlüssel mit NULL ohne Zuordnung lassen. Um nur Gruppen aus der primären Quelle zu behalten, filtern Sie nach einer Kennzahl, die das Vorhandensein in der primären Quelle anzeigt und für die keine Auffüllung eingerichtet ist. Siehe Gleichheitsvergleich für NULL in Joins.

Kategorie: Umgang mit Zeitangaben #

P37. Modifikatoren an Spalten #

Falsch: {customer_id: {+d: customer_id}} in einer Formel verwenden. Korrektur: Wenden Sie den Drilldown auf die Kennzahl an, die ausgewertet wird: {sales: {+d: customer_id}}. Andere Modifikatoren wie der Eingabemodifikator +f gibt es auch in einer Form für Spalten. Die Einschränkung gilt daher nicht für alle Spaltenmodifikatoren.

P38. YAML-Formeln ohne Anführungszeichen #

Falsch: formula: SUMIF({sales: {+d: dt_month}}, {dt_month} = {first_month}) ohne Anführungszeichen schreiben, wenn der Wert :, { oder - enthält. Korrektur: formula: 'SUMIF(...)'

P39. dataset: bei zusammengesetzten Kennzahlen #

Falsch: Eine zusammengesetzte Kennzahl referenziert andere Kennzahlen und enthält trotzdem dataset:. Korrektur: Lassen Sie dataset: weg, wenn die Formel andere Kennzahlen referenziert. Behalten Sie dataset: nur bei atomaren Kennzahlen bei.

P40. Kennzahl kann nicht neu definiert werden oder Formel ist doppelt vorhanden #

Falsch: SELECT AGG(sales) AS sales oder AGG(x) AS x verwenden, wenn sales bzw. x bereits als Kennzahl existiert. Korrektur: Verwenden Sie SELECT AGG(sales) ohne Alias oder mit einem neutralen Alias (AS sales_value). Wenn der Compiler die Meldung „use existing measure "X"“ ausgibt, verwenden Sie AGG(X), statt die Formel erneut auszuschreiben.

P41. DML-Syntax mit {...} im SQL einer Modellabfrage #

Falsch: SELECT {dt_month}, AGG({sales}) FROM MODEL. Geschweifte Klammern sind .dml-Formeln vorbehalten. Korrektur: SELECT dt_month, AGG(sales) FROM MODEL. Verwenden Sie AGG({sales: pop}) in Abfragen nur für die Schreibweise mit Modifikator.

P42. Spaltenname ohne Klammern im Vergleich zu {col} in .dml-Formeln #

Falsche Interpretation: Bei formula: calc_amt * 2 von vergessenen Klammern oder einer Prüflücke im Compiler ausgehen. Ohne Klammern wird calc_amt als physische Tabellenspalte gebunden (unverändert an SQL durchgereicht). Korrektur: Setzen Sie den Spaltennamen in geschweifte Klammern, wenn Sie auf die Definition der berechneten Spalte verweisen wollen: formula: '{calc_amt} * 2'. Schreiben Sie physische Spalten ohne Klammern: net: amount - discount. Siehe Datensatzdefinition (type: dataset).

Fehlerbehebung bei Modellen #

Prüfen Sie zuerst die Angabe unter dialect: sowie die Pfade und Namen unter includes: im Einstiegsmodell. Stellen Sie sicher, dass die Angaben unter dimension: im Datensatz jede Quellzeile eindeutig identifizieren. Übergeben Sie den vollständigen Schlüssel in der Reihenfolge der Deklaration an pk(...). Beheben Sie zuerst den ersten eindeutig gemeldeten fehlenden Verweis oder Konflikt und führen Sie dann den Linter erneut aus.
