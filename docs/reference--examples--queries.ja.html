入門例では共通の売上モデルを使用します。このモデルはsalesと一覧に示した取引列を提供しますが、ソースデータは作成しません。日付を使う例では現在の日付を基準とするため、過去のテストデータでは行が返らない場合があります。

例を実行するための前提条件: 基本クエリ、売上の期間比較、順位、構成比、商品数の集計には、このモデルを使用します。経費の例には追加で指標 expense が必要です。未払い残高の例には customer と outstanding、アカウント別の成長率の例には account と revenue が必要です。これらは環境に合わせて調整するための断片で、共通モデルに追加してそのまま実行できるものではありません。固定の日付と期待される結果が揃った実行可能なデータセットには、検証済みの売上演習を使用してください。

基本クエリ #

売上合計 #

SELECT AGG(sales) FROM MODEL

地域別の売上 #

SELECT region, AGG(sales) FROM MODEL GROUP BY region

今月の売上 #

SELECT AGG(sales) FROM MODEL WHERE dt_month = date(current_date, 'start of month')

地域別の今月の売上 #

SELECT region, AGG(sales)
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY region

明細クエリ：支払い済みの取引 #

SELECT dt_date, transaction_id, amount, is_paid
FROM MODEL.transactions
WHERE is_paid = 1
ORDER BY dt_date DESC

時間修飾子 #

今月と先月の比較 #

SELECT dt_month,
       AGG(sales) as this_month,
       AGG(sales, 'pp') as last_month,
       AGG(sales, 'pop') as mom_rate
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY dt_month

今月と前年同月の比較 #

SELECT dt_month,
       AGG(sales) as this_month,
       AGG(sales, 'ya') as last_year_month,
       AGG(sales, 'yoy') as yoy_rate
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY dt_month

年初来の成長率 #

SELECT dt_date,
       AGG(sales, 'ytd') as ytd_sales,
       AGG(sales, 'ytd', 'ya') as ytd_last_year,
       AGG(sales, 'ytd', 'yoy') as ytd_growth
FROM MODEL
WHERE dt_date = date(current_date)
GROUP BY dt_date

修飾子の重ねがけに注目してください。'ytd', 'ya' は、前年の年初から前年の同日までの期間を指します。

直近12か月の移動合計 #

SELECT dt_month, AGG(sales), AGG({sales: mat}) AS rolling_sales
FROM MODEL
GROUP BY dt_month
ORDER BY dt_month DESC
LIMIT 12

特定の月または四半期 #

-- August this year
SELECT AGG(expense) FROM MODEL WHERE dt_month = date(current_date, 'start of year', '+7 months')

-- Q2 this year
SELECT AGG(expense) FROM MODEL WHERE dt_quarter = date(current_date, 'start of year', '+1 quarter')

.dml での修飾子のネスト #

# In model.dml
sales_ytd:
    type: measure
    formula: '{sales: ytd}'

sales_ytd_last_year:
    type: measure
    formula: '{sales: {ytd: ya}}'

-- In query
SELECT dt_date, AGG(sales_ytd), AGG(sales_ytd_last_year)
FROM MODEL
WHERE dt_date = date(current_date)
GROUP BY dt_date

要点：時間修飾子には、時間コンテキストが確定していることと、マクロの前提条件を満たしていることが必要です。時間フィルターでも時間コンテキストを指定できます。yoy と pop は成長率を小数で返します（0.15 = 15%）。pp と ya は、比較対象となる過去の期間の指標値そのものを返します。日付を手動で計算するよりも、修飾子を使うことを推奨します。

順位とフィルター #

売上上位10商品 #

SELECT product, AGG(sales)
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY product
ORDER BY AGG(sales) DESC
LIMIT 10

順位修飾子の使用 #

SELECT product, AGG(sales), AGG({sales: rank}) AS sales_rank
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY product

{sales: rank} は、クエリ結果内で各商品の売上が何位かを返します。順位は売上の降順で決まります。

選択した期間内の順位 #

SELECT product,
       AGG(sales) as period_sales,
       AGG({sales: rank}) as selected_period_rank
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY product

このクエリはすでに商品だけでグループ化しています。月のフィルターを維持したまま、sales を直接順位付けしてください。時間の集計レベルを取り除く必要はありません。グループ化フィールドを取り除くことと、時間フィルターを取り除くことは別の操作です。

順位による絞り込み #

SELECT product, AGG(sales)
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY product
HAVING AGG({sales: rank}) <= 10

HAVING は集計後に絞り込むため、この句で rank を使用できます。

HAVING 句：未払い残高のある顧客 #

SELECT customer, AGG(outstanding)
FROM MODEL
GROUP BY customer
HAVING AGG(outstanding) > 0

要点：rank は RANK() OVER (ORDER BY measure DESC) を返します。rank_asc は値の昇順で順位を返します。順位付けの前に時間ディメンションや他のディメンションを取り除くには、-d を使用します。順位が N 位以内の結果を動的に絞り込むには、順位修飾子を HAVING と組み合わせます。

総計に占める割合（pot） #

SELECT product, AGG(sales) AS sales,
       AGG(sales, 'rank') AS sales_rank,
       AGG({sales: pot}) AS share_of_total
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY product
ORDER BY AGG(sales, 'rank')

pot は measure / grand です。パレート分析で使う累積構成比はシステムの fn マクロではありません。累計が必要な場合は、Model Query SQL で OVER() を使用します。

RFM と共起パターン #

RFM 分析と共起分析については、細かい集計レベルでの集計例を参照してください。

dt を含まないディメンション #

地域別の売上（全期間） #

SELECT region, AGG(sales) FROM MODEL GROUP BY region

地域別の商品構成比（時間によるグループ化なし） #

SELECT region, product, AGG(sales)
FROM MODEL
GROUP BY region, product

選択した期間と全履歴の比較 #

-- Selected month: retain the month filter.
SELECT region, product, AGG(sales) AS selected_period_sales
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY region, product

-- All history: remove the month filter, retain the same grouping.
SELECT region, product, AGG(sales) AS all_time_sales
FROM MODEL
GROUP BY region, product

これらは別々のクエリとして実行してください。-d はグループ化を取り除きますが、時間フィルターは維持します。これらのクエリは時間でグループ化しないため、-d: dim_dt は不要です。ここで個々の指標から時間の集計レベルを取り除こうとすると、検証に使用したコンパイラーによって拒否されます。分母に限ってグループ化とフィルターを取り除く方法については、ディメンション修飾子とフィルター修飾子を参照してください。

期間単位の変換 #

SELECT dt_year,
       AGG({sales: {dim_dt as quarter: pp}}) as last_quarter_at_quarter_grain
FROM MODEL
WHERE dt_year = '2024-01-01'
GROUP BY dt_year

dim_dt as quarter を指定すると、クエリが年単位でグループ化されていても、修飾子 pp は四半期単位で処理します。指標を変更後の集計レベル（四半期）で評価してから、その結果をクエリの集計レベル（年）のデータに結合します。

注記: dim_dt as <grain> が役に立つのは、変更後の時間の集計レベルがクエリの時間の集計レベルと異なる場合に限ります。クエリがすでに dt_quarter でグループ化されている場合、dim_dt as quarter: pp は不要な指定として拒否されます。この場合は AGG({sales: pp}) を直接使用してください。

要点：時間フィルターのないクエリは、すべての履歴データを対象にします。-d: dim_dt は、指標の評価に使うディメンションから現在有効な時間フィールドを取り除きます。有効な時間フィールドを指定するには、dt_date のような個別のフィールド名ではなく dim_dt を使います。-d で取り除けるのは、現在のクエリのグループ化に含まれるディメンションフィールドだけです。dim_dt as <grain> は、1 つの指標参照の時間の集計レベルを変更します。組み合わせる際は、同じ行にあっても、時間ディメンションのない指標と時間ディメンションのある指標を比較できない場合があります。

比較パターン #

前の期間との比較 #

SELECT AGG(sales) as this_month, AGG(sales, 'pp') as last_month
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')

アカウント別の成長率 #

SELECT account, AGG(revenue) as current, AGG(revenue, 'pp') as previous
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY account
HAVING AGG(revenue, 'pop') > 0.10  -- 10% growth

年初来と前年の比較 #

SELECT AGG(sales, 'ytd') as this_ytd, AGG(sales, 'ytd', 'ya') as last_ytd
FROM MODEL
WHERE dt_date = date(current_date)
GROUP BY dt_date

条件付きカウント #

修飾子は列ではなく指標に適用します。条件式の中で、指標に {+d: product} を適用します。

-- Count of products with per-product sales above threshold
SELECT DISTINCTCOUNTIF(product, AGG({sales: {+d: product}}) > 1000) as prod_cnt FROM MODEL

または、.dml で formula: 'DISTINCTCOUNTIF({product}, {sales: {+d: product}} > 1000)' を使って一度定義してから、SELECT AGG(high_sales_product_count) FROM MODEL でクエリを実行します。
