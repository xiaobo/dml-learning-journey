マテリアライズ：宣言から結果の確認まで

このページの内容
  • 1. 最適化前の結果を保存する
  • 2. 宣言してインストールする
  • 3. マテリアライズの利用を確認し、結果を比較する
  • 4. 更新と無効化を行う
  • 5. 検証記録を残す

結果が正しいこと、クエリがマテリアライズされたデータを参照すること、更新後も結果が正しいことの3点を確認します。 宣言を追加したり、SQLが短くなったりしただけでは、最適化が完了したとは判断できません。

前提として、コンパイラと対象データベースへの接続が必要です。また、マテリアライズを使わずにクエリを検証しておく必要があります。ここで示すのは作業手順であり、すべてのデータベースで互換性を検証したことを示すものではありません。

1. 最適化前の結果を保存する #

データとフィルターを固定し、元の結果、生成されたSQL、キーの集合全体を保存します。売上金額、費用、取引件数など、加算できる指標を選びます。利益率は必ず再計算し、比率を足し合わせてはいけません。後続のクエリに必要なフィールドを残す方法については、粒度の設計を参照してください。

2. 宣言してインストールする #

宣言のリファレンスに従い、粒度（行や集計値を定義するレベル）、指標、許可するマテリアライズを選びます。現在のバージョンのヘルプを確認してから、隔離された練習用データベースで次を実行します。

dmlc --advanced-help
dmlc --setup model.dml --connection=default

セットアップはデータベースにマテリアライズ用のプロシージャをインストールする書き込み操作です。診断出力をすべて確認します。通常のクエリでも、必要に応じてプロシージャがインストールまたは更新される場合があります。実際の動作は、現在のバージョンと接続によって異なります。

3. マテリアライズの利用を確認し、結果を比較する #

dmlc --validate query.sql --model=model.dml --connection=default --json
dmlc query.sql --model=model.dml --connection=default --output=optimized.json --replace

生成されたSQLまたは実行プランを調べ、想定した集計オブジェクトからデータを読み取るか確認します。最適化前の結果とキーごと、列ごとに比較します。重複行、欠落したグループ、NULL、書式設定前の比率は個別に確認します。ディメンションやフィルターを変えて再度確認します。すべての問いに対して同じ集計が使われるとは限りません。

4. 更新と無効化を行う #

値が既知のレコードを練習用データベースに追加します。どの結果が変わるはずかを先に計算してから、クエリを実行します。キャッシュが更新され、出力が変わることを確認します。診断でセットアップの再実行が求められた場合は、同じモデルと接続でセットアップを実行し、再度検証します。問題を隠すために生成されたテーブルを手作業で編集しないでください。

SQL Server では、クエリの準備とデータ変更に伴う更新が分離されており、同期制御された単一の実行プロセスがマテリアライズを構築します。生成されたprepare_sqlを実行します。準備、待機、利用可能かどうかの確認はここでまとめて行われ、通常は業務クエリのsqlを実行する前にdata_ready=1が返ります。エラーが発生した場合や待機時間が上限に達した場合は、クエリを中止し、原因を解消してから再試行します。

DML_MAZ_PROGRESSで未処理の作業、実行プロセスの状態、未処理の作業がすべて完了するまでの推定時間を確認します。必要に応じて、ほかの統計列も参照します。全体の進捗を確認しても、クエリごとに実行の準備が整っているかを確認する必要があります。デプロイ時に、生成されたsetup_sqlを実行します。パラメーター、無効化のみを行う方法、復旧手順については準備と更新の規約を、一連の手順を試すには月次集計と四半期集計を参照してください。

ソースデータの変更、更新操作、実際に参照されたオブジェクト、新しい結果を記録します。この手順を省くと、「リアルタイムで更新される」とは言えません。更新の仕組みと必要な権限は、接続ごとに確認します。

5. 検証記録を残す #

確認項目 検証記録
結果の正しさ 最適化前後の結果とその差分
マテリアライズの利用 SQLまたは実行プランで実際に参照されたオブジェクト
更新 変更記録、更新操作、新しい結果
効果 同じデータと定義を使った実行プラン。測定時間を示す場合は、キャッシュの状態と繰り返し回数も明記します。

このページでは作業手順のみを補足し、マテリアライズについて新たな主張は行いません。宣言の例はデータベースの互換性を報告するものではありません。
