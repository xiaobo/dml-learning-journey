-d 保留月份筛选，-df 在该指标计算中移除它。 两者都可以只输出一月，分母计算范围与报表输出行范围需要分别检查。

用同一份数据比较 #

地区 a 一月销售10、二月20；地区 b 一月销售30。筛选一月后：

地区 月份 销售额 -d 地区总额 -df 地区总额
a 2024-01-01 10 10 30
b 2024-01-01 30 30 30

只看一月时，地区 a 的销售占比可以是 10/10，也可以是 10/30，取决于分母是否随月份筛选。不筛选月份时，两种算法的分母都是 30：一月占 10/30，二月占 20/30。

保存两种口径，再改变查询 #

模型定义 地区所选月份销售额: '{销售额: {-d: dt_month}}' 和 地区全部月份销售额: '{销售额: {-df: dt_month}}'。时间维度 dt_month 对应原表中保存日期的列 month。

完整文件 / Complete file: fixed/model.dml 
dialect: duckdb
销售记录:
  type: dataset
  table: FACT
  dimension: [编号]
  columns:
    编号:
      abbr: id
    地区:
      abbr: region
    dt_month:
      abbr: month
    订单金额:
      abbr: amount
  measures:
    销售额: SUM({订单金额})
地区所选月份销售额:
  type: measure
  formula: '{销售额: {-d: dt_month}}'
地区全部月份销售额:
  type: measure
  formula: '{销售额: {-df: dt_month}}'
累计销售额:
  type: measure
  formula: 'SUM({销售额}) OVER (ORDER BY {dt_month} ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)'
  dimensions:
    - [dt_month]
完整文件 / Complete file: fixed/setup.sql 
CREATE TABLE FACT(id INTEGER,region VARCHAR, month DATE,amount INTEGER); INSERT INTO FACT VALUES (1,'a','2024-01-01',10),(2,'a','2024-02-01',20),(3,'b','2024-01-01',30);
完整文件 / Complete file: fixed/january.sql 
SELECT 地区, dt_month, AGG(销售额), AGG(地区所选月份销售额), AGG(地区全部月份销售额) FROM MODEL WHERE dt_month='2024-01-01' GROUP BY 地区,dt_month ORDER BY 地区,dt_month
完整文件 / Complete file: fixed/unfiltered.sql 
SELECT 地区, dt_month, AGG(销售额), AGG(地区所选月份销售额), AGG(地区全部月份销售额) FROM MODEL GROUP BY 地区, dt_month ORDER BY 地区,dt_month

模型不变，查询决定报表显示哪些月份。验证器比较所有列与完整行集合，确保 -df 没有把二月输出行带回来。

哪些结论不能直接推广？ #

这里是已知的地区、月份分组，不是动态透视轴或自动小计 API。对于时间查询，先看累计 KPI 的上下文，不要照搬字段替换。

运行与验证范围 #

下载完整项目，按包内 README.md 运行 verify.ps1。在 PowerShell 中运行，确保能直接调用 dmlc；脚本只在你指定的全新输出目录创建练习库。所有案例共用一个入口，结果与诊断保存在输出目录。

本例在 dmlc 0.3.16、2026-11-27 构建的 DuckDB 连接上验证。编译器指纹、用例列表和状态见包内 verification-summary.json。数据库验证和随后执行是独立操作，不保证同一快照。其他引擎需单独验证。
