本页介绍修饰符的参数、筛选效果以及修饰符的组合方式。引用和内置函数见表达式和函数。细粒度聚合示例展示了完整的处理阶段。

修饰符参数结构 #

在 {measure: {modifier_a: value, modifier_b: value}} 中，外层对象有且仅有一个表示目标指标的键。内层修饰符映射可以包含多个键，但必须遵守修饰符约束。

键或形式 修饰符参数
dim_dt 公式字符串，或包含 value 和 range 字段的对象
dim_dt as date, dim_dt as week, dim_dt as month, dim_dt as quarter, dim_dt as year, dim_dt as hour 周期转换变体。每个修饰符对象最多可指定一个时间变体。
+f 筛选器名称字符串、筛选器名称列表，或 {column: value} 之类的内联对象
-f 筛选器名称或列名的字符串，或由这些名称组成的列表
仅修饰符名称 dt-macro 或 fn-macro 的名称

时间修饰符 #

系统宏参考副本包含用于时间偏移的 dt-macro 定义和用于封装公式的 fn-macro 定义。增长率宏以小数形式返回比率。可用的宏、公式和 prerequisite 约束由所选可执行文件随附的资源决定。

两种宏类型

类型 返回值 示例
dt-macro 绝对数值 pp, ya, ytd, mat, p3m, ...
fn-macro（增长率） 以小数表示的比率 pop, yoy, mom

叠加。修饰符可以叠加使用。AGG(sales, 'ytd', 'ya') 返回上一年年初至上一年对应日期这一期间的指标值。完整的叠加规则见修饰符叠加。

时间上下文。时间修饰符要求 dim_dt 可解析，并且必须满足相应宏的前置条件。按时间字段分组是最明确的方式，时间筛选器也可以提供上下文。参见 Model Query 时间规则。

使用 dim_dt 进行周期转换

SELECT dt_year, dt_quarter,
       AGG({sales: {dim_dt as quarter: pp}}) as last_quarter
FROM MODEL GROUP BY dt_year, dt_quarter

即使查询按年份和季度分组，dim_dt as quarter 也会让 pp 按季度粒度计算。

函数修饰符 #

系统宏参考副本定义了 rank、pot、grand、firstday 和 lastday 等宏。可用的名称、公式和前置条件由所选可执行文件随附的资源决定。遇到未知修饰符时，诊断信息会列出所检查的构建版本中可用的名称。

筛选修饰符 +f 是架构级修饰符。它不是系统宏。

修饰符 语法 返回值 说明
+f: condition {measure: {+f: {col: val}}} 筛选后的值 在聚合时对指标应用筛选

+f 筛选原子输入行。它不是聚合后应用的谓词。

目标 / 谓词 行为
原子聚合中的列 筛选该聚合的输入
原子指标 + 源列谓词 支持。例如，{sales: {+f: "status = 1"}} 会生成带条件的 SUM。
简单复合指标 + 源列谓词 筛选条件会传递给该指标所依赖的原子指标。已用 divide({sales}, {cnt}) 验证。仅当所有依赖项都应应用该筛选条件时使用。
带有 +d 和源列 +f 的原子指标 在已检查的 AVG 上卷聚合中受支持。请检查筛选是否先于细粒度聚合。
引用聚合指标的谓词，例如 "{cnt} > 3" 会被拒绝，并返回 cannot use +f modifier with measure(s)。请采用细粒度筛选示例中的做法。

单独使用带筛选条件的原子指标引用时，按当前查询粒度求值。需要计算每个实体的值时，请保留 +d 和显式的外层聚合，尤其是使用 AVG、MIN、MAX、COUNT 时。没有符合条件的输入时，条件式 SUM 返回 NULL。显式指定 ELSE 0 的语义不同。按条件筛选聚合输入时，仅含未通过筛选的行的分组仍可能保留。

窗口函数 fn 宏会在编译生成的 SQL 中生成 rank() over (...)。在 Model Query SQL 中，可使用 AGG(measure, 'rank') 或 AGG({measure: rank}) 形式。完整列表和公式见 system_macros.dml。

.dml 中的筛选修饰符（以列为目标）

completed_sales:
    type: measure
    formula: "{amount: {+f: {status: 'completed'}}}"

Model Query SQL 中的筛选修饰符

SELECT AGG(sales, '+f', region = 'North') FROM MODEL

维度修饰符 #

修饰符 语法 效果
+d: dim {measure: {+d: dim}} 下钻时，将维度字段 dim 追加到目标求值维度，并在该粒度上对指标求值。结果不会自动上卷到查询粒度，需要显式指定外层聚合（SUM／AVG／…）。目标维度由查询的 GROUP BY 和指标的 dimensions: 约束共同决定。必需字段必须出现，... 允许查询包含额外字段。没有维度修饰符时，指标引用已处于目标求值维度的粒度。将该引用包在 SUM() 中会失败，并报错“cannot aggregate a measure w/o +d modifier”。任何 SUM({measure}) 都需要 +d，这一要求也适用于没有 dimensions: 声明的指标。
-d: dim {measure: {-d: dim}} 从指标的求值维度中移除字段 dim，使求值粒度变粗。要移除多个字段，请使用列表形式 {-d: [dim1, dim2]}。像 {-d: dim1, -d: dim2} 这样重复指定同一个键会导致 YAML 重复键错误。如果指标声明了封闭的允许维度集合，其中必须至少有一项允许移除后得到的求值或查询维度。省略指标的 dimensions: 时，可使用任何兼容的维度。查询中针对已移除字段的 filters: 仍会下推到数据集的 WHERE 子句，这可能使比率的分母失真。参见下文的移除维度和筛选条件。
-df: dim {measure: {-df: dim}} 此修饰符合并了 -d 和 -f 的作用。它从求值维度中移除一个维度字段（-d），同时从指标求值中移除针对该字段的筛选条件（-f）。查询中的 filters: 如果引用已移除的字段或依赖该字段的列（包括通过 pk() 链形成的依赖），就不会下推到更粗粒度查询的 WHERE 子句。请使用列表形式 {-df: [dim1, dim2]}。这等价于 DAX 中的 CALCULATE(expr, REMOVEFILTERS(dim))。
-f: name {measure: {-f: name}} 仅在计算指标时移除引用 name 的筛选条件。name 可以是筛选器名称（在查询的 filters: 中定义），也可以是列名。通过 pk() 链形成的列依赖关系也纳入判断。请使用列表形式 {-f: [name1, name2]}。不会改变分组。查询筛选条件仍决定报表包含哪些行。如果被阻止的筛选条件所针对的列不属于输出粒度，请限制行集合（例如使用 EXISTS），而不要直接省略该筛选条件。
dimension: [dims] {measure: {dimension: [dim1, dim2]}} 将计算所用的全部维度替换为列出的维度字段。它与数据集、查询和物化属性共用 dimension: 标记，但在这里，它只修改一处指标引用，而不声明数据集标识、查询分组或物化键。语义与 -d 接近，但生成的 SQL 不同：使用独立的聚合 CTE，而不是窗口 OVER (PARTITION BY …)。参见常见问题 P43。跨时间粒度计算时（例如在 dt_month 粒度的查询中使用 {m:{dimension:[dt_quarter]}}），通过日历建立对应关系，将较粗粒度的合计填到对应的较细粒度各行，而不是使用单个总计值。

简明术语表（避免歧义） #

写法 含义
{销量: {+d: 门店}} 按查询粒度 ∪ {门店}计算，并停留在该粒度，不会自动汇总回原粒度。
SUM({销量: {+d: 门店}})（或 AVG/MAX/…） 先得到较细粒度的值，再通过外层聚合汇总回当前查询粒度。
{销量: {-d: 门店}} 从计算粒度中移除 门店。门店 上的筛选条件仍可能下推。
{销量: {-df: 门店}} 从粒度中移除 门店，并且阻止与 门店 相关的筛选条件作用于该指标。
{销量: {-f: 门店}} 仅阻止与 门店 相关的筛选条件，分组保持不变。

同一维度字段上的修饰符冲突 #

语言规范规定，在同一个修饰符对象中，+d 的字段集合不得与 -d 或 -df 的字段集合有交集。不同字段可以同时使用，例如 SUM({销量: {+d: 门店, -d: 品牌}})。自 2026-11-15 的修复起，编译器会拒绝同一字段上的冲突并报错 conflicting dimension modifiers +d and -d/-df for [fields]。此行为已在 2026-11-20 和 2026-11-23 的构建版本中验证。参见修饰符的组合。

-df：兼具 -d 和 -f 的作用 #

-df 结合了以下两个修饰符的语义。

  • -d（不按该字段分组）从计算指标所用的维度中移除一个维度字段，从而在较粗粒度上聚合。
  • -f（移除筛选条件）在计算指标时移除该维度上的筛选条件。查询的 filters: 中引用该维度或通过 pk() 链依赖该维度的列的筛选条件，不会下推到较粗粒度查询的 WHERE 子句中。

-df 是 {-d: dim, -f: dim} 的简写。两种写法编译生成的 SQL 完全相同。需要简写时，请使用 -df。

如果比率指标的分母必须同时忽略某个维度的分组和筛选，请使用 -df。

解决的问题：不使用 -df 时，查询的 filters: 中的筛选条件会在聚合之前下推到数据集的 WHERE 子句。当 -d 为比率的分母生成较粗粒度的临时表时，分母基于筛选后的数据计算，因此会变小。-df 会阻止指定维度上的这类下推。筛选条件仅应用于粒度包含该维度的临时表，粒度已移除该维度的临时表不应用该条件。

何时使用 -df 或 -d

场景 修饰符 原因
比率的分母必须包含某个维度的所有值（例如，品牌销售额占比 = 该品牌销售额 / 所有品牌的销售总额）。 -df 如果下推 brand_id 上的筛选条件，分母就会变小。
比率的分母应反映筛选后的子集（例如，仅在所选品牌范围内计算占比）。 -d brand_id 上的筛选条件应同时应用于分子和分母。
已移除的维度字段上没有筛选条件 -d（或效果相同的 -df） 没有需要阻止的筛选条件。

示例：各门店内的品牌销售额占比。分子保留所选品牌，分母包含所有品牌。

brand_share:
    type: measure
    formula: 'divide({sales} * 100.0, {sales: {-df: brand_id}})'

在查询粒度为 [store_id, brand_id] 时，brand_id 上的查询筛选条件应用于分子。分母移除该字段及其筛选条件，同时保留门店上下文。

依赖关系追踪。编译器会追踪 pk() 链上的依赖关系。对 store_id 应用 -df 时，客户标准名称（pk({store_id}).MDM_STORE(store_id).store_name）上的筛选条件会被阻止，因为该列依赖于 store_id。

其他系统中的对应做法

系统 对应做法 语法
DAX（Power BI） CALCULATE(expr, REMOVEFILTERS(dim)) 在一次操作中移除分组和筛选上下文。
Tableau 无直接对应功能 将 FIXED LOD 与上下文筛选器（Context Filter）结合使用，或使用表计算筛选器（Table Calculation Filter）。
Malloy 无直接对应功能 使用阶段级的 where:（聚合后），而不是源级的 where:。
LookML 无直接对应功能 使用带筛选条件的指标（在指标上设置 filters:）。 
-- Product share within category
SELECT category, product,
       AGG(sales) as product_sales,
       AGG({sales: {dimension: [category]}}) as category_total
FROM MODEL GROUP BY category, product

-- Remove time grouping while retaining the selected time filter
SELECT region, AGG({sales: {-d: dim_dt}}) as selected_period_sales
FROM MODEL WHERE dt_month = date(current_date, 'start of month')
GROUP BY region

在使用 FULL OUTER JOIN 的复合指标中使用 {-d:} #

独立的指标数据集通常在对齐的计算粒度上组合（取键的并集）。对齐时，对完整的分组键进行NULL 安全的相等比较。如果其他维度一致，键中同一位置上的 NULL 值就会对齐。指定为保留行的 LEFT JOIN 和 nullpk 关联也使用 NULL 安全的相等比较。有关行集合、键的唯一性和缺失行的填充，请参见跨数据集组合和联接中的 NULL 相等比较。

要确定主侧行集合，请使用未填充值的存在性指标。该指标必须保证主侧实际存在的每个分组都返回非 NULL 值，缺失的分组则返回 NULL。对于 INNER 行集合，分组必须在两侧都存在。任意业务指标在有效分组中也可能为 NULL，而填充过的指标在缺失分组中也可能为非 NULL 值。两者都无法可靠地判断分组是否存在。仅靠涉及 NULL 的算术运算，无法移除仅存在于次侧的输出行。

组合修饰符 #

可在同一个引用中组合多个修饰符，但必须遵守同一维度中的冲突规则和修饰符约束：

# Filter + dimension (outer SUM rolls +d back to query grain)
formula: 'SUM({sales: {+d: customer, +f: {region: "North"}}})'

# Legal: +d and -d on DIFFERENT fields
formula: 'SUM({sales: {+d: customer, -d: brand}})'

# Rejected: the same field cannot appear in +d and -d or -df in one modifier object:
# formula: 'SUM({sales: {+d: store_id, -d: store_id}})'
# formula: '{sales: {+d: store_id, -df: store_id}}'

# Time + dimension
formula: '{sales: {+d: customer}, yoy}'

# Dimension + rank
formula: '{sales: {-d: dim_dt, rank}}'

# Dimension + filter removal (ratio with deferred filters)
formula: 'divide({sales: {-df: brand_id}} * 100.0, {sales: {-df: [store_id, brand_id]}})'

# Filter + absolute grain (e.g., ratio numerator/denominator at different grains)
formula: 'DIVIDE({sales: {+f: "status = 1", dimension: [prod_id]}}, {sales: {+f: "status = 1", dimension: [prod_id, store_id]}})'

在 Model Query SQL 中：

SELECT product,
       AGG({sales: {-d: dt_date, rank}}) as all_time_rank
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY product

串联修饰符 #

可在一个表达式中串联多个宏。编译器会自动创建与用户手动定义时相同的中间指标。

语法：{measure: {macro1, macro2, macro3}} 或 AGG(measure, 'macro1', 'macro2', 'macro3')

在常规串联中，第一个宏转换原始指标，下一个宏应用于得到的中间指标。时间修饰符与包含多个分支的函数组合时，也会转换这些分支，如下文所述。下面是一个顺序应用的示例。

# Stacking: yoy creates intermediate "sales_yoy", then rank applies to it
# Equivalent to:
#   sales_yoy:
#     type: measure
#     formula: '{sales: yoy}'
#   ...then: {sales_yoy: rank}
q_col: '{sales: {yoy, rank}}'

时间修饰符与多路径函数： 在已验证的构建版本中，编译器将 ytd 应用于 yoy 的当前期间分支和比较期间分支。在记录的月度验证中，{sales: {yoy, ytd}} 和 {sales: {ytd, yoy}} 生成了完全相同的 SQL：用 YTD 销售额除以上一年的 YTD 销售额，再减去 1。该结果不是各月增长率之和。请勿按类别对修饰符排序，也不要仅凭自动生成的中间指标名称推断出不同的含义。

firstday 等宏会改变定义行或汇总值时所用的层级，在多路径计算中还受额外约束。使用前，请编译实际要用的组合并检查编译结果。编写含 YAML 指示符的 +f 表达式时，请用引号括起表达式，例如 {sales: {+f: "amount > 5", yoy}}。

复用中间指标。 创建新的中间指标前，编译器会在现有指标中查找公式相同的指标，匹配时会考虑展开式、简写形式或映射形式。如果用户定义的指标或先前生成的指标匹配，编译器就会复用它。这样可以避免创建重复的中间指标，也便于用户自行指定中间指标的名称。

处理名称冲突。 如果自动生成的中间指标名称（如 sales_yoy）与某个现有指标同名，但公式不同，编译器会追加数字后缀，得到 sales_yoy__2、sales_yoy__3 等名称。

兼容性： 宏的前置条件、时间上下文、允许使用的维度、键是否重复以及重新聚合都会影响串联是否有效。请在目标构建版本上编译实际要用的组合。同时使用两个范围宏或重复使用宏键，并不是通用的组合方式。如果显式写出各个阶段后仍有错误，请保留诊断信息和复现用例。仅为中间指标手动命名，无法证明两种写法等价。

修饰符速查 #

修饰符只调整本次指标引用。用 {sales: {+f: {status: completed}}} 限定该指标的输入。用 +d 增加计算分组，再用外层聚合回到报表分组。用 -d 移除分组维度，用 -df 同时移除该维度上的相关筛选。期间修饰符 pp 取上期，pop 算环比，ytd 算年初至今。多个修饰符按声明顺序应用。

复合比率的时间修饰符 #

时间修饰符可直接应用于具名的复合指标。例如，用 formula: '{gross_margin: ytd}' 定义 gross_margin_ytd，其中 gross_margin 用毛利润除以营业收入。在累计期间内，系统先重新计算所依赖的指标，再计算比率，不会把各月的百分比相加。参见完整的盈利能力示例。这个经过验证的比率示例并不保证任意非可加公式都能在不检查其计算含义的情况下向上汇总。

固定轴汇总与输出行范围 #

固定汇总示例使用普通的 month 字段，查询按地区和月份分组。选中一月时，-d: month 的分母仍只计入一月，而 -df: month 的分母计入测试数据中的两个月。两个查询仍然只输出一月的行。这个测试用例无法验证动态透视轴、小计级谓词或任意情况下移除 dim_dt 的行为。
