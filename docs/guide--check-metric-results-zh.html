核对指标结果的三个例子

本页目录
  • 年初至今毛利率是 25%
  • 二月报表仍能取到一月销售额
  • 查找键重复，销售额可能从 30 变成 60

下面用三组可重跑的样例，核对累计比率、比较期和查找键。每组都给出可对照的数值或诊断。

年初至今毛利率是 25% #

北区一月收入 100、成本 60，二月收入 300、成本 240。两个月的毛利率分别是 40% 和 20%，算术平均是 30%。年初至今的毛利率按累计收入和成本计算，结果是 (400 − 300) ÷ 400 = 25%。

模型先汇总年初至今的净收入和销售成本，再用净收入减去成本，除以净收入，得出累计毛利率。打开累计毛利率指南，对照月度和累计结果并查看模型。指南区分了 DuckDB 执行与 SQL Server 编译的证据。

二月报表仍能取到一月销售额 #

报表只显示二月。北区二月销售额为 30，一月为 20，环比增长 50%。如果 SQL 在计算 LAG 之前就筛掉一月，二月便少了比较值。模型用 {销售额: pp} 在二月报表中取到上月销售额。先在时间上下文一课切换月份，再用 DuckDB 销售练习核对上月销售额一列。

报表有固定起止月份时，请写明范围。参见比较期怎样影响报表行。

查找键重复，销售额可能从 30 变成 60 #

北区两笔销售合计 30。地区表里有两行北区时，每笔销售都匹配两次，关联后的合计就成了 60。在重复键一课查看多出的行，再用 DuckDB 复合键练习跑一遍正常通过、制造重复、修复后再通过的过程。失败报告中会有 VALIDATION_ERROR，在 data.issues 下可查看冲突键。

用 --validate 获取校验报告。执行查询时加 --with-validation，遇到键校验失败就会停止。业务结果还要在同一份数据上用独立 SQL 对账。参见编译、校验与对账。
