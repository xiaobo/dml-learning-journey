Diese Einträge behandeln die Validierung, das Erfassen der CLI-Ausgabe, Dialekte und Dateinamen von Modellen. Der Befehlsablauf ist unter Kompilieren und validieren beschrieben.

P34. Eine Abfrage ohne vorherige Validierung als verlässlich verwenden #

Fehler: Eine Abfrage schreiben und sofort ohne Validierung ausführen, obwohl eine Datenbankvalidierung verfügbar ist. Abhilfe: Führen Sie die Abfrage mit --with-validation über die vorgesehene Verbindung aus oder erstellen Sie mit --validate einen Bericht. Die Validierung erkennt Kompilierungsfehler, prüft die vollständigen Dimensionen der von der Abfrage erreichten Datensätze anhand der vorgefundenen Daten und prüft die Hauptabfrage mit EXPLAIN. Sie belegt weder die Korrektheit der Ergebnisse noch die künftige Eindeutigkeit. Voraussetzung: Für die Validierung sind ein ausführbares Programm mit --validate und eine konfigurierte Verbindung erforderlich. Prüfen Sie --help und --advanced-help. Fehlt eine der beiden Voraussetzungen, vermerken Sie die Datenbankvalidierung als nicht ausgeführt. Siehe Validierung an der Datenbank.

P35. Spaltenbeschreibungen ignorieren #

Fehler: customer_name verwenden, obwohl die Beschreibung „Nur für den internen Gebrauch. Verwenden Sie stattdessen customer.“ lautet. Abhilfe: Lesen und beachten Sie die Spaltenbeschreibungen. Ersetzen Sie interne Felder durch ihre öffentlichen Aliase.

P36. Nicht passender Dialekt #

Fehler: Davon ausgehen, dass MSSQL jeden Datumsausdruck aus SQLite unverändert akzeptiert. Abhilfe: DML übersetzt unterstützte Datumsausdrücke im Stil von SQLite in den Zieldialekt. Prüfen Sie das erzeugte SQL und testen Sie genau den verwendeten Ausdruck. Für nicht unterstützte Formen benötigen Sie eine Alternative im jeweiligen Dialekt. Siehe Datumsausdrücke.

Kategorie: Compiler, YAML und Benennung #

P53. Befehlsverkettung in PowerShell mit && #

Falsch: cd path && dmlc --model=model.dml query.sql Korrektur: cd path; dmlc --model=model.dml query.sql

P53b. Name in FROM ≠ Dateiname bei --model= #

Fehler: dmlc q.sql --model=acme.dml mit SQL SELECT AGG(x) FROM MODEL
→ model file "acme.dml" does not match FROM "MODEL" (expected "MODEL.dml") (Exit-Code 65).
Abhilfe: Ändern Sie die FROM-Klausel in FROM acme, verwenden Sie --model=model.dml und behalten Sie FROM MODEL bei oder geben Sie das Verzeichnis an, das die passende .dml-Datei enthält (--model=<dir> findet darin <FROM>.dml).
Hinweis: dmlc -e weist Verzeichnisse zurück und benötigt eine .dml-Datei. Siehe Modellabfragen in SQL, Abschnitt „Abfragetypen“.

P63. Der Operator / in Modellabfragen, die unter Windows direkt in der CLI als SQL übergeben werden #

Symptom: file not found: SELECT .... Wegen des / in a / b behandelt die CLI die SQL-Zeichenfolge als Dateipfad. Abhilfe: Verwenden Sie DIVIDE(a, b), wenn Sie die Abfrage direkt an die CLI übergeben, oder übergeben Sie die Abfrage über eine .sql-Datei statt als Befehlszeilenargument.

P54. JSON mit CJK-Zeichen über eine PowerShell-Pipe #

Fehler: Bei chinesischen Feldnamen dmlc ... | Out-File result.json verwenden oder die Standardausgabe erfassen. Abhilfe: Verwenden Sie dmlc ... --output=result.json --replace oder in Node execSync(..., { encoding: 'utf8' }).

CLI-Optionen nach Build #

Ermitteln Sie anhand des Build-Zeitstempels und der Hilfe des ausführbaren Programms, welche Aufrufregeln gelten.

Frühere Option Geprüfter Build
--output-format=json --json für einen strukturierten CLI-Bericht
--output-dir=gen --artifacts=gen für Compiler-Artefakte
--validate-only bei einer Modellabfrage --validate für einen eigenständigen Validierungsbericht

Explain-change verwendet für seine eigene Vorabprüfung weiterhin --validate-only. Bei der Abfrageausführung sorgt --with-validation dafür, dass die Ausführung bei fehlgeschlagener Validierung abbricht, bevor Zeilen zurückgegeben werden.

SQL-Syntaxprüfungen #

Im Build vom 2026-11-23 kann --check --json trotz eines Parserfehlers Erfolg melden, etwa bei QUALIFY. Verwenden Sie den Exit-Code und die Diagnosemeldungen des Vorgangs, den Sie benötigen, etwa der strikten Kompilierung für eine Modellabfrage oder von --to-dml für die Konvertierung.

Kalendereinrichtung schlägt bei der Validierung fehl #

Wenn für DML_CALENDAR ein Berechtigungsfehler auftritt, prüfen Sie das ausgewählte Schema und die Rolle der Verbindung. Initialisieren Sie den Systemkalender über die Einrichtung des Systemkalenders mit einer Rolle, die Tabellen erstellen und Zeilen einfügen darf. Führen Sie anschließend die Validierung mit der Laufzeitrolle erneut aus.
