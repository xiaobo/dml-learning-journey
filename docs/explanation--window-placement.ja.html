ウィンドウ計算の結果は、評価段階で利用できる行によって決まります。明細ウィンドウは後続の指標集計より前に処理されます。複合式のウィンドウは、集計済みの指標の結果を入力とします。

計算 配置 入力行
各ソース行の属性 データセットの columns: に定義した計算列 明細行
グループ別に集計した指標の順位または割合 dataset: を含まない複合式 集計後の行
OVER を含むアトミック指標 検証したビルドでは拒否される サポートされる配置なし

生成された SQL を確認し、各ウィンドウがどの段階で評価されるかを確かめてください。コンパイル、データベースでの実行、結果の比較は、それぞれ別の検証項目です。

明細ウィンドウ #

取引記録:
  type: dataset
  table: FACT_SALES
  dimension: [売上明細番号]
  columns:
    売上明細番号:
      abbr: id
    顧客:
      abbr: customer
    地域:
      abbr: region
    売上金額:
      abbr: amount
    顧客別取引額: 'SUM({売上金額}) OVER (PARTITION BY {顧客})'
  measures:
    明細行別顧客取引額: 'SUM({顧客別取引額})'

このウィンドウは、顧客ごとの合計を、その顧客のすべての明細行に表示します。計算列を合計すると、同じ顧客の合計がソース行ごとに1回ずつ加算されます。結果は顧客ごとの合計を重複排除したものではありません。この例はウィンドウの配置を示すためのもので、推奨される売上指標ではありません。

行の順序に依存するウィンドウの結果は、並べ替え順、ウィンドウフレーム、同順位を解消するキー、対象となるソース行の集合にも左右されます。フィルターを適用する段階を変えると、パーティション内のすべてのウィンドウ結果が変わることがあります。

明細ウィンドウでは、集計前に最後の観測値を選ぶこともできます。dt_month と 売上金額 があるソースでは、検証済みのパターンで次の列と指標を追加します。

# Under the dataset's columns:
前月フラグ: 'IIF({dt_month} = MAX({dt_month}) OVER (), 1, 0)'
# Under the same dataset's measures:
前月収益: 'SUM({売上金額} * {前月フラグ})'

MAX(...) OVER () は、明細ウィンドウの入力から最新の月を1つ選びます。指標は、その月の金額だけを合計します。エンティティ単位のパーティションはありません。あるエンティティにその月の観測値がなければ、そのエンティティの直近の残高は繰り越されません。在庫や口座残高に式を採用する前に、「最後」をエンティティごとに決めるのか全体で決めるのか、観測値がない場合にどう扱うのか、どのフィルターでウィンドウの対象を絞るのかを定義してください。

集計後のウィンドウ #

アトミック指標 売上高: SUM({売上金額}) をもとに、この複合式は集計後の売上額に順位を付けます。

顧客順位:
  type: measure
  formula: 'rank() over (partition by {-d: 顧客} order by {売上高} desc)'

クエリの行を [地域, 顧客] の粒度で定義すると、パーティション式にはクエリのほかのフィールド（ここでは 地域）が残ります。検証した SQL は、地域と顧客でグループ化した後、地域ごとに SUM(amount) に順位を付けます。ファクトデータの物理行は、順位付けの入力にはなりません。

+d により、より細かい粒度で集計する段階が設けられます。これによってグループ化された値が明細ウィンドウの属性に変わることはありません。ソースのフィルター、ウィンドウ結果に対するフィルター、最終レポートのフィルターでは、選択される行の集合が異なることがあります。

Model Query は、検証済みのウィンドウ式を直接記述する形式も受け付けます。利用できるクエリのインターフェースについては、クエリリファレンスを参照してください。ある形式が受け付けられても、任意のウィンドウフレームや方言がサポートされるとは限りません。

行ベースのウィンドウと暦上の期間 #

集計後の行ベースのウィンドウは、その評価段階に残っている行を並べ替え順に使用します。累計売上のクエリをウィンドウの評価前に2月に絞り込むと、1月の行は除外されます。累計を求める名前付きクエリの例では、このフィルター適用時の動作と、再利用可能なウィンドウ指標を検証しています。

業務上の定義が、明示的に指定した終了日までの暦上の期間であれば、ytd などの時間マクロを使用します。選択した行を並べ替え、その順序に基づく範囲で計算する定義であれば、行ベースのウィンドウを使用します。欠けている月、フィルターを適用する段階、同順位の行の並べ方によって、フレームに含まれる行が変わることがあります。SUM ウィンドウが機能しても、累積の重複排除件数や累積比率が機能するとは限りません。それぞれの定義を個別にテストしてください。
