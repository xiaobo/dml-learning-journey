例を再現する #

プロジェクトをダウンロードし、新しいフォルダーに展開します。そのフォルダーから純収益の例を実行します。

cd net-revenue
dmlc -q setup.sql
dmlc -q --with-validation --model=model.dml monthly.sql
dmlc -q --with-validation --model=model.dml regional.sql
cd ..

すべての例を自動で検証するには、プロジェクトのフォルダーでPowerShellから次のコマンドを実行します。

./verify.ps1 -Output practice-output

実行のたびに新しい出力フォルダーを指定してください。

再現実行が成功すると、各ケースの最終ステータスは合格になり、results.json、未加工の診断出力、生成された SQL が出力ディレクトリに保存されます。失敗が想定されているケースでは、まず指定された診断メッセージが出て失敗し、修正後に成功する必要があります。パッケージに含まれる README には、JDBC での実行方法も記載されています。パッケージには人が読める形式のソースと期待される出力が含まれます。コンパイラのバイナリやサードパーティ製のランタイムは含まれません。JDBC の検証には、JDK と対応する JAR ファイルが別途インストールされている必要があります。

コンパイル、実際のデータベースでの検証、実行、結果の比較は、それぞれ独立した確認項目です。意図的に不正な内容を含めたケースでは、想定どおりに失敗し、修正後に検証に合格する必要があります。自分のテーブルに置き換える前に、キーが完全であることと、使用する時刻関連のフィールド、グループ化、フィルターの適用範囲を確認してください。

あるデータベースで例が成功しても、すべての方言や指標、あるいは行や集計値を定義するすべての粒度で同様に動作することが確認できたわけではありません。構文は言語リファレンスで定義されています。これらのガイドでは、具体的な課題を取り上げ、結果を再現できる形で解決方法を示します。
