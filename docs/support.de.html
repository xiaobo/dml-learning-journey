Speichern Sie zuerst die vollständigen Diagnoseinformationen und grenzen Sie die Untersuchung dann auf eine Kennzahl ein. Eine erfolgreiche Kompilierung belegt nicht, dass die Quellschlüssel zu den Daten passen. Eine bestandene Validierung ersetzt nicht die fachliche Prüfung der Ergebnisse.

Symptom Nächster Schritt
Modell nicht gefunden Prüfen Sie den Dateinamen und den Namen in FROM. Siehe Regeln zum Auffinden von Abfragen.
Kompilierungsfehler Speichern Sie den Exitcode und die JSON-Ausgabe. Siehe Referenz der Fehlercodes.

Unterlagen zur Reproduktion vorbereiten #

Speichern Sie die Ausgabe von dmlc --version, den Befehl, den Exitcode, die vollständigen Diagnoseinformationen, ein minimales Modell bzw. eine minimale Abfrage, bereinigte Eingabedaten und das erwartete Ergebnis. Entfernen Sie Passwörter, Token, echte Verbindungszeichenfolgen und personenbezogene Daten. Geben Sie Feedback über Ihren bestehenden Produktkontakt. Auf dieser Website ist noch kein öffentlicher Supportkanal aufgeführt. Übermitteln Sie daher keine privaten Daten an projektfremde Repositorys.

Versionen und bekannte Einschränkungen #

Beobachtungen zu einem bestimmten Build gelten nur für den dokumentierten Build und seine Testdaten. Frühere Probleme sind keine Fehlerliste für die aktuelle Version. Wenn Sie eine Abweichung feststellen, reproduzieren Sie sie mit dem aktuellen Compiler und speichern Sie den generierten SQL-Code. Prüfen Sie zuerst den Validierungsstatus der Vertriebsübung. Kennzeichnen Sie andere Dialekte oder nicht ausgeführte Szenarien als „not verified“.
