如果重复执行的查询可以复用按固定粒度存储的聚合结果，请使用物化。声明语法和适用条件以物化参考文档为准。

查询性能与 materialize 设计原则 #

提升查询性能的简明检查清单：

  • 确保时间列遵循 dt_date/dt_week/dt_month/dt_quarter/dt_year 约定（取周期的第一天）。
  • 优先使用少量可复用的指标（例如 sales、qty），避免为单次用途创建大量指标。
  • 让 Model Query 的 SQL 保持简单：使用 FROM MODEL，选择查询的维度字段和 AGG(measure)，再使用 GROUP BY 分组。
  • 如果重复聚合导致查询变慢，请在合适的粒度上添加 materialize。

何时使用 materialize：查询反复按固定粒度聚合相同的基础数据（例如按商品、门店或类别做月度汇总），且数据仅追加或可按周期刷新。如果数据量很小、粒度按查询临时确定，或模型语义仍在探索中，请避免使用。

粒度设计原则：

  1. 粒度决定了数据行或汇总值在哪个层级定义。粒度应足够细，以支持后续向上汇总，同时避免因过细而导致行数激增。常见粒度包括 DWD（按天加键字段）、DWS（按月或季度加分析维度）和 ADS（可直接用于报表）。
  2. 存储销售额、数量等可加指标，以便后续向上汇总。除非各组的客户集合互不重叠，否则不要将各组的去重客户数相加。保留实体键，或确认存在可用于预期汇总的受支持的数据表示形式。
  3. 将唯一标识数据行的字段放在 dimension: 中。将具有函数依赖关系的属性放在 dimension_columns: 中，例如由 category_id 派生的 category_name。请参阅物化声明规则。
DWS_SALES_DATE_CATEGORY:
    type: materialize
    parameters:
        dt_date: date
    dimension:
        - dt_date
        - category_id
        - cust_id
    measures:
        - 销售额
        - 销售量

materialize 是建模阶段的优化概念。将数据集作为物理表持久化到 DuckDB 是一项独立操作。有关完整示例，请参阅物化示例。

请按照物化工作流程进行设置、验证查询是否命中物化结果、执行刷新并检查结果。
