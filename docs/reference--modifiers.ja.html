修飾子に指定する値の構造 #

{measure: {modifier_a: 値, modifier_b: 値}}では、外側のオブジェクトに対象指標を示すキーがちょうど 1 つあります。内側の修飾子マップには、修飾子の制約を満たす範囲で複数のキーを指定できます。

キーまたは指定形式 指定する値
dim_dt 数式を表す文字列、または 値 と range のフィールドを持つオブジェクト
dim_dt as date, dim_dt as week, dim_dt as month, dim_dt as quarter, dim_dt as year, dim_dt as hour 期間変換のバリエーション。修飾子オブジェクトごとに、時間に関するバリエーションは最大 1 つです。
+f フィルター名を表す文字列、フィルター名のリスト、または {column: 値} のようなインラインオブジェクト
-f フィルター名または列名を表す文字列、もしくはそれらの名前のリスト
修飾子名のみ dt-macro または fn-macro の名前

時間修飾子 #

システムマクロの参照用コピーには、時間をずらす dt-macro の定義と、数式をラップする fn-macro の定義が含まれます。成長率マクロは比率を小数で返します。利用できるマクロと数式、および prerequisite の制約は、選択した実行ファイルに同梱されたリソースで決まります。

2 種類のマクロ

種類 戻り値 例
dt-macro 指標そのものの値 pp, ya, ytd, mat, p3m, ...
fn-macro（成長率） 小数で表した比率 pop, yoy, mom

重ねがけ。修飾子は重ねて適用できます。AGG(売上高, 'ytd', 'ya') は、前年の年初から前年の同じ基準日までの値を返します。適用時の詳しいルールは、修飾子の重ねがけを参照してください。

時間コンテキスト。時間修飾子を使用するには、dim_dt を解決でき、対応するマクロの前提条件を満たしている必要があります。時間フィールドでグループ化すると、コンテキストが最も明確になります。時間フィルターでもコンテキストを指定できます。Model Query の時間ルールを参照してください。

dim_dt を使った期間変換

SELECT dt_year, dt_quarter,
       AGG({売上高: {dim_dt as quarter: pp}}) as 前四半期売上高
FROM MODEL GROUP BY dt_year, dt_quarter

dim_dt as quarter を指定すると、クエリが年と四半期でグループ化されていても、pp は四半期単位で処理されます。

関数修飾子 #

システムマクロの参照用コピーでは、rank、pot、grand、firstday、lastday などのマクロを定義しています。利用できる名前、数式、前提条件は、選択した実行ファイルに同梱されたリソースで決まります。未知の修飾子に対する診断メッセージには、確認対象のビルドで利用できる名前が表示されます。

フィルター修飾子 +f はスキーマレベルの修飾子です。システムマクロではありません。

修飾子 構文 戻り値 説明
+f: condition {measure: {+f: {col: val}}} フィルター適用後の値 集計時に指標をフィルターする

+f はアトミックな入力行を絞り込みます。集計後に適用する述語ではありません。

対象 / 述語 動作
アトミックな集計内の列 その集計への入力を絞り込む
アトミック指標 + ソース列に対する述語 サポートされています。たとえば、{売上高: {+f: "注文状態 = 1"}} は条件付きの SUM を生成します。
単純な複合指標 + ソース列に対する述語 フィルターは依存先のアトミック指標に伝播します。この動作は divide({売上高}, {売上件数}) で確認済みです。依存先のすべてにフィルターを適用する場合にのみ使用してください。
+d とソース列に対する +f を指定したアトミック指標 確認した AVG によるロールアップではサポートされています。細かい粒度での集計より先にフィルターが適用されることを確認してください。
集計指標を参照する述語。例は "{売上件数} > 3" cannot use +f modifier with measure(s) というエラーで拒否されます。細かい粒度でのフィルターの例に従ってください。

フィルターを指定したアトミック指標への参照は、単独では現在のクエリの粒度で評価されます。エンティティごとの値を求める場合は、+d と明示的な外側の集計を維持してください。特に AVG、MIN、MAX、COUNT を使う場合に重要です。条件付きの SUM は、条件を満たす入力がなければ NULL を返します。ELSE 0 を明示した場合は意味が異なります。入力行を選別しても、条件を満たさない行だけを含むグループが残ることがあります。

ウィンドウ関数の fn マクロは、コンパイル済みの SQL に rank() over (...) を生成します。Model Query の SQL では、AGG(measure, 'rank') または AGG({measure: rank}) の形式で使用します。完全な一覧と数式については、system_macros.dmlを参照してください。

.dml でのフィルター修飾子（列が対象）

完了注文の売上高:
    type: measure
    formula: "{売上金額: {+f: {注文状態: 'completed'}}}"

Model Query の SQL でのフィルター修飾子

SELECT AGG(売上高, '+f', 地域 = 'North') FROM MODEL

ディメンション修飾子 #

修飾子 構文 効果
+d: dim {measure: {+d: dim}} ドリルダウンでは、評価対象のディメンションにフィールド dim を追加し、その粒度で指標を評価します。結果はクエリの粒度へ自動でロールアップされません。明示的な外側の集計（SUM／AVG／…）が必要です。評価対象のディメンションは、クエリの GROUP BY と指標の dimensions: 制約で決まります。必須フィールドは含める必要があり、... を指定するとクエリに追加のフィールドを含められます。ディメンション修飾子がない場合、指標参照はすでに対象のディメンションの粒度にあります。この参照を SUM() で囲むと、「cannot aggregate a measure w/o +d modifier」というエラーになります。+d は SUM({measure}) のすべての使用箇所で必要です。dimensions: 宣言のない指標にも適用されます。
-d: dim {measure: {-d: dim}} 指標の評価ディメンションからフィールド dim を除き、評価の粒度を粗くします。複数のフィールドを除くには、リスト形式の {-d: [dim1, dim2]} を使います。{-d: dim1, -d: dim2} のようにキーを繰り返すと、YAML でキーの重複エラーになります。指標が許可するディメンションを限定して宣言している場合は、そのうち少なくとも 1 つが、除外後の評価ディメンションまたはクエリのディメンションを許可する必要があります。指標の dimensions: を省略すると、互換性のあるディメンションをすべて使用できます。除外したフィールドに対するクエリの filters: は、引き続きデータセットの WHERE にプッシュダウンされます。このため、比率の分母が意図しない値になることがあります。後述のディメンションとフィルターの除外を参照してください。
-df: dim {measure: {-df: dim}} この修飾子は、-d と -f の両方の効果を持ちます。評価ディメンションからフィールドを除く（-d）とともに、そのフィールドに対するフィルターを指標の評価から除きます（-f）。除外したフィールド、またはそのフィールドに依存する列（pk() の連鎖を介して依存する列も含む）を参照するクエリの filters: は、粒度を粗くしたクエリの WHERE にプッシュダウンされません。リスト形式の {-df: [dim1, dim2]} を使います。DAX の CALCULATE(expr, REMOVEFILTERS(dim)) と同等です。
-f: name {measure: {-f: name}} nameを参照するフィルターを指標の評価時に限って除外します。nameには、クエリのfilters:で定義したフィルター名、または列名を指定できます。pk()チェーン経由の依存関係も対象です。リスト形式{-f: [name1, name2]}を使用します。グループ化は変更されません。レポートの行集合は引き続きクエリフィルターで決まります。ブロックしたフィルターの対象列が出力粒度を定める列に含まれない場合は、そのフィルターを暗黙に省略せず、EXISTSなどで行集合を絞り込みます。
dimension: [dims] {measure: {dimension: [dim1, dim2]}} 評価に使うディメンション全体を、指定したディメンションフィールドに置き換えます。データセット、クエリ、マテリアライズのプロパティと同じトークンdimension:を使いますが、ここではデータセットの識別、クエリのグループ化、マテリアライズのキーを定義するのではなく、1 つの指標参照を変更します。意味は-dに近いものの、生成されるSQLは異なります。ウィンドウのOVER (PARTITION BY …)ではなく、独立した集計CTEを生成します。注意点 P43を参照してください。時間の粒度が異なる場合（例として、dt_monthのクエリで{m:{dimension:[dt_quarter]}}を使用する場合）は、カレンダーを介して対応付け、粗い粒度の合計を対応する細かい粒度の各行に展開します。全体の合計を単一の値として使うわけではありません。

用語集（曖昧さを避けるために） #

書き方 意味
{销量: {+d: 门店}} クエリの粒度 ∪ {门店}で評価し、その粒度で処理を終えます。元の粒度への再集計は自動では行われません。
SUM({销量: {+d: 门店}})（またはAVG/MAX/…） 細かい粒度で値を求めた後、外側の集計で現在のクエリ粒度に戻します。
{销量: {-d: 门店}} 評価粒度から 门店 を除外します。门店 に対するフィルターは引き続き下位のクエリにプッシュダウンされることがあります。
{销量: {-df: 门店}} 粒度から 门店 を除外し、さらにその指標で 门店 に関連するフィルターをブロックします。
{销量: {-f: 门店}} 门店 に関連するフィルターだけをブロックします。グループ化は変わりません。

同じディメンションフィールドに対する修飾子の競合 #

言語仕様では、1 つの修飾子オブジェクト内で、+dのフィールド集合が-dまたは-dfのフィールド集合と重複することを禁止しています。SUM({销量: {+d: 门店, -d: 品牌}})のように、異なるフィールドなら併用できます。2026-11-15の修正以降、同じフィールドで競合すると、コンパイラはconflicting dimension modifiers +d and -d/-df for [fields]を返してコンパイルを拒否します。2026-11-20と2026-11-23のビルドで確認済みです。修飾子の組み合わせを参照してください。

-df：-dと-fの組み合わせ #

-dfは、次の 2 つの修飾子の動作を組み合わせます。

  • -d（グループ化の対象から外す）は、指標の評価に使うディメンションからフィールドを 1 つ除外し、より粗い粒度で集計します。
  • -f（フィルターを除外する）は、そのディメンションのフィルターを指標の評価から除外します。クエリのfilters:にあるフィルターのうち、そのディメンション、またはpk()チェーンを介してそのディメンションに依存する列を参照するものは、粗い粒度のクエリのWHERE句にプッシュダウンされません。

-dfは{-d: dim, -f: dim}の短縮形です。どちらもコンパイルすると同一のSQLが生成されます。短く書くには-dfを使います。

比率指標の分母で、あるディメンションによるグループ化とフィルタリングの両方を無視する必要がある場合は、-dfを使います。

解決する問題：-dfを使わない場合、クエリのfilters:のフィルターは集計前にデータセットのWHERE句へプッシュダウンされます。-dが比率の分母用に粗い粒度の一時テーブルを生成すると、フィルター適用後の元データから計算するため、分母が小さくなります。-dfは、指定したディメンションに対するこのプッシュダウンをブロックします。フィルターは、そのディメンションを粒度に含む一時テーブルにだけ適用され、そのディメンションを粒度から除外した一時テーブルには適用されません。

-dfと-dの使い分け

ケース 修飾子 理由
比率の分母にディメンションのすべての値を含める必要がある（例：ブランドの売上シェア = そのブランドの売上 / 全ブランドの総売上） -df brand_idのフィルターをプッシュダウンすると、分母が小さくなる。
比率の分母に、フィルターで絞り込んだ範囲を反映する（例：選択したブランド内だけでのシェア） -d brand_idのフィルターを分子と分母の両方に適用する。
除外したディメンションフィールドにフィルターがない -d（または同じ結果になる-df） ブロックするフィルターがない。

例：店舗ごとのブランドの売上シェア。分子では選択したブランドを対象とし、分母には全ブランドを含めます。

ブランド売上構成比:
    type: measure
    formula: 'divide({売上高} * 100.0, {売上高: {-df: brand_id}})'

クエリ粒度が[店舗番号, brand_id]の場合、brand_idに対するクエリフィルターは分子に適用されます。分母ではそのフィールドとフィルターを除外し、店舗のコンテキストを維持します。

依存関係の追跡。コンパイラはpk()チェーンの依存関係をたどります。客户标准名称（pk({店舗番号}).MDM_STORE(店舗番号).店舗名）は店舗番号に依存するため、店舗番号に-dfを適用すると、この列に対するフィルターがブロックされます。

FULL OUTER JOINを使う複合指標での{-d:} #

独立した指標データセットは通常、評価粒度をそろえて組み合わせます（キーの和集合）。粒度をそろえる際は、グループ化キー全体をNULLセーフな等価比較で照合します。キーの同じ位置にNULLがある場合、ほかのディメンションが一致すれば対応付けられます。行を保持するよう指定されたLEFT JOINおよびnullpkによる結合でも、NULLセーフな等価比較を使います。対象となる行集合、キーの一意性、欠落行の補完については、データセットをまたぐ組み合わせと結合時のNULLの等価比較を参照してください。

主側の行集合を決めるには、補完なしの存在判定用の指標を使います。この指標は、主側に実在する各グループでは必ず非 NULL になり、存在しないグループではNULLになる必要があります。INNERの行集合には、両側に存在するグループだけを含めます。任意の業務指標は、有効なグループでもNULLになることがあります。また、補完された指標は、存在しないグループでも非 NULL になることがあります。どちらもグループの存在を確実に判定する用途には適しません。NULLを含む算術演算だけでは、副側にしか存在しない出力行は除外されません。

修飾子の組み合わせ #

1 つの参照に複数の修飾子を指定できます。その際は、同じディメンション内での競合に関するルールと、修飾子の制約が適用されます。

# Filter + dimension (outer SUM rolls +d back to query grain)
formula: 'SUM({売上高: {+d: 顧客, +f: {地域: "North"}}})'

# Legal: +d and -d on DIFFERENT fields
formula: 'SUM({売上高: {+d: 顧客, -d: ブランド}})'

# Rejected: the same field cannot appear in +d and -d or -df in one modifier object:
# formula: 'SUM({sales: {+d: store_id, -d: store_id}})'
# formula: '{sales: {+d: store_id, -df: store_id}}'

# Time + dimension
formula: '{売上高: {+d: 顧客}, yoy}'

# Dimension + rank
formula: '{売上高: {-d: dim_dt, rank}}'

# Dimension + filter removal (ratio with deferred filters)
formula: 'divide({売上高: {-df: brand_id}} * 100.0, {売上高: {-df: [店舗番号, brand_id]}})'

# Filter + absolute grain (e.g., ratio numerator/denominator at different grains)
formula: 'DIVIDE({売上高: {+f: "注文状態 = 1", dimension: [商品番号]}}, {売上高: {+f: "注文状態 = 1", dimension: [商品番号, 店舗番号]}})'

Model Query SQL では次のように記述します。

SELECT 商品,
       AGG({売上高: {-d: dt_date, rank}}) as 全期間順位
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY 商品

修飾子の連続適用 #

1 つの式に複数のマクロを並べて適用できます。コンパイラは、ユーザーが手動で定義する場合と同じ中間指標を自動で作成します。

構文：{measure: {macro1, macro2, macro3}} または AGG(measure, 'macro1', 'macro2', 'macro3')

通常の連続適用では、最初のマクロが元の指標を変換し、次のマクロがその中間指標に適用されます。時間修飾子を複数の分岐を持つ関数と組み合わせると、後述のとおり、時間修飾子は各分岐も変換します。次に、順に適用する例を示します。

# Stacking: yoy creates intermediate "sales_yoy", then rank applies to it
# Equivalent to:
#   sales_yoy:
#     type: measure
#     formula: '{sales: yoy}'
#   ...then: {sales_yoy: rank}
q_col: '{売上高: {yoy, rank}}'

時間修飾子と複数の計算経路を持つ関数： 検証済みのビルドでは、ytd が yoy の当期側と比較期間側の両方の分岐に適用されます。記録された月単位の検証では、{売上高: {yoy, ytd}} と {売上高: {ytd, yoy}} が同一の SQL を生成しました。計算では、YTD の売上を前年の YTD の売上で割り、その結果から 1 を引きます。月ごとの成長率の合計ではありません。修飾子を種類別に並べ替えたり、自動生成された中間指標の名前だけを根拠に別の意味を推測したりしないでください。

firstday など、行や合計を定義する粒度を変えるマクロには、複数の計算経路に関する追加の制約があります。使用する組み合わせをそのままコンパイルし、結果を確認してから使用してください。{売上高: {+f: "売上金額 > 5", yoy}} のように、YAML の指示文字を含む +f 式を記述する場合は、式を引用符で囲んでください。

中間指標の再利用。コンパイラは新しい中間指標を作成する前に、同じ式を持つ指標がすでにないかを調べます。照合には、展開した式、略記形式、マップ形式を使用します。ユーザー定義の指標や以前に生成された指標が一致すれば、それを再利用します。これにより、重複する中間指標の作成を避け、ユーザーが中間指標の名前を指定できます。

名前の競合への対処。自動生成された中間指標の名前（例：売上高前年同期比）が、異なる式を持つ既存の指標の名前と重複する場合、コンパイラは数値の接尾辞を付けます。結果は sales_yoy__2、sales_yoy__3 のようになります。

互換性： 組み合わせが有効かどうかは、マクロの前提条件、時間コンテキスト、使用できるディメンション、キーの重複、再集計によって決まります。使用する組み合わせをそのまま対象のビルドでコンパイルしてください。範囲マクロを 2 つ使う方法や同じマクロキーを繰り返す方法は、汎用的な組み合わせ方ではありません。各段階を明示してもエラーが残る場合は、診断メッセージと再現例を保存してください。中間指標に手動で名前を付けただけでは、処理が同等であることは確認できません。

修飾子クイックリファレンス #

修飾子は、指定した指標参照にだけ作用します。{売上高: {+f: {注文状態: completed}}} で指標の入力データを絞り込みます。+d で計算時のグループ化を追加し、外側の集計でレポートのグループ化に戻します。-d でグループ化ディメンションを除外し、-df ではそのディメンションに対する関連フィルターも除外します。期間修飾子の pp は前の期間の値を取得し、pop は前の期間からの変化率を計算し、ytd は年初から対象時点までの累計を計算します。複数の修飾子は、宣言した順に適用されます。

複合比率への時間修飾子の適用 #

時間修飾子は、名前付きの複合指標に直接適用できます。たとえば、年初来粗利率 を formula: '{粗利率: ytd}' で定義します。ここで、粗利率 は売上総利益を売上高で割った値です。累計期間を対象とする場合は、まず計算に使う指標を再計算し、その結果から比率を求めます。月ごとのパーセンテージは足し合わせません。収益性の完全な例を参照してください。この比率の例は検証済みですが、任意の非加算式を、その意味を確認せずに上位の粒度へ集計できることを保証するものではありません。

固定軸の合計と出力対象の行 #

固定合計の例では、日付フィールド dt_monthを使い、地域と月でグループ化したクエリを実行します。1 月を選択すると、-d: dt_month では分母の計算対象が 1 月のままで、-df: dt_month ではテストデータに含まれる両方の月が分母の計算対象になります。どちらのクエリも、出力するのは引き続き 1 月の行だけです。このテストデータでは、動的なピボット軸、小計レベルの述語、任意の条件での dim_dt の除外動作までは確認できません。
