累積KPIの集計終了日を明示する

このページの内容
  • 1つの結果で2つの集計期間を比較する
  • 時間コンテキストがない場合の動作を確認する
  • 月別の集計結果には売上のない月も含まれることがある
  • 検証を実行して結果を確認する

累積指標には時間コンテキストが必要です。同じクエリの日付フィルターは、そのクエリ内の他の非累積指標にも適用されます。DMLが当日やファクトデータ内の最新日を暗黙に選ぶことはありません。

1つの結果で2つの集計期間を比較する #

1月の売上高は10、利益は3です。2月の売上高は20、利益は3です。2月のクエリでは、YTDの利益率は(3+3)/(10+20)=20%です。非累積の売上高は20で、累積売上高の30ではありません。

ファイル全体: ytd/model.dml 
dialect: duckdb
F:
  type: dataset
  table: YTD_FACT
  dimension: [id]
  columns:
    id:
    dt_month:
    revenue_amount:
    profit_amount:
  measures:
    revenue: SUM({revenue_amount})
    profit: SUM({profit_amount})
margin:
  type: measure
  formula: 'DIVIDE({profit} * 1.0, {revenue})'
margin_ytd:
  type: measure
  formula: '{margin: ytd}'
ファイル全体: ytd/setup.sql 
CREATE TABLE YTD_FACT(id INTEGER, dt_month DATE,revenue_amount INTEGER,profit_amount INTEGER); INSERT INTO YTD_FACT VALUES (1,'2024-01-01',10,3),(2,'2024-02-01',20,3);
ファイル全体: ytd/february.sql 
SELECT AGG(margin_ytd), AGG(revenue) FROM MODEL WHERE dt_month='2024-02-01'

モデルではmargin_ytdを'{margin: ytd}'として定義しています。分子と分母をそれぞれ累積期間全体で集計してから割り算します。30%と15%の平均は、別の問いに答える値です。

時間コンテキストがない場合の動作を確認する #

ファイル全体: ytd/missing_context.sql 
SELECT AGG(margin_ytd) FROM MODEL

このクエリはコンパイルに失敗し、dim_dtがないことを示すエラーが出ます。2月のフィルターを追加すると、20%が返ります。このフィルターは独立した集計終了日のパラメーターではありません。同じクエリ内の非累積の売上高も2月分だけになります。レポートで異なる期間の指標が必要な場合は、指標ごとに集計期間を定義して確認してください。

月別の集計結果には売上のない月も含まれることがある #

ファイル全体: ytd/months.sql 
SELECT dt_month, AGG(margin_ytd), AGG(revenue) FROM MODEL GROUP BY dt_month ORDER BY dt_month

このテストデータでクエリを実行すると、12か月分の結果が返ります。1月の累積利益率は30%、売上高は10です。2月の累積利益率は20%、売上高は20です。3月から12月までは、各月の累積利益率が20%、非累積の売上高がNULLです。クエリの累積計算を行う部分では、カレンダーから生成した月を使用します。これらの行は新しい取引を示すものではなく、NULLは測定値のゼロを意味しません。

レポートで集計の終了月を1つに絞る必要がある場合は、フィルターで明示的に指定してください。期間を変更した後は、結果に含まれる月と、各指標の計算に使われるデータの期間を確認してください。

検証を実行して結果を確認する #

プロジェクト一式をダウンロードし、README の手順に従って verify.py を実行します。必要なものは dmlc、Python、DuckDB です。練習用データベースは指定した新しい出力フォルダーに作成されます。実行結果と診断内容も同じ場所に保存されます。

この例は DuckDB 上で dmlc 0.3.16（ビルド 2026-11-13）を使って確認しました。実行ファイルのフィンガープリントと各検証ケースのステータスは、ダウンロードに含まれる verification-summary.json に記載されています。データベースでの検証とその後の実行は独立した処理です。両方が同じスナップショットを使用する保証はありません。他のデータベースエンジンでは個別に確認してください。
