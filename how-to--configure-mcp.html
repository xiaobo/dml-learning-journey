Configure a DMLC MCP client

Use this guide when the DMLC MCP server is not available or you see errors like "tool not found" / "server not configured". Host config samples: dmlc --mcp --help. After the server is up, ask dmlc (tools/list, then validateOnly) — ../SKILL.md §2.

This document is the canonical MCP setup/detection reference. See the setup checklist for the shortest task list.

1. Detect your IDE (for DMLC config path)

MCP config paths differ by IDE. Use one of these to identify the active environment:

Windows (PowerShell)

$env:TERM_PROGRAM
Get-Process | Where-Object {$_.ProcessName -match "cursor|windsurf|code"} | Select-Object ProcessName

macOS/Linux

echo "TERM_PROGRAM: $TERM_PROGRAM"
ps aux | grep -E "(cursor|windsurf|code)" | grep -v grep

Typical mapping: TERM_PROGRAM=vscode + Cursor process → Cursor; + Windsurf process → Windsurf; + Augment extension → Augment Code (VS Code); VS Code alone → VS Code.

2. Detect whether DMLC MCP is installed

Goal: Find the actual server id and tool names (do not guess).

  1. Check MCP registry

    • Cursor: C:\Users\<you>\.cursor\projects\<project>\mcps\ (or ~/.cursor/projects/<project>/mcps/ on macOS/Linux). Each server is a folder; tools are JSON descriptors under tools/.
    • Augment Code: Augment panel → Settings → MCP section. Servers are listed there; no file-based registry.

  2. Read tool schemas

    • Confirm the server id (folder name).
    • List tool names from filenames under tools/.
    • Prefer servers with DML tools: list_models, run_query, list_connections, generate_model, etc.

3. Verify the server works

  1. Call a low-risk tool: list_connections, list_models, or similar.
  2. Use the exact server id and toolName from the descriptors.
  3. Build arguments from the tool’s JSON schema — do not invent parameter names.

Errors:

  • "Tool not found" → wrong server id or tool name; re-check descriptors.
  • Connection/transport errors → server not starting; proceed to installation.

4. How to call MCP tools correctly

  • Always: Read the tool schema JSON first; use exact server id and toolName; match parameter structure (required vs optional).
  • Never: Guess parameter names; assume server name (e.g. always dmlc-mcp) without checking descriptors.

5. Install / enable DMLC MCP server

Use when no suitable DMLC server appears or all DML tool calls fail.

5.1 Prerequisites

  • Obtain the dmlc app-image from scripts (e.g. dmlc.exe on Windows).

5.2 Add server to MCP config

Edit the config file for your environment (see table above). Example:

{
  "mcpServers": {
    "dmlc-mcp": {
      "command": "D:\\absolute\\path\\to\\dmlc-mcp\\dmlc.exe",
      "args": ["--mcp"],
      "cwd": "D:\\absolute\\path\\to\\your\\workspace",
      "env": {
        "WORKSPACE_FOLDER": "D:\\absolute\\path\\to\\your\\workspace"
      }
    }
  }
}

Important:

  • Use absolute paths only — avoid ${workspaceFolder} placeholders.
  • Set both cwd and WORKSPACE_FOLDER to the workspace root.

5.3 Restart and verify

  1. Restart your IDE or MCP client (configs load at startup).
  2. Verify: Cursor → check mcps/ for a folder matching your server id; confirm tools/ descriptors exist.
  3. Call list_connections or list_models to confirm tools work.

5.4 Augment Code (specific guide)

Augment Code runs as a VS Code or JetBrains extension. DMLC uses local stdio (command + args), not Easy MCP or remote HTTP/SSE.

Option A: Import from JSON

  1. Open the Augment panel in VS Code or JetBrains.
  2. Click the options menu (⋮) → Settings.
  3. In the MCP section, click Import from JSON.
  4. Paste and edit (use your absolute paths):
{
  "mcpServers": {
    "dmlc-mcp": {
      "command": "D:\\absolute\\path\\to\\dmlc-mcp\\dmlc.exe",
      "args": ["--mcp"],
      "env": {
        "WORKSPACE_FOLDER": "D:\\absolute\\path\\to\\your\\workspace"
      }
    }
  }
}
  1. Click Save. Restart or reload Augment if needed.
  2. Verify DMLC tools appear in the Agent (e.g. list_connections, list_models).

Option B: Settings Panel (GUI)

  1. Augment panel → options menu → Settings → MCP section.
  2. Click + next to MCP.
  3. Name: dmlc-mcp
  4. Command: full path to dmlc.exe plus --mcp (e.g. D:\path\to\dmlc-mcp\dmlc.exe --mcp), or use separate command/args fields if the UI provides them.
  5. Environment variables: add WORKSPACE_FOLDER = your workspace root path.
  6. Save and restart/reload Augment.

Option C: Auggie CLI

Edit ~/.augment/settings.json or use:

auggie mcp add dmlc-mcp --command "D:\path\to\dmlc-mcp\dmlc.exe" --args "--mcp" -e WORKSPACE_FOLDER="D:\path\to\workspace"

Then run Auggie; DMLC tools will be available.

Reference: Augment Code MCP docs · Auggie CLI integrations

6. DMLC troubleshooting quick reference

Issue Fix
Server folder missing under mcps/ MCP not loaded; re-check config path, restart client
"Tool not found" Server id or toolName mismatch; copy exact names from descriptor JSONs
"Executable not found" / spawn failures Verify command path; dmlc.exe must exist at configured location
Path / data resolution errors Use absolute paths; set WORKSPACE_FOLDER and cwd to workspace root
Server loads but tools error at runtime Check client logs; reduce to smallest failing call (e.g. list_models) and iterate

For general MCP issues (Node.js, npx, env vars, permissions), see MCPEZ troubleshooting.

Quick setup checklist

Prerequisites: IDE MCP config access · dmlc executable path · workspace absolute path

  1. Add server to the MCP config — absolute command, cwd, WORKSPACE_FOLDER
  2. Restart IDE/client
  3. Verify: list_connections → list_models → run_query with validateOnly: true

Common failures: relative paths in config · wrong server id/tool name · not restarting after config changes
