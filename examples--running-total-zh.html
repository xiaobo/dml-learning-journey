累计销售额怎样定义一次、在多个查询中复用？

本页目录

  • 先筛选再开窗，会改变累计起点

把按时间排序的累计计算定义成有名指标，并写明可用粒度。 本例累计的是销售额，不能用来直接累加毛利率或每月去重客户数。

定义与结果 #

按月汇总，1月销售40、2月20；running_sales 返回1月40、2月60。

running_sales:
  type: measure
  formula: 'SUM({sales}) OVER (ORDER BY {month} ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)'
  dimensions:
    - [month]

ORDER BY month 决定时间顺序，ROWS 指明从第一行累计到当前行。本例没有分区，所以所有地区先汇成每月销售；dimensions: [[month]] 将使用粒度限制为月份。ISO 格式的 month 字符串按年月顺序排列。

完整文件 / Complete file: fixed/model.dml 
dialect: duckdb
F:
  type: dataset
  table: FACT
  dimension: [id]
  columns:
    id:
    region:
    month:
    amount:
  measures:
    sales: SUM({amount})
region_selected:
  type: measure
  formula: '{sales: {-d: month}}'
region_all_months:
  type: measure
  formula: '{sales: {-df: month}}'
running_sales:
  type: measure
  formula: 'SUM({sales}) OVER (ORDER BY {month} ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)'
  dimensions:
    - [month]
完整文件 / Complete file: fixed/running.sql 
SELECT month, AGG(sales), AGG(running_sales) FROM MODEL GROUP BY month ORDER BY month

另一条查询可以直接引用同一 running_sales。如果要按地区分别累计，应另行定义地区分区和相应允许粒度，并验证结果，不能仅在查询中追加地区就假定公式仍适用。

先筛选再开窗，会改变累计起点 #

完整文件 / Complete file: fixed/running_february.sql 
SELECT month, AGG(sales), AGG(running_sales) FROM MODEL WHERE month='2024-02-01' GROUP BY month ORDER BY month

只保留2月时，本例返回销售20、累计20，不会自动保留1月的40。这是选中结果范围内的累计。要表达截至2月的年累计，应使用具有时间上下文的 YTD 口径并核对其输入范围，参见累计 KPI。

不要把按指标值排序的累计排名宏当作按时间累计；排序字段属于指标定义的一部分。

运行与验证范围 #

下载完整项目，按包内 README.md 运行 verify.py。需要已有的 dmlc、Python 和 DuckDB；脚本只在你指定的全新输出目录创建练习库。所有案例共用一个入口，结果与诊断保存在输出目录。

本例在 dmlc 0.3.16、2026-11-13 构建的 DuckDB 连接上验证。编译器指纹、用例列表和状态见包内 verification-summary.json。数据库验证和随后执行是独立操作，不保证同一快照。其他引擎需单独验证。
