同一编号在不同地区重复，怎样正确关联？

将完整业务键声明为复合键，并按声明顺序查找。 id=1 可以同时出现在 east 和 west；必须唯一的是 (id, region) 组合。

先看输入和结果 #

目标表中 (1,east) 对应 East，(1,west) 对应 West。两条销售分别为10和20。查询应得到：

标签 销售额
East 10
West 20

只按 id 关联不足以区分这两条目标记录。示例使用最小夹具突出这个边界，金额单位不影响结果。

声明一次，在查询中复用 #

模型的目标数据集声明 dimension: [id, region]。事实表中的标签定义为 pk({id}, {region}).{D}.label；参数顺序与目标 dimension 一致。

完整文件 / Complete file: compound/model.dml 
dialect: duckdb
D:
  type: dataset
  table: DIM
  dimension: [id, region]
  columns:
    id:
    region:
    label:
F:
  type: dataset
  table: FACT
  dimension: [fid]
  columns:
    fid:
    id:
    region:
    amount:
    label: 'pk({id}, {region}).{D}.label'
  measures:
    sales: SUM({amount})
完整文件 / Complete file: compound/setup.sql 
CREATE TABLE DIM(id INTEGER, region VARCHAR, label VARCHAR); INSERT INTO DIM VALUES (1,'east','East'),(1,'west','West'); CREATE TABLE FACT(fid INTEGER,id INTEGER,region VARCHAR,amount INTEGER); INSERT INTO FACT VALUES (1,1,'east',10),(2,1,'west',20);
完整文件 / Complete file: compound/normal.sql 
SELECT label, AGG(sales) FROM MODEL GROUP BY label ORDER BY label

业务标签查找定义在模型中。查询按标签分组时复用它，不必再次手写关联条件。换成自己的数据时，应确认实际复合键，而不是机械复制 id, region。

数据变更后检查键声明 #

校验脚本按顺序执行：正常数据编译、验证、查询通过；插入重复 (1,east) 后，--validate-only 检出 DIMENSION_NOT_UNIQUE；删除重复数据并恢复唯一组合后，重新验证和结果比对通过。

这说明验证能够发现键声明与当前数据的不一致，帮助在信任结果前避免关联放大。它不证明以后写入的数据仍唯一。实际业务应修正来源、完整键或数据，在最终结果加 DISTINCT 不能可靠修复已经放大的聚合。

运行与验证范围 #

下载完整项目，按包内 README.md 运行 verify.py。需要已有的 dmlc、Python 和 DuckDB；脚本只在你指定的全新输出目录创建练习库。所有案例共用一个入口，结果与诊断保存在输出目录。

本例在 dmlc 0.3.16、2026-11-13 构建的 DuckDB 连接上验证。编译器指纹、用例列表和状态见包内 verification-summary.json。数据库验证和随后执行是独立操作，不保证同一快照。其他引擎需单独验证。
