为什么累计毛利率不能直接平均各月毛利率？

累计毛利率应先汇总期间内的收入和成本，再用累计毛利润除以累计收入。直接平均各月毛利率，会给收入不同的月份相同的权重。

用两个月看清区别 #

同一套毛利率示例数据中，North 的数值如下：

期间 净收入 销售成本 毛利率
2025 年 1 月 100 60 40%
2025 年 2 月 300 240 20%
1—2 月累计 400 300 25%

累计结果为 (400 − 300) / 400 = 25%。将 40% 与 20% 平均得到 30%，回答的是“各月毛利率的简单平均”，不是累计毛利率。两种算法在各月收入相等等情形下可能一致，但不能普遍互换。

自己切换一次 #

打开指标构造剧场，选择 North 和第四幕，从当月切换到本年累计：收入由 300 变为 400，成本由 240 变为 300，毛利率由 20% 变为 25%。

直接对已定义的毛利率应用 ytd：formula: '{gross_margin: ytd}'。它会在累计期间重新计算组成项与比率，不累加各月毛利率。下面的模型使用这一简写：

查看完整 DML 模型 
FACT_PROFITABILITY:
  type: dataset
  table: TABLE_PROFITABILITY
  dimension: [id]
  columns:
    id:
    region:
    dt_month:
    revenue_amount:
    cost_amount:
  measures:
    net_revenue: SUM({revenue_amount})
    sales_cost: SUM({cost_amount})

gross_profit:
  type: measure
  formula: '{net_revenue} - {sales_cost}'

gross_margin:
  type: measure
  formula: 'DIVIDE({gross_profit}, {net_revenue})'

gross_margin_ytd:
  type: measure
  formula: '{gross_margin: ytd}'

gross_margin_prior_ytd:
  type: measure
  formula: '{gross_margin: {ytd, ya}}'

margin_change_pp:
  type: measure
  formula: '100 * ({gross_margin_ytd} - {gross_margin_prior_ytd})'

百分点与增长率也要区分 #

North 去年同期累计毛利率为 20%。从 20% 升到 25%，增加的是 5 个百分点；相对增长率为 (25% / 20%) − 1 = 25%。报表中应分别标明。

可查阅完整案例、比较查询和编译记录。该编译记录覆盖 SQL Server 方言的严格编译与 SQL 检查，不代表 SQL Server 执行结果。另在 DuckDB 上执行了简写公式，验证 North 累计为25%、去年同期累计为20%，并与独立 SQL 对齐。物理表金额列应使用小数类型；收入为零时比率为 NULL，缺少历史值不自动补零。
