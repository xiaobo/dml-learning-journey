Define a business day in a fixed DuckDB timezone

On this page

  • Bound a day with two local midnights
  • Preserve distinct instants during a repeated local hour
  • Replay and adapt the recipe

Map instants to the business timezone before deriving a date or day boundary. This recipe uses America/New_York and tests DuckDB physical SQL. It does not establish automatic per-user or cross-database timezone support in DML.

Identify what the input represents #

Input values are TIMESTAMPTZ instants with explicit UTC offsets. The connection's session zone is UTC; the business zone is America/New_York. A timestamp without an offset is not automatically UTC. Establish how the source records it first.

SET TimeZone = 'UTC';
SELECT timezone('America/New_York', TIMESTAMPTZ '2024-01-01 02:00:00+00');

The local time is 2023-12-31 21:00:00, so the business date is the previous day. Convert to the business zone before extracting a grouping date.

Bound a day with two local midnights #

SELECT count(*)
FROM (VALUES
  (TIMESTAMPTZ '2024-03-10 04:59:59+00'),
  (TIMESTAMPTZ '2024-03-10 05:00:00+00'),
  (TIMESTAMPTZ '2024-03-11 03:59:59+00'),
  (TIMESTAMPTZ '2024-03-11 04:00:00+00')
) events(ts)
WHERE ts >= timezone('America/New_York', TIMESTAMP '2024-03-10 00:00:00')
  AND ts < timezone('America/New_York', TIMESTAMP '2024-03-11 00:00:00');

The result is 2. Include the start and exclude the end. The end is not always the start plus 24 hours: the verifier checks a 23-hour spring transition day and a 25-hour autumn transition day.

Preserve distinct instants during a repeated local hour #

2024-11-03 05:30 UTC and 06:30 UTC both map to local 01:30. They are distinct instants. Retain the event key and original instant rather than deduplicating by local timestamp alone.

Replay and adapt the recipe #

Download the project and follow its README's JDBC steps to run jdbc/VerifyJdbc.java. With the existing JDK and matching installed jars, run from the extracted project directory:

java -cp "C:/path/to/dmlc-assembly.jar;C:/path/to/duckdb-jdbc.jar" jdbc/VerifyJdbc.java "$PWD/jdbc" C:/path/to/driver-directory

Replace the paths; use a colon instead of a semicolon in the classpath on other systems. The program also tests the parameter-binding boundary, so expected semantic-placeholder parsing errors appear in the output. Check the final pass messages and process exit rather than treating every diagnostic as a failed replay. It does not download third-party runtimes.

The verifier checks midnight, repeated hours, 23/25-hour days and half-open interval filtering. Failures exit with a nonzero code.

The checked JDBC distribution uses the DuckDB 1.5.4 driver. To reuse a business date in DML, a database view can normalize timestamps first and expose the business date as a model column. Verify that integration on your model and connection; this physical SQL recipe does not establish arbitrary timezone-aware models.
