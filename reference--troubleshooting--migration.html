Model authoring pitfalls

Keep reusable definitions in the model and presentation choices in the query or reporting layer.

P1. Including presentation logic in DML

Wrong: Putting FORMAT(...), CONCAT(...), CAST(... AS VARCHAR) in measure formulas. Fix: Remove formatting from .dml. Handle in dashboard/rendering layer.

P2. Including query-only derived columns in DML

Wrong: Creating measures for calculations that only make sense in one specific query. Fix: Put query-specific expressions in Model Query SQL, not .dml.

P5. Not verifying compiled SQL matches golden SQL

Wrong: Assuming -c output is correct just because it compiles. Fix: Run both the original SQL and compiled SQL; compare result sets.

P6. Creating one-off measures for filters or query-dimension combinations

Wrong: sales_north, sales_south, sales_east — or sales_north when WHERE region = 'North' suffices. Fix: One generic measure sales; use WHERE region = 'North' in queries.

P7. Duplicating aggregation formulas

Wrong: revenue: SUM({amount}) and total_revenue: SUM({amount}). Fix: One atomic measure; reference it everywhere.
