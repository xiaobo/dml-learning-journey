累计指标需要明确的时间上下文；同一个查询的日期筛选也会影响其他普通指标。 不应默认为今天或数据中最新日期。

一个比率，两种时间范围 #

一月收入10、利润3；二月收入20、利润3。二月查询中，累计毛利率为 (3+3)/(10+20)=20%，普通收入为20，而不是累计收入30。

完整文件 / Complete file: ytd/model.dml 
dialect: duckdb
F:
  type: dataset
  table: YTD_FACT
  dimension: [id]
  columns:
    id:
    dt_month:
    revenue_amount:
    profit_amount:
  measures:
    revenue: SUM({revenue_amount})
    profit: SUM({profit_amount})
margin:
  type: measure
  formula: 'DIVIDE({profit} * 1.0, {revenue})'
margin_ytd:
  type: measure
  formula: '{margin: ytd}'
完整文件 / Complete file: ytd/setup.sql 
CREATE TABLE YTD_FACT(id INTEGER, dt_month DATE,revenue_amount INTEGER,profit_amount INTEGER); INSERT INTO YTD_FACT VALUES (1,'2024-01-01',10,3),(2,'2024-02-01',20,3);
完整文件 / Complete file: ytd/february.sql 
SELECT AGG(margin_ytd), AGG(revenue) FROM MODEL WHERE dt_month='2024-02-01'

模型中 margin_ytd 使用 '{margin: ytd}'。先在累计范围计算组成项，再相除，不能把30%与15%直接平均。

缺少时间上下文时 #

完整文件 / Complete file: ytd/missing_context.sql 
SELECT AGG(margin_ytd) FROM MODEL

这条查询在本例中编译失败，提示缺少 dim_dt。添加二月筛选后得到20%。但这不是一个独立于其他指标的截止参数；同一查询的普通收入也受该筛选约束。若一个报表要同时呈现不同期间口径，应显式定义并分别核对每项指标的范围。

按月份分组不保证只出现有销售的月份 #

完整文件 / Complete file: ytd/months.sql 
SELECT dt_month, AGG(margin_ytd), AGG(revenue) FROM MODEL GROUP BY dt_month ORDER BY dt_month

本夹具返回12个月：一月累计30%、收入10；二月累计20%、收入20；三月至十二月累计20%、普通收入为 NULL。累计分支使用日历产生的月份，不能把这些行描述为新增交易，也不能把 NULL 当成零收入。

如果报表只需要某个截止月份，请显式筛选。改变日期范围后，仍需检查输出月份与每个指标的范围。

运行与验证范围 #

下载完整项目，按包内 README.md 运行 verify.py。需要已有的 dmlc、Python 和 DuckDB；脚本只在你指定的全新输出目录创建练习库。所有案例共用一个入口，结果与诊断保存在输出目录。

本例在 dmlc 0.3.16、2026-11-13 构建的 DuckDB 连接上验证。编译器指纹、用例列表和状态见包内 verification-summary.json。数据库验证和随后执行是独立操作，不保证同一快照。其他引擎需单独验证。
