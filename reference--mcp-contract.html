MCP Contract (CLI + MCP)

How agents and integrators should consume DMLC outputs across CLI and MCP surfaces. Implementation truth (Java paths, normalizer tables, drift notes): ../../../dmlc_jdbc/docs/mcp-output-contract-v2.md.

Related: DMLC Error Codes Reference, Configure a DMLC MCP client.

1. Surfaces

Surface Launch Machine-readable output
CLI dmlc -q, dmlc -e, … stdout (format varies by mode)
MCP dmlc --mcp tools/call.result.structuredContent

2. MCP (authoritative for agents)

  • Parse structuredContent for logic (status, data, error, diagnostics, next).
  • Use content[0].text for human/model summary (SEP-1624); do not concatenate content[1] when structuredContent is available.
  • explain_change MCP: content[0].text is a slim digest (Headline, Drill-down slice / headline share= when analysisPath is set, Top drivers and/or factors, Filter / Analysis path / Dimensions); next.actions is the sole recovery authority; diagnostics.warnings[].type / diagnostics.observations[].type for blockers vs context (CLI raw JSON uses the same shapes).
  • Pass --no-content-mirror to omit content[1] JSON mirror and save tokens.
  • Tool failures use JSON-RPC success + isError: true (SEP-1303).

3. CLI vs MCP: deliberate differences

Feature CLI MCP
explain-change Raw ExplainChange.analyze() JSON on stdout; optional -o/--output file export (JSON only, CLI-only) v2 envelope via McpErrorHandler (inline JSON; use run_query with outputFile for large exports suggested in next.actions)
run_query output --output-format serializes to stdout when -o/--output is omitted (json/csv/tsv/jsonl/table); xlsx requires --output outputFile for exports; inline preview uses markdown table in content[0].text
validate-only --output-format=json returns a validation report with status, summary, checks[], generated SQL, diagnostics, next actions, and error Under structuredContent.data.metadata on success; failures use the shared envelope
compile SQL on stdout (dmlc -c); --output-format=json includes diagnostics, artifacts, and effectiveOutputOrder Read-only compile tool; successful structured data includes effectiveOutputOrder
list_models Not exposed as CLI mode MCP tool only

CLI remains optimized for scripting and pipes; MCP remains optimized for agent orchestration with stable schemas and recovery actions.

4. Recovery

Prefer structuredContent.next.actions over parsing warning text. Action type values use a stable public subset plus namespaced extensions (e.g. run_query.retry_with_longer_timeout).

Implementation SoT for action normalization: mcp-output-contract-v2.md. Confirm the live action catalog through tools/list because action types are extensible.

Structured error codes: DMLC Error Codes Reference.

5. Two failure layers

Layer When Where to read
Protocol error Bad JSON-RPC, unknown method/tool JSON-RPC error — not tool result
Tool result Known tool returned result.structuredContent + result.isError

JSON-RPC success ≠ business success. Check structuredContent.status and structuredContent.error.

6. Envelope (handled tool call)

{
  "content": [{ "type": "text", "text": "..." }],
  "isError": false,
  "structuredContent": { }
}
Field Agent rule
structuredContent Primary machine surface — always parse this first
content[0].text Human summary; run_query preview may be a markdown table; explain_change is digest only
content[1].text Optional JSON mirror of structuredContent; omit when host passes --no-content-mirror or payload > ~1MB
isError true when tool returned an errorCode (expected failures still use structured content)

Do not concatenate all content[].text blocks or treat content[0].text as the only source of truth.

7. Shared structuredContent skeleton

Tools share a common shape (normalizers may trim fields):

{
  "status": "ok",
  "data": {},
  "error": null,
  "diagnostics": {
    "warnings": [],
    "observations": []
  },
  "next": {
    "actions": []
  }
}

status values

status Meaning
ok Success
partial Truncated / hasMore
no_data Empty result set
invalid_input Bad params, compile/validation errors
not_found Model/file not found
timeout Query or compile timeout
blocked Policy (workspace, overwrite, path)
failed Execution or internal failure

error object

{
  "code": "COMPILE_ERROR",
  "message": "short message",
  "field": "optional param name",
  "details": {
    "compilationErrors": [],
    "generatedSql": "..."
  }
}

For COMPILE_ERROR, read error.details.compilationErrors and any generated SQL in details — not only message.

diagnostics

  • warnings[]: actionable blockers (type field) — e.g. missing_dimensions on explain_change
  • observations[]: quality/context (narrow_dimension_breakdown, results_truncated) — not blockers
  • Cross-tool entries may still use legacy code (e.g. JDBC_WARNING)

next.actions

Sole recovery authority. Prefer actions over parsing warning text or content[0].text.

type is not a closed set — handle unknown types gracefully. Common patterns:

  • run_query.retry_with_longer_timeout
  • run_query.rerun_with_output_file
  • run_query.fix_query_or_model
  • explain_change.drilldown_dimension

Action normalization details: mcp-output-contract-v2.md. Treat the live tools/list schema as authoritative when it differs.

8. Per-tool notes

Tool data highlights Agent gotchas
list_connections Connection IDs Preflight step 1
list_models workspaceFolder, model paths Preflight step 2; reuse absolute paths
find_references references[] with ownerLabel / ownerKind Cursor-based (filePath + zero-based line/character); use when IDE Peek lacks measure/column context
run_query Rows, metadata, export paths Use validateOnly first; large results → outputFile via next.actions
explain_change metadata (incl. analysisPath), summary, summarySlice, drivers Slice KPIs live in summarySlice when analysisPath is set. Recovery via next.actions only; full schema in explain-change-variance SKILL + explain-change.md

Shapes differ by tool — do not assume one universal data schema across tools.

9. Agent checklist on any tool error

  1. Read structuredContent.error.code → DMLC Error Codes Reference
  2. Read error.details (especially compilationErrors, generatedSql)
  3. Apply first applicable next.actions[] entry (merge params into retry)
  4. If diagnostics.warnings[].type is missing_dimensions / missing_formula, fix params before retry — do not loop discovery

Symptom-based compile fixes (patterns, not codes): Troubleshooting index.
