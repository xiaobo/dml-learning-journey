Model structure

This page owns model-level fields, datasets, column macros, and common metadata. The DML schema defines structural validation. Model composition owns include visibility and name resolution.

Model-level fields

Field Type Description
includes string[] Paths to other .dml files to merge (symbols are unioned)
dialect string Target SQL dialect (e.g. duckdb, mssql)
column-macros object Shared column definitions across multiple datasets
<name> object | string A dataset, measure, dt-macro, fn-macro, materialize, or query

Object name pattern: any string except reserved keywords (includes, column-macros, datasets, measures, columns, dimensions[dt], dt-macros, fn-macros, materializes, queries, dialects, and singular forms).

Simplified measure definition: a top-level mapping value that is a bare string is treated as a measure formula shorthand:

sales: SUM({amount})
# equivalent to:
sales:
    type: measure
    formula: SUM({amount})

Dataset definition (type: dataset)

<name>:
    type: dataset
    table: <table_name>          # required (or sql:)
    # sql: <SELECT ...>          # alternative to table: — derived dataset
    dimension: [col1, col2]      # dataset grain dimensions
    materialize: <name>          # optional, declare a materialize table for this dataset
    # or:
    # materialize:
    #     name: <name>
    #     parameters:
    #         <param>: <value>
    columns:                     # required
        col1:                    # direct column (pass-through)
        col2: expr               # calculated column (inline expression)
        col3:                    # full column definition
            abbr: <short>        # abbreviation for display
            description: <text>
            formula: expr        # calculated column (block form)
            # source: expr       # alternative to formula: data-source verification formula
            prerequisite: <expr> # column-level grain constraint
    dimensions[dt]:              # optional explicit time metadata; coarser standard dt_* fields may be system-derived
        dt_date: date
        dt_month: month
    measures:                    # atomic measures (inherit enclosing dataset; no dataset:)
        <measure_name>: <formula or full definition>
            abbr: <short>
            description: <text>

Constraints:

  • Exactly one of table: or sql: (mutually exclusive).
  • table: is exclusive. table: policy means dataset Policy owns that physical table. Other datasets must not FROM / JOIN the physical name in sql:. Write from {Policy} / join {Policy} (the compiler substitutes the dataset query name), or look up attributes with pk(...).{Policy}.Col and omit that join. To share a table without ownership, use sql: select * from <table> instead of table:.
  • Fact-table pattern: dimension datasets (Claim, Policy) use table:; a fact that only needs those attributes can stay on an unowned source table and look up via pk(), instead of joining the owned table in sql:.
  • Visibility: same-file forward dataset/measure/column references are supported in the checked build. Included files must resolve through their own definitions/includes, not through their parent. See model composition.
  • For direct file compilation, name the query after the file stem (report.dml → report).
  • allows: selects eligible materializations (ALL, NONE, or explicit names); it does not override measure dimensions.
  • columns: is required for the illustrated measure-query form.
  • dimensions[dt] values are enums: year, quarter, month, week, date, hour.
  • materialize: accepts either a scalar name or an object with required name: and optional parameters:. Both forms define the same dataset-scoped materialize identity.

Column definition shapes:

Shape YAML Meaning
Direct amount: (null) Pass-through to underlying table column
Calculated (inline) net: amount - discount (string) Derived column via expression
Calculated (block) net: { formula: amount - discount } Derived column with metadata
Verified net: { source: amount - discount } Compiler verifies formula matches underlying value

Brace binding in formulas (same rule as reference-scope checks):

Form in a formula: Binds as Example
Bare amount Physical (native) table column — compiler passes the name through to SQL net: amount - discount when both are Direct columns
{calc_amt} Calculated column (or measure / column-macro) — DMX expands the definition doubled: '{calc_amt} * 2'

Bare names on calculated columns mean "treat this identifier as a native SQL column," which can appear to work via SELECT-alias order but does not expand the calculated definition. Brace when the formula should reuse that definition.

Dependency-first ordering is a readability convention. A forward pk() target in the same file compiled successfully in the checked release; unresolved names can instead indicate a missing include, misspelling, or include visibility violation. See model composition.

Column-macros

Column-macros define columns shared across multiple datasets:

column-macros:
    datasets: [tx, orders]       # scoped datasets
    columns:                     # shared column definitions
        region: '{stores}.region'  # cross-dataset lookup
    dimensions[dt]:
        dt_month: month

    # OR per-dataset scope:
    <dataset_name>:
        <col>: <formula>

Common metadata fields

Metadata support is object-specific; consult the matching schema definition:

Field Type Description
abbr string SQL-safe short name for internal use only — temp tables, joins, and materialize output. Never appears in final query column aliases (those use the business name key or an explicit AS alias)
description string Human-readable description
tags string[] Free-form tags
prerequisite string (formula) Grain validity constraint (measures, columns, dt-macros, fn-macros)
