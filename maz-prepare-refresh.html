版本说明（2026-11-18）：以下是已确定、待实施的新接口设计。尚未证明当前分发版本支持 force_update 或 DML_REFRESH_MAZ；执行前核对目标库签名。旧版 mode 和 DML_INVALIDATE_MAZ 的回放不证明新签名已经可用。

根据任务选择入口 #

任务 操作 成功含义
打开报表、切换期间 Query 的 prepare_sql 普通准备 本次所需范围准备完成
核验报表，强制重新计算 prepare(force_update=1) 指定目标及本次必要上游强制重建完成
加载后立即更新相关结果 refresh(invalidate_only=0，默认) 指定入口和受影响下游刷新完成
补数后暂不重算 refresh(invalidate_only=1) 全部失效标记提交，等查询按需准备
月结预热 提前执行指定 Query 的普通准备 只准备实际报表需要的依赖

prepare 向上准备依赖，只接受精确名称。refresh 从变化入口向下处理影响，支持精确名称和 SQL LIKE。源变化未通知时可能复用旧数据；有效不等于源数据绝对最新。

差异刷新是按分片选择工作，不是源行级 CDC。全量刷新是本次指定范围的强制重建，不是全部历史。无论操作类型，每片的业务数据和成功状态共同提交，后片失败不撤销已提交片。

prepare 参数 #

参数 规则
@_materialize 必填，精确 Maz 名称；不支持模式
@_range_start / @_range_end 日期型 Maz 必须提供两个闭区间边界，Query 可自动推导；相交完整片均纳入
@_force_update 默认 0；1 强制重建本次目标和必要上游；不接受 null
@_parameters / @_user 保留已有类型参数绑定与审计用途，不扩大既有支持范围

强刷先使必要工作及受影响下游失效，只立即重建本次必要上游闭包；其他报表不会因此全部预热。Query 的共享依赖按分片和参数去重。普通有效热命中可直接复用，不要求每次遍历上游。

EXEC dbo.DML_PREPARE_MAZ
    @_materialize=N'SALES_QUARTERLY',
    @_range_start='20250101', @_range_end='20250331', @_force_update=1;

refresh 参数与全匹配 #

参数 规则
@_materialize 必填的精确名称或模式；省略或空值报错
@_match 默认 exact；可选 like，按数据库登记列的排序规则匹配
@_range_start / @_range_end 同时给出或同时省略；省略表示已有范围，不展开整个日历
@_invalidate_only 默认 0，统一失效后同步刷新；1 只失效不执行 writer；不接受 null
@_parameters / @_user 类型参数与审计；批量目标所需参数在失效前校验
匹配方式 示例
单个目标 exact + SALES_MONTHLY
前缀 like + SALES%
字面下划线前缀 like + SALES~_%
当前数据库全部已登记 Maz like + %

SQL LIKE 使用 %、_ 和方括号模式，~ 是转义符；* 不是全匹配。exact 不展开通配符。未知精确名称报错，模式零匹配返回 0 个目标。精确名称最多 128 个 UTF-16 代码单元，模式最多 512 个，不能截断后执行。

-- 源写入提交后，立即刷新二月及已物化的受影响下游。
EXEC dbo.DML_REFRESH_MAZ
    @_materialize=N'SALES_MONTHLY',
    @_range_start='20250201', @_range_end='20250228';

-- 全部已物化范围仅失效，随后按查询需要补齐。
EXEC dbo.DML_REFRESH_MAZ
    @_materialize=N'%', @_match=N'like', @_invalidate_only=1;

选择完整的变化入口和范围 #

源表有多个独立直接入口时，通知全部入口。只 refresh 季度不会发现未通知的旧月汇总；不知道缓存在哪层陈旧时，使用 Query 的强制 prepare。

日期边界采用闭区间，按相交完整分片展开，再计算下游影响；跨期移动覆盖旧、新期间。维表及不明影响选择足够大的范围。无法证明精确反向映射时，系统保守扩大已有下游范围，并报告扩大原因。单边日期、反向日期、日历不完整拒绝，不静默裁剪。

有日期的默认 refresh 可以首次构建显式选中的 Maz；仅传播发现的冷下游不自动预建。缺状态的中间 Maz 不阻断已有下游传播。无日期只处理已有范围；全库首次预热需显式给出有限日期。整表型 Maz 按一个逻辑分片处理，传入日期也会扩大到整表并报告。

当前日期分片不支持附带非日期值参数，不因批量接口而自动放开；整表只有一个当前参数绑定证明。

中断与重试 #

初始失效在一个元数据事务提交或回滚，随后逐片刷新。中断保留已提交片，当前片回滚；普通无效和缺失分片以后由查询按需构建。源提交和通知之间有窗口，加载方需可靠执行通知并重试。

情况 操作
普通 prepare 失败 排除错误后重发同目标、范围，复用仍有效的已完成片
强制 prepare 失败 普通 prepare 可补齐；再次 force_update=1 是一次新强刷
默认 refresh 失败 重发原 refresh 可完成，但会重新失效并可能重做已完成片
只想补剩余下游 对全部已知未完成下游执行普通 prepare；只 prepare 原入口不够
提交响应丢失 结果未知，重查状态并安全重试，不推断未提交

本期不增加待主动刷新状态、请求编号或持久批次，不承诺精确续跑。无参 refresh() 报错，不是恢复入口。

执行条件与结果边界 #

使用自动提交连接，IMPLICIT_TRANSACTIONS OFF 且无活动事务。账号需要入口及所有受影响 writer 的执行权限；批量参数和权限在失效前检查。状态查询保持只读。

setup_sql 安装定义和例程，prepare_sql 准备本次查询，sql 保持 SELECT/CTE。逐片提交不提供跨 Maz 或准备与查询之间的共同快照；严格准备失败后不能直接执行主查询。

结果报告匹配目标、实际范围、整表或保守扩大的原因、重建/复用/失败数与已知剩余范围。后台调度及结果未变复用分阶段交付，不是本页已验证能力。现有来源限制不变；教程仍使用大写 Maz 名避开已知混合大小写嵌套登记问题。
