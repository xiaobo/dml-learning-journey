Advanced measure examples

These fragments illustrate distribution, lifecycle, segmentation, and cumulative ranking. Each pattern requires its named source measures and dimensions. They are not acceptance fixtures.

Weighted distribution (multi-grain product)

Weighted distribution measures a brand's share of sales weighted by store importance. It requires multiplying measures evaluated at different grains and rolling up.

# Store-level sales (restricted to store + category grain)
store_cat_sales:
  type: measure
  formula: 'IIF({sales} > 0, {sales}, 0)'
  dimensions:
    - [dim_dt, store_id, category]

# Category-level sales (drop store)
cat_sales:
  type: measure
  formula: 'SUM({store_cat_sales: {+d: store_id}})'
  dimensions:
    - [dim_dt, category]

# Store weight = store sales / category sales (store + category grain)
store_weight:
  type: measure
  formula: 'DIVIDE({store_cat_sales}, {cat_sales: {-d: store_id}})'
  dimensions:
    - [dim_dt, store_id, category]

# Brand distribution flag (store + category + brand grain)
brand_dist_flag:
  type: measure
  formula: 'IIF({sales} > 0, 1, 0)'
  dimensions:
    - [dim_dt, store_id, category, brand]

# Weighted distribution = SUM(store_weight * brand_flag) at brand grain
weighted_distribution:
  type: measure
  formula: |-
    SUM({store_weight: {dimension: [dim_dt, store_id, category]}}
        * {brand_dist_flag: {dimension: [dim_dt, store_id, category, brand]}})
  dimensions:
    - [dim_dt, category, brand]

Key technique: dimension: modifier forces each component measure to evaluate at its required grain inside the SUM(). The compiler generates CTEs for each grain and joins them.

Product lifecycle tracking

Track product age from first sale, classify by lifecycle stage, and compute rolling averages that adjust for new products.

# First sale date per product (restricted to product grain)
first_sale_raw:
  type: measure
  formula: 'MINIF({dt_date}, {sales: {+d: dt_date}} > 0)'

# First sale date, looking back up to 6 years
first_sale:
  type: measure
  formula: '{first_sale_raw: p6y}'
  dimensions:
    - [dt_week, product]

# Weeks since launch
weeks_since_launch:
  type: measure
  formula: 'datediff(week, {first_sale}, {Dim Calendar}.dt_week)'
  dimensions:
    - [dt_week, product]

# Flag: product has 2+ years of sales data
has_2yr_data:
  type: measure
  formula: 'IIF(MAX({weeks_since_launch: {+d: dt_week}}) > 104, 1, 0)'
  dimensions:
    - [product]

# Total sales in first 2 years
first_2yr_sales:
  type: measure
  formula: |-
    SUMIF({sales: {+d: dt_week}},
          {weeks_since_launch: {+d: dt_week}} >= 0
          AND {weeks_since_launch: {+d: dt_week}} < 104)
  dimensions:
    - [product]

# Rolling 4-week average, adjusted for product age
weekly_avg_4w:
  type: measure
  formula: |-
    DIVIDE({sales: p4w},
           IIF({weeks_since_launch: {dimension: [product, dt_week]}} >= 3,
               4,
               {weeks_since_launch: {dimension: [product, dt_week]}} + 1))

Key techniques:

  • MINIF with {+d: dt_date} finds first sale at day grain, restricted to [dt_week, product].
  • Custom dt-macro p6y limits the lookback window (see Multi-level aggregation with +d Custom macro definitions).
  • datediff against {Dim Calendar}.dt_week computes age using the calendar dataset.
  • SUMIF with {+d: dt_week} filters to weeks within the first 104 weeks (2 years).
  • Rolling average denominator adjusts for products younger than 4 weeks.

RFM segmentation with percent_rank

Full RFM (Recency, Frequency, Monetary) segmentation using percent_rank() in measure formulas and CASE-based scoring.

# Monetary: MAT sales (moving annual total)
monetary:
  type: measure
  formula: '{sales: mat}'
  dimensions:
    - [dim_dt, customer_id]

# Recency: last purchase date
recency:
  type: measure
  formula: 'MAXIF({dt_date}, {monetary: {+d: dt_date}} > 0)'
  dimensions:
    - [dim_dt, customer_id]

# Frequency: number of active sales days
frequency:
  type: measure
  formula: 'DISTINCTCOUNTIF({dt_date}, {monetary: {+d: dt_date}} > 0)'
  dimensions:
    - [dim_dt, customer_id]

# Percentile ranks
recency_pct:
  type: measure
  formula: 'percent_rank() over (order by {recency} desc)'
  dimensions:
    - [dim_dt, customer_id]

frequency_pct:
  type: measure
  formula: 'percent_rank() over (order by {frequency} asc)'
  dimensions:
    - [dim_dt, customer_id]

monetary_pct:
  type: measure
  formula: 'percent_rank() over (order by {monetary} asc)'
  dimensions:
    - [dim_dt, customer_id]

# Scores (1-5 scale)
recency_score:
  type: measure
  formula: |-
    CASE
      WHEN {recency_pct} >= 0.8 THEN 5
      WHEN {recency_pct} >= 0.6 THEN 4
      WHEN {recency_pct} >= 0.4 THEN 3
      WHEN {recency_pct} >= 0.2 THEN 2
      ELSE 1
    END
  dimensions:
    - [dim_dt, customer_id]

# (frequency_score and monetary_score follow the same pattern)

# Segment classification
rfm_segment:
  type: measure
  formula: |-
    CASE
      WHEN {recency_score} <= 2 AND {frequency_score} <= 2 THEN 'Hibernating'
      WHEN {recency_score} <= 2 AND {frequency_score} <= 4 THEN 'At Risk'
      WHEN {recency_score} <= 2 AND {frequency_score} <= 5 THEN 'Cannot Lose Them'
      WHEN {recency_score} <= 3 AND {frequency_score} <= 2 THEN 'About to Sleep'
      WHEN {recency_score} <= 3 AND {frequency_score} <= 3 THEN 'Need Attention'
      WHEN {recency_score} <= 4 AND {frequency_score} <= 1 THEN 'Promising'
      WHEN {recency_score} <= 4 AND {frequency_score} <= 3 THEN 'Potential Loyalists'
      WHEN {recency_score} <= 4 AND {frequency_score} <= 5 THEN 'Loyal Customers'
      WHEN {recency_score} <= 5 AND {frequency_score} <= 1 THEN 'New Customers'
      WHEN {recency_score} <= 5 AND {frequency_score} <= 3 THEN 'Potential Loyalists'
      ELSE 'Champions'
    END
  dimensions:
    - [dim_dt, customer_id]

Key techniques:

  • percent_rank() over (...) inside measure formulas — window functions are valid in .dml formulas.
  • All RFM measures restricted to [dim_dt, customer_id] grain — the dim_dt system variable makes them work at any time grain.
  • MAXIF / DISTINCTCOUNTIF with {+d: dt_date} for recency and frequency calculations.
  • CASE expressions compose scores into named segments.

Product power ranking with cumulative distribution

Classify products into tiers (Top 50%, Top 80%, Top 95%) using window functions for cumulative sum.

# Product rank by total first-2-year sales
product_power_rank:
  type: measure
  formula: 'rank() over (order by {first_2yr_sales} desc)'
  dimensions:
    - [product]

# Tier classification via cumulative distribution
product_tier:
  type: measure
  formula: |-
    CASE
      WHEN SUM({first_2yr_sales}) over (order by {first_2yr_sales} desc)
           <= 0.50 * SUM({first_2yr_sales}) over () THEN 'Top 50%'
      WHEN SUM({first_2yr_sales}) over (order by {first_2yr_sales} desc)
           <= 0.80 * SUM({first_2yr_sales}) over () THEN 'Top 80%'
      WHEN SUM({first_2yr_sales}) over (order by {first_2yr_sales} desc)
           <= 0.95 * SUM({first_2yr_sales}) over () THEN 'Top 95%'
      ELSE 'Others'
    END
  dimensions:
    - [product]

Key technique: SUM() over (order by ... desc) computes a running total; SUM() over () computes the grand total. Their ratio gives cumulative distribution for Pareto-style classification. All restricted to [product] grain.
