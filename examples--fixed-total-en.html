-d retains the month filter; -df removes it for that measure. Both can display January only. Check the denominator's population separately from the output row population.

Compare the same data #

Region a has January sales 10 and February sales 20. Region b has January sales 30. After selecting January:

Region Month Sales -d region total -df region total
a 2024-01-01 10 10 30
b 2024-01-01 30 30 30

Region a's share can therefore be 10/10 or 10/30, depending on the business definition. Without a month filter both region totals are 30; a's January and February rows retain sales 10 and 20 respectively.

Save both definitions, then change the query #

The model defines region_selected: '{sales: {-d: month}}' and region_all_months: '{sales: {-df: month}}'. Here month is an ordinary ISO-formatted string, not the automatic time context dim_dt.

完整文件 / Complete file: fixed/model.dml 
dialect: duckdb
F:
  type: dataset
  table: FACT
  dimension: [id]
  columns:
    id:
    region:
    month:
    amount:
  measures:
    sales: SUM({amount})
region_selected:
  type: measure
  formula: '{sales: {-d: month}}'
region_all_months:
  type: measure
  formula: '{sales: {-df: month}}'
running_sales:
  type: measure
  formula: 'SUM({sales}) OVER (ORDER BY {month} ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)'
  dimensions:
    - [month]
完整文件 / Complete file: fixed/setup.sql 
CREATE TABLE FACT(id INTEGER,region VARCHAR, month VARCHAR,amount INTEGER); INSERT INTO FACT VALUES (1,'a','2024-01-01',10),(2,'a','2024-02-01',20),(3,'b','2024-01-01',30);
完整文件 / Complete file: fixed/january.sql 
SELECT region, month, AGG(sales), AGG(region_selected), AGG(region_all_months) FROM MODEL WHERE month='2024-01-01' GROUP BY region,month ORDER BY region,month
完整文件 / Complete file: fixed/unfiltered.sql 
SELECT region, month, AGG(sales), AGG(region_selected), AGG(region_all_months) FROM MODEL GROUP BY region, month ORDER BY region,month

The query chooses which months to display without changing the model. The verifier compares every column and the full row set, checking that -df does not restore February output rows.

Keep the demonstrated boundary #

This example uses known region/month groupings, not dynamic pivot axes or an automatic subtotal API. Ordinary-field behavior does not verify removal of a dim_dt time grain. For time queries, read the cumulative KPI context before substituting fields.

Run and interpret the checks #

Download the complete project and run verify.py as described in its README. It needs your existing dmlc, Python and DuckDB. The script creates a practice database only in the new output directory you specify. The shared verifier records results and diagnostics there.

This example was checked on DuckDB with dmlc 0.3.16, build 2026-11-13. The executable fingerprint and case statuses are in verification-summary.json in the download. Database validation and subsequent execution are independent operations; they do not guarantee a shared snapshot. Verify other engines separately.
