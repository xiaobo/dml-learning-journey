Replay the examples #

Download the project. From the extracted directory, use Python 3 with the example's duckdb==1.5.5 dependency and your already-installed compiler:

py verify.py --dmlc C:/path/to/dmlc.exe --output C:/path/to/new-practice-output

Replace both paths. The output directory must not exist; use a new one for each replay. The script creates its own practice database and local connection configuration there and does not read business data. Do not use Python -O, which disables assertions. Non-Windows users can invoke their Python 3 executable instead of py.

Successful replay ends with passed case statuses and records results.json, raw diagnostics and generated SQL under the output directory. Expected failure cases must fail with their specified diagnostics before repair succeeds. The package README also gives JDBC invocation details. It includes readable sources and expected outputs, not compiler binaries or third-party runtimes. The JDBC checks additionally need a JDK and the matching installed jars.

Compilation, live validation, execution and result comparison are separate checks. Deliberately invalid cases must produce the expected failure, then pass after repair. Before substituting your tables, check complete keys, time fields, grouping and filter scope.

A successful example on one database does not establish every dialect, metric or query grain. The language reference owns syntax; these guides show specific tasks with reproducible answers.
