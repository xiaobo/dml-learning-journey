怎样取得交易发生时有效的价格或等级？

用事件日期匹配有效期，并保持同一对象的区间不重叠。 本例使用 [valid_from, valid_to)：包含起点，不包含终点。

交界点应该匹配哪一条？ #

标签 有效期 事件日期 金额
Jan [2024-01-01, 2024-02-01) 2024-01-01 10
Feb [2024-02-01, 2024-03-01) 2024-02-01 20

2月1日已离开 Jan 区间，属于 Feb。查询返回 Feb 20、Jan 10，各事件只匹配一次。

把查找规则放进模型 #

目标数据集声明 dimension: [id, 'range(valid_from, valid_to)']。事实中的 pk({id}, {event_date}).{D}.label 同时提供对象编号和发生日期。

完整文件 / Complete file: range/model.dml 
dialect: duckdb
D:
  type: dataset
  table: DIM
  dimension: [id, 'range(valid_from, valid_to)']
  columns:
    id:
    valid_from:
    valid_to:
    label:
F:
  type: dataset
  table: FACT
  dimension: [fid]
  columns:
    fid:
    id:
    event_date:
    amount:
    label: 'pk({id}, {event_date}).{D}.label'
  measures:
    sales: SUM({amount})
完整文件 / Complete file: range/setup.sql 
CREATE TABLE DIM(id INTEGER, valid_from DATE,valid_to DATE,label VARCHAR); INSERT INTO DIM VALUES (1,'2024-01-01','2024-02-01','Jan'),(1,'2024-02-01','2024-03-01','Feb'); CREATE TABLE FACT(fid INTEGER,id INTEGER,event_date DATE,amount INTEGER); INSERT INTO FACT VALUES (1,1,'2024-01-01',10),(2,1,'2024-02-01',20);
完整文件 / Complete file: range/normal.sql 
SELECT label, AGG(sales) FROM MODEL GROUP BY label ORDER BY label

将标签替换为价格或等级时，仍要明确生效时间与事件时间的含义。本例证明相邻、有限区间的匹配，不代表开放终点、任意多对多关系或分摊规则已经验证。

验证重叠，再修复 #

脚本将 Jan 的终点改为2月2日，使2月1日同时落入两个区间。--validate-only 检出 DIMENSION_NOT_UNIQUE。恢复2月1日终点后，验证和两行结果重新通过。

正确修复应来自业务有效期规则，不能任意保留其中一条匹配记录来掩盖冲突。

运行与验证范围 #

下载完整项目，按包内 README.md 运行 verify.py。需要已有的 dmlc、Python 和 DuckDB；脚本只在你指定的全新输出目录创建练习库。所有案例共用一个入口，结果与诊断保存在输出目录。

本例在 dmlc 0.3.16、2026-11-13 构建的 DuckDB 连接上验证。编译器指纹、用例列表和状态见包内 verification-summary.json。数据库验证和随后执行是独立操作，不保证同一快照。其他引擎需单独验证。
