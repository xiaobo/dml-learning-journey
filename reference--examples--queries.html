The introductory examples use the shared sales model. The shared model supplies sales and the listed transaction columns; it does not create source data. Date examples use the current date, so a historical fixture may return no rows.

Example prerequisites: Basic queries, time comparisons of sales, rankings, shares and product counts use that model. The expense examples additionally require an expense measure; outstanding-balance examples require customer and outstanding; account-growth examples require account and revenue. Those are adaptation fragments, not runnable additions to the shared model. For an executable dataset with fixed dates and expected results, use the checked sales exercise.

Basic queries #

Total sales #

SELECT AGG(sales) FROM MODEL

Sales by region #

SELECT region, AGG(sales) FROM MODEL GROUP BY region

Sales this month #

SELECT AGG(sales) FROM MODEL WHERE dt_month = date(current_date, 'start of month')

Sales this month by region #

SELECT region, AGG(sales)
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY region

Detail query — paid transactions #

SELECT dt_date, transaction_id, amount, is_paid
FROM MODEL.transactions
WHERE is_paid = 1
ORDER BY dt_date DESC

Time modifiers #

This month vs last month #

SELECT dt_month,
       AGG(sales) as this_month,
       AGG(sales, 'pp') as last_month,
       AGG(sales, 'pop') as mom_rate
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY dt_month

This month vs same month last year #

SELECT dt_month,
       AGG(sales) as this_month,
       AGG(sales, 'ya') as last_year_month,
       AGG(sales, 'yoy') as yoy_rate
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY dt_month

Year-to-date growth #

SELECT dt_date,
       AGG(sales, 'ytd') as ytd_sales,
       AGG(sales, 'ytd', 'ya') as ytd_last_year,
       AGG(sales, 'ytd', 'yoy') as ytd_growth
FROM MODEL
WHERE dt_date = date(current_date)
GROUP BY dt_date

Note the stacking: 'ytd', 'ya' means "year-to-date one year ago".

Rolling 12-month total #

SELECT dt_month, AGG(sales), AGG({sales: mat}) AS rolling_sales
FROM MODEL
GROUP BY dt_month
ORDER BY dt_month DESC
LIMIT 12

Specific months/quarters #

-- August this year
SELECT AGG(expense) FROM MODEL WHERE dt_month = date(current_date, 'start of year', '+7 months')

-- Q2 this year
SELECT AGG(expense) FROM MODEL WHERE dt_quarter = date(current_date, 'start of year', '+1 quarter')

Nested modifiers in .dml #

# In model.dml
sales_ytd:
    type: measure
    formula: '{sales: ytd}'

sales_ytd_last_year:
    type: measure
    formula: '{sales: {ytd: ya}}'

-- In query
SELECT dt_date, AGG(sales_ytd), AGG(sales_ytd_last_year)
FROM MODEL
WHERE dt_date = date(current_date)
GROUP BY dt_date

Key points: Time modifiers need a resolved time context and must satisfy macro prerequisites; time filters can supply context too. yoy and pop return decimal growth rates (0.15 = 15%). pp and ya return the absolute previous-period value. Prefer modifiers over manual date math.

Rank and filters #

Top 10 products by sales #

SELECT product, AGG(sales)
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY product
ORDER BY AGG(sales) DESC
LIMIT 10

Using rank modifier #

SELECT product, AGG(sales), AGG({sales: rank}) AS sales_rank
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY product

{sales: rank} returns the rank of each product's sales within the query result (descending).

Rank within the selected period #

SELECT product,
       AGG(sales) as period_sales,
       AGG({sales: rank}) as selected_period_rank
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY product

The query already groups only by product. Keep the month filter and rank sales directly; no time-grain removal is needed. Removing a grouping field is not the same as removing the time filter.

Filtering by rank #

SELECT product, AGG(sales)
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY product
HAVING AGG({sales: rank}) <= 10

HAVING filters after aggregation, so rank is available there.

HAVING clause — customers with outstanding balance #

SELECT customer, AGG(outstanding)
FROM MODEL
GROUP BY customer
HAVING AGG(outstanding) > 0

Key points: rank returns RANK() OVER (ORDER BY measure DESC). rank_asc returns ascending rank. Use -d to remove time or other dimensions before ranking. Combine with HAVING for dynamic Top N filtering.

Share of total (pot) #

SELECT product, AGG(sales) AS sales,
       AGG(sales, 'rank') AS sales_rank,
       AGG({sales: pot}) AS share_of_total
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY product
ORDER BY AGG(sales, 'rank')

pot is measure / grand. Cumulative Pareto share is not a system fn-macro; use OVER() in Model Query SQL when you need a running total.

Dimension without dt #

Sales by region (all time) #

SELECT region, AGG(sales) FROM MODEL GROUP BY region

Product share by region (no time grouping) #

SELECT region, product, AGG(sales)
FROM MODEL
GROUP BY region, product

Selected period versus all history #

-- Selected month: retain the month filter.
SELECT region, product, AGG(sales) AS selected_period_sales
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY region, product

-- All history: remove the month filter, retain the same grouping.
SELECT region, product, AGG(sales) AS all_time_sales
FROM MODEL
GROUP BY region, product

Run these as separate queries. -d removes grouping, not the time filter. These queries do not group by time, so they do not need -d: dim_dt. Applying time-grain removal to individual measures here is rejected by the checked compiler. For denominator-specific removal of grouping and filters, see dimension and filter modifiers.

Period conversion #

SELECT dt_year,
       AGG({sales: {dim_dt as quarter: pp}}) as last_quarter_at_quarter_grain
FROM MODEL
WHERE dt_year = '2024-01-01'
GROUP BY dt_year

dim_dt as quarter means the pp modifier operates at quarter grain, even though the query groups by year. The measure is evaluated at the pivoted grain (quarter), then the result is joined back to the query grain (year).

Note: dim_dt as <grain> is only useful when the pivoted grain differs from the query's time grain. If the query already groups by dt_quarter, then dim_dt as quarter: pp is rejected as unnecessary — use AGG({sales: pp}) directly instead.

Key points: Queries without time filters analyze all historical data. -d: dim_dt removes the active time field from a measure's evaluation dimension (use dim_dt to target the active time field, not a specific field like dt_date — -d can only remove dimension fields that are in the current query dimension). dim_dt as <grain> changes the time granularity for one measure reference. Be careful with mixing: a measure without time may not be comparable to a measure with time in the same row.

Comparison patterns #

Period-over-period #

SELECT AGG(sales) as this_month, AGG(sales, 'pp') as last_month
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')

Growth rate by account #

SELECT account, AGG(revenue) as current, AGG(revenue, 'pp') as previous
FROM MODEL
WHERE dt_month = date(current_date, 'start of month')
GROUP BY account
HAVING AGG(revenue, 'pop') > 0.10  -- 10% growth

Year to date vs last year #

SELECT AGG(sales, 'ytd') as this_ytd, AGG(sales, 'ytd', 'ya') as last_ytd
FROM MODEL
WHERE dt_date = date(current_date)
GROUP BY dt_date

Conditional counts #

Modifiers apply to measures, not columns. Use {+d: product} on the measure inside the condition:

-- Count of products with per-product sales above threshold
SELECT DISTINCTCOUNTIF(product, AGG({sales: {+d: product}}) > 1000) as prod_cnt FROM MODEL

Or define once in .dml: formula: 'DISTINCTCOUNTIF({product}, {sales: {+d: product}} > 1000)' then SELECT AGG(high_sales_product_count) FROM MODEL.
