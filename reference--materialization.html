Materialization declarations

This page owns type: materialize, its grouping key, attributes, and measure selection. Choose a materialization grain covers design decisions. Materialization examples shows declaration fragments.

Materialize definition (type: materialize)

<name>:
    type: materialize
    parameters:                         # stored-procedure parameters
        <param>: <column_name>
    filters:                            # materialize-level filters
        <column>: <value>

    allows: [<materialize_name>]        # allowed materialize tables

    dataset: <dataset_name>      # optional, for direct dataset materialize
    dimension: [col1, col2]      # materialization grain — grain keys only
    dimension_columns:           # functionally dependent attribute columns
        <col>: <formula>          # (1:1 with grain keys, not grain themselves)

    measures: [<measure1>, <measure2>]  # measures to materialize

dimension: vs dimension_columns: — dimension: contains the materialization dimension: its dimension fields are the grain keys that uniquely identify a row (the compiler's GROUP BY keys). dimension_columns: lists attribute columns derivable from those grain keys — e.g. store_name depends on store_id, region_code depends on store_id. The compiler carries dimension_columns: through the GROUP BY without treating them as grain. Placing a derivable attribute in dimension: causes a compile error ("can be derived from [...], should it be moved to dimension_columns instead?").

No-formula inheritance — a dimension_columns: entry without a formula: inherits the column from the source dataset. The column must exist in the source dataset's columns: (else "not found from relate dataset(s)"). When the materialize grain is coarser than the source dataset's dimension, the compiler checks derivability: a column that varies at the finer source grain fails with "definition from dataset [...] cannot be derived from dimension [...], please advise". When the materialize grain matches the source dataset's dimension, any source column is accepted (1:1 row mapping).

Formula scope — when a dimension_columns: entry has a formula:, the formula may only reference pk() chain lookups and the materialization dimension's own fields — not source dataset columns or measures (errors "not defined, did you mean …?").

Constraints — one of:

  • dimension + measures (measure-list form), or
  • dataset + dimension + dimension_columns (dataset-scoped form), or
  • dataset only (inherits grain from dataset).

Materialization examples contains declaration patterns. There is no measure-level materialize: true flag — the compiler rejects it (undefined modifier 'materialize', see Troubleshooting index P64). Declaration forms: this section, and dataset-level materialize: <name> in model structure.
